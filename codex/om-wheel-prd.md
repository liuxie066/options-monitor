## 1. 目标、边界与成功信号

补齐 CC 被指派 → CSP 监控 → Put 被指派这一半，与已有 CSP → CC 衔接。
系统只负责监控、推荐、关联和事实跟踪，用户手动交易。启动监控不是下单授权。

成功信号：
- S1：普通 CSP/CC 的真实指派分别自动进入同标的 Wheel CC/CSP。
- S2：Wheel 内两个方向均可由用户决定启动下一阶段或永久结束对应分支。
- S3：已确认本金、Delta、排序与容量规则生成可解释推荐；无候选/缺数据明确等待。
- S4：部分指派可独立推进，未转换部分不受影响；成交归属和重复事件不造成重复占用。
- S5：历史普通 CC 不补建；现有 Wheel CC 同批切换新的候选 Delta 区间。

不做：自动交易、Wheel 内无确认跨阶段、跨标的轮转、结束后恢复、历史 CC 补建、
回测平台、新通用评分框架、普通 CSP/CC 策略改造或全账本重构。
部分指派属于首版承诺，不能为了最小化删掉。

## 3. 入口、主线与操作

### 3.1 四种入口/转换

| 触发 | 后续 | 人工确认 |
|---|---|---|
| 普通 CSP 被实际指派 | 对实际接货部分自动启动同标的 Wheel CC | 无 |
| 普通 CC 被实际指派 | 对实际卖出部分自动启动同标的 Wheel CSP | 无 |
| Wheel CSP 被实际指派 | 已接货部分等待决定是否进入 Wheel CC | 有 |
| Wheel CC 被实际指派 | 已卖出部分等待决定是否进入 Wheel CSP | 有 |

保留现有账户/市场启用及事实完整性前提，不因新增入口扩大到账户全部历史记录。
已有非 Wheel Put/Combo 启动及其他策略行为保留；本次不借机重构其他组合策略。
不存在通过“股票价内、到期、持仓消失”直接猜测指派的路径。

### 3.2 阶段内

监控 → 合格推荐 → 用户手动交易 → 真实成交且归属明确 → 持仓监控：
- 未成交继续监控；推荐不等于交易或预留的真实成交。
- 已有成交/有效交易意图的对应额度，不重复推荐占用。
- 到期未指派或已平仓后，按真实事实释放对应占用，继续本阶段。
- 指派后按实际转换数量进入 §3.1，不把推荐中的数量/费用当实际值。

### 3.3 用户决定

待确认信息包含同标的、来源事件、已转换数量、对应成本/卖出净收入、
下一阶段本金约束与 Delta 参数，以及仍在原阶段的数量。
参数明确区分当前采用值与推荐时估算，不新增独立页面或通知系统作为产品要求。

- **启动轮转**：为本次已转换部分启动下一阶段监控；不是下单或后续成交归属授权。
- **结束轮转**：对应分支永久结束，不支持回来启动；保留事实与历史收益。
- 未回应：保持待确认，不生成下一阶段推荐。
- 普通策略自动入口：告知已启动及其依据，不额外要求确认。
- 结束/重复处理不能影响尚在持仓监控的其他部分；同一指派不得再次启动已结束分支。

### 3.4 部分指派

按已转换数量独立推进，不等待整批。例：两张 CC 仅一张被指派，
已卖出部分进入/等待下一阶段，另一张仍监控原持仓。
Put 方向同理；资金、股票、成本和收益按对应数量归属，不能把整批卖出款重复给多个分支。
比较/推荐以实际合约乘数计算，不硬编码 100；不足一张的数量不擅自跨批次凑整。

## 4. 策略

### 4.1 本金边界

Wheel CC：
```text
strike × 覆盖股数 − 预计股票卖出费用 ≥ 对应股票接货成本
strike ≥ 当前股价
```

Wheel CSP：
```text
strike × 接货股数 + 预计接货费用 ≤ 上次卖出对应股票的实际净收入
strike ≤ 当前股价
```

接货成本不以历次 Put/Call 权利金摊低；卖出净收入也不加历史权利金提高上限。
新接货批次以实际交割及费用形成新成本。历史净收入是价格预算锚点，不证明当前可用现金充足。
还须通过既有实际账户资金/股票覆盖校验，不能重复分配容量。

### 4.2 筛选及参数

两侧目标绝对 Delta 为 0.30，允许 `0.25 ≤ |Delta| ≤ 0.35`（含端点）。
使用合约 Delta，不混用空头持仓的方向符号。Delta 缺失不补猜。
这是准入区间；区间内不以距离 0.30 最近作为第一排序。

Wheel CC 保留其余现有规则。
Wheel CSP 复用普通 CSP 公共行情、期限、流动性、收益/费用、波动率和容量逻辑；
本金/strike、Delta 和排序按本文专属规则。参数独立维护，不动态跟随普通策略配置。
两侧参数独立，初始 Delta 区间一致。不是把两侧所有业务参数强制绑定。
普通 CSP/CC 不改；没有合格合约就等待，禁止自动放宽本金或 Delta。

### 4.3 排序与展示

Wheel CC：通过硬约束后，按“假设本次被叫走后的生命周期净收益”降序，
保留既有经济口径及次级排序，不改成普通 CC 的单期收益率优先。

Wheel CSP：
```text
回补现金结余
= 上次卖出对应股票的净收入
− 本次接货总支出（含预计接货费用）
+ 本阶段此前已实现的 Put 净收益
+ 本次 Put 净权利金
```

通过硬约束后按上述结余降序，再复用对应侧既有次级排序。
比较须在同账户、同标的、同一对应回补范围内进行；此前已实现收益是共同常数。
不得把完整父批次收益复制给每个部分分支，不混入其他轮转任务的资金。
本次净权利金 = 建议卖出限价 × 合约乘数 − 预计完整期权卖出费用。

CC 的条件生命周期净收益与 CSP 的条件现金结余分别命名：
后者不等于按市价计算的总利润；两者都不是概率加权期望收益。
接回股票仍可能浮亏，Delta 区间和本金边界不保证盈利或一定被指派。

## 5. 数据及成交归属

| 数据 | 唯一依据/派生边界 | 不足时 |
|---|---|---|
| 现价、合约身份/乘数、Delta | 既有 OpenD 数据链路与合同 | 不使用猜测值给正式推荐 |
| 成交、交割、实际费用 | 券商事实经既有账本处理；保留合法人工确认事实路径 | 不把推荐或到期推断当事实 |
| 对应成本、卖出净收入 | OM 按事实核算的批次/数量归属 | 归属冲突不混用账户平均值 |
| 当前可用现金和覆盖股票 | 既有物理账户容量规则 | 不把历史卖出款当当前现金 |
| 预计费用 | 现有版本化费用估算，明确标为预计 | 关键费用不可得时不假设为零 |
| 分支状态与归属 | OM 生命周期记录、有效意图和明确用户操作 | 不按同标的模糊分配 |

时间/新鲜度、汇率、费用币种和净收益换算沿用对应公共合同，不再平行计算。
“无合格候选”和“数据不足无法判断”必须区分；历史估算不能覆盖真实成交。

成交关联沿用现有 Wheel CC：
- 唯一匹配有效意图且校验通过 → 自动关联。
- 没有匹配或同时匹配多个 → 不猜，由用户确认，可保持不属于 Wheel。
- 未归属的真实持仓依然参与账户占用，不漏算资金或股票。
- 用户点“启动轮转”不意味着之后所有同标的交易都属于本分支。

## 6. 存量与启用

- 不补建历史普通 CC 的 Wheel CSP。
- 自动新入口按指派实际发生时间与功能启用时间判断，不按入库时间误启动历史事件。
- 现有 Wheel CC 任务本次开发一起适配；启用后的下一次有效扫描使用新区间，无需重建。
- 旧推荐保留历史，不作为新区间下的当前有效推荐。
- 已成交持仓照常监控，不因 Delta 后来超区间自动退出；手动挂单不自动撤改。
- 发布、部署、实际启用是不同授权边界；本文不授权任何一步。

示例（假设乘数 100，其他条件均通过）：
上次卖出净收入 10,000；A 接货总支出 9,800、本次净权利金 200，结余 400；
B 接货支出 9,500、净权利金 150，结余 650。两者 Delta 合格则 B 优先。
这些是假设情景数值，不代表真实账户、回测结果或已实现利润。
