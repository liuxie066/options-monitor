# v3.5.1 release coverage erratum

Corrected on 2026-11-13 for [issue #798](https://github.com/liuxie066/options-monitor/issues/798).
The current-tree [coverage manifest](v3.5.1.json) corrects the implementation
attribution of four unchanged release notes. The published `v3.5.1` tag and
GitHub Release are unchanged. The original manifest remains available in
release commit `b42c25077`.

| Release note | Original attribution | Corrected attribution |
| --- | --- | --- |
| Bot context, bounded execution and durable memory | `40243377` | `3e496cf`, `8a23ba3` |
| OpenD header account and environment evidence | `8a23ba3` | `40243377` |
| SQLite locks and file permissions | `32debda` | `40243377` |
| Trade intake and notification recovery | `3e496cf` | `40243377`, `32debda`, `3e496cf` |

The implementation diffs establish these attributions:

- `3e496cf` introduces the Bot context, memory and execution boundaries and
  freezes notification outbox payloads. It therefore supports both the Bot
  note and part of the notification recovery note.
- `8a23ba3` bounds Bot SQLite writer contention by the execution deadline.
- `40243377` preserves protobuf header presence for `accID` and `trdEnv` in
  `src/infrastructure/futu_trade_push.py`; preserves SQLite locking while
  securing permissions in `src/infrastructure/private_storage.py`; and
  implements intake and receipt recovery in `src/application/trades/`.
- `32debda` preserves the retry window for late order association in
  `src/application/trades/inbox.py`.

Commit membership, release-note text, design evidence and the reviewed release
range are unchanged. The structural coverage validator checks those contracts;
it does not establish the semantic correctness of manual attribution.
