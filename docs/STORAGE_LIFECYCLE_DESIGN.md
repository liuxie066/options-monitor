# OM 存储、备份与清理整体方案

状态：设计提案，部分开发验证已完成。生产接入尚未实施。容量数字来自单一生产容器的时点测量，用于排序和设计验证。保留值、目标盘和生产执行需按实际环境确认。

## 1. 先解决什么

2026-11-18 北京时间 18:03，受测容器的 OM 为 4.6.43，容器可见根文件系统已用 96%，剩 4.7 GiB。OM 运行根可读部分约 20.4 GiB。优先处理两处：

| 证据 | 决定 |
| --- | --- |
| 扫描目录占 12.3 GiB。对 1,665 个目录做普通清理预览，14 天或最近 200 次给出 788 个候选、5.18 GiB；30 天或最近 200 次只给出 2 个候选、81 KiB。 | 优先核对第 15 至 30 天原始批次的用途。保留重要历史，给普通批次建立明确退出条件。两次预览均未证明候选可以删除。 |
| 可读维护目录抽样约 4.24 GiB。11 份数据库中经哈希确认 4 份内容重复，约 559 MiB 逻辑体积。 | 按维护批次整理，复用相同内容的归档副本，但各批次清单和回执独立保留。当前不能据此承诺物理释放量。 |
| 共享压缩对象 173 MiB。四个主要业务库主文件合计约 606 MiB。 | 继续用现有压缩格式。先建立最小系统恢复包，再补共享对象回收。606 MiB 仅用于估算，不含依赖、旁文件或工作空间。 |
| 容器内未发现独立备份挂载，也未发现名称明显对应 OM 的备份调度。部分维护目录无读权限。 | 已有文件视作历史快照，直到找到完整恢复证据。宿主机和阿里云后台备份状态均未知。 |

### 内容核对后的优先级调整

同一容器的内容核对覆盖 75 个运行路径库表、4 个历史库、1,665 个扫描目录及三份维护清单的 39 个文件哈希。按内容调整优先级：

1. **扫描先处理大文件。** 开仓快照约 6.81 GiB，组合收益快照约 3.17 GiB，取数回执约 1.17 GiB，均为逻辑体积。两类候选快照各 889 份，集中在 453 个批次；研究读取候选快照，封存清单也绑定其内容和依赖。近 48 小时已有开仓 v5，24 份平均 3.9 MiB；同期 v3 的 52 份平均 10.8 MiB。两组负载不同，不能当作严格压缩率，足以把首要动作改为继续观察 v5 写入，而不是立刻再换格式。组合收益 v4 同期 76 份平均 4.3 MiB，下一步验证跨快照的冻结输入有多少能安全复用。不得直接拆旧批次或重写已有哈希。对回执先测字段占用与引用，再决定哪些正文能在已封存对象中重建。
2. **Bot 库先处理控制审计的大正文。** 845 条 inbound_command_audit 的 JSON 约 190 MiB，其中 response_json 约 145 MiB，action_json 约 43 MiB。普通 bot_runs 事件远小于控制审计。先追踪重放对响应正文的依赖，保留身份、状态、校验值及幂等和投递证据；仅对确认完成且过重放窗口的正文试验归档。现有完整库继续进入恢复备份，直到精简合同验证通过。
3. **两个业务库的大头是证据，不能按状态删。** 账本有 753 条交易事件、267 个投影 lot，生命周期证据 2,455 条，raw_json 约 60 MiB；绩效估值和汇率证据就在账本库。成交收件箱有 241 条已处理记录及 25,318 条证据，两个主要证据 JSON 字段合计约 45 MiB。已处理状态不等于历史证据可弃；若要缩小，先用内容去重或归档证明保留审计、对账和历史复算能力。
4. **决策历史要测输入与结果的实际重叠。** 1,336 条决策，其中 1,266 条成功，覆盖 2026-09-08 至 11-18。input_json 和 payload_json 各约 99 MiB，逐条解码时常见字段高度相似。字段相似不等于内容相同，先用实测对照证明可重建及 hash/读取语义兼容，保留当前不可变合同。
5. **维护快照先整批搬。** 4.6.4、其重试批次和 4.6.7 三份清单的 39 项回读哈希全部匹配。它们是首批适合验证归档恢复的对象，尚未证明可删除。其余批次中，修复证据、迁移原件与回滚快照有不同用途，权限未知和缺清单者继续保护。

## 2. 每种数据写什么、留多久

### 存储必要性表

| 对象 | 写入方和读者 | 必须保存什么 | 可减少什么与保留边界 |
| --- | --- | --- | --- |
| 账本、成交证据、同步进度 | 账本与摄取流程写；对账、持仓、绩效、恢复读取 | 交易事实、费用、指派、证据来源、处理进度 | 可重建投影先验证重建；证据正文只在对账和历史复算等价时去重。已处理状态不授予删除资格。 |
| 开仓与组合收益快照 | Tick 写；快照清单、历史研究、回放读取 | 当时的决策输入、规则、结果及校验绑定 | 同一批已冻结的事实可存引用，前提是能精确重建且归档自带依赖。优先量化组合收益，开仓先跟踪 v5。 |
| 行情取数回执和共享对象 | 行情采集及封存写；封存校验、研究及诊断读取 | 来源、时点、状态、摘要、引用及唯一错误证据 | 成功正文已完整封存在共享对象时可验证引用化；失败或部分成功正文先确认仍有诊断依据。共享对象按引用回收。 |
| 决策历史 | 决策历史库写；历史查询及追溯读取 | 可验证的冻结输入、结果和身份 | 逐条量化输入与结果重叠；只有能保留不可变合同、哈希校验和旧版读取时才改格式。 |
| Bot、投递和控制审计 | 控制与通知入口写；重放、对账、诊断和恢复读取 | 投递结果、身份、去重键、未完成及结果不明的操作 | 普通正文与诊断短留。控制响应正文过重放窗口且确认无需在线读取后才可归档。 |
| 报表、缓存和普通日志 | 报表、任务及服务写；运营和排障读取 | 当前结果、故障和业务审计所需证据 | 可验证重建的报表短留，普通日志轮转。审计暂以 14 天在线可读为提案，压缩移出前核实查询能力。 |
| 研究、事故和维护包 | 归档、事故处置及迁移写；研究、恢复及回滚读取 | 完整批次、清单、回执和冻结依赖 | 可去重相同内容，分别保留批次身份；重要归档留第二份独立副本。 |
| 发布、缓存及暂存 | 升级流程写；运行、回滚及待完成任务读取 | 当前版本、已验证回滚版和在途依赖 | 先退役无用途的 release，再清无引用依赖与缓存，暂存单独限额。 |

扫描保留建议为最近 14 天或最近 200 次，再加上 HK/US 各自最后可读的成功扫描、活跃批次、最新指针、待处理投递依赖和已保护的研究及事故批次。先退役逻辑批次，再回收共享对象。

第 15 至 30 天的批次先分类。已有文档定义的归档退役入口保护 30 天或最近 200 次，其限制保持有效。普通清理的 14 天候选只作为容量对照。若后续希望更早腾空间，应先确定消费方需要，批准统一保留合同，再由对应入口实施。现有 run 历史可能服务研究回放、事故检查和配置复盘。配置复盘会依赖每个市场最后一个可读成功批次及其行情对象。

### 压缩验收表

用同一批冻结输入对照旧写法与新写法，覆盖 HK/US、单/多账户、成功/部分成功/失败、普通和大批次。先固定可接受的运行、读取与恢复耗时，再做试验。原始字节和磁盘实际分配字节分开计量，包含共享对象、索引、临时文件及尚未退役的原件。

| 对象 | 测量 | 通过条件 |
| --- | --- | --- |
| 开仓 v5 和组合收益快照 | 单批与每日新增字节、文件数、写入耗时、额外 CPU、读取耗时 | 相同冻结输入得到相同策略决策及通知；研究可读取，归档能独立恢复。v5 现场两组体积只作为观察基线。 |
| 取数回执和共享对象 | 按来源和结果拆出重复正文，统计同批共享前后的实际写入、对象数和峰值 | 成功证据可校验和精确重建，失败与部分成功原因可读；横跨账户、市场和观察时点的引用保持原有隔离。 |
| 决策历史与控制审计 | 逐条计算输入/结果及响应/动作的内容重叠，比较库及旁文件增长、常用查询和重放耗时 | 历史查询、哈希语义、重放与幂等验证通过；旧记录继续可读，恢复验证覆盖精简后的数据。 |
| 封存批次和备份 | 比较压缩体积、原件与副本并存的峰值、归档与恢复时间、实际释放字节 | 可从目标盘校验并独立恢复；退役完成后才计入净节省。优先复用现有 gzip，不为未经证实的收益增加另一种格式。 |

## 3. 系统恢复包放阿里云磁盘

**默认目标**是独立于 OM 运行盘的阿里云备份数据盘。如果已经挂在 OM 运行主机，直接写指定挂载；如果在另一台机器，用现有 SSH 通道交付加密包，由目标端归档和轮换。当前两种拓扑均未确认。每次先检查卷或挂载身份与剩余空间，缺盘即失败。不要回落到同名目录所在的根文件系统。

**备份清单**以有效路径和启用服务为准。最小基线如下：

- 持仓账本、成交收件箱、各启用账户的成交摄取与正股同步状态。两个持仓同步目录还各有 inbox.sqlite3，虽无成交证据记录，仍有 4/3 条 lifecycle 尝试状态，须先追查启用路径和恢复语义。旧 Pi 库及无用户表的旧 trade_inbox.sqlite3 归为历史候选，核对读路径后再决定是否纳入常规恢复包。
- 决策历史、Bot/控制库、在途操作、投递回执和去重状态。
- 配置 YAML、实际覆盖配置、服务声明与 OM 版本。记录绩效证据、其他启用数据源及快照引用的依赖是否独立落盘，若是则纳入。
- 按需引用不可变对象或必要生产批次，不打包整个运行根。凭据用独立密钥库保管，清单记录恢复方法。保存可取得的对应 release；首次演练应验证版本、依赖和密钥都能取回。

**权限与故障隔离**：优先由备份接收端发布并轮换，生产写入身份只能交付新包，不能修改或删除已发布备份。若同机部署暂时做不到，由实施验收记录这项缺口，独立离线副本仍需按约定刷新。外接盘更新并验证后断开。阿里云盘快照可作为额外恢复路径，单独验证权限、取回与恢复能力。

**生成及发布**：列出所有相关写入方，覆盖定时任务、运行中的服务和人工命令。先阻止新任务、排空在途工作，再在有时限的停写窗内用 SQLite Backup API 逐库导出并冻结关联文件。单库一致性不能替代跨库一致性。停写超时、必需文件缺失或中途失败时整批失败，恢复原服务状态并核对。接入独立暂存交接后，可以在取得一致快照时恢复服务，再压缩、加密和传输。现有手动命令尚未拆分停写和发布步骤，应按完整命令时长安排停写。校验后在目标盘发布并读回。生成、目标端读回和独立恢复分别记录，半包和未知状态不计入可用恢复点。

当前开发核心 `stage_offline_backup` 与 `verify_offline_backup` 只处理显式文件清单和已经停写的
独立 SQLite 输入。输入若存在 WAL、SHM 或回滚日志副文件，核心拒绝处理，避免漏掉仍在副文件中的提交。
核心使用私有目录、不覆盖旧恢复点，以清单摘要绑定文件大小与哈希，并检查库完整性。
它只验证逻辑字节预算，目标盘峰值、跨库停写和确认属于外层流程。输出是待加密暂存目录，
还不是可发布恢复点；生产接入必须补上卷验证、加密、独立读回及接管演练。

**保留和恢复目标**：日备 7 个成功日期、周备 4 周、月备 3 个月，重合只存一份。升级前备份留到回滚窗口关闭。暂按最多回退 24 小时、半天内恢复设计。从最新通过目标端读回的**快照时点**计算恢复点年龄，超目标告警。离线副本刷新间隔须另定。首次、每月、关键版本迁移或换密钥后演练，从空环境开始计时，覆盖取密钥和版本、解密、恢复、对账及安全接管。轮换前复核剩余恢复点及可用性，保护最后一份已验证恢复点。

首版轮换预览由 `om service backup-rotation-preview` 提供。它只检查单一系列、同一来源与文件清单范围的显式清单，
匹配发布和恢复回执并重新读回最新已恢复包；没有匹配证据时不输出可删除候选。
受控执行入口 `om service backup-retire` 需要精确计划摘要、显式确认和新回执路径。执行前重新验证候选及保留的恢复点，按包记录删除进度。接收端仍须验证目录权限、挂载、预算和恢复演练后才能上线。

**命名**：恢复点按 UTC 命名，如 `OM/backups/prod/<host>/2026/2026-11-18T021500Z_<host>_full.tar.gz.cms`，升级前用途为 `pre-upgrade`。开发核心使用 OpenSSL CMS 与 AES-256-GCM，写入方仅需接收方证书，恢复需独立保存私钥。完整清单进加密包，外部回执仅保留备份 ID、时间、密文大小和哈希、验证状态。

隔离测试已验证 CMS 密文发布和恢复。发布核心要求预先绑定已挂载卷及设备号，拒绝普通目录或错误设备。
目标端只收密文，先读回哈希，再以不可覆盖的文件名发布。恢复以可信回执中的密文和内部清单摘要为准，
并限制解包条目和字节。运行方还需设置源端暂存预算，覆盖 gzip 明文暂存与密文并存；该核心当前
不负责凭据配置、传输调度或跨主机接收权限，真实目标盘接入尚未实施。正式 CLI 与独立回执见 [Runbook](../RUNBOOK.md#备份与隔离恢复手动)。

## 4. 外接盘怎么归档和退役

按 `OM/archives/research/<市场>/<年>/<市场交易日>_<市场>_<数据集>_<原批次ID>/` 和 `OM/archives/incidents/<年>/` 摆放。维护修复证据单独放 `OM/archives/maintenance/<年>/<UTC时间>_<原维护批次ID>/`。来源不明的文件保留原名登记到 `OM/inbox/legacy/`。先检查源清单、路径、哈希和用途。复制到目的地后读回恢复，旧文件名保留映射。已绑定路径的归档移动后重新验证，不直接改包内结构。

- **run 批次**：优先复用有界 pull、restore、retire 现有入口。归档带上所选 run 及共享对象依赖，恢复回执须绑定目的地和精确批次。退役先出精确预览，经授权后执行。
- **watchlist**：复用 day pack/restore。当前 pack 仍保留原件，新增压缩包本身不能释放空间。退役前验证交易日下游接续和研究读取，再决定新增源退役能力。
- **维护/修复快照**：按原维护批次恢复。检查清单、回滚用途、回执和保留窗口。旧批次整包压缩优先；仅在相同哈希大量出现且恢复路径已验证时，复用已有内容去重方式。无完整清单的批次先留待核实。
- **共享对象**：待逻辑批次退役后，从所有仍保留的有效清单计算引用。使用严格的 `storage-gc-preview --retired-only`，它保护仍存在的清单与行情回执载荷引用。对应的 `storage-gc-retire` 只接受停写树、精确严格预览摘要、候选数量预算与独立回执路径。活跃发布、保护批次、宽限期内及引用未知对象不删。独立归档必须自带依赖，不能继续依靠准备回收的生产对象。
- **临时恢复树**：源退役流程还要求完整恢复树时持续保留。验收及退役终态确认后释放，留下哈希和可核验回执。轮换备份包是独立的删除计划。

## 5. 用预算管总量

已有只读入口 `om research storage-baseline` 输出 `runtime_storage.run_artifacts`，按已知产物和 `other` 汇总文件数、逻辑字节与文件分配块字节。分配块按文件路径累计，可能重复计入硬链接，不含目录本身，也不代表可回收空间。跨批比较应使用同一范围和同一指标。

按每类实际分配字节和文件数计量，记录净增长、空间高水位、实际释放量。为运行、日志、共享对象、暂存、升级、阿里云备份、外接盘归档分别设预算。分区预算还要扣掉非 OM 占用和恢复/升级预留；现有 4.7 GiB 可用空间不足以支持未经估算的大批量同盘复制。

到预警线，先回收已到期且已验证可回收的数据。进一步吃紧时，先停止可选研究、调试导出和重复封存；新批次写入前检查预算。保护集超预算、归档目的地不可用或账本空间受威胁，显式报告阻塞。权威历史持续追加时，还需约定归档后的查询范围或扩容，不能承诺固定容量仍无限保留全部历史。

## 6. 交付顺序和验收

| 顺序 | 需要改什么 | 验收条件 |
| --- | --- | --- |
| A | 固定分类计量和只读清理预览。把每市场成功批次、事故、研究、在途投递及引用列为保护理由。 | 可以解释每个候选为何进入或退出，容量数据可追溯。未知引用阻断该批退役。 |
| B | 增加 OM 一致快照、加密、目标盘验证、回执与恢复入口。复用 SQLite 和系统原有部署能力。 | 从阿里云目标盘取回，空目录解密恢复；账本完整性与投影通过，决策、同步状态、配置可读；对账前自动任务和发送保持关闭。 |
| C | 小批验证现有归档/退役入口，统一外接盘命名；再处理维护批次和旧存量。 | 抽中一批可以从外接盘完整恢复。目标引用闭合，失联时保留现有回执并核对结果，不自动重放。 |
| D | 补可监测的轮换、日志和共享对象回收，配置预算与写入限额。 | 首轮验证最低剩余空间、单批峰值和失败积压上限，包含暂存、加密包、失败重试及恢复副本并存。上线后按适用保留周期复核趋势。缺盘、半包、校验失败、备份失败、进程中断和引用漂移有离线验收，全程保护可恢复点。 |

正式删除前列明目标、精确集合、预计释放量和保护条件。执行时复核计划、源身份和最新引用；若预览后有新引用、引用未知或对象漂移，保留对象并重新预览。首批 run 退役沿用现有 30 天或最近 200 次保护。执行后核对结果回执、仍可读取的有效引用和实际空间。先做小批、再扩大。恢复到新目录时任何一步失败都保留生产状态；接管前核对备份时点之后的成交与投递，防止重入账和重复发送。

## 7. 部署前必须拿到的证据

1. 阿里云备份盘所属主机、挂载点、身份、配额和故障隔离情况。
2. 用户接受的最大数据回退、最长恢复时间、停写窗口，以及外接盘卷名、空间和加密方式。
3. 研究历史的保留范围和重要归档第二副本位置。试验实际包大小、传输时间、恢复耗时和峰值占用后确定具体字节阈值。
4. 现有维护批次剩余保护资格、不可读目录与新版入口在线上实际可用的证据。证据不足的对象继续保护。

以上是实施前置条件。研究结论本身不会替代目标确认、首次恢复演练或删除授权。
