- 日期：2026-10-10。

## 1. 问题与目标

维护者查询运行状态时，需要同时知道「最近一次运行」和「最近一次确实发生扫描的运行」。两者可能不同，例如最近一次只完成调度或跳过扫描。当前查询分别搜索历史，且对每个候选先读取完整状态，再判断市场及扫描情况。历史越多、跨市场排除越多，无关文件读取越多。

本次目标是在保持查询结果和公开接口的前提下，减少同一次 runtime status 请求的目录枚举、文件读取与 JSON 解析。修复责任在历史选择与数据装配的 owner，不通过 CLI 缓存结果或减少必要的市场校验获得提速。

成功信号：

1. 同一次请求的历史目录只枚举、排序一次，两个选择器共享目录序列和已读取的筛选事实。
2. 未选中的 run 不加载维护详情、预取详情或通知正文；已读筛选文件在完整装配时直接复用。
3. 固定输入下，选择结果、选择计数、缺失信息、警告及 public/private 输出与修复前等价。
4. 请求结束后不保留缓存；下一次请求能看到新运行和已更新文件。

## 5. 修复方案

在 `private_runtime_status_tool` 一次调用中维护局部历史读取结果，生命周期与该次调用一致。优先复用现有函数及内部数据结构，不引入通用 cache 类或新业务实体。

### 5.1 先选择，后装配

1. 固定本次 runtime root、runs root、所选账户、目标市场和通知截断参数。
2. 按现有路径规则读取 pointer，并按需要懒加载一次历史目录列表。wheel-activation 等不查询历史的快速路径保持不枚举。
3. 每个候选只读取 `state/tick_metrics.json`、`state/last_run.json`、所选账户的 `state/last_run.json`；复用现有市场和扫描谓词，避免另写一套简化判断。
4. latest 和 latest-scanned 分别按原规则选中目录，共享筛选文件结果。可以分两次逻辑迭代同一目录序列，不要求为追求一个循环合并两套状态机。
5. 只为两个选择结果中的不同 run 装配完整 payload；已有筛选文件复用。其余维护、预取及通知内容仅在此时读取。若两者同一个 run，完整装配最多一次。
6. 分别输出原 selection 元数据，再进入原有 summary、诊断及公开投影流程。

选择阶段需要读取这些 JSON 的现有完整对象；「最小筛选事实」指减少文件种类和重复解析，不要求新 JSON 格式、流式字段提取或写入摘要文件。

### 5.2 请求内一致性与缓存边界

- 同一请求、同一历史文件的首次读取结果复用至请求结束；文件信息和解析结果一起保存，避免旧 JSON 与后读的新 metadata 混装。
- 沿用本次请求的读取失败表现；缺失或解析失败也不得由另一个选择器反复重读。不得把异常改成一次成功命中。
- 复用对象不得被筛选器或装配逻辑修改；需要添加派生字段时构造自己的结果，避免 latest 与 latest-scanned 相互污染。
- 不使用模块级字典或长期 ContextVar 存储，不跨 root、账户集合、市场或并行请求共享结果。
- 并发更新时，以本次已观察的目录序列和单文件首次观察为边界；这不是跨文件事务快照。新 run 在下一次请求可见，已观察文件不为了重新选择反复刷新。新增缓存不得隐藏外层已有的取消、超时或异常终止，结束后必须释放局部引用。
- 本次不新增 `source_changed` 状态或一致性重试协议；如实现发现必须改变外部错误合同，先单独讨论，不借优化扩展范围。

### 5.3 责任边界

主要改动落在 `runtime_status_impl.py` 的历史读取与选择链路。`diagnostics.py`、CLI 和公开投影原则上只验证兼容，不新增缓存或重复选择逻辑。复用 `_run_payload_matches_market`、`_run_payload_has_scan` 与现有文件信息读取责任；需要内部参数调整时保持公开工具 schema、命令和权限合同。

建议以一个完整行为增量交付：请求内去重、按需装配及其回归测试一起完成，避免只缓存完整 payload 而仍读取所有不匹配 run 的详情。

## 6. 验收

### 6.1 性能与读取预算

使用临时目录和计数 reader，不接生产或真实 provider。记录目录枚举/排序次数、按路径 JSON 读取与解析次数、完整 `_run_payload` 装配次数、通知正文读取次数；计数仅用于测试/研究，不新增生产日志或公开字段。

| 场景 | 验收要求 |
| --- | --- |
| 历史基准：无 pointer，50 US run、2 账户，查 HK；八个 JSON 均存在 | latest/latest-scanned 均未找到，计数各为 50，市场排除各为 50；目录枚举/排序各最多一次；历史 JSON 读取不超过 200，完整 payload 和通知正文读取为零。 |
| 所有 run 市场匹配，但都未扫描 | 最新运行正常返回，最新扫描未找到；每个筛选文件最多读一次，仅选中的最新运行读取详情。 |
| latest 与 latest-scanned 同一 run | 筛选结果复用，完整装配一次；每个历史 JSON 正常情况下最多解析一次。 |
| 两者不同 | 仅这两个不同 run 读取完整详情；未选中的候选不读无关详情。 |
| 有效 pointer 命中 | latest 保留 pointer 优先级；latest-scanned 仍按 mtime/name；pointer 指向的目录进入历史序列时不重复读取。 |
| 连续两次请求与并发不同范围请求 | 两次之间新增 run/更新文件能被第二次看到；不同 root、市场或账户请求无交叉复用。 |

没有额外历史路径的固定场景中，令被检查的不同 run 数为 N、所选账户数为 A、最终不同完整 run 数为 K（最多 2），历史 JSON 读取上界为 `N × (A + 2) + K × 2A`。显式路径或 pointer 在 runs root 外时，应将实际检查的额外 run 纳入 N，不漏算。

800 → 最多 200 是该不匹配基准的读取次数至少减少 75%，不是线上响应时间保证。实际耗时另在相同环境、冻结输入下重复测量并报告中位数、文件字节数与读取计数；不设置无依据的绝对毫秒或生产提速百分比。

### 6.2 语义回归矩阵

使用固定时钟、mtime 和同一份只读 fixture 比较修复前后完整结果；仅排除真实动态时间等明确非确定字段，并记录排除原因，不能忽略选择计数、warnings 或缺失字段。

必须覆盖：

- pointer 有效、相对路径、过期/不存在、指向错误市场、指向比历史更旧的 run，以及 mtime 相同的名称排序。
- US/HK/混合市场、全部未知市场、tick 与账户市场矛盾、市场只在 scheduler decision 或账户 last-run 中出现。
- 无目录、无扫描、最近运行未扫描但较旧运行已扫描；扫描事实各来源、tick accounts 字典/列表、非布尔值。
- 显式 run_id/run_dir、两者同时提供、指定不存在或非法 run_id；所选账户变化。
- JSON 缺失、空、损坏、读取异常、通知不存在/截断；未选中 run 的无关详情不能被加载，也不能影响选中结果。
- 请求中目录或文件改变、异常退出、外层已有取消/期限机制，以及下一次请求不复用上次观察。
- public Tool Gateway、可信 private collector 与 CLI 输出合同，包含通知诊断、预取摘要和账户隔离。

沿用 [Agent plugin smoke](../tests/test_agent_plugin_smoke.py)、[Runtime status CLI](../tests/test_runtime_status_cli.py)、[Ledger context](../tests/test_runtime_status_ledger_context.py) 的相关覆盖；新增读取计数及请求隔离测试应靠近历史 owner。实现前按实际改动选择相关测试，并保留项目交付门禁；本文纯文档交付不运行业务全量测试。
