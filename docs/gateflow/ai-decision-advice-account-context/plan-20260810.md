## Goal

把 AI Decision Advice 的账户级输入收紧为唯一、可审计的拼接路径：Candidate Engine
继续拥有当前 OM 账户的候选与容量；AI 战略组合只认该账户显式映射的 PM distribution；
开放期权只认共享或独立 SQLite ledger 对该 OM 账户生成的 prepared projection；最终投影
不得混用 Futu 运营持股、默认账户或其他账户事实。

## Preflight and baseline

- 独立 worktree/branch 已从干净的 `origin/main` 创建，原 main 工作区既有改动保持不动；
- 设计文档已先行补齐账户级唯一来源矩阵、投影分母和共享 ledger 隔离规则；
- 现有相关基线：
  `python3.12 -m pytest -q -p no:cacheprovider` 对 prepared PM、prepared option、Advice
  contexts/projection、Daily Brief notification flow 共执行 88 项，结果 `88 passed`；
- 不调用真实 PM、OpenD、DeepSeek、通知或生产运行环境。

## First-principles decision

现有 preparation 和 tick handoff 已按账户工作，不需要增加新的 context assembler、账户模型、
数据源、配置键或 fallback。当前最有价值的缺口是：

1. Advice 最终 freeze 边界只核对 run/account/config hash，没有明确拒绝缺失 prepared schema、
   非 PM 的可用组合 authority，或缺失 prepared source 标记的期权 context；
2. 现有测试分别覆盖 PM 映射和共享 ledger 空账户，但没有以两个账户的非零期权仓位证明
   preparation 到 frozen projection 全链路不会串仓。

因此只强化现有边界并补跨边界回归，不重写 preparation 或 projection 算法。若先写的回归
证明现有生产路径已经满足某项合同，该项只保留测试，不做无收益的生产改动。

## Slice S1 — Final input authority contract

### Change

在 `src/application/ai_decision_advice/contexts.py` 的既有 freeze owner 中补齐来源合同：

- PM envelope 必须声明正确的 prepared schema；`ready/degraded` 必须来自
  `portfolio_management`、具有非空 `mapped_pm_account`，且 provider validation 为
  `passed`；否则作为明确 unavailable gap，不读取资产行或投影分母；
- option context 必须声明正确的 prepared schema 和 `context_source=prepared`，并继续
  满足既有 run/account/config、filters.account、行账户和 trusted snapshot 校验；否则作为
  unavailable gap，不读取仓位或汇率；
- 保持 `None` 和正式 unavailable prepared artifact 的现有 soft-dependency 行为；不把 PM
  或 option 缺失升级为 Candidate Engine/原始监控失败；
- 不接受 Futu/holdings shape，也不添加兼容转换或其他账户 fallback。

同时修复 freeze 之前的证据范围数据流：

- `src/application/ai_decision_advice/orchestration.py` 不再用一套较弱的独立判断直接读取
  raw PM/option rows；
- 由 contexts owner 提供一个窄的 verified-symbol derivation helper，让 orchestration 的
  evidence symbol set 复用与 final freeze 完全相同的 prepared authority、账户绑定和 payload
  验证结果；不复制第二套 schema/provider/source 规则，也不新增 context layer；
- 非法 PM/option 来源必须与显式 unavailable 在 evidence views、`EvidenceIndex.index_hash()`、
  frozen external evidence hash 和 input bindings 上等价；合法来源中的持股/期权 symbol 继续
  进入证据范围。

### Tests first

更新 `tests/test_ai_decision_advice_contexts.py` 的 prepared fixtures，使其与生产 authority
一致，并增加以下反例：

1. 可用组合缺 schema、provider 非 PM、缺 mapped PM account 或 validation 未通过；
2. 期权 context 缺 schema、source 非 prepared；
3. 上述反例均只能得到 typed unavailable gap，不能产生资产权重、持股分母、开放合约或
   可用投影；
4. 相同 candidate 下，非法 PM/option payload 不得新增 evidence view，且 frozen external
   evidence/hash 必须与对应 unavailable 输入完全一致；
5. 正式 PM/option authority 的现有 ready、degraded、zero-position 和 mismatch 行为不变，
   合法持股/期权 symbol 仍会进入 evidence scope。

### Acceptance

- 最终模型输入只消费设计文档声明的两种 prepared authority；
- 错误来源即使碰巧带有相同 run/account/config，也不能取得 Advice 数据权威；
- 错误来源不能通过 pre-freeze evidence symbol derivation 改变模型输入或 reuse identity；
- Candidate snapshot 的筛选、排名和容量字段不变。

## Slice S2 — Account-isolated preparation-to-projection regression

### Change

优先只补测试，使用现有 owners 完成两条跨边界证明；只有测试暴露真实缺陷时，才在对应
preparation/loader owner 做最小修复：

1. **Futu operational + PM strategic**：构造运营 portfolio source 为 Futu、同时显式启用
   PM 且 `holdings_account` 与 OM account 不同的账户配置，证明 PM client 只请求映射账户；
   Advice 投影分母来自返回的 PM distribution，Candidate snapshot 内容保持原样；
2. **one SQLite, two logical accounts**：在同一测试 ledger 放入 `lx`、`sy` 的不同非零
   期权仓位，一次 preparation 后分别 load/freeze；证明两边 summary、candidate contracts、
   exact/near-expiry 叠加和新增一张 projection 只包含本账户合约，并继续共享同一物理读取
   generation；
3. 对其中一个账户制造 manifest/account/config mismatch，证明它失败关闭且另一账户不受
   影响，不借用对方的 PM 或期权事实。

主要测试 owners：

- `tests/test_prepared_portfolio_distribution.py`
- `tests/test_prepared_option_positions_context.py`
- `tests/test_ai_decision_advice_contexts.py`
- 必要时 `tests/test_daily_decision_brief_notification_flow.py`

### Acceptance

- 同一 OM 账户的 candidate、PM、option 三个 authority 才能组成投影；
- Sell Put 总市值比例、Covered Call 持股比例和已有期权叠加都随账户事实变化；
- 共享物理 SQLite 只减少读取，不扩大逻辑账户授权；
- Futu 只保留 Candidate Engine 运营用途，不成为 Advice strategic fallback。

## Risks and controls

- **误拒绝合法 prepared fixture/caller**：先把 fixture 对齐生产 envelope，搜索所有 freeze
  callers；合法生产来源由 preparation constants 明确绑定；
- **把 unavailable 误当硬失败**：保留现有 gap/`needs_review` 软依赖语义并做回归；
- **测试伪造与真实 ledger 路径不一致**：共享 ledger 回归必须走 repository、preparation、
  strict loader、freeze/projection，不直接拼最终 model payload；
- **跨账户缺陷被汇总掩盖**：逐账户断言 contract rows、summary、projection 和 gaps，不只比较
  总 hash；
- **范围膨胀**：任何新实体、fallback、配置项、schema migration 或策略变化都视为 plan
  amendment，停止并重新评审。

## Rollback

本 work unit 不做数据库、配置或运行态迁移。回滚只需恢复本分支的 source/test/docs commit；
既有 prepared artifact、ledger 与生产服务不受影响。
