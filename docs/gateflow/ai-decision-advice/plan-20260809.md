# Gateflow Plan — ai-decision-advice

- Gate: `plan`
- Work unit: `ai-decision-advice`
- Design doc: `docs/AI_DECISION_ADVICE_DESIGN.md`（含 2026-08-09 六点边界补充）
- Branch: `feat/ai-decision-advice`
- Status: `draft, pending plan review`

## 1. Goal / motivation / success signal

目标与成功信号同 `goal-confirmation-20260809.md`：两阶段架构（Collector 提前
采集公开证据；Advice 在简报形成时基于冻结输入生成可审计建议），结果进入既有
Daily Brief / 候选提醒与 Agent 读取面，验收以设计文档第 21 节矩阵为准。

## 2. Non-goals / scope boundary

同 goal confirmation 非目标清单。另明确：

- 远端 systemd 新 timer 的实机安装/升级走既有 `发布并升级远端` 流程，不在本
  work unit 内；
- `config.yaml` 生产值（`ai_decision_advice.enabled` 的真实开关）不在本 work
  unit 内修改；仅提供 schema、示例和校验；
- 不动 Combo Yield / Close Advice 的任何行为。

## 3. Design alignment 与第一性原理判断

设计文档 22 节全部纳入验收来源。第一性原理判断：该 work unit 成立——
Candidate Engine 输出已封存（`opening_candidate_snapshot.v1`），简报组装已
消费冻结输入，缺口只有四块：DeepSeek Responses/web_search 调用能力、证据
采集与持久化、Advice 生成与校验、渲染与读取面。每块都有单一明确的所有权
边界，可以按 slice 顺序落地。

## 4. 模块与文件所有权

新增模块全部收敛在一个目录，避免横向扩散：

```text
src/application/ai_decision_advice/
  __init__.py
  config.py            # enabled 解析 + DEEPSEEK_API_KEY 检查 + 固定常量
  identity.py          # 观察集合 + symbol_identity_snapshot（OpenD 身份）
  collector.py         # 搜索批次编排、5min 预算、去重、修复重试
  evidence_store.py    # external_evidence.jsonl 追加写 + 冻结索引推导
  contexts.py          # 四类冻结输入构建 + hash
  projection.py        # 新增一张合约的确定性风险投影
  advice.py            # Advice 调用、30s 预算、结构修复、复用判断
  validation.py        # ai_decision_advice.v1 输出校验与降级
  advice_store.py      # ai_decision_advice.jsonl 追加写 + 读取面
  prompts/__init__.py  # 两套 Prompt Pack 编译（片段 + SHA-256）
  prompts/evidence/*.md

src/infrastructure/deepseek_responses.py  # 窄 Responses client（web_search + 结构化输出）
```

## 5. 合同 / schema / 状态机变更

1. 新配置根键 `ai_decision_advice: {enabled: bool}`；`enabled: true` 且环境缺
   `DEEPSEEK_API_KEY` → config validate 失败；旧键 `ai_interpretation` /
   `ai_strategy_advice` 出现即报错；
2. 新持久化产物（唯一真源）：
   - `output_shared/state/ai_decision_advice/external_evidence.jsonl`；
   - `output_shared/state/ai_decision_advice/symbol_identity_snapshot.json`
     （原子写整份快照）；
   - `output_runs/<run_id>/accounts/<account>/state/ai_decision_advice.jsonl`；
3. 新输出 schema `ai_decision_advice.v1`（设计文档第 10 节原文）；
4. Daily Brief 规范化结构新增 `ai_decision_advice` 段（见 S6 前置契约）；
   Agent `daily_decision_brief_read` 输出同步扩展（向后兼容：仅新增字段）；
5. 通知 diff 语义扩展落在 domain 层（设计文档 14.1）：
   `keep/switch/defer/needs_review` 实质变化进入既有 diff
   （含 `needs_review` → `keep`）；`unavailable` 变化、证据时间/措辞/reuse
   不触发。

## 6. 实施 slices

### S1 — 配置合同 + DeepSeek Responses adapter

- Objective: `ai_decision_advice` 配置可校验；`deepseek_responses.py` 能以
  注入的 HTTP 层调用 Responses API，支持 `web_search` 工具声明、结构化输出
  （JSON schema response format）、usage/审计字段提取、超时；
- Files: `config_yaml.py`, `config_validator.py`, `configs/examples/...`,
  `src/infrastructure/deepseek_responses.py`, `ai_decision_advice/config.py`；
- 不改 Copilot 的 provider registry 与 model_client；
- Tests: 新增 `tests/test_ai_decision_advice_config.py`、
  `tests/test_deepseek_responses.py`（全部 mock HTTP，不联网）；
- Stop: 校验行为或 adapter 合同不确定。

### S2 — 观察集合与身份快照

- Objective: 从配置扫描标的 + 普通股票持仓 + 开放期权持仓构建 canonical 去重
  观察集合；优先复用市场快照 `code/name`，缺失时按 `code_list` 调 OpenD
  `get_stock_basicinfo`；冻结 `symbol_identity_snapshot`；优先级与饥饿保护队列；
  快照原子写入
  `output_shared/state/ai_decision_advice/symbol_identity_snapshot.json`
  （schema：per-symbol code/market/exchange/name/aliases/observed_at(UTC) +
  整份内容 hash），随观察集合或 OpenD 身份变化确定性重建；
- Files: `ai_decision_advice/identity.py`；
- Tests: `tests/test_ai_decision_advice_identity.py`（mock gateway；断言快照
  schema、原子重写幂等、内容 hash 稳定）。

### S3 — External Evidence Collector + 证据存储

- Objective: 搜索批次编排（批 5、并发 2、总预算 5min、启动补刷、4h 调度决策、
  24h 全量核对决策）、URL/内容指纹去重、一次格式修复重试、严格 JSON Schema、
  追加写 `external_evidence.jsonl`（batch 审计 + 标的语义记录分离）、冻结索引
  推导与 8h 过期判断、no_evidence / identity_unavailable 状态；
  所有刷新/过期/全量核对时间一律 UTC，以证据记录持久化的 `last_success_at`
  为基准；每条证据记录携带生成时的身份快照 hash；
- Files: `ai_decision_advice/collector.py`, `evidence_store.py`,
  `prompts/evidence/*`, `service_deploy.py`/`service_ops.py`（opt-in timer）；
- Tests: `tests/test_ai_decision_advice_collector.py`,
  `tests/test_ai_decision_advice_evidence_store.py`（注入假 model runner；覆盖
  UTC 过期判断、证据-身份 hash 绑定）。

### S4 — 冻结输入与一张合约风险投影

- Objective: 从候选快照、portfolio context、option positions ledger 投影、
  证据冻结索引构建四类输入及 hash；新增一张合约的集中度/叠加/到期日投影；
  隐私过滤（无 NAV/成本/账户标签/订单号）；
  v1 不含行业维度（无可靠数据源，设计文档 7.2 已注明）：输入与投影只覆盖
  symbol / currency / 到期日集中度；
- Files: `ai_decision_advice/contexts.py`, `projection.py`；
- Tests: `tests/test_ai_decision_advice_contexts.py`（断言输出无 industry
  键、无隐私字段）、`tests/test_ai_decision_advice_projection.py`。

### S6 前置契约 — brief view `ai_decision_advice` 字段

S6 生产、S7 消费共用同一 brief view 契约，先行冻结：

```text
brief["ai_decision_advice"] = {
  "status": "completed" | "unavailable" | "not_applicable",
  "unavailable_reason": str | None,      # evidence_stale / no_evidence /
                                         # context_missing / timeout / invalid_output ...
  "evidence_as_of": str | None,          # UTC ISO
  "sell_put": {
    "action": "keep|switch|defer|needs_review" | None,
    "baseline_candidate_id": str | None,
    "selected_candidate_id": str | None,
    "rationale": {...} | None,
    "source_refs": [...] | None,
  } | None,                               # None = 合法零候选
  "covered_call": [                      # per-symbol
    {"symbol": str, "action": ..., "baseline_candidate_id": ...,
     "selected_candidate_id": ..., "rationale": ..., "source_refs": ...}
  ] | None,
  "zero_candidate": {"sell_put": bool, "covered_call": bool},
  "reused": bool,
  "advice_record_id": str | None,
}
```

渲染层只读该结构；domain diff 按 14.1 比较其中的动作字段。

### S5 — Advice 节点、校验降级与持久化

- Objective: Advice 调用（30s 账户总预算、一次结构修复、严格 JSON）、
  `ai_decision_advice.v1` 校验与降级规则（引用被拒候选 / CC 跨标的 switch /
  未支持动作 → needs_review；证据过期 → unavailable）、复用条件判断、
  `ai_decision_advice.jsonl` 写入、合法零候选短路（不调模型）；
- Files: `ai_decision_advice/advice.py`, `validation.py`, `advice_store.py`,
  `prompts/advice/*`；
- Tests: `tests/test_ai_decision_advice_advice.py`,
  `tests/test_ai_decision_advice_validation.py`。

### S6 — Tick 编排挂点与 brief 装配

- Objective: 在 `tick_notification_flow` 简报生成前运行/复用 Advice（预算用尽
  不阻断），把 Advice 产物挂进 brief view；候选提醒路径承载 unavailable；
  固定简报与候选提醒两条路径都当轮运行或复用 Advice（同一 30s 账户预算，
  超时/失败即 unavailable，不推迟提醒）；
  diff 语义扩展按设计文档 14.1 落在 domain 层
  （`domain/domain/daily_decision_brief.py` 的
  `normalize_daily_decision_brief` + `diff_daily_decision_briefs`），
  动作迁移 material、`unavailable` 变化不 material；
- Files: `tick_notification_flow.py`, `daily_decision_brief_service.py`,
  `domain/domain/daily_decision_brief.py`；
- Tests: `tests/test_daily_decision_brief_service.py`（扩展）、
  新增 `tests/test_ai_decision_advice_orchestration.py`（覆盖固定简报与
  候选提醒两条路径的超时、复用、unavailable 分支）、domain diff 测试扩展。

### S7 — Daily Brief 渲染

- Objective: `### AI建议` 聚合区块（SP 单条 / CC 按标的聚合）、文案合同
  （15.2/15.3）、来源展示（15.4）、展示预算与 AI 引用候选强制展开（15.6）、
  持仓表格→逐项列表（15.5）、候选主显示持有期净收益 + 门槛年化（15.5）；
- Files: `daily_decision_brief_renderer.py`, `ai_decision_advice/render.py`；
- Tests: `tests/test_daily_decision_brief_renderer.py`（扩展）、
  `tests/test_ai_decision_advice_render.py`。

### S8 — Agent 读取面 + 文档收尾

- Objective: `daily_decision_brief_read` 结构化输出扩展 `ai_decision_advice`
  （动作、引用候选、输入 hash、cutoff、证据与来源、运行/校验/复用/降级状态）；
  更新 `docs/AGENT_WIKI.md`、`docs/DEPLOY_LINUX_MAC.md`（新 timer 说明）、
  设计文档实施状态；
- Files: `agent_tools/daily_brief.py`, docs；
- Tests: `tests/test_daily_decision_brief_agent_tool.py`（扩展）。

## 9. Risks / open questions

| 风险 | 处置 |
|---|---|
| DeepSeek Responses `web_search` 实际参数形态未经真机验证 | adapter 以注入 HTTP 层 + 可更新常量隔离；真机验证放在发布前受控 canary，不阻断 code slices |
| S6 编排挂点影响现有通知可靠性 | Advice 全部失败路径收敛为 `unavailable`，不阻断、不重试、不延迟回执；测试覆盖超时分支 |
| 持仓表格→列表影响既有渲染测试 | 独立 slice S7，按用户已确认的文案合同改测试断言 |
| JSONL 追加写的并发（collector timer 与 tick 进程） | 追加写 + 每行自包含； evidence_store 以 (symbol, evidence_run_id) 推导索引，容忍行间交错 |
| 组合数据无行业字段 | v1 去掉行业维度（用户已裁决），设计文档 7.2 注明后续扩展前提 |

Open questions: 无 blocking。

## 10. 不过度设计说明

- 不建通用 LLM 编排框架：两个节点各自一个窄函数面；
- 不做适配器插件系统：SP/CC 语义差异直接在 validation/render 中表达；
- 不引入数据库：两份 JSONL + 可重建索引；
- Prompt 复用 Copilot 的“清单 + 片段 + 编译 hash”模式但不复用其 Scene 机制，
  因为 Advice 不需要对话态；
- collector timer 复用既有 systemd render 机制，不新建调度框架。
