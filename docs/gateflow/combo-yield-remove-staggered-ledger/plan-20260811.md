## Goal / Motivation / Success Signal

**Goal**: 从交易落账（resolver）、手动配对 CLI、组合生命周期、归组推理、绩效归因与文档中移除错期（`staggered_expiry_pair` / `diagonal`）组合收益的支持，使组合收益策略只保留 same-expiry（同期）一种结构。

**Motivation**: 用户在策略层面已决定不做错期组合（previous work unit `combo-yield-remove-staggered` 已移除策略配置面）；本轮把 ledger/生命周期/归组/归因面的错期代码一并移除，消除「策略配置已不支持、但落账与生命周期仍保留推理」的隐藏死面与行为分叉。

**Success signal**:

- 全仓 `rg` 对 `staggered_expiry_pair`、`staggered_combo_yield_`、`execute_staggered_combo_yield_pairing`、`pair-combo-yield`、`invalid_diagonal_expiry_order` 无命中（除 config_validator / shadow 的 removed 配置文案，见 non-goals）。
- 相关 pytest 全绿（见验证命令），无测试再引用错期行为。
- 旧 diagonal/错期数据落入 fail-closed 路径（`review_required` / `unsupported_expiry_structure`），不产生新推理、不自动配对、不阻塞同期待处理数据。

- 不改 `config_validator` 与 shadow replay 中关于 removed 配置项的文案与拒绝逻辑（属于上一 work unit 已交付的配置面）。

- 不改动同一 work unit 之外的用户未跟踪文档。

## First-Principles Judgment and Direct Code Evidence

1. **resolver 保留了一整套错期开仓推理，且失败会返回 `unresolved`**：`src/application/trades/resolver.py:415` 在 `combo_enrichment.reason.startswith("staggered_combo_yield_")` 时直接 failure；`:719-944` 包含 `_enrich_staggered_combo_yield_open`、`_validate_staggered_combo_yield_open`、`_staggered_combo_yield_leg_role`、`_with_staggered_combo_yield_payload`、`_explicit_combo_yield_group_id`。错期开仓显式意图不再有策略支撑，应落为普通单腿 + 关系 pending，而不是失败或错期推理。
2. **手动配对模块只服务错期**：`src/application/positions/combo_pairing.py` 428 行，核心为 `resolve_staggered_combo_yield_pair` / `execute_staggered_combo_yield_pairing`；CLI `option_positions.py` 的 import(47)、parser(722)、write_controls(962)、dispatch(2156-2187) 全部只接错期配对。same-expiry 由 lifecycle/归组自动处理，无手动入口需求。
3. **生命周期把错期映射为 diagonal 并校验到期序**：`domain/domain/combo_yield_lifecycle.py:34-38` 将 `staggered_expiry_pair` 映射为 `diagonal`；`:80-82` 只接受 `{same_expiry, diagonal}`；`:162-163` 存在 `invalid_diagonal_expiry_order`。策略已不支持错期后，diagonal 不应再是合法结构，旧数据应 fail-closed 进入 `unsupported_expiry_structure` → `review_required`。
4. **归组推理仍会为 put 早到期生成 staggered 边**：`domain/domain/combo_reconciliation.py:443-447` 中 put 到期早于 call 时仍构造 `staggered_expiry_pair` 结构；`match_post_trade_combo_pairs` 应只产生 same-expiry 配对。
5. **归因仍校验 diagonal 到期序**：`domain/domain/performance/strategy_attribution.py:145-148` 对 `diagonal` 结构做 `invalid_diagonal_expiry_order` 校验；结构不再可能由生命周期产生，该校验成为死面。
6. **生产数据无错期存量**：`output_shared/state/option_positions.sqlite3` trade_events 3 条（0 staggered）、position_lots 2 条（0 diagonal）、combo_pair_inferences 0 行。删除不触碰存量数据。
7. **receipt「关系待确认」文案并非错期专用**：保留文案，仅调整测试夹具。

## Contract / Schema / State-Machine / Public-Interface Changes

- **无 schema/存储变更**：不动 `structure_mode` 字段语义、不开新列、不改 combo_pair_inferences 表。
- **CLI 公共接口变更**：删除 `om option-positions pair-combo-yield` 子命令及其 write_controls 条目。需要同步更新 CLI 帮助文档/示例。
- **状态机变更**：
  - resolver：错期显式 pair-intent 开仓不再走错期 enrichment；与普通单腿一致，由 lifecycle/归组后续处理（关系 pending）。
  - lifecycle：inventory 只接受 `{same_expiry}`；`diagonal` 不再被识别，落入 `unsupported_expiry_structure` → `review_required`（fail-closed）。
  - 归组：`_build_edge` 不再产生 staggered 边；put 早到期时配对返回 None（同错期边被拒绝的行为）。
  - 归因：删除 diagonal 到期序校验分支。
- **错误语义变化**：`staggered_combo_yield_*` 错误码全部移除；旧错期开仓意图不再报 `unresolved`，而是作为普通单腿落账（与 same-expiry 落账一致）。

## Implementation Decisions

1. resolver 中保留 `combo_enrichment` 返回值结构，只删错期分支；`_combo_yield_pair_intent_id` 若仅被错期使用则一并删除，若 same-expiry 路径仍使用则保留（实现时按调用点裁决）。
2. `combo_pairing.py` 整文件删除；CLI 同步删除 import、parser、write_controls key 与 dispatch 分支。若 CLI 帮助文本列有该子命令，一并删除。
3. lifecycle：`_expiry_structure` 保留对 `structure_mode=staggered_expiry_pair` / 显式 `expiry_structure=diagonal` 的识别并返回 `"diagonal"`；inventory 校验集收窄为 `{"same_expiry"}`，`diagonal` 落入 `unsupported_expiry_structure` → `review_required`（fail-closed，不得误报 `same_expiry_mismatch`）；删除 `invalid_diagonal_expiry_order` 分支与相关测试。
4. 归组：`_build_edge` 的 `structure_mode` 恒定 `same_expiry_pair`（put==call 到期时），put 早到期直接 `return None`，删除 staggered 推理与证据。
5. 归因：删除 diagonal 到期序校验块，替换为 fail-closed 校验——`expiry_structure` 非 `same_expiry`（含 `diagonal`）一律追加 `unsupported_expiry_structure`，使旧 diagonal 组落入 `partial` + `strategy_group_invalid`，不得静默按同期归因。若 `diagonal` 枚举在其他文件引用，逐处确认并清理（或保留枚举值但不再产生）。
6. 文档：策略架构文档删除错期生命周期/CLI 示例；旧 post-trade 计划文档标注范围收窄（保留历史记录，不重写历史）。
