## Finding decisions and fixes

### DR-S3-01 — accepted — fixed

The model-visible timestamps remain available for quality and audit context, but
reuse bindings now hash a dedicated semantic view. The view recursively omits
only observation/refresh metadata (`observed_at_utc`, `source_observed_at`,
`frozen_at`, `last_checked_at`, `last_success_at`) while retaining portfolio
quality states, option content, coverage states, evidence content and all
projection facts.

Regression coverage proves that changing only those timestamps leaves every
semantic binding and the projection hash stable. It also proves that evidence,
position and PM quality changes still change the relevant hashes.

### DR-S3-02 — accepted — fixed

Simplified `SP+LC` labels now require all of the following:

- a valid, hash-matching Combo identity for `combo_yield`;
- one valid, hash-matching ledger membership fact with `status=exact`;
- exact equality between membership record IDs and the identity's two legs;
- membership bindings matching each leg's role, open event, account and symbol;
- both formal `ContractKey` objects matching the current open-position rows.

Missing, conflicting, duplicated or stale membership facts and mismatched
contract keys all fail closed and produce no simplified structure. No heuristic
pairing was added.

### DR-S3-03 — accepted — fixed

For a complete (`ready` or `degraded`) PM distribution, an absent symbol or
currency key now means a real `0.0` exposure. Finite signed weights, including
negative asset/currency/cash weights, are preserved. An unavailable portfolio
continues to return `null` exposures rather than invented zeros.

### DR-S3-04 — accepted — fixed

Model-visible candidate option details now retain `multiplier` in both the
aggregation key and output row. Standard and adjusted contracts sharing the
same symbol/type/side/strike/expiry remain separate.
