## 1. Goal / motivation / success signal

本 work unit 修复已落地 AI Decision Advice 与确认策略之间的数据权威、投影、证据和
校验漂移。每个 OM 账户的 Advice 最终只能消费同一 run 的：

1. 完整已接受策略候选；
2. 显式启用、按账户读取并严格校验的 PM 战略组合分布；
3. OM SQLite ledger 已生成并验证的 prepared option context；
4. 与该账户候选和持仓相关、身份及搜索完成状态可审计的公开证据。

模型调用前，代码为每个候选生成新增一张合约的确定性投影和严格 fact registry；模型
输出必须覆盖精确 scope、逐项绑定输入和事实，不能把缺失数据、未搜索或不可信来源解释
成安全。成功信号以设计文档第 21 节验收矩阵和 goal artifact 的九项信号为准。

## 2. Non-goals / scope boundary

- 不修改 Sell Put / Covered Call 的召回、硬门槛、排序、收益率、限价、资金或容量口径；
- 投影只服务 Advice，不成为 Candidate Engine gate，不推荐张数，不自动执行；
- 不伪造执行后权重，不新增组合 Greeks、统一风险分数或行业集中度；
- 不做跨账户综合 Advice，不把 Futu 运营持仓冒充 PM 全组合分布；
- 不修改 portfolio-management 仓库、数据库或 OpenAPI；其行级 schema 加强属于独立跨仓
  work unit；
- 不修改 Combo Yield / Close Advice 行为；
- 不新增手动搜索、刷新或写入工具；
- 不调用真实 DeepSeek、PM、OpenD、通知或生产服务完成常规测试；
- 不发布、不升级远端、不修改生产配置或 secrets。

## 3. Design alignment 与第一性原理判断

本 work unit 成立。当前 Candidate Engine 已有正式候选快照，SQLite option ledger 已有
同 run prepared authority，PM client 已有 loopback-only 和 API version 边界；缺口不是
再建一套数据系统，而是让 Advice 消费这些既有权威边界，并补上 PM 的可选账户级读取。

直接代码证据：

- `orchestration.py` 仍按路径重读 legacy `portfolio_context.json` 和
  `option_positions_context.json`，以 `bool(dict)` 合并判断完整性；
- `_option_lots_from_context()` 不消费权威 `open_positions_min`，`contexts.py` 又只认
  nested `contract_key`，真实仓位可能被冻成空集合；
- `projection.py` 默认缺失 multiplier 为 1、按行计数且只看 exact expiry，并未接到
  production call path；
- `validation.py` 未校验期望 scope 集合相等，也没有 frozen fact registry；
- Collector 的公开 CLI 当前只把配置标的交给观察集合，持仓、期权和近期候选为空；
- evidence 结果未建立“请求 symbol -> completed web search -> provider 原生引用”的
  可验证链条；
- `config_validator.py` 的 `cfg.get(...) or {}` 会吞掉 falsey 非 object；
- `PortfolioManagementClient` 只有通用 distribution view，没有 Advice 专用的单账户
  strict contract；
- Daily Brief 已读取部分账户工件，却把 `state_dir` 交回 Advice 自行重读，形成双重事实面。

第一性原理判断：候选规则本身没有理由改变；最高 ROI 是修复输入权威、确定性计算和
validator，而不是扩大模型自由度或再造通用 LLM workflow。

## 4. Implementation decisions

### 4.1 数据与调用边界

- `portfolio_distribution.provider` 默认 `none`，只有显式
  `portfolio_management` 才读取 PM；PM 是 Advice soft dependency。
- PM 每个 OM 账户单独调用一次，账户映射复用 `holdings_account`；请求固定
  `by_asset=true&include_value=true&group_cash=false`，禁止 `accounts=all`。
- PM prepared distribution 是新 run-scoped immutable envelope；provider 未启用、响应
  不可信或失败时仍发布明确 unavailable envelope。
- 开放期权不建新真源，复用并验证既有 prepared option manifest + payload；Advice 不
  直接访问 SQLite、Futu、Feishu 或 legacy JSON。
- Daily Brief/Advice 接收已经加载和验证的显式对象，不把目录路径当作数据依赖。

### 4.2 PM CNY consumer contract

当前 PM producer 的 `portfolio.api.v1` 把 `by_asset[].value` 取自
`market_value_cny`，OM prepared envelope 固定记录 `valuation_currency=CNY`。由于
vendored OpenAPI 尚未声明行级结构与单位：

- OM 以严格 fixture 和 adapter integration test 固定当前 v1 consumer contract；
- 运行时只接受完整单账户、有限数值、正式资产类型和明确 freshness/trust；
- 不声称宽松 OpenAPI schema 已经证明单位；PM producer schema 加强列为跨仓 residual
  risk，不在本 work unit 修改。

### 4.3 冻结事实与投影

- `FrozenInputs` 改为显式包含 candidates、portfolio distribution、option positions、
  projections、external evidence 和 fact registry，以及它们的独立 hash。
- 全部开放期权先按经济合约键聚合 `contracts_open`；所有仓位参与计算，只有候选标的
  展示聚合明细，其他标的只展示账户级方向/类型/到期汇总。
- 每个候选固定新增一张：Sell Put 以同 run prepared option context 中已验证 FX 将
  `strike * multiplier` 转为 CNY 后除以 PM 组合总市值；Covered Call 以
  `multiplier / PM 当前该标的持股数量` 计算叫走比例。
- exact expiry 与前后 7 个日历日（不含 exact）分别按实际开放张数计数；新增后当前
  对应 bucket 固定 `+1`。
- strike、正 multiplier、FX、PM 正总市值或 CC shares 缺失时写 gap，绝不默认值。

### 4.4 Advice 与证据的 fail-closed 边界

- 期望 scope 由候选池确定：有 Put 候选恰好一个 SP；每个有 Call 候选的 symbol 恰好
  一个 CC。遗漏、重复、额外 scope 修复一次后仍存在，整账户 unavailable。
- 模型只能引用 frozen fact registry。未知引用或事实不支持动作时单 scope 降级
  `needs_review`；binding/scope 结构错误整账户 unavailable。
- `keep` 需要候选、fresh+trusted PM、trusted option context、完整 projection 和全部
  账户相关 evidence coverage；缺口只降级 `needs_review`，不伪造 `defer`。
- 每次正式记录使用密码学随机、不可预测且仅限当 run 的 `account_ref`；reuse 记录生成
  新 run-local ref，不暴露旧 ref。
- Collector 批次结果的 symbol 集合必须与请求严格相等；每个 symbol 必须绑定本响应
  completed web-search audit。证据 URL 还必须绑定同一响应的 provider 原生引用；无法
  绑定就丢弃证据行。
- DeepSeek 官方文档只保证 server-side `web_search` 及调用状态，不保证稳定 citation
  shape；adapter 用真实形状 fixture 固定，运行时缺失即失败关闭，不做宽松猜测。

### 4.5 匿名观察集合与入口

- Tick 在 private lock 内更新共享 `observation_set.json` 的 canonical-market partition；每个
  partition 只含 canonical symbol、market、确定性 priority、generation、时间和 hash。
  publisher 先跨当前市场账户合并并去除来源，只替换本 market partition，再原子写回整份
  snapshot；不得覆盖其他 market 或发生并发 lost update。
- 来源为配置扫描标的、PM 可搜索证券、开放期权底层、近期已接受候选；现金/MMF/合成
  code 不搜索但仍保留组合权重。
- Collector 只读匿名观察集合；启动时缺失则只补刷配置标的。
- 从 `./om` 移除 `ai-evidence-collector` 公开分发；systemd 继续调用窄的内部 managed
  service entry，不增加手动刷新面。

## 5. Contract / schema / state-machine / public-interface changes

### 5.1 配置

```yaml
ai_decision_advice:
  enabled: true
  portfolio_distribution:
    provider: portfolio_management  # none | portfolio_management
```

- 任一出现的节点必须是 object；falsey 非 object 也拒绝；
- provider 默认 `none`；不探测自动启用；
- 仍只有顶层 Advice enabled 开关，不新增 per-account 开关。

### 5.2 PM prepared envelope

```text
output_runs/<run_id>/accounts/<account>/state/
  prepared_portfolio_distribution.v1.json
```

Envelope 固定为：

```text
authority = schema/run_id/OM account/mapped PM account/provider/status/reason/
            account_config_sha256/fetched_at/validation
payload   = upstream observed_at/freshness/trust/valuation_currency/
            normalized assets/derived totals
integrity = payload_sha256
```

`payload_sha256` 只覆盖 canonical JSON `payload`，不覆盖自身。Tick handoff 另计算完整文件
bytes 的 `artifact_sha256` 并保存在内存 authority map/调用边界，不写回 envelope，避免自引用。
loader 同时验证 expected artifact hash（有 handoff 时）、payload hash 和全部 authority binding。
ready 与 unavailable 都是确定性状态；只有 ready payload 中的绝对值供本地投影，模型只收
权重、质量和 gap。

### 5.3 Option prepared authority

继续使用：

```text
prepared_option_positions_context.v1.json
option_positions_context.json
```

manifest 的 run/account/config/payload hash、status，以及 payload 的
`context_status=available`、`decision_snapshot_status=trusted`、
`open_positions_min` list 必须全部成立。合法 `[]` 与 unavailable 是两个状态。

### 5.4 Frozen inputs / output bindings

`input_bindings` 从 `portfolio_context_hash` 收紧为：

```text
candidate_snapshot_hash
portfolio_distribution_hash
option_positions_hash
fact_registry_hash
external_evidence_hash
external_evidence_run_id
```

旧 binding 不作为新正式记录的兼容输入；旧记录因版本/binding 不匹配自然不可 reuse。

### 5.5 Evidence / observation state

- 新增 `output_shared/state/ai_decision_advice/observation_set.json`；
- identity snapshot 同时保存 artifact hash 与不含 `observed_at` 的 semantic hash；
- evidence success 与 failure 分开追加，failure 不能隐藏 <=8h 的 last success；每条成功
  status 显式保存 search mode、有序 `active_evidence_refs` 和 `semantic_snapshot_hash`；
- 增量成功从上一成功 snapshot 显式合并 active refs，零增量保持 hash；24h full success
  用本轮完整集合替换 active refs，full zero 明确清空；freeze 不扫描所有历史 evidence 猜成员；
- `evidence_as_of` 为相关可用 symbol 的最早实际 `last_success_at`；
- identity semantic hash 变化时旧证据留作审计但不进入当前索引。

### 5.6 Advice 状态转换

```text
inputs invalid / scope structural invalid / repair still incomplete
  -> whole-account unavailable

single decision unsupported fact/action
  -> deterministic needs_review

PM or option context degraded/unavailable, projection gap, coverage gap
  -> decision ceiling needs_review

valid zero candidate
  -> no model call, no investment action, deterministic no-candidate text
```

### 5.7 Public interface

- 删除 `./om ai-evidence-collector` 子命令和公开帮助入口；
- managed service collector entry 保留；
- Agent/Daily Brief 只读正式 Advice 记录，不触发采集或模型调用；
- structured read 只新增/收紧字段，不新增写能力。

**Objective / expected outcome**

配置能无歧义表达 provider；PM client 能构造固定单账户 distribution 请求并返回可供
application 严格校验的 response，且保留 loopback/API version 防线。

**Allowed files**

- `src/application/ai_decision_advice/config.py`
- `src/application/config_validator.py`
- `src/application/config_yaml.py`
- `src/infrastructure/portfolio_management_client.py`
- `configs/examples/config.yaml.example`
- `tests/test_ai_decision_advice_config.py`
- `tests/test_layered_config.py`
- `tests/test_portfolio_management_client.py`
- `tests/test_portfolio_management_contract_vendor.py`

**Exact changes / data flow / invariants**

- 新增 typed provider resolver；缺失 -> `none`，只接受 `none|portfolio_management`；
- 修复 falsey 非 object 被 `or {}` 吞掉；旧 retired keys 继续拒绝；
- authoring YAML 到 US/HK runtime snapshot 原样保留这一窄配置；
- client 新增单账户 distribution 方法，固定 query flags、URL encode account、验证
  response object/API version/status；禁止空 account 和 `accounts=all`；
- fixture 证明当前 v1 `by_asset[].value` 是 CNY consumer contract，同时明确 vendored
  schema 尚不能单独证明行单位。

**Non-goals**

不在本 slice 计算权重、发布 prepared artifact、调用真实 PM 或改 PM producer。

**Completion / stop**

聚焦测试通过且没有引入 PM 网络调用即完成。若 producer 的实际 `value` 不再为 CNY，
停止并把跨仓 contract 变化列为 blocking question。

### S2 — Account-scoped prepared PM distribution and Tick soft dependency

**Prerequisite**: accepted S1.

**Objective / expected outcome**

每个账户在 Tick prepared phase 最多读取 PM 一次，发布绑定 run/account/config/hash 的
ready/degraded/unavailable envelope；PM 失败绝不移除账户或阻断 Candidate Engine。

**Allowed files**

- new `src/application/prepared_portfolio_distribution.py`
- `src/application/tick_account_execution.py`
- `src/application/multi_account_tick.py`（仅传递状态/metrics 所需窄改）
- `src/infrastructure/portfolio_management_client.py`（只修 S2 暴露的 adapter bug）
- new `tests/test_prepared_portfolio_distribution.py`
- `tests/test_tick_account_execution_barrier.py`
- `tests/test_multi_account_tick.py`

**Exact changes / data flow / state transitions**

1. 对 Advice enabled 的每个账户读取 provider 配置和 `holdings_account` 映射；
2. provider none 直接发布 `unavailable: provider_none`，不调用 PM；
3. provider PM 时单账户调用 client，严格校验 success/accounts/freshness/trust/
   observed time/by_asset/errors/row account isolation；
4. 每行 allowlist code/normalized_type/currency/quantity/value，拒绝 non-finite value；
   OM 以 value 重算 total/asset/currency/cash+MMF 权重，不信 ratio/total；
5. fresh+trusted empty by_asset 为合法 ready zero；非空必须有正有限 total；
6. stale+trusted/partial 标记 degraded；unknown/untrusted/protocol/transport 为 unavailable；
7. initial prefetch 分支用既有 safe run-state writer 原子、write-once 发布单 envelope，建立
   `prepared_portfolio_distribution_by_account`、artifact path/hash/status maps；
8. `prefetch_done=True` recovery 分支只能从 exact run/account state 加载并验证既有 envelope，
   恢复同样的 maps；缺失、损坏或 binding 不符转 Advice soft-unavailable，不重新调用 PM、
   不像 option hard barrier 那样移除 scanning account；
9. Tick outcome 把已验证对象和 artifact authority 显式交给 notification/brief 组装；后续
   Advice 不再按路径重读。initial 与 recovery 对同一 artifact 产生相同 payload/hash；
10. 日志/metrics 只记录 provider、状态、hash 和 reason，不记录 PM account 或绝对值。

**Invariants / error handling**

- PM preparation 是 soft dependency；异常转 unavailable envelope，不抛成 scan barrier；
- 账户 A 的行、hash 或失败不得进入账户 B；
- 本地 envelope 可含计算所需 absolute values，但任何 model serializer 必须另做 allowlist；
- 不复用既有 hard `prepared_portfolio_context` 作为战略分布；
- 同一 run initial path 最多调用 PM 一次/account；recovery path 的 PM 调用数固定为 0。

**Non-goals**

不改 existing Futu/holdings operational context，不生成模型输入，不发布共享观察集合。

**Validation / expected assertions**

```bash
./.venv/bin/python -m pytest -q \
  tests/test_prepared_portfolio_distribution.py \
  tests/test_tick_account_execution_barrier.py \
  tests/test_multi_account_tick.py
```

覆盖 PM none、fresh trusted、合法空资产、stale/partial、wrong account、foreign breakdown、
non-finite、transport failure、多账户隔离、一次读取、scan 继续、write-once、payload/authority/
artifact hash tamper、initial→recovery 零额外调用、recovery missing/corrupt soft degradation。

**Completion / stop**

所有状态都能发布或恢复确定性 envelope，且 PM 故障/重入缺失下原 Candidate Engine 结果
不变。若 tick 只能通过把 PM 变成 hard barrier 或在 recovery 重取 PM 才能集成，停止并
回到 plan。

### S3 — Option aggregation, privacy freeze, one-contract projection and fact registry

**Prerequisite**: accepted S2.

**Objective / expected outcome**

纯确定性层能从已验证 PM/option 对象生成最小模型输入、每候选投影、完整 fact registry
与独立 hash；不猜数据，不泄漏私有字段。

**Allowed files**

- `src/application/ai_decision_advice/contexts.py`
- `src/application/ai_decision_advice/projection.py`
- `src/application/prepared_option_positions_context.py`（仅复用/暴露已验证 FX 读取 helper）
- `tests/test_ai_decision_advice_contexts.py`
- `tests/test_ai_decision_advice_projection.py`
- `tests/test_prepared_option_positions_context.py`（仅 helper regression）

**Exact changes / functions / data flow**

- `build_frozen_inputs` 接收已验证 candidate snapshot、prepared PM envelope、prepared option
  payload/manifest、冻结 evidence index；不接受 legacy portfolio/position 猜测形状；
- 按 `symbol+option_type+side+strike+expiry+multiplier` 聚合正
  `contracts_open`；invalid row 使 option input unavailable，不静默丢行；
- 全部仓位参与 account summary，候选 symbol 才产生聚合 contract detail；可靠 group
  identity 才输出简化 SP+LC/CC+LP 标签；
- PM serializer 只输出 asset/currency/cash+MMF weight、quality/observed time/gaps；
- `project_one_contract` 不再默认 multiplier；SP 使用 validated same-run FX 和 PM CNY
  total；CC 使用 PM quantity；exact/near ±7 和同义务按 contracts 求和；
- 为 candidate/projection/portfolio/position/coverage/evidence/gap 建 deterministic fact IDs；
- `FrozenInputs` 输出 candidate/portfolio_distribution/option_positions/projection/
  fact_registry/evidence hashes；同内容 hash 稳定、账户/run 差异由 binding envelope 绑定。

**Invariants / error handling**

- valid `open_positions_min=[]` 是完整空；manifest/payload/status/account/hash 不匹配由调用者
  传入 unavailable，freeze 不把它改为空；
- 绝对 values、quantity、FX、账户、IDs、premium/cost/note/raw payload 不进入 model input；
- 缺 strike/multiplier/FX/PM total/CC shares 写 projection gap 并设置 scope ceiling；
- 不生成 after-trade weight，不更改 Candidate Engine rows。

**Non-goals**

不调用模型、不决定 action、不改 evidence collector 或 notification。

**Validation / expected assertions**

```bash
./.venv/bin/python -m pytest -q \
  tests/test_ai_decision_advice_contexts.py \
  tests/test_ai_decision_advice_projection.py \
  tests/test_prepared_option_positions_context.py
```

覆盖 US/HK/CNY FX、missing FX/multiplier/total/shares、同经济合约多行聚合、actual contract
counts、exact vs ±7、同义务/long legs、可靠/不可靠 combo identity、跨账户拒绝、隐私键
递归扫描、fact/hash 稳定。

## 11. Why this is not over-designed

- 复用现有 PM client、prepared option authority、run-state safe writer、JSONL evidence 和
  Daily Brief/Agent 读取面，不新增数据库或通用 provider framework；
- 只新增一个缺失的 PM prepared envelope 和一个匿名 observation snapshot；两者分别解决
  run/account 权威与 Collector 隔离，不能由现有 operational context 安全替代；
- 只计算用户已确认的一张合约比例和张数，不引入 Greeks、优化器、统一分数或参数引擎；
- fail-closed 规则集中在 prepared validator、fact registry 和 Advice validator，不把语义
  分散到 renderer 或 prompt；
- public CLI 做减法，PM/DeepSeek 均保持 optional，不扩大生产控制面。
