## Finding decisions and fixes

### DR-S5-01 - accepted - fixed

The managed runner now reads evidence history before queue construction and passes
the latest per-symbol attempt time into `RefreshQueue`. Same-priority symbols that
were never attempted or were attempted longest ago move ahead of recently handled
symbols.

### DR-S5-02 - accepted - fixed

Provider exceptions are contained at the batch boundary. The affected symbols get
failed status records, prior successful snapshots remain current, and later batches
continue while the shared budget remains.

### DR-S5-03 - accepted - fixed

Identity failures are tracked separately from completed searches. A run with a
non-empty observation set and no completed symbol is failed; mixed results are
partial and expose explicit counts.

### DR-S5-04 - accepted - fixed

The infrastructure adapter rejects every top-level Responses status other than
`completed`, retaining only a content-free response fingerprint for diagnosis.

### DR-S5-05 - accepted - fixed

The stale public collector command was removed from the operator documentation.
Both documents now describe the opt-in internal managed-service boundary.

### DR-S5-RR-01 - accepted - fixed

Collector batches now execute in waves of at most two workers and share the same
monotonic five-minute deadline. A barrier regression proves two calls overlap.

### DR-S5-RR-02 - accepted - fixed

The production managed runner now connects the identity builder to an OpenD
basic-info adapter. The adapter groups explicit codes by market, uses the existing
gateway and preserves partial successful batches.

### DR-S5-RR-03 - accepted - fixed

IDNA normalization errors are caught at the provider-controlled URL boundary. A
malformed hostname is discarded and cannot terminate the collector round.

### DR-S5-RR-04 - accepted - fixed

Observation timestamps are parsed, required to be timezone-aware and normalized to
UTC before acquiring the publication lock. Invalid input raises before replacing an
existing valid snapshot.
