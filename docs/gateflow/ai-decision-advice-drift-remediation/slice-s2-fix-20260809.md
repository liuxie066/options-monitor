## Finding decisions and fixes

### DR-S2-01 - accepted - fixed

The loader now converts every artifact semantic-validation failure into `PreparedPortfolioDistributionError`. This includes invalid row values and numeric overflow after otherwise valid JSON/hash parsing. Tick recovery therefore catches every invalid PM artifact at the typed boundary and returns `recovery_artifact_unavailable` without interrupting Candidate Engine.

Regression: a valid ready artifact is changed to contain a string quantity, its payload hash is recomputed, and the loader still returns the typed artifact error. The existing recovery corrupt-artifact test proves the account scan continues.

### DR-S2-02 - accepted - fixed

Initial adoption no longer relies on an error-message string to decide that an artifact is absent. It uses `lstat` on the exact run/account state path after the safe read fails:

- truly absent -> first PM read may proceed;
- existing, symlinked, non-regular, or otherwise unsafe -> immediate in-memory `artifact_invalid`, zero PM reads, no overwrite.

Regression: an artifact symlink is rejected with PM call count zero.

### DR-S2-03 - accepted - fixed

The v1 loader now closes `authority`, `validation`, and `integrity` fields and enforces the complete deterministic status machine:

- ready/degraded require PM provider and passed validation;
- disabled/provider-none require provider `none`, not-applicable validation, and an empty unavailable source payload;
- transport/protocol/HTTP/config/read failures require PM provider, failed validation, and no synthetic source facts;
- PM response errors and quality-unavailable reasons require source timestamps and the matching deterministic quality reason;
- dataset and reason-code arrays are sorted and unique.

Regressions reject extra authority fields and impossible unavailable reason/validation combinations even when the payload hash itself is valid.
