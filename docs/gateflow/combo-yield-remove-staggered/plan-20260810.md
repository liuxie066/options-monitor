## 1. Goal / Motivation / Success Signal

### Goal

从 Combo Yield **开仓策略路径**完整移除错期 `staggered_expiry_pair` 支持，使同期 `same_expiry_pair`
成为唯一策略结构、单一排序路径（Goal Confirmation 目标 1-7）。

### Motivation

- 错期排序口径与同期不一致：错期两个 rank key 与同期主键不同（`put_only_period_net_return` 期间非年化 vs
  `net_credit_retention` 主键），同一条"为 Put 选 Call"流水线并存两套口径（用户第一问）。
- 现有投资策略思想下错期不是必要结构：生产配置全部为 `same_expiry_pair`，生产 ledger 零错期数据，错期仅存在于
  示例配置与扫描/研究代码（用户第二问）。
- 用户已明确决策：删除全部错期开仓路径代码，不修复错期排序（用户第三问）。

### Success Signal

- `rg -i "staggered|错期" domain/ src/ tests/` 在开仓路径零命中（保留 ledger/生命周期错期支持与历史
  gateflow artifacts、CHANGELOG 中的历史记录）。
- `yield_enhancement_rank_key` 不再分支到 staggered；`rank_yield_enhancement_calls_for_put` 只有单一排序路径。
- `_build_pair_row` / `compute_yield_enhancement_metrics` 不再存在 `is_staggered` 分支与错期 None 字段。
- `YIELD_ENHANCEMENT_STRUCTURE_MODES` 只含 `same_expiry_pair`；config validator 不再接受 staggered/gap 字段。
- 全量 pytest（剔除既有时间敏感与 HTTP 沙箱失败）与 ruff 通过；US/HK `config validate` + `config build --dry-run` 通过。
- Daily Brief / 通知 / 报告不再输出错期文案（"🧩 Combo Yield · 错期全额融资"）。

## 8. Implementation Decisions

1. **删除 domain 函数 `structure_mode` 参数**：`compute_yield_enhancement_metrics` /
   `validate_yield_enhancement_pair` / `compute_yield_enhancement_funding_decision` 的 `structure_mode`
   参数在 S1 直接删除——唯一生产调用方 `sell_put_call_helper.py` 在 S1 同 slice 同步删除传参，
   `engine/__init__.py` 导出同步更新。`rank_yield_enhancement_calls_for_put` 保持单一路径（无该参数）。
   `structure_mode` 仅保留在 row/alert 数据字段层（值恒为 `same_expiry_pair`），不作为 domain 参数存在。
2. **S1 与 S2 边界**：`sell_put_call_helper.py` 是 domain 指标/排序的唯一生产消费者，且与
   `resolve_staggered_expiry_gap_days` 有 import 耦合，故 S1 必须同时清理扫描/配对与 domain；
   S2 清理配置/校验/数据需求（此时不再有 import 方）。
3. **config validator 行为**：删除 gap 校验分支；`min/max_expiry_gap_days` 从
   `YIELD_ENHANCEMENT_ALLOWED_FIELDS` 移除，并在 `_reject_unknown_keys` 之前仿照 `removed_funding_keys`
   模式做显式 removed-fields 检查、`die("...已移除，Combo Yield 仅支持 same_expiry_pair")`——明确报错，
   不做静默兼容。
4. **通知面**：删除 `_format_staggered_combo_alert` 与两个 dispatch 分支，保留同期格式化路径不动；
   保留 `structure_mode` extras 字段输出（值为 same）。
5. **research/shadow**：`ComboYieldResearchPolicy` 只允许 same；`combo_variants` 变体生成不再产出
   staggered variant；`combo_evaluation.py` 的 staggered 分支删除；`strategy_attribution.py` **只把
   `staggered_expiry_pair` 从 line 145 共享 set 移除**，保留 `diagonal` 分支与"call expiry 不得早于 put
   expiry"校验——`diagonal` 是独立 ledger 归因形态（`expiry_structure`），不属于开仓 `structure_mode`，
   该文件属于保留面，仅做此最小修改。
6. **测试清理**：删除或改写 staggered 用例；保留对 `same_expiry_pair` 主键与单一排序的断言强度。
   不因删除而削弱同期断言。
7. **文档**：`STRATEGY_ARCHITECTURE.md` / `PRODUCT_ARCHITECTURE.md` 错期章节删除或改写为"仅同期"；
   CHANGELOG、历史 gateflow artifacts 不改。
8. **不删除 shadow 排序**：`rank_yield_enhancement_shadow_rows` / `yield_enhancement_pair_shadow_rank_key`
   属于同期路径的 shadow/baseline 对比，保留。
