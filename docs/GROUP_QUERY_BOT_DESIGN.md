# 群查询bot 设计方案

状态：已确认设计。按 2026-11-10 用户确认的修订顺序，S1 最小接入预检和 S2 五方法 API 已完成本地实现、离线验证与复审；S3 自然语言、会话存储和可选服务生命周期已完成本地实现并进入离线审查。真实个人群接入、模型/行情真实联调、发布和部署均未验证；真实 G2 是最终联调和实际使用的前置。入口见[插件说明](../plugins/group-query-bot/README.md)。

整理日期：2026-11-09。

## 1. 已确认需求与成功标准

新增可选插件「群查询bot」，绑定一个新建的飞书应用机器人。目标为个人用户组成的飞书群，授权群成员通过 @这个 bot，用自然语言查询指定标的，以及平仓、上移、下移建议；不要求成员提供组织名称。bot 需要独立配置模型 API Key，使用当前行情回答。目标个人群能否接入应用机器人须按第 8 节联调核验。

数据访问通过受鉴权的业务 API 完成，权限由 API 服务端控制。群查询凭据不得访问远端 `lx`、`sy` 的账户、资金、持仓、收益，也不得通过报告、日志或其他接口间接获得这些数据。SSH 不属于查询链路，也不承担接口授权职责。

成功标准：

1. 未安装插件的普通用户无需配置新 bot、模型或查询 API；正常启动、扫描和通知不加载该插件。
2. 授权群成员能够自然语言查询；必要参数缺失或有歧义时，bot 先追问。
3. 当前建议能追溯到本次评估的行情时间、权限、输入、费用口径和策略版本。
4. 使用群查询 API 凭据直接请求、绕开模型请求或修改请求参数，都无法取得账户数据。
5. 不同群、发送者和会话的临时参数互不串用。
6. 缺失、延迟、过期、部分数据、有效零候选和服务故障有不同的可见结果。

## 2. 产品范围

首版按 OM 现有策略定义：上移为已卖出 Call 提高行权价，下移为已卖出 Put 降低行权价；支持美股、港股标准期权及其标的。

| 能力 | 必要输入 | 输出 |
| --- | --- | --- |
| 标的和合约查询 | 标的；查询具体期权时提供可唯一定位的合约 | 标的报价、合约报价、行情时间与状态 |
| 指定标的候选查询 | 标的、Put/Call 方向；期限等采用明确展示的公共策略默认值或用户指定值 | 范围内候选、指标、排序和覆盖情况 |
| 指定标的与 Delta 区间的候选查询 | 标的、合约绝对 Delta 区间；Put/Call 方向需明确，期限可采用公共配置 | 区间内的合格候选、实际 Delta、生效区间、排序和覆盖情况；使用 query_candidates 的可选筛选参数 |
| 平仓场景评估 | 原合约、short 方向、张数、开仓权利金 | 买回成本、净兑现比例、剩余收益指标、平仓或持有判断及原因 |
| Put 下移场景分析 | 原 short Put、张数、最晚新到期日；可选最低新行权价 | 满足规则的新合约、净增现金、行权价变化、延期及排序 |
| Call 上移条件分析 | 原 short Call、张数、最晚新到期日；可选最高新行权价 | 上移候选、扣费现金比较、行权价提升及未核验条件 |

仅提供标的时，可以查询行情和开仓候选，不能据此推断用户已有仓位。平仓和移仓只使用用户主动提供的临时参数，不关联真实账户。

首版不提供交易、下单、账户接入、资金配置、持仓同步、收益报告、运维控制或长期持仓档案。候选查询不承诺用户具备相应现金或股票覆盖，也不按真实账户容量推荐张数。

## 3. 用户交互与自然语言

以下是输入示例，不包含真实行情或交易结论：

```text
@bot 看看 NVDA 未来一个月的 Put，有哪些候选？
@bot 给 NVDA 找绝对 Delta 在 0.18 到 0.22 之间的 Put，期限用默认范围。
@bot 我卖了两张 NVDA 2026年12月18日到期的180 Put，开仓收了每股4.2美元，现在值得平仓吗？
@bot 上面这张 Put 能不能往下移？最晚新到期日是2027年1月15日。
@bot 看看 NVDA 2026年12月18日的190 Call 上移，1张，最晚到2027年1月15日。
```

### 3.1 自然语言处理流程

bot 使用独立配置 API Key 的模型理解自然语言，模型传输和凭据绑定见第 9 节。模型负责识别意图、提取参数、生成追问，并在拿到工具结果后自己组织语言回复。报价、金额、费用、年化、排序和建议状态仍由业务 API 的确定性计算产生；宿主把展示级事实整理成中文事实卡（数值、日期、合约代码、费用假设、覆盖缺口与未核验条件）作为工具消息交给模型，模型只能引用事实卡中的数字，回复发送前再由宿主校验。与五项固定能力无关的通用问题（如交易所日程、市场规则、合约常识、概念解释）由模型调用宿主提供的 answer_general 工具提交回答；宿主原样展示且不附加实时查询声明，但不得给出具体价格、费用、年化数值或买卖建议，不得声称执行实时查询；涉及时区或夏令时的信息须提示以交易所官方说明为准。

每个用户回合按以下流程处理：

1. **校验事件并准备上下文**：通过新 bot 身份、授权群、真实 mention、消息去重及第 9.1 节模型前准入检查后，宿主取出该用户当前有效会话的必要对话和已确认参数，连同新消息提供给模型。
2. **识别意图与整理参数**：模型判断对应第 6.6 节五个固定方法中的哪一个，提取标的、方向、合约、张数、权利金、Delta 区间等业务字段，并结合本会话已确认条件理解修改或引用。
3. **补齐必要信息**：必要参数缺失或有歧义时先追问，保存有限期的待补参数；信息不足时不提交该业务请求。
4. **校验并调用固定 API**：宿主校验方法和业务参数，填写请求与会话元数据；API 服务端独立执行鉴权、能力授权、范围和额度校验，再获取行情并计算。模型不能填写宿主身份或选择任意接口。
5. **组织回复**：工具返回后，宿主生成中文事实卡（只含展示级数值和状态，不重算任何金额），模型据此用简短口语回复；宿主不再附加结构化结果块。发送前宿主校验回复：数字、日期和合约代码必须来自事实卡或用户原话；平仓和移仓必须说明费用为估算、不是账户实际扣费；条件移仓必须说明股票覆盖未经核实；最近已知报价必须说明不是当前实时价；无法完成时必须给出原因；内部字段名、英文状态码、JSON、表格和超长回复一律拒绝。校验失败时先按具体原因让模型重写一次；再次失败或预算不足时，由宿主从同一份结构化事实生成简短兜底回复。每次后续模型调用也受第 9.1 节预算约束。澄清类回复在宿主侧统一附加一次固定的「未执行实时查询」说明（通用问题回答不附加）；该说明由宿主生成、不写入会话历史，也不随多轮累计。历史工具结果以事实卡作为工具消息回放；旧格式降级为仅供指代的用户上下文。

参数理解遵守以下规则：

- 标的重名、市场不明、合约或年份有歧义、权利金单位不明时，先确认，不猜测。
- 相对日期由服务端按市场日期归一化，回复展示完整日期和实际搜索范围；不能从旧会话继承已过期的日期边界。
- 合约乘数、币种与交割单位由合约证据确认，不默认每张 100 股。
- 最晚新到期日必须由用户明确提供，不能由模型静默选择。
- 查询结果、用户文字和历史对话均不能改变 API 权限、固定工具集合、地址或凭据。
- 模型故障时说明自然语言服务不可用；不以模型知识代替实时行情。

### 3.2 会话上下文与记忆范围

第一期支持有限期的多轮会话上下文。bot 宿主使用插件实例独立的 SQLite 数据库保存必要对话、待补参数和已确认输入，历史对话仅保留最近 24 小时，并在每次模型调用时组装该会话未过期的相关上下文；不依赖模型供应商自动、永久记住群成员，也不启用跨会话长期个人记忆。存储位置及到期清理规则见第 10 节。

| 内容 | 第一期使用方式 |
| --- | --- |
| 最近必要对话、待补参数、已确认查询条件 | 在有效会话内用于追问、指代和条件修改；发送给模型的上下文受预算限制 |
| 用户主动提供的合约、张数、开仓权利金 | 仅作为临时场景输入，同一有效会话内可继续引用；输入身份和修改规则遵守第 7.2 节 |
| 之前的报价和评估结果 | 仅表示原评估时点的事实；新评估重新获取或验证符合当前资格的行情，不能沿用旧结论冒充当前建议 |
| 跨会话个人持仓、成本档案、长期偏好 | 不建立、不自动恢复或沿用 |
| 远端 lx、sy 的账户、持仓、收益 | 不读取，不进入会话上下文或模型输入 |

会话范围至少绑定新 bot 身份、租户、群、发送者和线程。即使两名成员处于同一群、同一线程，也不能互用成本、临时持仓或待补参数；线程不存在时仍保留发送者隔离。这里的租户是飞书平台技术标识，不要求个人群成员提供组织名称；实际事件中应用侧与发送者侧租户字段的含义和可用性须在联调时核验，不能伪造身份来绕过缺字段校验。后续「上面这张」只引用同一范围内用户已确认的临时输入；过期或存在多个候选引用时重新确认。

群内输入和回复对群成员可见。发送给模型供应商的内容限于必要对话和允许的查询结果，不包含接口凭据、系统提示中的秘密或远端账户数据；用户主动提供的合约与成本明确标识为临时场景输入。

历史对话采用按记录时间计算的 24 小时滚动保留期，后续消息、读取和服务重启不延长旧记录的保留期；待补参数及已确认临时输入的副本同样不得绕过原输入的保留期。服务重启后自动恢复同一身份下仍未过期的会话，先清理与过滤过期记录，再组装上下文，不能恢复过期输入或延长原保留期。每次模型调用最多带入最近 10 轮未过期的历史对话，一轮指一次用户消息及对应 bot 回复；历史对话、已确认参数和历史查询结果合计不超过 **4000 tokens**。轮数和 token 上限共同生效，只影响模型上下文，不提前删除仍在 24 小时保留期内的数据库历史。

超出历史预算时优先保留必要的已确认参数和最近完整对话，较早历史不发送；不能截断业务字段后继续提交请求。必要信息无法容纳或上下文不可用时，重新确认或缩小本次任务。系统指令、工具定义、本次消息及本轮工具结果、输出预留另行计入模型总窗口与第 9.1 节预算检查，4000 tokens 不是整次模型调用的总输入或账单上限。

### 3.3 多轮查询示例

以下示例为同一用户在同一有效会话内的交互流程，不包含真实行情或交易结论；每次用户请求仍须 @当前 bot。

```text
用户：@bot 看看 NVDA 的 Put，期限 14 到 45 天。
bot：以 NVDA、short_put、dte=[14,45] 查询并回复候选。

用户：@bot Delta 限制在 0.18 到 0.22。
bot：沿用已确认标的、方向和期限，增加 abs_delta_range=[0.18,0.22] 后查询。

用户：@bot 只展示前 5 个。
bot：沿用已确认筛选条件，将 limit 改为 5，按当前行情资格返回结果。
```

只修改某个条件时，其他仍然有效的已确认条件可以继续使用；重新评估的请求、输入身份和行情资格仍执行各自合同，不能仅凭对话中的旧结果跳过校验。

## 4. 可选插件与部署角色

| 项目 | 拟议名称或约定 |
| --- | --- |
| 展示名称 | 群查询bot |
| 插件标识 | `group-query-bot` |
| 分发包 | `om-group-query-bot-plugin` |
| Python 包 | `om_group_query_bot` |
| 源码目录 | `plugins/group-query-bot/` |
| 默认状态 | 不安装、不启用、不启动服务 |

插件提供两种按需启动的角色，放在同一个可选包内，不另建插件框架：

1. **bot 端**：飞书接入、群与 @校验、自然语言、多轮参数补齐、受限 API 客户端、消息回复。
2. **API 服务端**：凭据鉴权、能力授权、范围校验、公共策略配置、行情取数与场景评估编排。

首版限定 bot 与 API 同机部署，作为独立进程运行并使用各自显式配置。查询 API 仅监听本机回环地址 `127.0.0.1`，由管理员配置端口；bot 使用固定回环 HTTP 地址及专用 Bearer 凭据调用，所有业务读取仍经过 API 授权。同机不增加绕过 API 的读取路径，也不开放到局域网或公网。跨主机部署及其 HTTPS 入口不属于第一期交付与验收范围。

bot 端按需复用现有 `feishu` 插件的传输与模型适配器，不需要券商插件。API 端按需使用已有行情 provider 和 `position-advice` 计算能力；群查询角色不依赖账户、portfolio 或账本读取能力。

安装、依赖检查和服务启动分开。沿用现有官方插件登记、精确 Release 匹配、资产校验和升级选择机制；缺依赖时列明缺项，不静默安装或启动服务。升级不自动给普通用户增加该插件。

以下仅为拟议 CLI，当前不可作为已实现命令使用：

```text
om plugins install group-query-bot --confirm
om group-query-bot serve --config <bot端专用配置>
om group-query-bot api-serve --config <API端专用配置>
```

## 5. 总体调用链与责任

```text
飞书授权群中的 @新bot
  → 飞书事件身份、群和 mention 校验
  → bot 端群/用户配额与模型预算准入
  → bot 端模型理解与参数补齐
  → 固定业务请求适配器
  → 同机回环 HTTP 查询 API：鉴权 → 能力授权 → 参数与范围校验
  → 现有行情 provider + 场景输入合同 + 策略/费用 owner
  → 结构化业务结果和证据摘要
  → bot 端事实卡（展示级中文事实）与模型口语回复
  → 宿主回复校验（数字来源、必需说明、长度）与兜底
  → 新bot 回复原消息
```

API 同时承担行情查询和建议计算，不再为本功能增加一层独立行情网关。bot 不直接调用 OpenD SDK、现有完整 Tool Gateway、账户服务或远端 shell。

服务端处理临时输入时，只读取公共策略、费用、市场配置和本次行情。即使 API 与原有 OM 共用主机，群查询处理函数也不能加载账户默认值、读取账本或搜索账户历史报告。

接口授权是数据访问的主要边界。独立进程、最小运行凭据和网络配置是部署措施，不能替代服务端授权，也不能以「换了目录」或「只读模式」作为验收依据。

## 6. API 身份与权限合同

### 6.1 三类凭据分离

| 凭据 | 持有方 | 权限 |
| --- | --- | --- |
| 新飞书 App Secret | bot 端 | 以新应用身份收发消息 |
| 模型 API Key | bot 端 | 调用指定模型服务 |
| 群查询 API 凭据 | bot 端及 API 服务端的校验配置 | 仅调用服务端授予的群查询能力 |

模型 Key 不授予 OM 数据权限；飞书群身份也不能自行升级为账户授权。群查询 API 凭据不是现有管理凭据或账户查询凭据的别名。

首版采用独立 Bearer 凭据和固定的服务端授权配置，不为单个 bot 引入通用 IAM、OAuth 或 JWT 平台。凭据通过 secret store 管理，校验材料不写入普通配置；比较方式复用已有安全鉴权范式。

### 6.2 服务端授权记录

服务端将已验证凭据绑定到固定 principal、能力集合和市场范围。下面是拟议授权结构，实际字段尚未实现：

```yaml
principal_id: group-query-bot
credential_ref: group_query_bot.query_api.token
capabilities:
  - market:read
  - candidates:evaluate
  - scenario:close
  - scenario:roll-down
  - scenario:roll-up
markets: [us, hk]
account_scope: []
```

`account_scope: []` 明确表示无任何账户权限，不能解释为全部账户、默认账户或无需检查。未列出的能力一律拒绝；新增服务端接口不会自动进入群查询授权。

授权配置只由管理员在服务端设置。请求中的 `scope`、`role`、`principal_id`、账户标签或模型生成的任何声明都不能覆盖它。API 服务端不向 bot 返回全部工具、配置、凭据或账户清单。

### 6.3 拟议 API 与能力映射

所有路径、schema 和 scope 名称都是本设计提出的新合同，尚未注册到现有 API。

| 方法与路径 | 所需能力 | 允许的业务输入 |
| --- | --- | --- |
| `POST /api/group-query-bot/v1/quotes` | `market:read` | 单个标的，可附一个明确期权合约 |
| `POST /api/group-query-bot/v1/candidates` | `candidates:evaluate` | 标的、策略方向、期限及可选的绝对 Delta 区间等有界筛选条件 |
| `POST /api/group-query-bot/v1/scenarios/close` | `scenario:close` | 用户提供的原合约、张数、权利金及输入身份 |
| `POST /api/group-query-bot/v1/scenarios/roll-down` | `scenario:roll-down` | 用户原 short Put、张数、最晚新到期日及允许的边界 |
| `POST /api/group-query-bot/v1/scenarios/roll-up` | `scenario:roll-up` | 用户原 short Call、张数、最晚新到期日及允许的边界 |

外层鉴权先于业务分发；每个接口的应用处理入口也必须接收并核验已验证 principal，避免未来新增调用者绕过路由授权。未通过授权前，不进行行情、账本、portfolio 或报告读取。

接口采用明确字段白名单。以下字段不作为群查询业务输入接受：`account`、`accounts`、`lot_id`、`position_lot_id`、`config_path`、`runtime_root`、报告或文件路径、任意 URL、OpenD host/port、任意工具名和任意 SDK 方法。嵌套对象同样严格校验，不静默忽略未知字段。

市场、标的、方向、期限、合约数量和候选范围均在服务端校验并设资源上限。模型不能自定义 API 地址、请求方法、认证头或调用其他路径；客户端只提供固定业务函数。

每个请求另有 `request_context` 元数据，由 bot 宿主根据已验证的飞书事件填写租户、群、发送者和线程身份；模型可见的业务参数 schema 不包含这些字段。API 将凭据绑定的 bot 实例、principal 与上述身份共同规范化为 `conversation_scope_sha256`，用于会话输入、缓存和审计隔离。线程不存在时使用明确的空值，不能省略发送者后退化为群级共享上下文。API 信任已鉴权 bot 服务提供的事件上下文作为隔离标签，它不是独立的用户授权证明，也不能扩大凭据的能力或市场范围；直接 API 请求同样受 principal 总额度约束。

### 6.4 账户数据拒绝规则

群查询 principal 不具备以下能力，包括它们的别名、批量形式和嵌套读取路径：

- 账户列表、资金、现金、净值、持仓、订单、成交、收益和业绩。
- 本地账本、账户报告、简报、决策历史、运行日志、回执、源码与配置浏览。
- portfolio 查询、管理 Control、通用 Tool Gateway 执行、文件或 shell 执行。

如果共用的 API 宿主还挂载了账户接口，群查询凭据必须在这些接口得到拒绝；未挂载的路径返回不存在。不能依赖模型「不调用」或 bot 隐藏按钮来实现拒绝。

对于允许接口，也不能通过缺省参数、历史参考、错误消息、缓存键或调试输出泄露 `lx`、`sy` 数据。临时输入不生成真实 lot，不映射到 `lx`、`sy` 或伪造的配置账户。

### 6.5 错误与响应

传输层区分：缺失/无效凭据为 401；已认证但能力或市场越权为 403；不存在的路径为 404；非法输入为 400；限频为 429；上游或服务不可用使用相应 5xx。返回有界、脱敏的错误，不包含原始异常、秘密或内部文件路径。

统一响应提供请求 ID、schema 版本、传输成功标志、业务数据和错误。传输成功不代表行情完整或建议可评估；业务状态继续使用现有 owner 的语义，不能把 `partial`、`not_evaluable` 或 `unavailable` 改成零候选。

结果至少保留：规范化输入及 `input_id`、`input_source=user_provided`（场景请求）、带时区的输入事实时间、评估时间、实际搜索边界、行情来源与观测时间、权限和市场状态、覆盖缺口、费用版本、策略版本及适用的封存证据标识。响应不携带账户上下文或完整内部产物。

#### 6.6.2 `query_quotes`

**用途**：满足单独查行情的需求，例如「NVDA 现在多少钱？」或「NVDA 2026年12月18日到期的 180 Put，买卖价和 Delta 是多少？」。返回标的或指定期权的价格、bid/ask、Delta、行情时间以及实时、延迟等状态，供用户了解当前行情。

**调用关系**：`query_candidates`、`evaluate_close`、`evaluate_roll_down` 和 `evaluate_roll_up` 各自在本次查询或评估中获取所需行情，并按对应规则校验、封存证据。模型可以直接调用这四个函数，`query_quotes` 不作为它们的必经前置步骤；先前独立查价的响应也不能替代本次评估要求的行情证据。

**已确认范围**：第一期保留独立查行情的 `query_quotes` 及其 `/quotes` 入口，用于标的和指定期权的价格、指标及行情状态问答。该能力是第一期交付范围，连同其余四个业务方法组成五个方法清单。

入参 `parameters`：

| 字段 | 类型 | 必填/默认值 |
| --- | --- | --- |
| `symbol` | `Symbol` | 必填 |
| `contract` | `OptionContract` | 可选；省略时仅查询标的，提供时同时查询标的与该期权 |

出参 `data` 除公共字段外：

| 字段 | 类型与语义 |
| --- | --- |
| `underlier` | `Quote` 或 null，含标的报价 |
| `option` | 指定合约时为 `Quote` 或 null；未请求合约时为 null，并从 effective_parameters 明确这是未请求而非缺失 |
| `quote_status` | `current`、`delayed`、`last_known` 或 `unavailable`，按本次请求所需报价的共同资格表达；逐证券资格仍保留在各 Quote 中 |
| `missing_requirements` | 缺少的合约、字段、权限或状态证据数组；未请求的可选部分不算缺失 |

最近成交时间不充当 bid/ask 更新时间；查询方法可展示明确标记的非实时数据，不输出平仓或交易资格。不能定位到上市合约时明确报输入/合约身份错误，不自动换成邻近合约。

#### 6.6.3 `query_candidates`

使用同一个方法和 `/candidates` 路径查询开仓候选。Delta 筛选通过可选的绝对值区间表达，与期限、行权价等条件共同生效。

入参 `parameters`：

| 字段 | 类型 | 必填/默认值 |
| --- | --- | --- |
| `symbol` | `Symbol` | 必填 |
| `strategy` | `short_put` 或 `short_call` | 必填；自然语言未明确方向时先追问 |
| `dte` | `[min_dte, max_dte]`，整数且 `1 <= min <= max <= 365` | 可选，采用公共策略对应方向的期限窗口并回显 |
| `strike` | 正数，指定精确行权价 | 可选，省略时用公共策略范围；可与 Delta 区间同时使用 |
| `abs_delta_range` | `[min_abs_delta, max_abs_delta]`，有限小数且 `0 <= min <= max <= 1`，闭区间 | 可选，省略时采用公共策略 Delta 范围；例如 `[0.18, 0.22]` 表示合约报价 Delta 的绝对值在 0.18 到 0.22 之间，包含端点 |
| `limit` | 整数 1..50 | 可选，默认 10，仅限制展示，不缩小取数或改变正式排序 |

Delta 采用合约报价的小数口径；`abs_delta_range` 不表示按张数或乘数放大的持仓净 Delta。Put/Call 方向由 strategy 明确，不能仅凭 Delta 符号推断。自然语言只说一个 Delta 数值或「接近 0.20」而未明确上下界时先追问区间，不静默添加容差；单位含糊时同样先确认，不把 `20` 猜成 `0.20`。

群查询请求只使用 `abs_delta_range` 表达 Delta 筛选；只有上限的查询可表达为 `[0, 上限]`。服务端按公共策略 owner 解析内部 `max_abs_delta`，有上限时与请求区间取交集，不自动放宽公共策略。交集为空时返回 `INPUT_ERROR` 并说明冲突；部分相交时回显实际生效区间。未传区间时采用公共策略的 `[0, 生效上限]`；公共策略关闭 Delta 过滤且请求也未给区间时，生效范围为 null，沿用原策略行为。显式请求区间时，即使公共策略关闭 Delta 上限，也必须校验 Delta 并执行请求区间筛选。

示例业务参数：

```json
{
  "symbol": "NVDA",
  "strategy": "short_put",
  "abs_delta_range": [0.18, 0.22],
  "limit": 10
}
```

出参 `data` 除公共字段外：

| 字段 | 类型与语义 |
| --- | --- |
| `strategy`、`effective_filters` | 实际方向及最终生效阈值、期限/行权价范围 |
| `requested_abs_delta_range` | 用户请求的绝对 Delta 闭区间；未传时为 null |
| `effective_abs_delta_range` | 与公共策略共同限定后的实际闭区间；没有 Delta 过滤时为 null |
| `outcome` | `found`、`none` 或 `unable`，保留现有候选 owner 语义；只有范围完整且无合格候选时才为 none |
| `coverage` | `Coverage`，即使 outcome=found 也可能部分覆盖 |
| `candidates` | 已排序数组；每行包括合约代码、OptionContract、DTE、bid/ask、sell_limit、Delta/IV/RV 等证据指标、multiplier、`calculation_contracts=1`、净权利金、期间/年化净收益指标、费用和原因 |
| `candidates[].delta`、`candidates[].abs_delta` | 报价原始带符号 Delta 及其绝对值；Put/Call 符号、单位、来源和时效沿用 owner 校验；缺失或不可验证时保留 null 和原因 |
| `displayed`、`omitted` | 展示数和省略数；先计算/排序完整已取集合，再应用 limit |
| `exclusion_summary` | 排除原因与计数；不包含账户数据 |
| `fee_model` | `FeeModel`，明确每手比较假设 |

候选 owner 对完整的已取有界集合执行 Delta 区间匹配及原策略硬规则，沿用现有策略排序，最后应用 limit；bot 不从已截断结果中二次筛选。Delta 区间是筛选条件，返回顺序仍表示原策略排序口径。

每行净权利金和收益沿用 owner 的 `net_premium`、`period_net_return`、`annualized_net_return` 等口径；候选金额按一张合约计算，不是建议张数，也不证明股票或资金覆盖。Delta/IV/RV 等字段是否阻断资格由对应策略 owner 决定；启用 Delta 区间筛选时，缺失、过期、来源/单位/符号不合法的 Delta 不能补零或放行。仍有无法判断是否命中的合约时，保留未评估计数与覆盖缺口，不能报告完整零匹配。

当前源码 `option_candidates` 仅支持 Delta 上限参数，尚无本文的区间合同。实施时在既有候选输入/策略 owner 扩展区间筛选，并由同一个群查询方法适配；不复制取数、金融计算或排序实现。

#### 6.6.4 `evaluate_close`

入参 `parameters`：

#### 6.6.5 `evaluate_roll_down`

入参 `parameters`：

不接受 opening_premium，移仓现金比较不使用原开仓权利金。出参 `data` 除公共场景字段外：

| 字段 | 类型与语义 |

| `scope`、`coverage` | 实际请求日期/行权价边界和 `Coverage`；不适用而未搜索时 coverage 为 null |
| `candidates` | 排序后的经济合格候选；每行含新合约、bid/ask、费用、accepted、原因及 metrics |
| `candidates[].metrics` | `old_close_cost`、`new_net_premium`、`net_credit`、`strike_drop_pct`、`extension_days`、新旧 capital basis、`incremental_period_return`、`incremental_annualized_return`、新旧 `remaining_max_annualized_return` 及年化差等现有指标 |
| `displayed`、`omitted`、`fee_model` | 展示计数及实际张数下的两腿 `FeeModel` |
| `calculation_kind` | 固定为 `leg_cashflow_estimate`，两笔单腿报价下的现金估算 |

不足以证明搜索完整时不能返回「没有合格方案」。相同到期日允许 extension_days=0，依赖延期天数作分母的指标此时为 null，不除零、不阻断其他有效指标。

#### 6.6.6 `evaluate_roll_up`

入参 `parameters`：

| 字段 | 类型 | 必填/默认值 |
| --- | --- | --- |
| `position` | `ScenarioPosition`，option_type 必须 call、side 必须 short | 必填；仅等量替换这一份输入的全部张数 |
| `search_bounds.max_new_expiration` | `YYYY-MM-DD`，不早于原到期日且符合公共配置期限上限 | 必填，无默认值 |
| `search_bounds.max_new_strike` | 大于原行权价的正数 | 可选，省略时使用已明示的公共搜索资源边界 |
| `limit` | 整数 1..50 | 可选，默认 10，仅展示限制 |

不接受股票快照、实际覆盖、账户、lot 或 covered_shares；用户口头声明持股不构成验证凭证。出参 `data` 除公共场景字段外：

| 字段 | 类型与语义 |
| --- | --- |
| `schema_version` | 数据 schema 固定为 `group_query_roll_up_result.v1`，与外层响应 schema 区分 |
| `status`、`outcome`、`scope`、`coverage` | 数据完整性、适用性与实际搜索范围，含义与下移相同，不表示账户可执行资格 |
| `analysis_kind`、`account_eligibility`、`stock_coverage`、`unverified_conditions` | 第 7.4.1 节规定的必填条件分析字段，覆盖始终未经核验 |
| `position`、`old_quote` | 用户原 Call 及本次用于买回估算的报价 |
| `candidates` | 按共享经济排序键排列的正净现金候选；每行使用 economic_result，不返回正式 credit_roll |
| `candidates[].metrics` | `old_close_cost`、`new_net_premium`、`net_credit`、`net_debit`、`strike_increase`、`strike_increase_pct`、`extension_days`、`assignment_proceeds_uplift`、`assignment_net_improvement`、条件资金分母及期间/年化指标 |
| `displayed`、`omitted`、`fee_model`、`calculation_kind` | 展示计数、两腿估费及固定 `leg_cashflow_estimate` |

`assignment_net_improvement` 是假设双方最终按各自行权价交股的条件差额，不是已实现或预期收益；分母使用 `hypothetical_stock_market_value`。即使经济条件成立，account_eligibility 也保持 not_verified。

#### 6.6.7 公共失败语义

| HTTP / code | 含义 | 调用方行为 |
| --- | --- | --- |
| 400 / `INPUT_ERROR` | 字段、单位、身份或范围非法，或输入 ID 与内容不一致 | 修正或追问，不以默认账户/近似合约补齐 |
| 401 / `UNAUTHORIZED` | 凭据缺失或无效 | 停止业务调用，提示管理员检查配置 |
| 403 / `PERMISSION_DENIED` | 能力或市场越权 | 不换工具、账户或通道重试 |
| 404 / `NOT_FOUND` | 未开放的 API 路径 | 不发现/调用通用工具入口 |
| 429 / `RATE_LIMITED` | principal、并发或请求预算受限 | 有界等待重试提示或结束本次请求，不无限重试 |
| 503 / `DEPENDENCY_UNAVAILABLE` | 无法完成请求所需的服务/插件不可用 | 明确依赖故障；不得称为零候选 |
| 504 / `UPSTREAM_TIMEOUT` | 请求抵达时截止预算已耗尽，或上游在本次 deadline 内未完成 | 预算耗尽时不开始业务 I/O、不再重试；等待结束不等于实际工作结束，按第 9.2 节保留占用并处理迟到结果 |
| 500 / `INTERNAL_ERROR` | 不能正常产出受控业务结果的内部故障 | 脱敏返回追踪 ID，不输出内部路径或原始异常 |

可以正常生成不可评估、部分覆盖、不适用或有效零结果时，使用成功 envelope 并保留相应业务状态；只有接口本身失败才使用失败 envelope。已认证但非法的请求不能被降级成业务不可评估来掩盖鉴权或输入错误。历史报告读取、配置管理、账户查询和交易均没有对应的第一期方法。

## 7. 实时行情与策略复用

### 7.1 行情资格

通过现有 `market_data_provider` 和 required-data/evidence owner 获取行情，API 请求编排一次取数并封存本次评估证据；纯计算阶段只消费已验证输入，不在 renderer 或模型里再次取价。

当前建议沿用[持仓建议合同](CLOSE_ADVICE_CONTRACT.md)：标的与期权均须具备已确认实时权限，观测时间相容、同市场日期、未超共享 300 秒窗口，市场连续交易、期权状态 NORMAL 且明确未停牌，并满足快照后的状态复验。接口成功、最近成交时间或模型回答都不能代替报价时效证据。

300 秒是现有策略资格上限，不是 bot 刷新频率或「即时成交」承诺。普通行情展示可以展示已知延迟或最近报价，但必须标注；这种展示资格不能升级为当前建议资格。

### 7.2 平仓

复用现有 Close Advice 唯一策略、费用估算和证据校验。用户必须提供可确认的原合约、short 方向、张数和开仓权利金；乘数、币种等由证据补齐。原始开仓价单位须明确。

扩展现有输入 owner，使 `user_provided` 场景使用独立输入身份，不再要求配置账户；账本来源继续执行原有账户与 lot 身份要求。不能通过填入虚拟账户绕过现有校验。

当前 `evaluate_position_advice` 仍要求账户并可查找账户历史报告，不能直接成为群查询 API 的处理函数。场景编排应接收完整临时输入和公共配置，再调用现有计算 owner，不复制财务公式。下面的输入和证据绑定合同同时适用于平仓、Put 下移和 Call 上移。

#### 7.2.1 无账户场景输入合同

拟议输入 schema 为 `group_query_scenario_input.v1`，分为宿主元数据、用户确认的业务输入及服务端补齐的证据字段：

| 字段 | 来源与规则 |
| --- | --- |
| `request_id` | bot 宿主为一次 API 调用生成；用于请求追踪，不作为长期结果缓存键 |
| `input_id` | bot 宿主在输入确认后生成的不透明 ID；只标识同一会话内不可变的输入，不能作为读取其他请求的入口 |
| `input_source` | 固定为 `user_provided`，不接受模型改写 |
| `input_as_of_utc` | 宿主记录用户确认当前场景事实的带时区 UTC 时间；不是开仓日期，不能晚于评估时刻 |
| `operation` | 对应当前固定路由的 close、roll-down 或 roll-up，不能在 body 中改成另一能力 |
| `position` | 第 6.6.1 节的 ScenarioPosition：规范化标的、合约身份、short 方向和张数 |
| `opening_premium`、`opened_at` | 仅平仓接受；权利金按明确单位归一化，开仓日期可选；字段含义和合法性见第 6.6.4 节，其他场景拒绝这些字段 |
| `search_bounds`、`limit` | 移仓的最晚新到期日、该方向允许的行权价边界和展示上限；平仓接口不接受这些字段 |
| `contract_evidence` | 服务端从合约证据取得的币种、乘数、交割单位和规范化合约身份；不能把用户猜测作为已核验事实 |

请求中的 `position` 只接受该操作的用户可填字段，`contract_evidence` 是服务端内部补齐部分，不开放客户端覆盖。客户端必须提交完整的已确认业务输入，不仅凭 `input_id` 请求服务端恢复旧持仓；任一已确认业务字段（含操作、搜索边界与展示 limit）改变时，宿主生成新 `input_id`。追问沿用当前会话的待确认输入，重新评估则有新的 `request_id` 和评估身份。

服务端按版本化规则规范化金额、日期、代码、枚举和数量，再复用现有 canonical SHA-256 能力生成 `input_sha256`。摘要覆盖完整业务输入、合约身份、币种/乘数及搜索边界，不包含可随请求变化的追踪时间或文本表达。同一输入 ID 出现不同摘要时拒绝请求，不能覆盖原绑定；在不同会话范围内，即使输入相同也不能复用含用户参数的结果。

#### 7.2.2 请求级计划与封存绑定

服务端为每次评估生成新的 `assessment_id`，冻结本次有效公共策略和费用模型，然后规划精确原合约、所需替代合约范围、日历及市场状态。场景计划使用独立版本 schema，以 `inputs[input_id]` 组织需求，不创建 `accounts`、账户 lot 或账户报告。

在现有 required-data/evidence owner 增加场景计划的构建、校验和索引入口，复用其合约需求、覆盖、receipt 和 payload 完整性逻辑；不把场景计划传给只接受账户映射的 `account_requirement_index`，也不通过放松原账户 runner 的身份检查来接入。账本计划与账户评估入口保持各自现行 schema；场景入口直接装配已验证领域输入，复用计算 owner。

每个场景评估绑定至少包含：

- 已认证 `principal_id`、`conversation_scope_sha256`、`input_id`、`input_sha256` 及 `input_as_of_utc`；
- `assessment_id`、评估时间、场景计划 schema/摘要；
- 快照 manifest 摘要，以及计划选用的 receipt、payload 摘要和观测时间；
- 有效公共策略摘要、策略版本、费用模型 ID 与版本。

使用上述明确字段生成版本化 `binding_sha256`。API 内部保存可核验的计划、绑定与行情证据，响应只返回允许的摘要和标识，不暴露内部路径或账户结构。输入身份、经济摘要、计划、快照、配置或费用模型任一不匹配时为不可评估；鉴权和输入错误仍按第 6 节返回，不用不可评估掩盖它们。计算阶段不修补证据、不回读账户报告，也不临时重新取价。

缓存命中也必须复验绑定和当前行情资格；不能仅用标的、`input_id` 或 `request_id` 命中场景结果。缺失绑定和同一行情下不同成本、数量、搜索边界的输入都必须有负向测试；账户计划、正式平仓和正式 CC 覆盖守卫保留回归验证。

### 7.3 Put 下移

原仓、候选身份、价内/价外适用范围、等量替换、更低行权价、不早于旧到期日、最晚到期边界、两腿费用、正净增现金和排序均沿用现有 Put 移仓规则。原始开仓权利金不参与这次移仓现金比较。

旧仓按 ask 买回，新仓按 bid 卖出；两腿按实际张数分别估费。输出是 `leg_cashflow_estimate`，不能表述为组合盘口或成交保证。净增现金不等于交易链已经盈利。

### 7.4 Call 上移

现有正式 Covered Call 上移要求核验实际股票及全部未关闭 short Call 的覆盖；群查询 API 没有这些账户证据。

因此本功能提供条件分析：复用同一策略 owner 的合约校验、经济计算和排序能力，显式标注股票覆盖未经券商/账本核验。即使用户声明有股票，也只是用户输入，不能当作已验证覆盖，不得绕过现有正式上移的覆盖守卫。

实现时在现有 owner 抽出或扩展共享经济计算，正式账户评估仍要求原覆盖证据；群查询返回场景条件与现金比较，不把结果包装为已确认账户可执行的正式建议。新 Call 仍可能价内，上移不保证消除提前指派。

#### 7.4.1 条件结果的机器可读合同

Call 上移场景返回新的 `group_query_roll_up_result.v1` 数据 schema。通用 envelope 仍保留传输成功与数据完整性语义；下列字段专门表达场景条件，不能复用正式账户执行资格：

| 字段 | 必需值或语义 |
| --- | --- |
| `analysis_kind` | 固定为 `conditional` |
| `account_eligibility` | 固定为 `not_verified`，不能因净现金为正而升级 |
| `stock_coverage.verification_status` | 固定为 `not_verified`；没有查询券商股票或账本 Call 义务 |
| `stock_coverage.required_shares` | 已验证合约乘数 × 本次场景张数，表示所需交割股数；缺证据时为 null 并保留不可评估原因 |
| `unverified_conditions` | 至少列出实际持股数量、全部未关闭 short Call 的覆盖与重复占用未经核验；用户声明不能移除这些条件 |
| `candidates[].economic_result` | `positive_net_credit`、`non_positive_net_credit`、`excluded` 或 `not_evaluable`；只表示经济规则结果 |
| `candidates[].metrics` | 通过证据校验后计算的现金、行权价、延期和排序指标；缺失不填零 |
| `input_id`、`binding_sha256` | 绑定第 7.2 节的本次输入与证据 |

结果不输出具有已验证含义的 `covered_shares`，也不输出正式 `recommendation=credit_roll`。使用股价 × 所需交割股数作为条件年化分母时，`capital_basis_kind` 必须标为 `hypothetical_stock_market_value`，不能沿用 `covered_stock_market_value` 暗示股票覆盖已成立。

共享 owner 提供经济指标和排序键；场景入口按 `economic_result` 选取经济条件合格的候选，不能为了复用正式排序器而伪造覆盖或正式建议状态。部分数据、无候选、不适用和不可评估继续按各自含义表达。

API 客户端和 renderer 必须校验这些必需字段；字段缺失或出现已验证覆盖/正式建议标志时，拒绝将其展示为合格场景结果，并报告结果合同不一致。直接 HTTP 客户端也能识别这是条件分析，不能只靠自然语言免责声明。正净现金、用户声明持股和缺少覆盖字段三种输入都须验证不会获得正式资格；正式 CC 路径继续验证现有覆盖守卫。

### 7.5 休市、历史和不完整数据

首版在无当前合格行情时不生成新的当前建议；可展示明确标注时间的最近报价。账户历史报告不是本插件的参考来源，也不沿用现有主动评估中的账户历史搜索。

旧会话中的结果只表示原评估时点的结果，不能改用今天的 DTE、费用或价格继续宣称有效。将来若增加历史场景参考，须使用本插件自身、同身份且完整绑定的证据合同后另行设计。

| 情况 | 用户可见结果 |
| --- | --- |
| 输入完整、行情资格有效 | 当前场景评估、指标与理由 |
| 规则不适用于原合约 | 明确不适用及原因，不声称无机会 |
| 搜索完整且无合格候选 | 明确当前范围内没有合格候选 |
| 数据部分可用 | 标出缺口和仅针对已覆盖范围的结果 |
| 延迟、过期、无权限或休市 | 无当前建议；标明原因与可展示的参考时间 |
| API、模型或行情源故障 | 指明故障所属环节，不伪装成零结果 |

### 7.6 公共策略与费用配置合同

API 服务端的显式配置是群查询公共策略的唯一选择入口。它提供市场范围、行情 provider/路由、候选模板与流动性等公共阈值、允许的查询边界和费用模型选择；不得包含账户列表、账户覆盖、资金或生产账户路径。用户只可调整当前接口白名单允许的搜索参数，不能切换配置文件、行情地址或费用模型。

公共模板复用现有策略 owner 的规则、参数解析与默认值，不从生产账户 runtime config 导出，也不复制一套财务公式。缺少必要的公共模板、参数或行情路由时明确失败，不回退仓库根配置、用户 home 配置或默认账户。

在候选 owner 增加接收已校验公共策略与显式行情路由的准备入口；原有 CLI/runtime config 入口保留其 freshness 校验。不能直接调用现有 `_prepare` 后通过跳过 freshness、伪造生成元数据或加载生产配置来适配群查询。公共配置使用自身 schema 和规范化后的 `public_policy_sha256`，每次评估冻结一次，贯穿计划、计算和回复；实现时复用现有解析与校验 owner。

首版费用模型固定为 `futu_option_estimate`，仅支持现有富途美股/港股期权标准估算，不增加其他券商模型。这个 ID 表示公开估算假设，不表示用户真实券商身份，也不授予账户访问能力。

- 开仓、买回和新卖出各腿复用现有 fee owner，按实际张数及合约乘数计算；不把单张费用简单乘张数。
- API 返回 `fee_model.id`、`fee_model.version`、`fee_basis`、币种、各腿估算费用和 `is_actual=false`。版本由现有费用规则/版本化 basis 的明确映射确定，不用请求日期冒充规则版本。
- 回复固定展示「按富途标准费用模型估算，非账户实际费用」；港股保留 owner 的 conservative-estimate 口径。不能把估算写成群成员真实成交费率或真实收益。
- 请求其他券商真实费率时明确当前不支持；不查询账户补齐，不猜测费率，不用零费用代替缺失。仅因用户提及其他券商，不把富途估算称为该券商费率。
- 费用模型不支持、必要输入缺失或费用证据不完整时，依赖费用的平仓/移仓结果不可评估；独立报价仍可按自身资格展示。

有效公共策略摘要须覆盖费用模型 ID、版本与费用假设，并纳入第 7.2 节绑定和场景缓存键。相同合约在策略或费用版本改变后不能复用旧结论。须验证无生产账户配置时仍可独立校验公共配置、缺失不回退、费用假设在 API 和回复可见，以及配置/费用版本变化使旧绑定失效。

## 8. 新飞书 bot 绑定与消息处理

管理员必须创建新的飞书应用机器人，提供独立 App ID 和 App Secret；不继承已有通知或管理 bot 的绑定。新建身份是部署验收项，启动校验凭据与配置的应用身份一致；若有已登记的旧应用 ID，可核对不是同一应用，不能声称仅靠凭据校验就证明应用刚刚新建。

沿用现有飞书插件长连接，无需公网事件回调地址。首版只开通接收 @消息和回复所需权限，服务端按配置检查群范围及真实 mention 身份：默认是显式群白名单，也可配置唯一通配 `["*"]`，此时群范围完全由飞书侧「谁可邀请 bot 入群」控制；通配不能与具体群 ID 混用，任何情况下都必须 @ 当前 bot。

SDK 事件适配需保留 mentions，并在业务处理前核对目标是当前新 bot；不能只从文本删除 @标签。来自配置群范围外的事件（使用具体白名单时指白名单外的群；通配时仍须是群聊）、未 @当前 bot 或缺少身份信息的事件，不进入模型与查询 API。

会话/审计库、配置、缓存、服务名和锁绑定本插件实例，不能回退到现有 bot 的默认路径。按消息身份去重，事件回调及时确认并异步执行慢查询；回复绑定原消息。发送失败、发送结果不明和确认送达分别记录，不能承诺跨飞书故障恰好一次。

已确认目标是个人用户组成的飞书群，用户不以组织归属区分群成员，不能把加入某个组织作为成员使用本功能的前提。应用的租户、认证和共享设置仍按飞书平台实际规则配置。

官方对外共享文档要求应用满足相应认证、发布和共享条件，但未明确保证所有个人群都能加入应用机器人。部署前须用新应用在目标个人群核验入群、接收 @事件、回复和发送者身份字段；未通过时明确记录平台接入阻塞，不能宣称已支持。普通 webhook 自定义机器人按官方说明不能响应 @消息，不作为本需求的替代入口。

### 8.1 个人群最小接入验证

2026-11-10 用户确认先完成全部本地功能和离线审查，真实接入验证后置为最终联调和实际使用前置。取得指定测试环境授权后，用新应用和既有飞书传输执行本节最小接入验证；此步骤只接收测试消息、校验身份并发送固定测试回复，不调用模型、行情或账户能力。后置可能在业务代码完成后暴露个人群平台限制，该顺序风险已由用户选择接受。

必须验证并记录以下结果：

1. **目标群与新应用**：新应用机器人能够加入指定个人群，平台要求的认证、共享、发布和审核条件已满足，能收到 @当前 bot 的消息并回复原消息。
2. **真实身份映射**：保留脱敏 SDK 事件样本，明确应用身份、应用侧与发送者侧租户字段、发送者 ID、群、线程及 mention 对象的来源与对应关系。线程缺省按明确空值处理；个人用户字段缺失时须先确定有平台证据支持的映射，并同步第 6.6.1 节合同，不能伪造租户或省略发送者。
3. **拒绝与隔离**：错误应用、不在配置群范围内的事件（使用具体白名单时指白名单外的群；通配时仍须是群聊）、@其他 bot、缺必要身份的事件不得进入业务处理；同群同线程的两名用户分别建立上下文；重复事件不重复发送测试回复。

通过标准是有可复核的入群、@收发结果及脱敏身份样本，并据此固定事件适配与隔离测试。未通过时记录具体平台条件或字段阻塞，不声明实际接入或完整验收通过，不改用仅能推送的 webhook 机器人冒充已支持。可以继续本地代码开发；最终完整业务联调必须先取得本节接入证据。本文不表示已经执行过真实验证。

### 9.1 限额与调用准入合同

模型和行情预算分别在实际产生消耗的入口执行，不能只在查询 API 限流。两端使用有界默认值并在启动时校验配置；管理员可显式调整，模型和群消息不能放宽。bot 端至少具有群/用户请求频率、并发、上下文和输出上限、单次请求 deadline、模型调用次数及 token 预算；API 端至少具有 principal 请求频率、并发、期限/合约/候选范围及行情请求预算。不引入通用分布式限流平台。

第一期已确认以下小群默认值；每条用户消息对应一个处理回合，澄清后的下一条用户消息重新准入：

| 限制 | 首版默认值与计数口径 |
| --- | --- |
| 单用户请求频率 | 每分钟 3 次，按可信发送者身份跨线程统计 |
| 单群请求频率 | 每分钟 10 次 |
| 单用户同时处理数 | 1 |
| bot 总并发 | 2 |
| API 并发 | 2，API 独立强制执行 |
| API principal 请求频率 | 每分钟 30 次 |
| 单回合处理总时限 | 90 秒 |
| 单回合模型调用 | 最多 4 次，含重试 |
| 单回合业务 API 调用 | 最多 3 次，含重试；底层行情调用另受 provider 配额与公共搜索范围限制 |
| 每次模型输出上限 | 2000 tokens |
| 单回合估算总 token 预算 | 32000 tokens，累计每次调用的输入估算及输出预留，重试同样计入；不是精确账单承诺 |
| 历史上下文 | 第 3.2 节最近 10 轮与 4000 tokens 上限同时生效，不替代整回合预算 |

调用次数是允许的上限；若 deadline、剩余 token 或模型实际窗口不足，应提前停止，不能为凑足次数跳过其他预算。行情 provider 的实时权限、配额及公共搜索边界继续独立生效。

| 强制点 | 身份与预算 | 拒绝后的行为 |
| --- | --- | --- |
| bot 接收合法事件、完成消息去重后，第一次调用模型前 | 使用已验证的 bot/租户/群/发送者身份检查群总额度与用户额度；用户额度跨线程统计，不能靠新线程重置 | 固定文案说明限额或繁忙，不调用模型、查询 API 或行情 provider |
| bot 每次后续模型调用及重试前 | 检查剩余调用次数、deadline、上下文、输出预留和本次请求 token 预算；复用现有估算与预留能力 | 停止后续模型/工具调用，明确预算或超时原因，不生成虚构建议 |
| API 在鉴权授权后、业务 I/O 前 | 按已认证 principal 检查请求频率、并发、范围和行情预算；事件上下文不能增加总额度 | 返回 429 或明确的输入范围错误，不开始取数 |

澄清、问候和无需查询 API 的对话也消耗 bot 侧额度；每个新的用户回合都重新准入。已去重的重复事件不再触发付费处理。模型重试计入调用次数，API 429 不能触发模型无限重试或降级到直接行情读取。

bot/API 各自负责本进程的并发占用，处理回合与其尚未结束的实际 I/O 共用该回合的占用归属；等待超时或调用方返回不等于后台工作已经结束。失败、取消和超时按第 9.2 节停止新工作、处理在途 I/O，并在实际工作结束后释放相应槽位，不能先释放再无限产生仍在运行的请求。最终回复保留实际已取得结果的数据时间；停止条件不会把旧结果升级为当前结果。token 预算按现有估算和输出上限控制，实际 usage 用于审计，不把它表述为供应商账单的精确金额上限。

验收必须覆盖：模型前限额拒绝时模型调用计数为零；纯澄清回合受限；同一用户新线程不能绕过额度；重试/多轮触发本次预算后停止；直接 HTTP 请求仍受 API principal 限额；未开始工作时不占用槽位，已开始工作则按第 9.2 节核验实际结束后的释放。测试只替换实际模型和行情传输，验证限额发生在调用之前。

### 9.2 截止时间、实际 I/O 与并发释放

**时间传递**：bot 通过本回合准入后一次性建立 90 秒总截止时间，同时使用本地单调时钟控制等待和后续工作；每次模型调用、业务 API 调用及重试均只使用剩余时间，不重新获得 90 秒。固定 API 客户端在第 6.6.1 节外层填写同一 `request_deadline_utc`。它是宿主元数据，不属于用户业务输入，不进入 `input_sha256`。

API 在授权后、业务 I/O 前校验该时间；格式不合法按 INPUT_ERROR 处理，预算已耗尽则按现有 504/UPSTREAM_TIMEOUT 返回且不开始取数。有效预算取请求截止剩余时间与 API 服务自身配置上限的较小值，再转换为 API 本地单调时钟截止时间。该字段只能缩短服务端允许的预算，不能扩大 principal 能力、额度或资源范围。每个 provider 调用和重试继续使用该预算的剩余部分。

**传输约束**：模型适配器、HTTP 客户端和行情 owner 必须设置不超过剩余预算的传输超时，并在下一次 I/O、分页、批次或重试前检查截止与取消状态。沿用已有传输能力，不新增通用取消服务或任意执行入口。现有 [bounded_call](../src/application/read_execution.py) 仅停止调用方等待；不能据它返回超时或 HTTP 断连，就认为底层 I/O 已经终止。

**占用与结束**：

- 尚未开始实际工作的拒绝请求不占用处理槽。开始处理后，bot 的总槽及单用户槽归属于该回合及其未结束工作；API 槽归属于对应处理及 provider 工作。
- 到期或取消后立即停止新模型/API/provider 调用和重试，结束本回合等待，使用固定超时或取消说明，不再调用模型生成收尾文字；向在途传输发出其支持的取消或关闭请求。
- 如果某 SDK 或传输不能可靠取消，在实际工作返回前保留其所属处理槽及预算计数；新请求按仍被占用的额度拒绝或限流。不能因父调用已返回而提前释放槽位，再启动不受计数约束的后台工作。
- 实际工作结束后由其清理路径释放相应占用，且只释放一次。迟到结果不得恢复本轮正常业务回复、推进已停止的会话状态或再次发送消息；必要状态仅进入有界脱敏审计。

90 秒约束本回合等待和新工作发起；对未能即时取消的在途 I/O，必须保留占用并依靠有限传输超时收敛，不能宣称远端供应商计算已在同一时刻停止。记录等待结束与实际工作结束的区别，不能把仍工作的槽位当作泄漏而强行提前归还。

验收使用可控慢传输和计数探针：截止前已耗尽预算时上游调用为零；重试不延长原 deadline；两个槽位均有在途工作且等待已超时时，第三个请求仍被限制；释放模拟 I/O 后槽位才恢复；取消、异常、正常完成各只释放一次，迟到结果不写入正常会话或 outbox。模型与 API 两端分别验证，不用单纯捕获等待超时代替实际并发验证。

## 10. 存储、审计与回复

### 10.1 bot 端独立 SQLite 会话存储

第一期采用 bot 端、按插件实例独立的 SQLite 数据库保存会话上下文。数据库位于运行群查询bot 的主机，由管理员显式指定实例数据目录；不使用现有管理 bot 的默认库，也不写入真实持仓账本或账户报告。

拟议文件位置如下，表示部署时的实例数据目录，不是仓库中已有文件：

```text
<群查询bot实例数据目录>/conversation.sqlite3
```

首版 bot 和业务 API 位于同一主机，对话数据库由 bot 端管理；API 仅接收本次业务参数和必要请求身份，不读取群对话历史。API 端保存自身的行情/场景证据和必要脱敏审计，均保留 24 小时，见第 10.2 节；不提供群成员历史检索或证据下载接口。

| 保存内容 | 用途与边界 |
| --- | --- |
| 必要用户消息、bot 回复 | 仅保存该 bot 已接入的有效交互及相关回复，不采集整个群的聊天记录 |
| 已确认条件、待补参数、临时合约输入 | 支持第 3 节补参、指代与条件修改，不能成为跨会话持仓档案 |
| 会话身份 | 绑定 bot 实例、租户、群、发送者和线程，所有上下文读取按完整身份隔离 |
| 时间信息 | 保存记录首次创建时间、失效时间及会话最后活动时间；最后活动时间不延长旧记录的保留期 |

模型调用时只读取并发送同一会话中未过期、与当前请求相关且符合预算的上下文。服务重启后自动从 SQLite 恢复同一 bot 实例、租户、群、发送者和线程下未过期的会话；恢复前先执行第 10.2 节清理和失效过滤，不跨身份或跨会话恢复，不改变原记录的失效时间。旧报价和结论仍保留原时点，新评估重新验证行情资格。

### 10.2 对话、评估证据与脱敏审计保留 24 小时

第一期历史对话只保留最近 24 小时。原始消息以 bot 首次保存的 UTC 时间 `created_at_utc` 为起点，`expires_at_utc = created_at_utc + 24小时`；派生参数、摘要和包含原输入的回复副本还须受原输入失效时间约束，具体按第 10.4 节计算。当前时间达到失效时间即过期；新消息、读取、模型调用或服务重启均不重置旧记录的时限。

- 保留期适用于对话正文，以及用于续接对话的摘要、待补参数和已确认临时输入副本。派生状态不得晚于其依赖的原输入失效，不能通过复制到摘要或新状态中延长旧内容的寿命；需要继续使用时由用户重新确认输入。
- 每次组装上下文先过滤过期记录；过期内容不能发送给模型、用于参数继承或恢复会话。
- bot 运行期间定期从 SQLite 删除到期的对话及其派生会话状态；服务启动时先清理并过滤过期数据，再处理会话恢复或新消息。停机期间不会执行清理，重启后不得使用已过期内容。
- 消息去重、投递状态及必要请求 ID 的最小元数据保留 **7 天**，按首次创建的 UTC 时间计算，到期后自动清理；只包含消息 ID、会话身份摘要、状态和时间，不包含聊天正文、成本或合约参数。24 小时正文清理不能提前删除仍在 7 天保留期内的最小去重状态。投递记录如包含对话正文，其正文仍遵守 24 小时保留期，不能随元数据保留 7 天。

API 行情/场景评估证据同样保留 24 小时，按本次评估批次创建的 UTC 时间计算并整批到期；其中可能包含本次行情、规范化的用户临时参数、计划与计算绑定。脱敏审计按每条记录首次创建时间保留 24 小时，只记录必要请求身份、状态及原因，不保存聊天正文。API 端同样在使用前过滤失效证据，运行时清理、启动时先清理；只清理群查询自身记录，不删除真实账户产物或其他仍在使用的共享数据。

24 小时约定针对本插件管理的对话、会话副本、API 评估证据和脱敏审计，不自动删除飞书群中的消息，也不代表模型供应商的留存约定。API 证据与审计不作为恢复已过期对话的来源。两端数据按各自服务的数据目录权限限制读取，不向群成员开放历史库或审计；主机管理员按运维权限管理。

### 10.3 审计、缓存与回复

bot 端另保存必要的脱敏审计和投递状态。审计按第 10.2 节保留 24 小时，去重与投递最小元数据保留 7 天；原始聊天、成本和完整临时输入不进入通用日志。保留的数据执行最小读取权限。模型个人记忆、通用项目浏览与账户历史检索不启用。

缓存仅复用符合当前时效的公共行情；包含用户输入或评估结果的缓存按实例与会话输入身份隔离。可供续接对话的缓存副本同样遵守第 10.2 节保留期。重复事件可以复用未过期且仍可投递的已绑定回复；用户主动发起的新评估必须重新判断行情资格，不能把消息去重当作长期结果缓存。

结果回复由模型基于宿主提供的中文事实卡组织成简短口语，先给结论，再给关键数字；宿主校验数字来源、必需说明与长度后再发送，校验失败先重写一次，仍失败则使用宿主兜底回复。金融数值只来自事实卡（即 API 数据的展示级加工，不重算）；自然语言不得把条件分析写成真实账户资格，不得省略会改变结论的部分覆盖或不可评估原因。

### 10.4 记录粒度与分层清理合同

以下区分必须独立判定留存期的逻辑记录，不要求每类各建一张表。实现可复用既有 SQLite 连接和事务能力，但不能只给现有整会话 messages_json、memory_json、runs/events 或 outbox 换数据库路径，就认为已经具备逐记录 TTL。承载正文与承载最小元数据的记录必须能分别清理。

| 逻辑记录 | 最小内容与身份 | 失效与清理规则 |
| --- | --- | --- |
| 用户消息、bot 回复正文 | 记录 ID、完整会话范围、角色、正文、首次创建和失效时间；包含旧输入的回复另记录来源依赖 | 原始消息最多保存 24 小时；包含原输入的派生正文还受来源失效时间限制 |
| 待补参数、已确认输入版本 | 输入 ID、业务字段、完整会话范围、原始来源记录 ID 与失效时间 | 每个版本可独立失效，最晚不超过其原始来源；改 limit 或换 input_id 不自动续期 |
| 摘要或上下文缓存副本 | 仅在实现确有需要时生成；保存来源依赖与失效时间，不引入额外摘要模型调用要求 | 最晚随最早失效的依赖一起到期；不能仅依据最近一次写入时间保留 |
| 待投递回复正文 | 关联投递身份的独立正文或可单独清除的 payload 部分 | 最多 24 小时并遵守来源限制；正文到期后停止重发，不把原投递结果改写成成功或失败 |
| API 评估批次 | assessment_id、本次规范化输入、计划/绑定、证据清单与引用、批次创建和失效时间 | 批次创建后 24 小时整批失效；24 小时是留存期，行情使用资格仍按第 7.1 节判断 |
| 脱敏审计 | 请求身份或摘要、状态、原因、记录创建和失效时间 | 首次创建后 24 小时，不包含正文、成本或完整临时输入 |
| 去重与投递最小元数据 | 消息 ID、必要请求 ID、会话身份摘要、原状态及时间 | 首次创建后 7 天；不包含正文、业务参数或能还原它们的 JSON 副本 |

原始来源是用户提供或明确重新确认事实的消息，不是最近复制该事实的摘要。派生记录的失效时间取自身创建后 24 小时与全部实际依赖来源失效时间的较早者，保留可计算这一上限的来源记录 ID 和时间；来源、时间与 TTL 均由宿主或服务端填写，模型不得覆盖。用户明确重新提供或确认完整事实时才按第 7.2 节建立新的确认记录，不能由 bot 自动重写旧输入来续期。

清理与恢复按以下顺序执行；bot 与 API 各自使用本地事务或现有 owner 的清理批次，不要求跨库事务：

1. **先限制读取**：所有会话、正文、缓存与证据读取同时验证完整范围和 `expires_at_utc > 当前UTC时间`，不先恢复到模型上下文再做过滤。启动时先运行过期过滤与清理，再接入恢复和新消息；运行时定期重复清理。
2. **清理 bot 的 24 小时内容**：在本地事务内清除过期消息、输入版本、派生摘要/缓存及待投递正文，避免留下能继续继承过期参数的副本。与这些正文关联但仍未满 7 天的最小去重/投递元数据继续保留，原发送结果及结果不明状态不因正文删除而改变。
3. **清理 API 的 24 小时内容**：先使到期批次不再可读，再清理该批次独有的输入、计划、绑定、清单和证据引用。共享行情 blob 按现有 owner 的引用规则回收，只移除群查询自身到期引用；仍被其他有效业务引用的数据不得删除，不能按宽泛目录或文件名批量删除。
4. **清理 7 天元数据**：按其首次创建时间清除到期的最小去重/投递记录；正文清理不会提前触发此步骤，也不能以投递恢复为由保留过期正文。

清理按实例或评估命名空间和失效时间执行，可重复运行，不重写创建时间、失效时间或业务输入。清理失败须记录脱敏错误并报告，读取过滤仍生效，不能为了恢复服务而放宽 TTL。验收至少覆盖未满、恰满及超过失效时间、重启恢复、重复清理、原消息到期但后续只改展示参数、摘要与 outbox 副本、共享证据仍有活跃引用等情形。

## 12. 实施顺序与验证

1. **准备最小接入与离线验证**：用最小飞书接入适配、固定回复及合成事件验证身份、拒绝、隔离与去重。按用户于 2026-11-10 确认的顺序，先完成后续全部本地功能和审查；第 8.1 节的目标个人群真实入群、@收发及身份映射留到最终联调前另获授权验证，未通过不得宣称实际可用。
2. **建立 API 权限边界**：落实第 6.6 节五个方法的请求/响应与错误 schema、独立凭据、固定能力映射、市场范围和严格字段校验；使用替代依赖验证未授权请求不会进入业务读取，并落实第 9.2 节截止时间传递。
3. **接入标的和候选查询**：落实第 7.6 节公共配置、显式行情路由和富途费用假设；复用行情与候选 owner，验证无账户配置下的实时资格、搜索边界、覆盖缺口和有效空集；provider I/O 使用剩余预算并保留真实占用。
4. **补齐无账户场景合同**：实现第 7.2 节输入/计划/封存绑定及第 7.4.1 节条件结果 schema，再装配平仓、Put 下移和 Call 上移；与原计算 owner 做相同经济输入对照，并回归正式账户身份与覆盖守卫。
5. **接入插件 bot 端**：新应用绑定、群和 mention 校验、第 9.1 节模型前准入与每轮预算、模型专用 Key、第 3 节会话上下文组装与多轮参数补齐、固定 API 客户端及结果渲染；落实最近 10 轮且历史上下文不超过 4000 tokens 的上限，以及第 9.2 节实际 I/O 结束和并发释放合同。
6. **完成可选分发与生命周期**：默认缺席、依赖检查、独立服务配置、实例数据目录，按第 10.4 节确定 SQLite 记录及其他证据存储粒度，再实现 24 小时正文/证据/审计与 7 天最小元数据清理、重启恢复、升级/停用、机密交付和投递恢复；不引入通用插件依赖系统。
7. **在明确授权的测试环境真实验收与完整联调**：先按第 8.1 节取得个人群接入及真实身份样本，再安全配置模型和 API 凭据，核实行情权限后验证完整链路。本地功能和离线测试完成不能替代这两项真实验收；未通过时记录阻塞，生产与外部操作另按授权范围执行。

| 两端限额 | bot 模型前限额拒绝时模型/API 调用为零，纯澄清受限、新线程不重置用户额度；重试计入预算；API principal 独立受限；已开始的工作按第 9.2 节实际结束后释放所属槽位 |
| 截止与实际 I/O | 五个方法都要求宿主填写 request_deadline_utc，模型不可改写；非法值拒绝，耗尽预算时零取数；后续调用和重试不重新计时；用受控慢传输验证两槽工作未结束时第三请求仍受限、实际结束后才恢复槽位且只释放一次，正常/异常/取消路径均覆盖；迟到结果不进入正常会话或 outbox |
| 行情失败 | 延迟、过期、休市、停牌、权限不足、部分覆盖、空集、上游失败分别输出，不伪造当前建议 |
| 密钥与数据 | 三类凭据独立选择；缺失不回退；值不进日志、提示词或回复；模型未收到远端账户数据，用户自述参数仅作为临时场景输入 |
| 投递与恢复 | 事件确认、异步计算、重投、服务重启和发送结果不明按各自身份处理，不重复承诺确认送达；去重/投递最小元数据保留 7 天，到期清理，不包含正文或业务参数；验证 24 小时正文清理后最小去重状态仍有效 |

## 13. 已确认决策与部署核验

### 13.1 本轮逐项确认结果

| 项目 | 已确认决定 |
| --- | --- |
| 第一期方法 | 五个方法，包含独立 query_quotes；Delta 区间使用 query_candidates 的可选参数 |
| 目标群 | 个人用户组成的飞书群，不要求成员提供组织名称；平台接入能力须按第 8 节验证 |
| 部署方式 | 首版 bot/API 同机，独立进程与配置，API 只监听 127.0.0.1，固定回环 HTTP 地址与专用 Bearer 鉴权 |
| 模型配置 | 供应商、型号、模型 API 地址由管理员独立配置，实际值部署时填写；使用专用模型 Key |
| 会话存储 | bot 端、插件实例独立 SQLite，放在管理员指定的实例数据目录 |
| 对话保留 | 24 小时，按记录首次创建时间计算，后续消息及重启不续期 |
| API 证据与脱敏审计 | 同样保留 24 小时，不用于恢复过期对话 |
| 去重与投递最小元数据 | 保留 7 天，仅消息 ID、会话身份摘要、状态与时间，不含正文或业务参数 |
| 重启恢复 | 自动恢复同一身份下仍未过期的会话，启动先清理并过滤过期记录 |
| 模型历史上下文 | 最多最近 10 轮，历史对话/参数/结果合计不超过 4000 tokens |
| 请求与模型额度 | 第 9.1 节小群默认值：用户 3 次/分钟、群 10 次/分钟，bot/API 各并发 2，单回合 90 秒；其余次数与 token 上限按该节执行 |

### 13.2 部署时填写的实际配置

这些是部署参数，不再作为未决定的产品取舍：

- 新飞书应用身份、授权群 ID，以及专用凭据的安全交付。
- 模型供应商、型号、模型 API 地址及专用凭据引用。
- 查询 API 的本机回环端口及专用凭据引用，按第 9 节交付机密。
- bot 实例数据目录及 API 自身证据、审计存储位置。
- 显式公共策略、行情路由及其 provider 连接配置；不从生产账户配置或默认账户回退。

### 13.3 必须用目标环境证据核验的事实

- **最终联调和实际使用前按第 8.1 节核验个人群接入**：新应用机器人能否加入目标个人群、接收 @并回复，以及真实事件中的应用/发送者身份字段；所需认证、共享和审核配置按飞书平台规则完成，并留存脱敏样本与通过/阻塞结果。用户已确认可以先完成本地开发；官方外部群说明、静态设计和离线测试均不能代替这项真实验证。
- 行情源实际实时权限、限额及公共搜索范围是否满足本功能。
- 面向该个人群成员展示行情的数据授权范围；个人可获取行情不等于已经证明群内展示授权。

这些核验不改变已确认的功能目标和接口授权边界，也不能用静态设计代替运行证据。本轮未创建真实应用、调用模型或行情接口，未检查生产有效配置、账户数据或线上运行状态。
