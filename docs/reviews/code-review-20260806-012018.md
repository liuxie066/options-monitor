## Findings

### DR2-01-已修复-高-无 RV 的 no-expirations 既有成功路径被新的 RV 校验拒绝
- **入口/函数**: `prefetch_required_data()` / `ensure_required_data()` -> generated success-empty payload -> `finalize_required_data_quote_candidate()`
- **文件(行号)**: `src/application/multi_tick/required_data_prefetch.py:690-715`; `src/application/required_data_steps.py:408-456`; `src/application/opend_symbol_outputs.py:175-199`
- **输入场景**: expiration discovery 正常返回 `success_empty/no_expirations`，fetch plan 的 `require_realized_volatility=False`，因此没有任何 executable request。
- **实际分支**: 两个既有 no-expirations payload producer 都写入 `realized_volatility.status=not_applicable_no_contracts`。首轮修复后的 validator 在 require-RV=false 时只接受 `skipped/not_requested`。
- **预期行为**: no-expirations 是已经证明没有可请求合约的正常 empty 终态；`not_applicable_no_contracts` 与 require-RV=false 不冲突，应继续被现有 prefetch/finalizer 接纳。
- **实际行为**: validator 抛出 `internal_contract_error: success-empty required-data RV evidence contradicts fetch contract`，使此前可成功落盘并出 receipt 的 no-expirations 路径回归失败。
- **直接证据**: `_success_empty_payload_from_plan()` 和 in-process prefetch 的 synthetic payload 均固定产生 `not_applicable_no_contracts`，而新 validator 的 false 分支只允许 `status=skipped && reason=not_requested`。已有 boundary test 明确构造 `require_realized_volatility=False` 的 no-expirations plan，但只检查 payload 字段，没有经过 finalizer。
- **影响**: 无到期日的合法批次会在 required-data finalization 阶段失败，账户 barrier 被阻断；这是正常 empty 兼容路径的用户可见回归。
- **建议改法和验证点**: require-RV=false 时同时接受 `skipped/not_requested` 和 `not_applicable_no_contracts`，因为二者分别对应“未请求 RV”和“无合约所以不适用”；require-RV=true 仍只接受 no-contract 状态。新增 `require_realized_volatility=False + no_expirations + not_applicable_no_contracts` 的 public validator/finalizer 回归。
- **修复结果**: require-RV=false 现仅接受上述两个明确 empty 状态；新增 no-expirations public validator 回归，并连同 in-process prefetch/read-model boundary 共 142 项通过。
