### CR-S1-01-未修复-中-同一合约的顶层通用原因可能压过已有的具体嵌套证据原因
- **入口/函数**: `candidate_universe_summary()` -> `_contract_scope_reason_code()`
- **文件(行号)**: `src/application/opening_candidate_snapshot.py:599-618, 681-709`
- **输入场景**: 一个 unresolved-only contract scope 有多个 unavailable rejects；其中一个只有顶层
  `input_missing`，另一个在 `metric_value.reason_code` 中携带 `term_matched_rv_unavailable`。
- **实际分支**: helper 对每个 reject 先做局部 fallback，再把 `input_missing` 和
  `term_matched_rv_unavailable` 放入同一个集合，最后对全集按字典序取第一项。
- **预期行为**: 按 Slice 1 契约，具体嵌套诊断的优先级高于顶层 canonical fallback；只有所有 reject 都没有
  `reason_codes` / `reason_code` 时才退回 `input_missing` 或 `input_invalid`。
- **实际行为**: `sorted({"input_missing", "term_matched_rv_unavailable"})[0]` 返回 `input_missing`，Daily Brief
  仍会丢失已封存的 RV 具体原因。
- **直接证据**: 599-618 行把三种优先级压平到同一个 `candidates` set；现有新增测试只覆盖单 reject，未覆盖
  “一个有 detail、另一个只能 fallback”的合法多 reject scope。
- **影响**: 不改变 partial/fail-closed 分类，但会在真实混合证据失败时继续显示通用警告，违反成功信号 3，降低诊断准确性。
- **建议改法和验证点**: 分别收集 `metric_value.reason_codes`、`metric_value.reason_code` 和顶层 reason 三层
  candidates，只从第一个非空层做确定性选择；新增多 reject 回归并交换 reject 顺序，证明结果与顺序无关且具体 RV
  原因始终获胜。
