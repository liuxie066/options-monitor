## Assumptions tested

1. `trd_logined` can be read without constructing `OpenQuoteContext`. The installed Futu SDK defines `get_global_state()` on the common context base, and the current direct push listener already calls it on `OpenSecTradeContext`; the proposed broker-only readiness is therefore implementable.
2. Configured account IDs are required identities rather than alternatives. Current portfolio code queries the whole result of `resolve_futu_account_ids()`, so subset readiness would be a false green. Revision 2 now requires the full member set and full cross-config union.
3. A logical account spanning US/HK can remain one broker plane. Revision 2 requires endpoint/environment equality, retains member provenance, permits only an explicit ID union, and makes the aggregate validation executable through the existing config-validation facade.
4. “交易分开” requires more than distinct account labels. Revision 2 requires pairwise-distinct configured broker endpoints and read-only endpoint-to-listening-PID proof, while allowing the shared quote route to overlap one broker process.
5. Existing direct listener/backfill behavior can remain unchanged. Revision 2 validates each source's endpoint, mapped full ID set, and current implicit `REAL` environment against the binding instead of changing transport/state semantics.
6. Multi-ID lifecycle reconciliation does not require a new state machine. Lifecycle cases already carry immutable `futu_account_id`; a collector dispatcher can select that exact allowed identity and remove the current first/single-ID restriction without changing case identity or persistence.
7. Quote failure can remain auxiliary to broker intake. The plan fixes the order as current durable inbox/`_process_payload()` first, optional timing second; static conflict and transient outage share existing `needs_review`/incomplete-receipt behavior and cannot stop listener startup.
8. Existing `needs_review` behavior includes possible idempotent lifecycle-outbox creation. Revision 2 preserves that transition key/fingerprint/delivery authority instead of incorrectly promising zero outbox effects.
9. Public compatibility requires value semantics, not only retained field names. The plan now fixes assigned-stock override behavior, exact additive output fields, legacy readiness conjunctions, account-primary semantics, and non-duplicated summary counts/warnings.
10. Source correctness does not prove resource improvement. The matched-window/MAD experiment and absolute incident closure remain separate gates.

## Architecture boundary review

The owning boundaries are coherent:

- effective symbol fetch configuration remains the sole ordinary quote authority;
- account configuration owns single-config broker bindings and the private aggregate binding set;
- infrastructure owns independent SDK context construction and capability readiness;
- application composition roots receive explicit quote/broker dependencies;
- lifecycle domain identity, transactions, inbox, ledger, outbox, and delivery authority remain unchanged;
- the existing config-validation and health facades expose read-only evidence without creating a second configuration source.

Direct push/history contexts remain deliberately outside the gateway refactor, but their resolved source identity is validated against the same broker binding. HOME, credentials, services, process topology changes, and Incus capacity remain correctly separated.

## Best-practice review

The plan fails closed at the correct boundaries: every required account ID must be observed in the configured environment, no broker/first-symbol/default-port fallback can satisfy quote authority, and no account ID is exposed unmasked. Broker readiness is read-only and does not imply trade unlock.

Safety-critical ordering is explicit and testable. Quote failure occurs after durable broker intake for running listeners, preserves existing case/outbox semantics, and does not widen listener recovery. Explicit CLI apply retains a zero-write preflight boundary. Partial construction and shutdown paths have deterministic close coverage.

Public compatibility is also testable rather than aspirational: old health projections and summary counts are fixed, additions are named, and the assigned-stock exception is labeled and excluded from scheduled acceptance.

## Optimal-solution review

The chosen sequence is the narrowest solution that satisfies the stated product structure:

1. prove current route/source/PID facts;
2. derive quote and broker authority from existing configuration;
3. split lazy SDK capabilities and readiness;
4. migrate pure callers;
5. split only the dependencies of mixed callers while retaining their state machines;
6. expose bounded compatibility diagnostics;
7. measure natural workloads before deciding any HOME, process, or capacity redesign.

Stopping one OpenD, adding a third quote-only OpenD, or moving HOME directories would act on the incident without first proving source routing and would cross separate operational boundaries. Conversely, only changing configuration would leave the current gateway and health coupling intact. Revision 2 addresses the owning source boundary first.

## Overengineering review

The private binding set and pure quote resolver are justified by multiple current callers and two rendered markets. They do not introduce a provider registry, persisted route entity, fallback graph, quote owner, or generalized lane. The additive `--related-config-path` option reuses an existing read-only command instead of adding another tool.

The capability-aware health slice is broader than a single caller migration but necessary: otherwise health itself would continue creating quote traffic on broker-only endpoints and could not verify the target topology. The multi-ID collector dispatcher is a small composition correction around an identity already persisted on lifecycle cases, not a new capture/apply protocol.

## Overcoupling review

The primary overcoupling is removed in the plan: quote and trade SDK clients are independently lazy; quote route conflict cannot stop direct broker listener startup; broker account-primary health does not depend on quote readiness; and mixed callers cannot reuse the broker endpoint for market facts.

The remaining shared quote dependency is intentional and visible. Legacy aggregate health stays fail-closed for whole-system readiness while typed child/account projections preserve fault isolation. Physical overlap between quote and lx broker roles is explicitly treated as logical, not security, isolation.

## Residual Risks and tracking

- The exact production rendered configs may fail the new broker-binding/source audit. That blocks affected rollout and requires separately authorized config correction; it does not authorize the implementation to relax validation.
- Local fixtures do not prove the target sy Futu broker endpoint or complete production identities. Retain the P0/F sanitized audit and per-config health results.
- Removing OM-created quote contexts from a broker endpoint may not reduce OpenD mmap refaulting or NVMe IO. Track this only through the frozen natural-window experiment and the separate Incus incident criteria.
- The shared quote endpoint remains a market-data availability dependency and remains exposed to quote-right displacement and shared subscription quota.
- The lx OpenD may still carry both quote and lx broker roles. Distinct logical capabilities/PIDs do not provide credential, HOME, device, or OS least-privilege isolation.
- Typed health probes themselves create bounded provider traffic; keep field/snapshot probes quote-only and outside high-frequency broker checks.
- Listener process isolation, HOME/`Device.dat` migration, service startup sequencing, capacity changes, and automatic quote failover remain separate work units.
