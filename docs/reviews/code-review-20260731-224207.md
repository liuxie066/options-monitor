## Findings

### DR-01-未修复-高-只读 coherent reader 静默丢弃损坏行，可能错误证明 lifecycle delegation

- **入口/函数**: `preview_trade_intake_reconciliation_from_sqlite()` -> `reconcile_trade_intake_state()` -> `_delegated_lifecycle_cases_by_deal()` -> `lifecycle_account_coherent_facts()` -> `_ReadOnlyTradeReconciliationEvidenceRepository.read_lifecycle_account_rows()`
- **文件(行号)**: `src/application/ledger/read_only_evidence.py:44-71,73-215,360-380`; `src/application/ledger/repository.py:2421-2509,2557-2584`; `src/application/trades/state_reconcile.py:36-97,446-516`; `src/application/quality/intake_checks.py:218-247`
- **输入场景**: 同一账户存在一条可被 canonical resolver 接受的 pending lifecycle case，同时 SQLite 中还存在一条 `raw_json` 损坏的同账户 lifecycle case、evidence、allocation、source claim、timing policy、position lot 或 trade event。竞争 case 可能占用同一 lot；损坏行也可能包含本应使 anchor 冲突或令完整 generation 不可解析的事实。
- **实际分支**: 新读取器用 `_read_json_query_from_conn()` 解析 coherent bundle；任何 `TypeError`/`ValueError` 都在 `except` 后直接 `continue`。`_read_position_lots()` 同样静默跳过坏 JSON。因此 canonical overlay 收到的是被删减后的闭包，并可对剩余 case 返回 `direct`/`bridged`。随后 preview 固定返回 `available=True`，发布 exact delegated deal ID；quality 再从 actionable pending 中减去该 ID。
- **预期行为**: account-coherent reader 必须保留正式 ledger repository 的 fail-closed 语义。只要账户闭包中的必需持久化 JSON 无法解析，预览就不应证明 delegation；错误应向上传播，使 reconciliation preview unavailable，并让 unresolved deal 保持 actionable。
- **实际行为**: 损坏行被当作不存在；剩余 case 可被标记 `lifecycle_pending_delegated`，`actionable_pending_after_reconcile_count` 可能降为 0，从而隐藏需要人工处理的 unresolved intake。
- **直接证据**: 正式 repository 对相同 SQL 结果调用 `_json_object()`，解析失败会传播并在 transaction 中 rollback（`repository.py:2432-2509,2571-2583`）；新增 reader 则在 `read_only_evidence.py:372-375` 明确吞掉解析错误。临时 SQLite 复现写入一条合法 pending case 与一条同账户损坏 case 后，正式 reader 返回 `JSONDecodeError`，而只读 preview 返回 `preview_available=true`、`delegated_ids=["futu:lx:1001:deal-option-waiting"]`、`actionable_pending=0`，且 coherent bundle 仅剩合法 case。
- **影响**: lifecycle/ledger 数据损坏会被静默降级成“已由 lifecycle 接管”，削弱 quality gate 和人工核查信号；在 operations-sensitive trade-intake 路径上属于错误的 fail-open。
- **建议改法和验证点**: coherent reader 的 JSON/object 解码应严格失败，不得跳过；可保留宽松 helper 仅服务既有非权威诊断列表，但 `read_lifecycle_account_rows()` 必须调用 strict decoder，并与正式 repository 对非对象 JSON、畸形 JSON、空值和非法 `created_at_ms` 保持一致。新增真实 SQLite 回归：分别向 cases/evidence/allocations/source claims/timing policies/lots/trade events 注入损坏 payload，断言 preview 不发布 delegated ID、上层将 preview 标为 unavailable、quality 不扣减 actionable pending；至少覆盖“一条合法 case + 一条损坏竞争 case”。
