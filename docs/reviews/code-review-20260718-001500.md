### S8-CR-01-未修复-[中]-组件视图同时暴露期间总计和逐月行，默认聚合会重复计算
- **入口/函数**: `analysis_query` -> `_materialize_views` -> `_performance_component_rows`
- **文件(行号)**: `src/application/agent_tools/analysis.py:1848-1860, 2155-2176`
- **输入场景**: 查询 YTD、自然年或跨月 range 后，对 `option_activity_components`、`option_cash_components` 或 `option_pnl_components` 按 component 求和，或不按 `month` 过滤直接消费全部行。
- **实际分支**: `_performance_component_rows` 对 `[*period_rows, *monthly_rows]` 同时展开；同一期间总计与构成它的每个月都进入同一个公开 view。
- **预期行为**: 一个可聚合的分析 view 在默认扫描下应只有一个明确 grain；如果同时提供多个 grain，必须有强制的 grain discriminator/过滤策略，避免同一经济事实出现两次。
- **实际行为**: 对多月期间，同一金额既以 `month=None` 的期间行出现，又以每个自然月行出现，`sum(amount_cny)` 会把期间总计和月度合计相加。
- **直接证据**: `period_rows` 与 `monthly_rows` 在 2155-2160 同时传入；1848-1860 无 grain 去重或选择；catalog 推荐过滤字段不包含 period/month grain discriminator。
- **影响**: 分析答案可静默高估一倍（或在部分期间产生其他重复比例），违反本次重构的“语义不可混算”目标。
- **建议改法和验证点**: 让 component views 只暴露一个默认 grain。推荐只暴露 monthly rows when available，单月/无 monthly breakdown 时才回退 period row；或者拆成 period/month component views。添加 YTD 两个月 fixture，证明 component 合计不含 period-total 重复行。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### S8-CR-02-未修复-[中]-analysis 的 broker scope 被实现读取但公共 schema 和 Copilot 字段禁止传入
- **入口/函数**: `analysis_query` public tool contract -> `_analysis_performance_request`
- **文件(行号)**: `src/application/agent_tools/analysis.py:1643-1654, 4902-4962`
- **输入场景**: 调用者需要只分析一个 broker 的期权表现，传 `broker`；或 Copilot 规划 broker-scoped analysis query。
- **实际分支**: `_analysis_performance_request` 会读取并转发 `payload["broker"]`，但 `ANALYSIS_QUERY_TOOL.input_schema` 没有 `broker`，`copilot_input_fields` 也缺少 `broker`，同时漏掉已有的 singular `account`。
- **预期行为**: 关键 scope 参数从公共 schema/模型字段到最终 service 有完整数据链；不支持的参数不应存在死读取。
- **实际行为**: 严格 tool validation 拒绝 `broker`，Copilot 也无法生成该字段；实现中的 broker 分支实际上不可达。Copilot 的 singular account 字段也不会进入其可用输入提示。
- **直接证据**: 1647-1652 读取 `broker`；4919-4942 schema 只列 period/account(s)/month(s)/symbol(s)；4959-4962 的 Copilot 字段缺 `account` 和 `broker`。
- **影响**: broker-scoped profit/cash/activity 问题会被扩大到账户/全部 broker，可能返回错误归因或混合口径。
- **建议改法和验证点**: 在 schema 增加可选 `broker`，在 `copilot_input_fields` 增加 `account`、`broker`、`refresh_quotes`（若允许模型控制）；添加测试证明 broker/account 被转发给 `option_performance_report_tool` 且不被 scope 扩大。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
