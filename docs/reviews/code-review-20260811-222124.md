## Findings

### CR-S1-RR-03-未修复-高-非良性 `not_applicable` 范围被摘要为完整候选集

- **入口/函数**: `seal_opening_candidate_snapshot()` -> `candidate_universe_summary()` ->
  `_require_advice_evaluable_candidate_snapshot()` / `freeze_candidates()` -> Advice renderer
- **文件(行号)**: `src/application/opening_candidate_snapshot.py:592-650,875-916`;
  `src/application/ai_decision_advice/orchestration.py:258-275`;
  `src/application/ai_decision_advice/render.py:229-242`
- **输入场景**: Put 家族有一张完整证据候选；Call 家族的一个标的因
  `covered_call_portfolio_context_unavailable` 被记为 `not_applicable`。这个 reason 不是“没有持仓”的
  良性 `covered_call_underlying_not_held`，而是无法判定是否可做 Covered Call。
- **实际分支**: `_strategy_results()` 正确把 Call 家族归为 `data_unavailable`，但
  `candidate_universe_summary()` 只把 `failed/incomplete/unavailable` 或 reason=`partial_data` 的 strategy
  scope 列为 affected。它因此返回 `status=complete`。Advice 因 Put 候选存在而合法继续，但
  frozen input 和渲染都不显示 Call 范围缺失。
- **预期行为**: candidate-universe 投影必须与 `_strategy_results()` 的可用性语义一致：
  `not_applicable` 只有空 reason 或明确良性的 `covered_call_underlying_not_held` 可视为完整；
  其他非良性 reason 都必须进入 affected scopes。同理，`completed` 上任何非法定干净
  no-candidate reason 也不得被摘要为 complete。
- **直接证据**: 行 631–639 的 affected predicate 没有使用同文件的
  `_BENIGN_ACCOUNT_NOT_APPLICABLE_REASONS` / `_CLEAN_NO_CANDIDATE_REASONS`；行 887–916 的策略聚合
  却会用这两组语义把同一输入归为不可用。Advice 行 266–270 允许有其他候选时携带
  `data_unavailable` sibling，所以披露完全依赖 summary 的正确性。
- **影响**: AI Advice 可能对不完整策略范围输出看似完整的综合判断，重现本 work unit
  要消除的“有证据缺失但未披露”类错分类。Daily Brief 另有 strategy-status 降级，因此影响
  主要集中在 Advice frozen input/文案。
- **建议改法和验证点**: 在单一 helper 中复用现有 clean/benign reason 集合，以 strategy
  scope 的 status+reason 投影 affected；增加回归确认“未持有标的”仍是 complete，“持仓上下文
  不可用”必须 partial，并会进入 Advice 的 `candidate_universe` 披露。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
