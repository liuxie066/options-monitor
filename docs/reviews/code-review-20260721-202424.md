## Findings

### DR-S6-001-未修复-低-四格测试未直接证明 fixed no-send 不会被错误确认

- **入口/函数**: `test_no_send_four_way_matrix_updates_snapshot_without_publishing_envelope`
- **文件(行号)**: `tests/test_daily_decision_brief_notification_flow.py:266-283`
- **输入场景**: `fixed=True`, `candidate=False`, `no_send=True`
- **实际分支**: 测试只断言 current 可用、没有 retryable envelope、pending candidates 为 0、scheduled target 已提交。
- **预期行为**: 按 approved plan §16.3，`--no-send` 不得推进 fixed report 或 candidate 的 confirmed/alerted 状态，也不得发布新的 envelope。
- **实际行为**: 如果实现错误地写入一个 `status=confirmed` 的 fixed report，`read_retryable_daily_decision_brief_delivery()` 仍会返回 `envelope=None`，pending 仍为 0，现有测试会错误通过。
- **直接证据**: repository retry reader 只返回 `ambiguous`/`pending` envelope；confirmed fixed report 会被过滤。当前测试未检查 `fixed_reports`、`candidate_delivery` 或 `alerted_candidates` 的持久状态。
- **影响**: 回归门可能漏掉 no-send 静默推进确认水位，导致后续真实固定报告被当成已送达而丢失。
- **建议改法和验证点**: 在四格测试中直接断言该交易日 `fixed_reports == {}`、`candidate_delivery is None`、`alerted_candidates == {}`；保留 pending-candidate 和 processed-target 断言。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
