### CR-S2-01-未修复-高-多 lot close 拆分会把整笔 close fee 复制到每个 allocation

- **入口/函数**: `persist_trade_event_object()` → `_events_for_storage()` / `_canonical_close_events_for_storage()` → canonical projection.
- **文件(行号)**: `src/application/ledger/writer.py:113-158`, `170-207`; `domain/domain/ledger/economics.py:222-228`.
- **输入场景**: 一笔 broker/canonical close 交易关闭数量跨越两个或更多 FIFO lot，并携带一笔实际总费用，例如 2 contracts、总 fee 2 USD，分别命中两个 1-contract lot。
- **实际分支**: writer 为每个 target lot `replace(event, contracts=match.contracts_to_close)`，但保留原事件完整 `fees` 与 `fee_provenance`；projection 随后把每个拆分事件的完整 close fee 放进各自 allocation。
- **预期行为**: 拆分后的 close fee 总和必须等于原始 close event fee；按 target contracts 比例分配并让最后一段吸收 Decimal 余数，provenance 仍指向同一来源。
- **实际行为**: 每个 allocation 都扣完整费用，N 个 lot 会把 realized net 费用放大 N 倍。
- **直接证据**: `writer.py:150-156` 与 `199-205` 只替换 event ID、contracts、target/raw payload，没有替换 `fees` 或 provenance amount；`economics.py` 对每个 close event 独立调用 `fee_fact_for_event()` 并全额扣除。
- **影响**: 多 lot close 的 realized net PnL 系统性错误，现金费用也会在后续 S3 被重复统计。
- **建议改法和验证点**: 在两个 writer split path 共用一个 Decimal fee-allocation helper；按原始总 contracts/匹配 contracts 分配，最后一段吸收余数；把分配后的 amount 同时写入 event `fees` 与 `raw_payload.fee_provenance.amount`。增加 canonical 与 normalized-deal 两条路径的 conservation 测试。
- **修复风险（中）**: 需要保持 event ID/idempotency 与旧 payload 兼容，但改动可局限于 writer split。
- **严重程度（高）**: 高。

### CR-S2-02-未修复-高-经济 metadata 错误会阻止原本合法的 lot close 状态迁移

- **入口/函数**: `project_trade_events()` → `_apply_close_event()`.
- **文件(行号)**: `domain/domain/ledger/projection.py:247-273`; plan contract `docs/gateflow/option-performance-refactor-plan-20260717-224048.md:728-732`.
- **输入场景**: close event 的 lot/contract/quantity 都合法，但 fee provenance amount 非法、价格非有限、或 allocation Decimal 转换失败。
- **实际分支**: `build_option_economic_allocation()` 抛 `TypeError`/`ValueError` 后，projection 记录 `economic_allocation_failed` 并立即 return；`lot.apply_close(event)` 位于 try 之后，因此完全不执行。
- **预期行为**: S2 必须保留已有 `PositionLot`/risk behavior。经济事实不可计算时应显式缺失/诊断，但不能让新 reporting metadata 改变风险 lot 是否已关闭。
- **实际行为**: 原本会关闭的 lot 仍显示 open，cash-secured/locked-shares 风险视图错误；S2 引入了对生产风险状态的回归。
- **直接证据**: `projection.py:247-267` 的异常分支 return；实际 state transition 仅在 `projection.py:268`。
- **影响**: 风险敞口、仓位状态和后续 close resolution 可能错误，严重于单纯报表缺失。
- **建议改法和验证点**: 先独立执行并提交既有 `lot.apply_close()` 状态迁移；经济 allocation 构建失败时保留 lot close、发出明确 diagnostic 且不产出伪造 allocation。增加 malformed fee provenance 回归测试，断言 lot closed、allocation absent、diagnostic present。
- **修复风险（中）**: 下游 S3 必须把缺 allocation 的 effective close 视为 incomplete；当前 slice 可通过 diagnostic 明确该状态。
- **严重程度（高）**: 高。

### CR-S2-03-未修复-高-Close currency/multiplier 不一致会被静默按 open lot 单位计算

- **入口/函数**: `_apply_close_event()` → `build_option_economic_allocation()`.
- **文件(行号)**: `domain/domain/ledger/projection.py:218-245`; `domain/domain/ledger/economics.py:190-215`; `domain/domain/ledger/events.py:105-155`.
- **输入场景**: direct canonical close 与 target lot 的 `ContractKey` 相同，但 close event currency 或 multiplier 与 open lot 不同，例如 open USD×100、close HKD×10。
- **实际分支**: projection 只比较 `ContractKey`；该 key 不含 currency/multiplier。allocation 随后使用 lot currency/multiplier，却使用 close event price/fees，未发出任何 mismatch diagnostic。
- **预期行为**: 不同 currency/multiplier 的 close economics 必须 fail closed；不能把不同单位的价格和费用组合成 observed gross/net PnL。既有 lot 状态可按 CR-S2-02 保持兼容迁移，但 economics 必须缺失并诊断。
- **实际行为**: allocation 看起来完整且带 open lot currency，金额可能相差倍数或混币。
- **直接证据**: `projection.py` 的唯一 identity check 是 `lot.contract_key != event.contract_key`；`events.py` validation 未比较 target lot units；`economics.py` 从 lot 取 multiplier/currency、从 close event 取 close price/fee。
- **影响**: 静默错误 realized PnL，且质量标记可能仍为 actual。
- **建议改法和验证点**: allocation 前规范化比较 close event currency 与 lot currency、close event multiplier 与 lot multiplier；不一致时发 `target_economic_units_mismatch`，不产 allocation，但保持 lot state transition。增加 currency 与 multiplier 两个测试。
- **修复风险（低）**: 仅新增经济边界校验，不改变合法 writer 路径。
- **严重程度（高）**: 高。

### CR-S2-04-未修复-中-Estimated fee 被用于 production realized net

- **入口/函数**: `fee_fact_for_event()` → `build_option_economic_allocation()`.
- **文件(行号)**: `domain/domain/ledger/economics.py:22-58`, `222-228`; plan contract `docs/gateflow/option-performance-refactor-plan-20260717-224048.md:230-239`.
- **输入场景**: close event fee provenance 为 `basis=estimated` 且 amount 可解析。
- **实际分支**: fee fact 被标记 estimated，但只要 amount 非空，allocation 仍计算 `realized_pnl_net = gross - open fee - close fee`，仅把 `fee_quality` 标成 estimated。
- **预期行为**: accepted plan 明确 estimated closing fee 只属于 `estimated_*` close advice，不能进入 realized/unrealized production PnL。Production net 应为 null/incomplete，gross 保留。
- **实际行为**: realized net 产生一个估算值，后续 S3 很容易把它作为生产净利润输出。
- **直接证据**: `economics.py:223-228` 只判断 amount 是否为空，不判断 basis 是否 actual；plan `4.3` 的最后一条明确禁止 estimated close fee 进入 production PnL。
- **影响**: 将估算费用伪装成已实现净利润，违反核心质量语义。
- **建议改法和验证点**: production `realized_pnl_net` 仅在所有 incurred fee facts `basis=actual` 时计算；estimated/missing 都返回 null，同时保留 fee fact 与 quality 供诊断/close-advice 使用。增加 estimated open/close fee 测试。
- **修复风险（低）**: 收紧 completeness，不改变 gross。
- **严重程度（中）**: 中。

### CR-S2-05-未修复-中-非法 fee provenance basis 被静默降级成 legacy 推断

- **入口/函数**: `fee_fact_for_event()`.
- **文件(行号)**: `domain/domain/ledger/economics.py:22-65`.
- **输入场景**: raw payload 明确存在 `fee_provenance`，但 basis 拼写错误或未知，例如 `actaul`，同时 event fees 非零。
- **实际分支**: basis 不在 enum 时函数跳出 provenance 分支，继续把非零 fee 当作 `legacy_nonzero_fees` actual。
- **预期行为**: 显式但非法的 provenance 应 fail closed；不得丢弃用户提供的坏 metadata 并重新宣称 fee 为 actual legacy fact。
- **实际行为**: 拼写错误被掩盖，net PnL 仍完整，source 被改写为 legacy。
- **直接证据**: `economics.py:27-51` 仅在 basis 合法时 return；否则直接进入 `numeric_fee != 0` legacy branch。
- **影响**: 质量/来源错误且无 diagnostic，可能让不可信 fee 进入 realized net。
- **建议改法和验证点**: provenance 是 dict 且 basis 非法时返回 missing FeeFact（reason 带 invalid basis）或显式 diagnostic-compatible error；结合 CR-S2-02，不能阻止 lot close。增加 invalid basis + nonzero fee 测试。
- **修复风险（低）**: 只影响 malformed metadata，正确 payload 无变化。
- **严重程度（中）**: 中。
