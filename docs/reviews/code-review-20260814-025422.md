## Findings

### S2-DR-01-已修复-高-调整逻辑把快照里的历史字段误当成真实平仓状态

- **入口/函数**: `project_stored_trade_events_to_position_lots()` ->
  `_fold_resumable_publication()` -> `_fold_publication_transition()` adjust
  branch.
- **文件(行号)**: `src/application/ledger/publisher.py:344-402,523-560`;
  `domain/domain/ledger/projection.py:388-478`.
- **输入场景**: 一个 bootstrap/open snapshot 的 `raw_payload.fields`
  已包含非空 `last_close_event_id`，但共享 projector 尚未对该 lot 应用任何
  close；随后发生普通 adjust。
- **实际分支**: stateful publisher 从当前 public fields 推断是否已有 close。
  看到 snapshot 自带的非空字段后，它错误恢复旧 `last_action_at`，而不是
  让 adjust 成为新的 last action。
- **预期行为**: 是否已应用 close 必须来自 domain transition state，而不是
  任意 legacy public field。没有真实 close 的 adjust 应与旧 full oracle
  一样更新 `last_action_at`。
- **实际行为**: full public API 已在零诊断输入上产生字段漂移，违反 S2
  “byte/field compatible” stop condition。
- **直接证据**: 差异 fixture 中 legacy oracle 的 `last_action_at=adjust time`，
  新 fold 返回 open time；条件只检查 `fields["last_close_event_id"]`，没有
  domain close provenance。
- **影响**: checkpoint 尚未启用时 full writer 就可能改写 public row；启用后
  resumed writer 会持续传播错误时间和 close provenance。
- **建议改法和验证点**: transition 携带 apply 前 accumulator 的标量
  `last_close_event_id`，adjust 仅在该标量非空时恢复 close 时间。新增
  bootstrap snapshot 自带字段但无真实 close 的 full/resume differential
  regression。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S2-DR-02-已修复-中-普通平仓会删除 bootstrap 快照原本拥有的自动到期字段

- **入口/函数**: `_fold_publication_transition()` close branch.
- **文件(行号)**: `src/application/ledger/publisher.py:523-570`.
- **输入场景**: bootstrap/open snapshot 的完整 public fields 原本包含
  `auto_close_exp_src` 或 `auto_close_grace_days`；之后发生普通 close，close
  payload 本身不是 expire-auto-close。
- **实际分支**: 新 fold 在每个 close 前无条件删除两个字段，以清理前一个
  expire-close 覆盖；旧 full oracle则每次从 open snapshot 重建，因而保留
  open baseline 字段，再叠加当前 close fields。
- **预期行为**: current public fields 与旧 oracle逐字段一致；需要清理的是
  上一次 close 的临时覆盖，不是 open snapshot baseline。
- **实际行为**: 零诊断 full projection 丢字段，已用 direct legacy converter
  differential fixture复现。
- **直接证据**: 相同 open+close 输入中 legacy fields 保留 `from-open/9`，
  stateful fold 返回两个字段均缺失。
- **影响**: 已迁移 bootstrap lot的公开字段可能在任意普通 close后改变，
  并造成 head fingerprint/verification mismatch。
- **建议改法和验证点**: publication state 每个 active lot仅保留这两个字段的
  open baseline；每次 close先恢复 baseline或删除不存在的 baseline，再应用
  当前 close覆盖。不要保存 open历史payload或close向量。覆盖 full、state
  serialization round-trip与resume fixture。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

## Residual Risk

- Full oracle仍按设计保留 O(E) 排序、完整 retained lots和 applied
  transitions；S2只保证 resumable tail/checkpoint state有界，S3/S4才选择
  strict tail。
- Publication state大小为 O(active lots + complete current public fields)。
  这是精确 field compatibility所需，不应把它误写成 O(1)。
- S3必须在 fast open 前用 durable row/index检查 derived lot-id collision；
  active-only state无法证明 closed历史里没有同 id。
- 本 review未执行 live migration/activation；符合 S2 non-goal。
