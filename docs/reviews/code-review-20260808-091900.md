## Findings

### 1-未修复-低-新测试只断言 `_run` 参数透传，未直接证明主策略与 Combo underwriting 决策一致
- **位置**: `tests/test_combo_yield_steps.py::test_combo_yield_put_underwriting_inherits_sell_put_hard_gates`
- **问题类型**: 测试缺口
- **当前写法**: 测试捕获 underwriting 回调的 `sell_put_cfg` 并断言字段值。
- **反例/失败场景**: 若未来 `combo_yield_steps.py` 在调用 underwriting 前对 `yield_sp` 做裁剪或覆盖（例如删除 `min_net_income`），本测试的字段断言能抓住删除；但若 underwriting 内部对相同字段有不同消费路径，本测试无法证明“主策略与 Combo 产生同一组过滤结果”。
- **为什么有问题**: S1 的目标是“put 腿继承主策略硬门槛”，最强证明是同一 row 在主策略与 Combo 路径下 underwriting 决策一致，而不只是配置字段透传。
- **直接证据**: 测试捕获回调只验证透传；未调用 `enrich_and_filter_sell_put_underwriting` 对比过滤结果。
- **影响**: 回归防护弱于目标语义。
- **建议改法和验证点**: 可选增强：用真实 `enrich_and_filter_sell_put_underwriting` 对同一 row 分别以主策略 cfg 与 `yield_sp` 调用，断言过滤后 index/decision 一致。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Adversarial Failure Pass

- 若 `market_sp` 缺失 `min_net_income`，underwriting 默认 50.0 仍生效，与主策略一致（主策略同样从 `sp` 解析默认）；
- 若 `max_spread_ratio` 缺失，主策略显式注入 `liquidity.max_spread_ratio`，Combo 不注入，`resolve_sell_put_underwriting_config` 会回退默认 `DEFAULT_CANDIDATE_LIQUIDITY.max_spread_ratio`。两者可能不同：主策略用运行时 global liquidity，Combo 用默认。已在 plan 标记为“必要时补充注入”，当前生产配置 example 显式含 `max_spread_ratio`，因此实际一致；列为 residual risk。

## Semantic Ownership Drift Pass

- 无所有权漂移：测试只验证 `combo_yield_steps.py` 的既有 underwriting 调用链，不新增第二套门槛逻辑；
- 无过度耦合：不引入跨模块共享可变状态。

## Residual Risks

- `max_spread_ratio` 缺失时主策略与 Combo underwriting 可能回退不同默认值：assigned to S2（在删除配置字段时统一处理），并在 aggregate deepreview 复核。

## Conclusion

**pass-with-risks**。S1 无生产代码变更，测试验证了 underwriting 配置透传；低严重度测试增强项 deferred 到 S2/S4 附近统一处理。
