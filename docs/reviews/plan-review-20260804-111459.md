## Goal, boundary, and success signal reviewed

The amendment adds the gateway-pool owner and its direct tests to S1 so that closing worker-local gateways is a
lifecycle reset rather than a successful provider observation. It intentionally preserves endpoint identity,
construction, thresholds, retry behavior, registry behavior, and public signatures.

The relevant success contract is compositional:

1. `_fetch_one_inprocess()` records one success only after a complete typed provider payload, and records one failure
   when provider validation fails;
2. artifact failure after that provider success does not convert the provider outcome to a gateway failure;
3. `close_current_thread()` closes and forgets worker-local gateways and resets its connection-failure counter without
   invoking `mark_success()`;
4. repeated cleanup is harmless and each unique local gateway is closed once per retained local registration.

## Assumptions tested

1. **Cleanup currently creates the false-success observation.** Confirmed. `close_current_thread()` ends with
   `self.mark_success()` (`src/infrastructure/futu_gateway_pool.py:64-80`), and canonical in-process prefetch passes
   that method as `cleanup_worker_fn` (`src/application/multi_tick/required_data_prefetch.py:1241-1249`).
2. **The same method is also the failure-threshold reset boundary.** Confirmed. `mark_failure()` calls
   `close_current_thread()` at the close threshold (`src/infrastructure/futu_gateway_pool.py:92-100`). Merely deleting
   the success call would leave the old failure count active; the amendment correctly requires a direct counter reset.
3. **Provider truth is decided outside the infrastructure pool.** Confirmed. `_fetch_one_inprocess()` validates the
   typed provider payload, calls `mark_success()` after that validation, and avoids `mark_failure()` for a later
   artifact-only failure (`src/application/multi_tick/required_data_prefetch.py:698-784`). The pool therefore should
   own only connection reuse/lifecycle state, not infer provider success from cleanup.
4. **The added file is necessary and sufficient for the discovered owner-boundary defect.** Confirmed. Repository-wide
   search finds this pool as the only `ThreadLocalFutuGatewayPool` implementation and canonical required-data prefetch
   as its only application caller. No new public contract, schema, or cross-layer dependency is required.
5. **Existing integration regressions alone do not exercise real cleanup.** Confirmed. The typed-provider-error and
   artifact-failure tests replace `close_current_thread` with a no-op
   (`tests/test_required_data_prefetch_inprocess.py:456-570`). The amendment's new pool-level regression is therefore
   necessary; together, the tests prove the provider decision and cleanup contracts without depending on executor
   scheduling.

## Required review lenses

### Architecture boundary review

Pass. The application layer continues to interpret typed provider outcomes, while the infrastructure pool owns its
thread-local gateway and failure-counter lifecycle. The amendment adds the actual owner to the S1 allowlist instead
of leaking cleanup semantics into the coordinator or finalizer.

### Best-practice review

Pass with a validation condition. Separating an explicit provider-success transition from resource cleanup prevents
cleanup, retry, and `finally`-style paths from fabricating health evidence. The regression should assert both halves:
`mark_success()` is not invoked and the next connection-failure sequence starts from zero. It should also call cleanup
twice and include a duplicate local gateway reference so the stated idempotence/unique-close signal is executable,
not just descriptive.

### Optimal-solution review

Pass. The smallest credible repair is inside `close_current_thread()`: retain direct lifecycle reset while removing
the semantic call to `mark_success()`. Moving health interpretation into `PrefetchCoordinator`, adding a new health
service, or changing retry policy would be wider and less reliable for this defect.

### Overengineering review

Pass. The amendment adds no type, protocol, state machine, configuration, persistence, or public method. A direct
thread-local reset is proportional to the existing implementation.

### Overcoupling review

Pass. Provider-result classification remains in required-data prefetch, gateway lifecycle remains in the pool, and
the coordinator retains its generic cleanup callback. The new tests can verify each owner independently rather than
requiring a broader threaded integration harness.

## Findings

No material findings. The scope amendment is code-generation-ready and matches the existing ownership and call path.

## Open Questions

None.

## Residual Risks and tracking

- `PrefetchCoordinator` submits `max_workers` cleanup tasks but does not guarantee one task executes on every worker
  thread (`src/application/multi_tick/prefetch_coordinator.py:413-415`). The enclosing required-data flow separately
  calls `close_registered()` after executor shutdown (`src/application/multi_tick/required_data_prefetch.py:1284-1285`),
  so gateway objects still receive a global close attempt and worker-local counters die with the executor threads.
  This does not block the amendment; track any future executor-affinity/lifecycle redesign outside S1 as already
  stated in the amendment's residual risk.
- `close_registered()` may attempt to close gateways already closed by worker cleanup, and close errors are swallowed.
  That behavior predates the amendment and registry behavior is explicitly out of scope. Track it only if a concrete
  non-idempotent gateway-close failure is observed.

## Final conclusion

`pass-with-risks`. Add the two named files to S1 and implement the direct thread-local failure-counter reset. Acceptance
should include the pool regression described above plus the existing provider-error/artifact-error assertions. No
broader gateway lifecycle, coordinator, retry, or registry redesign is justified by this amendment.
