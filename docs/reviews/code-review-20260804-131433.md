## Findings

### DR-01-未修复-中-Legacy 多匹配会被无关的 OpenD 渲染失败过滤，confirmed drift 仍可写入绑定

- **入口/函数**: `service_drift()` -> `_build_drift()` -> `_expected_bundle_from_profile()` -> `render_service_bundle()`
- **文件(行号)**: `src/application/service_drift.py:422-456, 822-861`; `src/application/service_deploy.py:469-506`; `docs/plans/incus-opend-reclaim-remediation-plan-20260804.md:148-175`
- **输入场景**: 一个 `source=opend`、无 `binding` 的 legacy profile 选择 `lx` 和 `sy`；canonical config 中两者都声明历史端点 `127.0.0.1:11111`，但只有 `lx` 有可渲染的 OpenD root，`sy` 缺 root（同样的问题也可由 `sy` 的跨市场 root 不一致触发）；随后执行 `./om service drift --confirm`。
- **实际分支**: compatibility loop 不是直接解析每个账户的 endpoint，而是为每个账户完整调用一次 `render_service_bundle()`。`lx` 渲染成功并进入 matches；`sy` 在 recorder root/service 校验中抛出 `ValueError`，随后被 `except ValueError: continue` 无条件丢弃。`matching_accounts` 因而从真实的两个 endpoint match 变成单个 `lx`，drift 被标记为 supported；confirmed path 随后写 unit 和 profile。
- **预期行为**: Legacy identity migration 必须只按所有 selected Futu account 的跨市场 host/port 判断。两个账户都匹配历史 endpoint 时应返回结构化 ambiguity error，并在 `--confirm` 下保持零写入；OpenD root/service 是否可渲染只能在唯一 endpoint owner 已确定后单独校验。
- **实际行为**: Drift 报告 `legacy_strategy_lab_recorder_binding_inferred`，并可把 `binding.account=lx` 及其 service name 写入 profile；账户选择事实上受无关的 root/service renderability 影响，违反了 endpoint ambiguity 的 fail-closed 契约。
- **直接证据**: `_expected_bundle_from_profile()` 在 `src/application/service_drift.py:424-431` 捕获并忽略 candidate render 的所有 `ValueError`，而 endpoint match 只在 render 成功后才于 `:432-441` 计数；缺 root 会在 `src/application/service_deploy.py:478-488` 抛错。受控复现使用两个相同 endpoint、仅 `lx` 有 root 的 legacy profile，dry drift 返回 `supported=true` 和单一 `lx` compatibility warning；加 `confirm=True` 后返回 `changed=true`，profile 实际写入 `{"account":"lx","host":"127.0.0.1","port":11111,"service_name":"options-monitor-opend.service"}`。现有 ambiguity test `tests/test_service_deploy.py:1686-1737` 给两个账户都配置了 root，因此没有覆盖被 candidate render error 错误过滤的多匹配。
- **影响**: 计划承诺的 zero/multiple-match 零写入边界失效；在版本偏差或部分损坏的 account/OpenD 配置下，drift 会把一个本应保持未决的账户身份固化进 profile，并可能改写 sampler dependency/unit，使审计与恢复基于错误的“唯一匹配”事实。
- **建议改法和验证点**: 从 `render_service_bundle()` 中拆出或复用一个无副作用的 account endpoint resolver：先独立解析所有 selected Futu accounts 的 account type/host/port 和跨市场一致性，按历史 endpoint 计数并在零/多匹配时立即返回结构化错误；只有唯一后再做 OpenD root/service mapping 和完整 render。不要用宽泛 `ValueError` 把非 endpoint 条件转成“不匹配”。新增回归：两个 endpoint 都是 `11111`，第二个账户分别缺 root、root 跨市场不一致，dry/confirmed drift 都必须 `supported=false`、`operations=[]`，且 unit/profile 字节不变。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### DR-02-未修复-中-非整数 OpenD port 会被静默截断，绕过“非法端点必须失败”

- **入口/函数**: `./om service render` -> `resolve_yaml_runtime_config()` -> `validate_config()` -> `build_account_runtime_plan()` -> `_resolve_strategy_lab_recorder_binding()`
- **文件(行号)**: `src/application/config_validator.py:1238-1247`; `src/application/account_config.py:78-84, 247-268`; `src/application/service_deploy.py:469-476`
- **输入场景**: Canonical YAML 将所选 Futu account 的 port 写成 JSON/YAML number `11111.9`（或其他非整数 float），然后渲染 OpenD-source recorder。
- **实际分支**: Config validation 只尝试 `int(value)`，因此 float 通过“must be an integer”检查；`build_account_runtime_plan()` 再通过 `_int_or_none()` 执行 `int(11111.9)`，把原值无提示地变为 `11111`；binding resolver 只看到转换后的 in-range integer，最终正常返回 bundle。
- **预期行为**: Port 必须是合法整数且在 `1..65535`；非整数 canonical value 应在任何 artifact 形成前 fail closed，不能更改其数值后继续。
- **实际行为**: 生成的 sampler `ExecStart` 含 `--opend-port 11111`，profile 也记录 `11111`，与 canonical 输入 `11111.9` 不一致。
- **直接证据**: `validate_config()` 的 `int(value)` 仅验证“可转换”而不验证无损整数语义；`_int_or_none()` 返回转换结果；`_resolve_strategy_lab_recorder_binding()` 随后仅检查转换结果的范围。受控 public YAML-path 复现用 `port: 11111.9` 成功渲染出 `--opend-port 11111`，没有异常。新增测试只覆盖 `None` 和 `70000`（`tests/test_service_deploy.py:1346-1355`），未覆盖 float/boolean/非整数表示。
- **影响**: 这个 change 的核心安全信号是“显式且可审计的 endpoint”，但当前链路可以让实际 sampler endpoint 与 canonical config 文本不一致；错误配置可能连接到意外端口而不是阻止部署或 drift。
- **建议改法和验证点**: 在 config/account endpoint 的 owning boundary 做无损整数校验，拒绝 bool、非整数 float、非规范字符串及越界值；binding resolver 不应依赖已经丢失原始类型/小数部分的宽松 coercion。分别通过 YAML authoring 和 legacy runtime-JSON profile 路径新增测试，证明非法值在 render/drift 写入前失败，合法 integer port 保持原值。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
