## Findings

### DR-SP-01-未修复-高-跨标的排序从未获得接货后集中度

- **入口/函数**: `run_sell_put_scan_and_summarize()` -> `enrich_and_filter_sell_put_underwriting()` -> `rank_underwriting_candidates()` -> `rank_candidate_rows()`
- **文件(行号)**: `src/application/sell_put_strategy_risk.py:100-177`; `domain/domain/engine/candidate_engine.py:431-450`; `src/application/short_vol_risk_context.py:16-86`; `domain/domain/short_vol_assessment.py:46-162`
- **输入场景**: 两个不同标的的 Sell Put 代表合约落在同一 `0.002` 持有期收益带，账户已有股票或 Short Put 暴露，两个标的的接货后 symbol concentration 不同。
- **实际分支**: 排序尝试读取 `symbol_concentration_after` / `concentration_score`；但候选后处理用 `_ = portfolio_ctx` 丢弃账户事实，只补 `net_income_cny` 和 underwriting 字段，没有调用仓库中已有的 portfolio risk context / concentration 计算。因此 `_sell_put_concentration_sort()` 对真实候选恒常返回 missing，跨标的立即落到净接货折价。
- **预期行为**: 对有完整 NAV、持股和已有 Short Put 证据的候选，生成并持久化 `symbol_concentration_after`；只在跨标的且收益接近时把较低集中度作为排序参考，不把它恢复为硬门槛。
- **实际行为**: 候选 CSV 缺少集中度事实，文档声称的跨标的第一 tie-break 从不生效；在收益带内可以选中已有暴露更高的标的。
- **直接证据**: `candidate_engine.py:431-438` 将两个集中度字段都缺失时排到 missing，`441-449` 随后直接比较净接货折价；`sell_put_strategy_risk.py:116` 显式忽略 `portfolio_ctx`，`122-135` 只生成 CNY 和 underwriting 字段。同时 `short_vol_risk_context.py:16-86` 已能构造所需账户事实，`short_vol_assessment.py:68-116,147-159` 已能计算并显式标记集中度是否可评估。
- **影响**: 正式推荐排序与已确认策略不一致；一个风险暴露更高的标的可在收益接近时被排在前面，且 explain 会声称集中度参与了选择。
- **建议改法和验证点**: 在 Sell Put underwriting enrichment 这个持有 `portfolio_ctx` 的 owner 边界构造一次 portfolio risk context，对每个候选只投影已有 concentration 计算的事实字段，不启用旧 stress/delta/concentration 硬门槛。新增集成测试：同收益带的两标的中，较低 `symbol_concentration_after` 排在前；证据不完整时字段显式 unavailable 且不触发硬拒绝。
