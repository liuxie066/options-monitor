## Findings

### F1-未修复-高-已关闭的 Put 容量可被同一 residual Call 组再次融资
- **入口/函数**: broker/structured open intake → `resolve_trade_deal()` → `_enrich_combo_yield_open()` → `_resolve_combo_yield_companion()`
- **文件(行号)**: `src/application/trades/resolver.py:808-863`
- **输入场景**: 一个显式 diagonal group 先完成 1 张 Long Call + 1 张 Short Put；Put 随后平仓或 assignment，Call 仍 open；之后又提交同一 `strategy_group_id`、同一 Put expiry 的新 Sell Put open。
- **实际分支**: resolver 在读取 group lots 时，先于腿类型和历史数量判断执行 `if open_quantity <= 0: continue`；已关闭 Put lot 被忽略，因此 `existing_same_leg_open` 仍为 0。剩余 Call 的 `companion_open` 为 1，`0 + incoming_open <= 1`，新 Put 被接受并重新绑定到同一 Call。
- **预期行为**: 已确认的产品边界是“一个 Call 只服务一个 Put financing cycle”。同一 group 一旦已有 Put/Call 合约容量被消费并关闭/assignment，就不能把 residual Call 重新用于第二轮 Put；证据不足时应 fail closed。
- **实际行为**: residual Call 可被静默复用，新旧融资周期共享同一 immutable group identity；后续 option inventory 重新呈现为 `active_combo`，掩盖原 residual lineage。
- **直接证据**: `src/application/trades/resolver.py:820-824` 在识别 row leg 之前跳过 closed lot；`src/application/trades/resolver.py:829-833` 只累计当前 open 的同腿数量；`src/application/trades/resolver.py:855-863` 只用当前 open companion capacity 做数量检查，没有历史 opened/closed capacity 或 cycle-consumed 检查。Goal confirmation 明确记录单 group 单 financing cycle（`docs/gateflow/diagonal-combo-yield-goal-confirmation-20260718-122023.md:64`）。
- **影响**: 错误持仓语义、错误 group lifecycle、可能生成错误组合级 Close Advice；assignment 后尤其可能把 assigned-stock lineage 与第二轮 Put 混在同一 group。
- **建议改法和验证点**: resolver 对显式 diagonal group 的所有历史 lots（含 closed）先做 pair/expiry/quantity 审计；任何已消费/已关闭容量上的新 open 都返回明确 unresolved reason；同时使用 historical opened capacity 与 current open capacity 双重约束。新增 residual Call 后重开 Put、assignment 后重开 Put、closed historical opposite-leg expiry 冲突测试，并保留正常 partial-fill 两腿顺序测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高
