## Findings

### DR-S5-01 — 已修复 — 高 — dirty production source could reuse the previous commit identity

- **入口/函数**: `verify_position_projection_migration()` -> `_source_commit()`
- **文件(行号)**: `src/application/ledger/position_projection_migration.py:623-674`
- **问题**: `git rev-parse HEAD` alone identifies the last commit, not the
  source bytes currently loaded. Uncommitted changes under `domain/`, `src/`,
  or `scripts/` could therefore produce a shadow/acceptance binding that
  claimed the previous commit.
- **影响**: Activation evidence could be generated for code that was not
  represented by its recorded commit, weakening the exact-source cutover
  contract.
- **修复**: `_source_commit()` now returns no identity when production source
  has tracked, staged, or untracked changes; verification records
  `source_commit_unavailable` and cannot become pass/ready. The scan is limited
  to production source paths, so unrelated docs, tests, benchmark artifacts,
  and `.venv` do not invalidate evidence.
- **验证**: Added clean/dirty subprocess regressions and kept activation's
  exact current-commit comparison.

### DR-S5-02 — 已修复 — 中 — status crashed on the legacy store it must diagnose

- **入口/函数**: `position_projection_migration_status()`
- **文件(行号)**: `src/application/ledger/position_projection_migration.py:1108-1224`
- **问题**: Before migration, legacy `position_lots` has no normalized
  `account` column. Status queried it unconditionally and raised
  `sqlite3.OperationalError` instead of returning readiness reasons.
- **影响**: Operators could inventory a legacy store but could not use the
  advertised read-only status surface to understand why it was not ready.
- **修复**: Status now inspects the table/column contract first, reports
  `position_lots_table_missing` or `position_lots_account_column_missing`, and
  only runs compatible SQL. Fingerprint scope also degrades to zero when its
  source column is absent.
- **验证**: Added an unmigrated-store regression that returns structured
  `not_ready` without mutation or SQL failure.

### DR-S5-03 — 已修复 — 高 — activation trusted incomplete nested evidence

- **入口/函数**: `activate_position_projection_checkpoints()`
- **文件(行号)**: `src/application/ledger/position_projection_migration.py:946-1017`
- **问题**: The activation boundary checked `reference_host.comparable=true`
  without proving the expected and current fingerprints were equal, and used
  `.get()` on unvalidated nested component values. A malformed manifest could
  crash, while a self-consistent but incomplete manifest could omit the exact
  host or shadow parity facts.
- **影响**: The high-risk mode transition did not independently enforce every
  accepted evidence invariant.
- **修复**: Activation now validates component mappings, exact 64-character
  host-fingerprint equality, shadow readiness, full-oracle parity, runtime
  shadow parity, both binding mappings, and unresolved failure lists before
  opening a write transaction.
- **验证**: Added malformed-component and mismatched-host regressions; existing
  store/source/schema/generation drift tests remain passing.

## Residual Risk

- `retained_lots_10x` remains an explicitly non-guaranteed capacity diagnostic;
  it does not silently expand the activation gate.
- Runtime timing telemetry is intentionally bounded to 256 samples in the
  current process and is not durable across a fresh CLI process.
- Full inventory/verification remains O(E + L) by design; it is an explicit
  migration/audit path, not the ordinary append writer. Ordinary append work
  remains bounded by tail events and changed-account current lots.
- Formal exact-host 5-warmup/30-repetition evidence must be regenerated after
  the final clean source commit because the manifest binds that commit.
