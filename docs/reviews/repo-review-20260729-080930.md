### 1-未修复-严重-远端归档清理既不 fail-closed，也未把确认绑定到已校验的删除计划

- **入口/函数**: `./om research archive prune-remote --confirm` → `archive_prune_remote()`
- **文件(行号)**: `src/interfaces/cli/research.py:145-157,799-812`; `src/application/research/archive.py:448-544,936-965,968-1023`
- **输入场景**: 远端 cleanup dry-run 退出码为 0，但 stdout 不是合法 JSON、schema 漂移或缺少 `delete_runs`；或者 preview 后、confirm 前远端 run 集合发生变化。
- **实际分支**: `_run_command()` 只按退出码设置 `ok`；坏 JSON 被转换为 `parse_error` 对象，`_planned_delete_runs()` 返回空集合，因而 `unverified=[]`、`confirmable=True`。确认阶段重新执行一条独立 cleanup 命令，没有 plan digest 或删除 allowlist。
- **预期行为**: 解析、tool/schema、目标集合任一项不可信时必须阻断；confirm 只能应用完全相同且仍新鲜的预览计划。
- **实际行为**: 未验证任何待删 run 时仍可发出真实 `--confirm --yes`；preview 后新增的删除目标也不受本地归档校验。
- **直接证据**: fake runner 返回退出码 0、stdout=`not-json` 时，最小复现得到 `deletion_guard.confirmable=True`、调用远端两次并最终 `changed=True`。现有测试只覆盖合法 preview 和显式未验证 run。
- **影响**: 未归档的唯一远端运行证据可能被不可逆删除，直接破坏审计、Shadow Replay 和复盘证据链。
- **建议改法和验证点**: 严格验证 tool name、顶层 `ok`、schema、`delete_runs` 字段；preview 生成不可变 plan digest/目标 allowlist，confirm 使用 CAS；补 malformed JSON、空对象、字段缺失、schema drift、preview/apply TOCTOU 测试。
- **修复风险（低/中/高）**: 高
- **严重程度（低/中/高/严重）**: 严重

### 2-未修复-高-归档 verified 只表示目录非空，未证明内容完整、当前存在或来自待清理主机

- **入口/函数**: `archive pull/verify` → `inventory.latest.json` → `archive prune-remote`
- **文件(行号)**: `src/application/research/archive.py:121-158,161-282,448-501,656-749,1037-1062`
- **输入场景**: 某 run 只有一个 rsync partial 文件；verify 后本地副本被删除/替换；或同一 `--remote` 标签先后指向两个存在同名 run id 的主机。
- **实际分支**: `_run_inventory()` 以 `bool(files)` 认定 verified；digest 只含路径、size、mtime。prune 不读取带 source 的 sync manifest、不重扫本地内容、不绑定 SSH target/host identity。
- **预期行为**: 授权远端删除前，应证明当前本地副本与具体源主机的完整清单、内容 hash 和完成 generation 一致。
- **实际行为**: 任意残留文件、过期 inventory 或另一主机的同名 run 都可形成删除授权。
- **直接证据**: 单文件临时 run 被标成 `verified=True`；生成 inventory 后移走 run，prune 仍可用旧 run id 放行。部分 pull 也会直接写 live archive，失败时不留完整 manifest。
- **影响**: 操作员可能在本地副本不完整、已不存在或来源错误时删除唯一远端证据。
- **建议改法和验证点**: 远端提供不可变 inventory；sync generation 记录 source identity、每文件 size/hash 和完成标记；prune 前重扫并比较；绑定 host fingerprint、runtime root 和 plan generation。补 partial、post-verify mutation、跨主机同 run id 测试。

- **严重程度（低/中/高/严重）**: 高
