## Findings

### S1-CR-01-已修复-高-owner snapshot 的 market 未与 v2 status scopes 绑定

- **入口/函数**: `publish_candidate_snapshot_manifest()` / `load_candidate_snapshot_bundle()` -> `_snapshot_strategy_scopes()`
- **文件(行号)**: `src/application/candidate_snapshot_manifest.py:112-215, 307-342, 482-513`
- **输入场景**: v2 status index 声明 `US/NVDA/combo_yield/sp_lc`，但 `combo_yield_candidate_snapshot.v2` 自身的 `market` 是 `hk`；symbol、mode、status、count、quote receipt、config hash 和 policy hash 均保持一致。
- **实际分支**: `_snapshot_strategy_scopes()` 只用 `(symbol, strategy_mode)` 建 key；manifest 的 `covered_scopes` 直接复制 index projection。publisher 和 loader 都只校验 snapshot schema/config/policy/status/count/quote，不比较 snapshot `market` 与该 owner 的 index markets。
- **预期行为**: 单一-market owner snapshot 必须与它覆盖的每个 v2 scope market 完全一致；一个 owner 跨多个 market 而 schema 只能表达一个 market 时应 fail closed。
- **实际行为**: manifest 可以把 `market=hk` 的 owner snapshot 封成覆盖 US scope 的完整终态；manifest 顶层仍会声明 `markets=["US"]`。
- **直接证据**: `_scope_projection()` 保留 market，但 `_snapshot_strategy_scopes()` 的 scope key 和逐项比较均不使用 market；owner entry 没有从 snapshot 投影或校验 market。
- **影响**: terminal manifest 不再能证明 run/account/market 身份完整，后续 research/replay 可能把另一市场的候选事实当成当前 scope；Daily Brief 的二次 market guard只能报 consumer gap，不能修复已错误封存的 authority。
- **建议改法和验证点**: 在 manifest owner binding 中要求 snapshot market 等于该 owner 唯一的 index market，并拒绝单个 owner 的 multi-market scopes；publisher 与 loader 共用同一校验。新增 wrong-market 和 multi-market-owner 回归测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S1-CR-02-已修复-高-completed Combo scope 缺失 typed evidence payload 时仍可被封成干净 no_candidate

- **入口/函数**: `run_watchlist_pipeline_default()` -> `_partition_combo_evidence()` -> `seal_combo_yield_candidate_snapshot()` / `seal_cc_lp_candidate_snapshot()` -> manifest publication
- **文件(行号)**: `src/application/pipeline_watchlist.py:345-375, 987-1018, 1114-1169`; `src/application/combo_yield_candidate_snapshot.py:412-479`; `src/application/cc_lp_candidate_snapshot.py:134-193`
- **输入场景**: v2 index 中一个 SP+LC 或 CC+LP scope 为 `completed` 且 `candidate_count=0`，但 scan adapter 没调用 `combo_evidence_sink_fn`（例如 wiring 回归、自定义/injected facade 忽略 sink，或 capture 丢失）。
- **实际分支**: `_partition_combo_evidence()` 只拒绝收到的 extra/duplicate payload，不检查每个 completed expected scope 都已收到 payload。sealer 因而接收四个空集合，推导 `opening_status=no_candidate`；manifest 的 selected count 也是 0，最终成功发布 `complete`。
- **预期行为**: 对需要用 v2 替代 CSV 的 completed Combo scope，typed scan evidence envelope 是完整性条件；缺失时不得发布 terminal manifest。failed/unavailable scope 可仅由 status 说明，但不能把缺失的 completed evidence解释成真实空结果。
- **实际行为**: 真实“所有候选被过滤且有 Funding/diagnostic 证据”和“capture 根本没有发生”都封成相同 clean `no_candidate`。
- **直接证据**: `seen` 在 `_partition_combo_evidence()` 结束后未与 expected completed scopes 比较；owner sealer 的 evidence 参数默认全为空，`combo_opening_status(..., selected_count=0)` 合法返回 `no_candidate`。
- **影响**: 本次迁移要保留的 Funding Put/rejection/rank 证据可静默丢失；S2 research/Strategy Lab/Shadow Replay 会把证据中断误判为合法零候选，重现最初“最近推荐为 0”无法区分真空与错误过滤的问题。
- **建议改法和验证点**: `_partition_combo_evidence()` 接收 index statuses，并要求每个 `completed` Combo scope 恰有一个 typed payload；缺失时 fail closed 且 manifest 不出现。分别覆盖 SP+LC/CC+LP clean-zero、failed-without-payload、duplicate payload。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S1-CR-03-已修复-高-Combo v2 内嵌 evidence 未绑定 snapshot scope/run/account

- **入口/函数**: `seal_combo_yield_candidate_snapshot()` / `validate_combo_yield_candidate_snapshot()` -> `_funding_put_decisions()` / `_pair_evaluations()` / `_rank_records()` / `_pairs()`
- **文件(行号)**: `src/application/combo_yield_candidate_snapshot.py:133-313, 354-407, 412-479`; `src/application/pipeline_watchlist.py:345-375, 1124-1144`
- **输入场景**: 外层 evidence envelope 是预期的 `NVDA/sp_lc`，但内嵌 Funding Put decision、rejected pair diagnostic 或 unselected rank row 的 symbol 是 `AAPL`，或 diagnostic 携带另一 run/account。selected pair 仍为空或只含正确 NVDA row。
- **实际分支**: pipeline 只校验 envelope 顶层 symbol；sealer 分别规范化内嵌集合并校验 pair/rank 引用关系，但从不把记录 symbol/run/account 与 snapshot 的 scope set/run/account 比较。manifest 只按 selected rows 计数，因此 rejected/unselected/candidate-decision 污染不会被发现。
- **预期行为**: snapshot 中每条 Funding Put、pair evaluation、rank record 和 ranked pair 都必须属于已声明 scope symbol；出现非空 run/account 时必须等于 snapshot identity；SP+LC pair ID 还应与 symbol/put/call legs 的稳定身份一致。
- **实际行为**: 一个内容 hash 自洽的 v2 snapshot 可包含另一 symbol/account/run 的非最终证据并被 terminal manifest 接纳。
- **直接证据**: `_funding_put_decisions()` 只比较 decision 自身两份 symbol/contract；`_pair_evaluations()`、`_rank_records()`、`_pairs()` 不接收 allowed scopes/run/account；`_bind_selection_states()` 只比较 arbitrary pair ID 集合。
- **影响**: account/symbol 级拒绝漏斗、nearest miss、rank shadow 和 Funding Put projection 会交叉污染，违反 S1 明确的 multi-symbol/account partition contract，并使 S2 迁移后的研究结论不可审计。
- **建议改法和验证点**: 在 snapshot owner boundary 对所有嵌套集合做 scope/identity binding；拒绝 unknown symbol、conflicting run/account 和与 legs 不一致的 pair ID。新增 rejected-only、ranked-below、Funding Put、wrong-account/run 的负向测试，以及多 symbol 正向测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### S1-CR-04-已修复-中-completed scope 的 terminal reason 比较是单向的

- **入口/函数**: `publish_candidate_snapshot_manifest()` / `load_candidate_snapshot_bundle()` -> `_snapshot_strategy_scopes()`
- **文件(行号)**: `src/application/candidate_snapshot_manifest.py:176-191`
- **输入场景**: status index row 是 `status=completed, reason_code=null`，owner snapshot scope 是 `status=completed, reason_code=partial_data`，其 aggregate `opening_status` 也据此为 `partial_data`。
- **实际分支**: reason 校验只在 `index_status != "completed"` 或 index 自身有 reason 时执行；因此 snapshot 单方面增加 reason 会被接受。
- **预期行为**: manifest 绑定的是同一份 terminal scope fact，status、reason、count 和 quote receipt 都应双向完全一致；空 reason 也是一个明确值。
- **实际行为**: 同一 bundle 的 v2 index 可以声称 clean completed，而 owner snapshot 声称 partial/data reason，两个消费者可得出不同完整性结论。
- **直接证据**: 条件 `if (index_status != "completed" or index_reason) and snapshot_reason != index_reason` 在 completed/no-reason 时跳过比较。
- **影响**: terminal authority 内部自相矛盾，Daily Brief、Advice 与未来 research/replay 可能依赖不同层而产生不同状态分类。
- **建议改法和验证点**: 对所有 terminal statuses 无条件比较规范化 reason；增加 completed snapshot-only reason 与 index-only reason 的双向测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
