## Findings

### S1-DR-01-未修复-高-period normalizer 会删除 UI 明确锁定的 month scope

- **入口/函数**: `run_contract()` -> `run_engine()` -> `_execute_tool_call()` ->
  `_tool_input()` -> `build_tool_payload()` ->
  `_normalize_option_performance_copilot_input()`
- **文件(行号)**:
  `src/application/copilot/engine.py:604,693-699`;
  `src/application/copilot/tools.py:32-62`;
  `src/application/agent_tools/positions.py:216-244`
- **输入场景**: UI/调用方通过 `explicit_scope.month="2026-07"` 固定查询月份；模型同时
  为 `option_performance_report` 生成 `period="mtd"`（可以不带 month，或带任意
  month）。
- **实际分支**: `_tool_input()` 先把 scene 的固定 month 覆盖进模型 arguments；
  `build_tool_payload()` 无法再区分 month 来源；normalizer 看到 explicit
  `period="mtd"` 后把所有 irrelevant period fields 删除，其中包括 UI 固定 month。
- **预期行为**: runtime context 已声明为 fixed scope，模型参数不能覆盖或删除；
  如果 period 与固定 month 冲突，应保留冲突并 fail closed，促使模型按固定 scope
  重试，或由一个有 provenance 的适配顺序解析。
- **实际行为**: payload 成功变成 MTD，固定 month 静默丢失；工具可能查询当前月而
  不是 UI 指定月，并返回可信外观的错误金额。
- **直接证据**:
  `src/application/copilot/engine.py:693-699` 以 model arguments 为底，再用 scene
  `config_key/symbol/month/reference_year` 覆盖，证明 month 是 authoritative scene
  input；`src/application/copilot/tools.py:42-55` 随后把这个已经混合的 mapping 交给
  normalizer；`src/application/agent_tools/positions.py:237-239` 对 MTD 无条件
  `pop("month")`。现有
  `tests/test_copilot_phase1.py::test_explicit_scope_cannot_be_overridden_by_model_tool_arguments`
  只验证 config_key，未覆盖 month 与 period discriminator 的冲突。
- **影响**: 用户明确月份被静默改写，期权收益报告可能返回错误期间；由于工具成功，
  比原来的可见 `INPUT_ERROR` 更难发现。
- **建议改法和验证点**:
  - 保留 model/static inputs 与 fixed scene inputs 的 provenance，不要在
    `_tool_input()` 中先压平成一个 mapping。
  - 对 model/static explicit inputs 先执行 tool normalizer，再按原优先级叠加 safe
    defaults，最后叠加非空 fixed scene fields。
  - fixed month 与 model MTD 冲突时，让 canonical validator 拒绝；fixed month 与
    model `period=month` 时应覆盖模型 month 并成功。
  - 新增 run-contract regression，分别证明上述冲突失败和一致 period 成功；保持
    `config_key` fixed-scope regression。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高
