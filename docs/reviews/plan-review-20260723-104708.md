# Plan Review

## Reviewed Target and Scope

- Target: `docs/gateflow/daily-brief-close-tier-wording-plan-20260723.md`
- Work unit: `daily-brief-close-tier-wording`
- Review mode: adversarial implementation-plan review
- Included: renderer ownership, tier projection, actionable filtering/counting, detail metric naming, fallback behavior,
  focused validation, rollback
- Excluded: P0 strategy changes, shadow policy promotion, runtime config, deployment, notification sending

## Assumptions Tested

1. **Tier already exists at the renderer boundary.** Confirmed: `_position_view()` carries both `tier` and
   `tier_label`, while `_position_status_label()` currently ignores them when `close_action=close`.
2. **The four requested labels are existing policy vocabulary rather than newly invented strategy states.**
   Confirmed by `domain/domain/close_advice.py:TIER_LABELS`.
3. **Changing only the returned label could accidentally hide rows or change actionable counts.** Confirmed:
   `_position_has_advice()` is label-based through `_POSITION_ACTIONABLE_LABELS`; the plan explicitly requires
   adding all four labels and testing counts/fallbacks.
4. **The new metric name describes the existing formula.** Confirmed:
   `_remaining_annualized_return()` annualizes current option mid over strike for puts or spot for calls, with no
   fee deduction; “剩余权利金毛年化” is more precise than the existing generic label.
5. **Unknown or legacy rows remain safe.** The plan preserves the generic “建议平仓” fallback when tier is absent
   or unrecognized, so existing close actions remain visible.

## Mandatory Review Lenses

### Architecture Boundary Review

Pass. Strategy classification remains owned by `domain/domain/close_advice.py`; the renderer consumes an existing
tier and owns only Chinese notification wording. The plan does not introduce a reverse import, new schema, or
parallel strategy calculation.

### Best-Practice Review

Pass. The allowlisted mapping prevents arbitrary upstream `tier_label` text from leaking into user notifications,
and explicit degraded/fallback tests cover malformed or version-skewed input.

### Optimal-Solution Review

Pass. A renderer-local projection is the smallest change that corrects the observed user-facing defect without
prematurely promoting the evidence-gated P2 policy. Reworking `close_action` semantics in the service would widen
the change into strategy behavior and violate the confirmed scope.

### Overengineering Review

Pass. The plan adds no new service, config key, state, schema, abstraction layer, or rollout switch. A single atomic
slice is proportionate.

### Overcoupling Review

Pass with a tracked residual risk. The existing actionable filter is coupled to rendered labels. This work unit
updates the complete label allowlist and tests it rather than refactoring filtering semantics, which keeps the
bug-only scope narrow. A future renderer refactor may make actionability predicate-based, but it is not required to
fix this defect safely.

## Residual Risks and Tracking

- The P0 policy can still classify a weak-tier position as a formal close recommendation. This notification fix
  exposes the distinction accurately but does not change the strategy. Track under the existing
  `close-advice-strategy-optimization` evidence gate.
- `_POSITION_ACTIONABLE_LABELS` remains presentation-coupled. The plan fully covers the new vocabulary, so this is
  not a blocker; revisit only if the renderer later gains more action kinds or localization.
- The remaining annualized value is still the existing gross heuristic. This work unit clarifies its name but does
  not validate investment suitability or promote it to a net-return metric.

## Conclusion

`pass-with-risks`

The plan is code-generation-ready, preserves the confirmed bug-only boundary, and includes the key regression
guard that prevents differentiated tier labels from disappearing during actionable filtering.
