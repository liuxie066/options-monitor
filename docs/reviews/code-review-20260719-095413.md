## Findings

### ADR-1-未修复-中-journal formatter only sanitizes warning/error detail, so other envelope fields can break the line bound
- **入口/函数**: `format_runtime_status_journal_summary`
- **文件(行号)**: `src/application/runtime_status_cli.py`, generated `lines` before `_bounded_utf8`
- **输入场景**: any included field such as config path, service evaluation, notification reason, or trade source summary contains an embedded newline.
- **实际分支**: helper output is appended directly to `lines`; only error and first warning use `_single_line`.
- **预期行为**: journal mode enforces at most 20 physical lines regardless of envelope text.
- **实际行为**: an embedded newline in a non-warning field creates extra physical lines; byte bound remains intact but line bound can be exceeded.
- **直接证据**: `_config_line`, `_service_line`, `_trade_intake_line` results are not passed through `_single_line`; current adversarial test puts newlines only in warning/error fields.
- **影响**: malformed or unexpected runtime metadata can violate the stated logging contract and amplify journal output.
- **建议改法和验证点**: sanitize every final logical line before joining, cap the list at 20, and add a test with multiline non-warning fields.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
