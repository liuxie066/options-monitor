## Findings

### PR-01-未修复-中-Ruff 默认配置不能发现删除后遗留的未使用 import
- **位置**: `Tests / Validation` and `Implementation Decisions`
- **问题类型**: 测试缺口 / 最佳实践偏离
- **当前写法**: Plan states that now-unused imports will be removed and proved with Ruff, but only specifies `python3.12 -m ruff check`.
- **反例/失败场景**: Removing `bj_now()` can leave `ZoneInfo` unused, or removing `copy_if_exists()` can leave `shutil` unused. The repository Ruff configuration selects only `E9` and `F821`, so ordinary `ruff check` succeeds while dead imports remain.
- **为什么有问题**: The work unit's purpose is dead-code reduction. Shipping new dead imports would leave the cleanup incomplete and invalidate the stated success evidence.
- **直接证据**: `pyproject.toml` configures `[tool.ruff.lint] select = ["E9", "F821"]`; several target functions own imports that may become unused after deletion.
- **影响**: Incomplete cleanup and misleading validation; later maintainers still carry dead dependency edges.
- **建议改法和验证点**: Add an explicit `python3.12 -m ruff check --select E9,F821,F401 <touched files>` command and require zero findings. List exact focused pytest files so the implementation agent does not improvise validation scope.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
