## Findings

### CR-S1-001-未修复-高-bootstrap target 为 symlink 时会漏判并用目标 venv 创建它自己
- **入口/函数**: `scripts/install_agent_plugin.sh` -> `om_select_bootstrap_python` -> `python -m venv .venv`
- **文件(行号)**: `scripts/python_runtime.sh:97-128`, especially target normalization at line 103 and candidate normalization at line 122
- **输入场景**: repo `.venv` is a symlink to a shared/cached venv (a pattern already used by `service_upgrade.py`), and `PYTHON`/`OM_PYTHON` or the first PATH candidate points through `<repo>/.venv/bin/python`.
- **实际分支**: `target_path` stays lexical as `<repo>/.venv`, while `_om_python_command_path` resolves the candidate parent with `pwd -P` to the symlink destination, e.g. `<cache>/venvs/hash/bin/python`. `_om_path_is_within` therefore returns false and accepts the candidate.
- **预期行为**: bootstrap selection must reject any interpreter belonging to the target venv, whether the target is a real directory or symlink, before `install_agent_plugin.sh` mutates `.venv`.
- **实际行为**: the selected interpreter can be the target/shared venv itself; the next command asks it to create/update the symlinked target, potentially mutating a shared cached environment.
- **直接证据**: target canonicalization only canonicalizes the parent plus basename (`target_path="$(cd "$target_parent" ...)/$target_base"`), but candidate canonicalization resolves its parent physically (`pwd -P`). `src/application/service_upgrade.py:_link_release_venv` creates release `.venv` symlinks to shared caches, so this is a repository-real state, not a speculative layout.
- **影响**: shared venv partial mutation / multiple releases affected / bootstrap safety contract violated.
- **建议改法和验证点**: canonicalize an existing target directory/symlink with `cd "$target_venv" && pwd -P`; retain lexical parent normalization only for a missing target. Add a test where `.venv` symlinks to a shared directory and the explicit candidate points through the symlink; assert rejection and no invocation.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
