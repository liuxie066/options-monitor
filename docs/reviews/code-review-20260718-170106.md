## Findings

### S1-01-已修复-[高]-关闭现金事实会派生与开仓不同的生命周期 ID

- **入口/函数**: `build_period_performance()` -> `_close_event_cash_facts()` -> `_event_fact_kwargs()` -> `resolve_event_attribution()`
- **文件(行号)**: `domain/domain/performance/engine.py` `_event_fact_kwargs`; `domain/domain/performance/attribution.py` `resolve_event_attribution`
- **输入场景**: 一个带有正确 Combo Yield strategy snapshot 的 close/expire/assignment event，且 `target_lot_id` 指向原始 Funding Put 或 Participation Call lot。
- **实际分支**: `_event_fact_kwargs()` 只对 open event 传 `lot_id_for_open_event(event)`；close event 传 `None`，resolver 回退到 close `event_id`。
- **预期行为**: 同一 lot 的 open cash、close cash、realized allocation、valuation 和 capital facts 使用同一个 lifecycle identity。
- **实际行为**: close cash facts 得到 `funding_cycle:<close_event_id>` 或 `participation:<close_event_id>`，realized facts则使用 `target_lot_id`，导致一个经济生命周期被拆成两个 ID。
- **直接证据**: `resolve_event_attribution(... lifecycle_source_id or event.event_id)`；allocation resolver 明确使用 `target_lot_id`。
- **影响**: S2 按 lifecycle 聚合时，close cash/fees 与 realized PnL 无法归到原 cycle，funding/lifecycle conservation 和 partial-close replay会错误。
- **建议改法和验证点**: 对 open 使用 canonical open lot ID；对 close-like event 使用 `target_lot_id`；没有 target lot 的 close 保持 attribution unavailable/issue，不能用 close event ID伪造生命周期。新增 close-event identity parity 测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
