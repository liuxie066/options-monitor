## Findings

### 1-未修复-高-trade-intake delegation 绕过 canonical lifecycle resolver，无效或过期自证明可把 unresolved 记录从 quality gate 中扣除

- **入口/函数**: `preview_trade_intake_reconciliation_from_sqlite()` -> `reconcile_trade_intake_state()` -> `_delegated_lifecycle_cases_by_deal()` -> `build_trade_intake_datasets()`
- **文件(行号)**: `src/application/trades/state_reconcile.py:115-122,212-231,442-568,571-676`; `src/application/quality/intake_checks.py:159-207,248-340`; `src/application/ledger/lifecycle_overlay.py:500-697,720-798`; `tests/test_trades_state_reconcile.py:575-641`; `tests/quality/test_om_quality_checks.py:641-696`
- **输入场景 A**: 一条 unresolved broker deal 有 pending lifecycle case、zero-price evidence 和 source claim，但 case 没有 `target_contracts_by_lot`，或 claim quantity/receive-time/lot capacity 与 canonical facts 不一致。
- **实际分支 A**: `_delegated_lifecycle_cases_by_deal()` 另行实现一套 case/evidence/claim/bridge 判定，只检查 pending status、合约 identity、zero price 和 claim self-hash；它不消费 canonical resolver 的 target manifest、lot capacity、anchor quantity/received-at、allocation/void、reservation overlap 与 conflict 结果，且 cases/evidence/claims 由三次独立读取组装。满足这套较弱规则就返回 `lifecycle_pending_delegated`。
- **输入场景 B**: runtime status 中的 intake-state JSON 保留旧 `broker_evidence_accepted + lifecycle_adoption.status=accepted`，但当前 read-only reconciliation preview 没有证明任何 delegated row，或已证明的 delegated deal 与当前 actionable pending deal 不是同一条。
- **实际分支 B**: quality 取 `max(state_delegated_count, preview_delegated_count)`，再仅按数量从 `pending_count` / `unresolved_count` 扣减，没有要求当前 preview authority 与具体 deal id 一一对应。因此 state 中的历史自证明可以覆盖 preview 的零证明，并把 OM-INT-001/002/003 全部判为 pass。
- **预期行为**: 只有同一 coherent ledger generation 中的 canonical lifecycle resolution 证明 active case 为 non-conflict direct/bridged anchor，且 source key 精确对应当前 pending deal 时，才能把该 deal 从 actionable intake 集合排除。preview 可用时必须以 preview 为权威；preview 不可用时，历史 state diagnostics 最多只能导致 unknown，不能升级为 pass。
- **实际行为**: 无效 lifecycle case 或已过期的 state 自证明能够隐藏当前 unresolved broker deal，数据集返回 `trusted`、`blocked_consumers=[]`，并宣称可用于 option positions、lifecycle 和 close advice。
- **直接证据**: canonical resolver 在解析 active case 时首先要求非空 target manifest、对应 lot 及容量，随后验证 anchor quantity/received time、allocation 和账户级 reservation conflict。现有 state-reconcile 测试的 case 只有 `target_lot_ids=[]`、没有 `target_contracts_by_lot`，但仍明确断言 `lifecycle_pending_delegated`。现有 quality 测试又在 `reconciliation_preview_available=True`、preview delegated count 缺失（即 0）时，仅凭 state diagnostics 断言 dataset `trusted` 且无 blocked consumers。这两个测试单独执行均通过，证明不安全分支是当前明确契约，而不是猜测。
- **影响**: 核心 intake 质量门可在 canonical lifecycle 已 conflict/不完整或当前 ledger 根本未证明 delegation 时放行，使本应阻断的仓位、生命周期和平仓建议消费者继续使用不一致事实。
- **建议改法和验证点**: 删除 state reconciler 内的平行 lifecycle/bridge resolver，从 read-only coherent ledger facade 复用现有 account lifecycle overlay，输出经 canonical resolution 验证的精确 delegated deal-id/source-key 集合。quality 应做 pending deal-id 的集合差，preview 可用时禁止 state-side `max` 覆盖；preview 不可用时 fail closed/unknown。新增缺 manifest、quantity mismatch、received-time 缺失、allocation/void conflict、overlapping reservations、stale state vs zero-preview 及读期并发变更回归，断言这些情况仍保留 actionable unresolved 或返回 unknown。
