# Code Review

## Findings

### 1-未修复-中-snapshot 兜底把混合证据的 partial_data 扩大为整策略 data_unavailable

- **入口/函数**: `evidence_summary_from_decisions()` -> Sell Put / Covered Call `_evidence_scan_status()` -> `opening_candidate_snapshot._strategy_results()`
- **文件(行号)**: `src/application/candidate_scanning.py:305-340`; `src/application/sell_put_steps.py:158-180`; `src/application/sell_call_steps.py:259-272`; `src/application/opening_candidate_snapshot.py:724-786`; `tests/test_scan_volume_gate_min_zero.py:178-206`; `tests/test_opening_candidate_snapshot.py:448-524`
- **输入场景**: 某策略本轮没有最终候选；同一策略范围内至少一个合约因 `input_invalid` 或 `input_missing` 缺少决策证据，同时另一个合约已用完整证据被判为 `contract_ineligible` 或策略拒绝。扫描层按证据覆盖比例把该范围正确投影为 `status=completed, reason=partial_data`。
- **实际分支**: `_strategy_results()` 先计算 `has_unavailable_input`，随后 `if not counts and has_unavailable_input` 在读取 `reason=partial_data` 的分支之前直接把策略设为 `data_unavailable`。这个 `any` 型兜底没有保留扫描层已经计算出的“部分不可用、部分已有效评估”语义。
- **预期行为**: snapshot 应保持上游 `completed/partial_data` 的最小失败范围，将该策略封存为 `partial_data`；只有全部已评估合约均缺少证据时，才应把整策略标为 `data_unavailable`。若 snapshot 需要防御上游错误的 clean `no_candidate`，也应复用与扫描层一致的覆盖计数规则。
- **实际行为**: 只要零候选策略中存在一个输入不可用 decision，snapshot 就把整策略从 `partial_data` 提升为 `data_unavailable`。这与当前新增的扫描契约测试相冲突：同样的混合 decision 在扫描层明确要求得到 `("completed", "partial_data")`。
- **直接证据**: `candidate_scanning.py:305-340` 将 `input_invalid` / `input_missing` 计入 `evidence_unavailable_count`；两个 `_evidence_scan_status()` 都在 `unavailable < evaluated` 时返回 `completed/partial_data`。但 `opening_candidate_snapshot.py:742-750` 仅检查是否存在任意不可用输入，并抢先于 `opening_candidate_snapshot.py:763-766` 的 `partial_data` 分支执行。用一个 `input_missing` decision 加一个 `contract_ineligible` decision，并传入 `status=completed, reason=partial_data` 调用 `_strategy_results()`，当前确定性输出为 `strategy_status=data_unavailable`、`candidate_count=0`。文档 `docs/candidate_strategy.md:357-381` 要求正式区分 `partial_data` 与 `data_unavailable`，并按最小范围传播失败。
- **影响**: snapshot、审计状态和用户侧文案会夸大失败范围。Daily Brief 对 `partial_data` 保持策略可用并输出“部分行情证据不可用，候选结果不完整”，对 `data_unavailable` 则进入更强的不可用路径（`src/application/daily_decision_brief_service.py:691-716`; `src/application/daily_decision_brief_renderer.py:131-171,1538-1541`）。AI Decision Advice 对两者都 fail closed，因此本问题不会放宽模型调用，但会造成状态合同、可观测性及下游呈现不一致。
- **建议改法和验证点**: 当 scan status 已是 `completed/partial_data` 时优先保留该状态；针对上游误报 clean `no_candidate` 的防御性检查，应按 decision 覆盖数区分“全部不可用”和“部分不可用”，或抽取扫描层与 snapshot 共用的单一状态投影函数。新增 snapshot 回归测试：一个 `input_missing` 加一个有效 `contract_ineligible` 且零候选时，`strategy_status` 与 `opening_status` 均为 `partial_data`；保留现有“唯一 decision 为 `input_invalid`”测试，继续断言 `data_unavailable`。
- **修复风险（低/中/高）**: 低
