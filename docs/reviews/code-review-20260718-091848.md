## Intent and Contract Alignment

S10 is intended to make the v1 option-performance migration provable rather than merely plausible: exact native activity/cash/gross checks must fail closed, expected semantic differences must be classified without hiding correctness failures, missing evidence must never become zero, configured/proven empty scopes may become observed zero only when the absence of facts is trustworthy, and legacy references must remain isolated behind an exact allowlist.

The review followed the public Agent/CLI call path into `build_option_period_performance`, the domain report status construction, reconciliation identity checks, coverage traversal, fee-delta classification, legacy report injection, and the S10 tests/docs.

## Findings

### F1-未修复-[高]-proven-scope normalization turns unreadable ledger facts into observed zero

- **入口/函数**: `option_performance_report_tool` → `build_option_period_performance` → `_apply_proven_zero_semantics`
- **文件(行号)**: `src/application/agent_tools/materialization_impl.py:498-512`; `src/application/performance/service.py:168-196`
- **输入场景**: A configured account has a ledger row in the requested period, but the row cannot be decoded/projected (for example, invalid `contracts`). The public tool marks the account scope as proven solely because the account exists in config.
- **实际分支**: The domain engine emits no monetary facts and a report-level `quality.status=partial` with decode warnings. `_apply_proven_zero_semantics` then recursively rewrites every `not_observed` amount envelope to `observed`, `{}`, and `cny=0.0` without checking the partial diagnostics.
- **预期行为**: “No events in a proven scope” may become observed zero only when the ledger proves there are no relevant facts. Decode/projection failures mean evidence completeness is not proven; affected metrics must remain `not_observed`/`partial` and must not be asserted as observed zero.
- **实际行为**: The report says premium and option cash are observed zero while simultaneously warning that the only period event could not be decoded.
- **直接证据**: `_apply_proven_zero_semantics` tests only the local envelope status (`service.py:189`) and ignores report quality/diagnostics. A read-only reproduction with a configured `lx` row containing invalid `contracts` returned `quality.status=partial` plus `premium_collected_gross={by_currency:{}, cny:0.0, status:"observed"}`.
- **影响**: Missing/corrupt production evidence is silently converted into an authoritative zero, violating the central “missing is not zero” contract and potentially understating cash, premium, and PnL.
- **建议改法和验证点**: Make zero promotion conditional on a clean empty report, not just configured account membership. At minimum, require report-level quality to be `not_observed` with no missing/warnings and no relevant rows/facts before recursively promoting zeros. Add a service/public-tool test with an undecodable in-period row and assert metrics are not promoted.
- **修复风险（中）**: The condition must still promote a genuinely empty configured scope and must not suppress partial diagnostics.
- **严重程度（高）**: This produces financially incorrect observed values from corrupt evidence.

### F2-未修复-[高]-realized reconciliation is skipped when either detail side is absent, allowing a false migration pass

- **入口/函数**: `reconcile_legacy_monthly_report` → `_identity_realized_check`
- **文件(行号)**: `src/application/performance/reconciliation.py:64-93,207-234`
- **输入场景**: Legacy output contains a realized close row, while the v1 report omits rows (`include_rows=False`) or loses the corresponding realized allocation; the aggregate premium and cash values still match.
- **实际分支**: `_identity_realized_check` returns `status=not_applicable` whenever either `legacy_rows` or `v1_rows` is empty. `reconcile_legacy_monthly_report` counts only `status=fail`, so the whole reconciliation returns `pass`.
- **预期行为**: A one-sided realized-detail set is an exact-reconciliation failure. Only two explicitly present, genuinely empty detail sets may be treated as a valid zero/not-applicable case; an omitted required detail payload should be insufficient evidence rather than pass.
- **实际行为**: A reproduction with legacy `event_id=close-1`, realized gross USD 100, and `v1_report["rows"]=[]` returned overall `status=pass` and `option_realized_gross.by_close_event=not_applicable`.
- **直接证据**: The early return at `reconciliation.py:209-214` conflates “both empty”, “one side empty”, and “rows omitted”; `reconciliation.py:78-87` does not treat `not_applicable` as blocking.
- **影响**: The final migration gate can report success even when v1 dropped all realized PnL detail, undermining the exact gross reconciliation required by the approved S10 plan.
- **建议改法和验证点**: Distinguish missing `rows` keys from present empty lists; fail on one-sided identities or malformed/omitted detail payloads; pass an explicit zero check only when both present detail lists are empty and aggregate realized gross also agrees. Add tests for omitted rows, legacy-only rows, v1-only rows, and both-empty zero.
- **修复风险（低）**: This tightens a validation-only module and may require reconciliation callers to request `include_rows=True`, which should be explicit.
- **严重程度（高）**: It creates a false positive in the gate whose purpose is to prove accounting equivalence.

### F3-未修复-[中]-coverage gate does not inspect envelopes inside breakdown lists

- **入口/函数**: `assess_report_coverage` → `_amount_envelopes`
- **文件(行号)**: `src/application/performance/reconciliation.py:112-153,397-405`
- **输入场景**: A monthly/account/symbol breakdown metric is `partial`, has a missing fee/FX/mark reason, but is encoded as empty native amounts plus `cny=0.0`.
- **实际分支**: `_amount_envelopes` returns immediately for every non-`Mapping`; it never descends into lists. All public breakdown collections are lists, so the corrupt nested envelope is not checked.
- **预期行为**: The report-wide coverage gate must apply the same missing-evidence invariants to top-level totals and every emitted breakdown row.
- **实际行为**: A reproduction with `breakdowns.monthly[0].pnl.realized_net={status:"partial", missing:["fee:x"], by_currency:{}, cny:0}` returned coverage `status=pass` with no failures.
- **直接证据**: `reconciliation.py:397-405` recurses only over mapping values and has no list branch, unlike the recursive service normalizer.
- **影响**: A report can pass the S10 null/coverage gate while user-visible monthly/account/symbol values encode missing evidence as zero.
- **建议改法和验证点**: Recurse through lists/tuples while preserving indexed paths (for example `breakdowns.monthly[0].pnl.realized_net`). Add coverage tests for all breakdown collection shapes.
- **修复风险（低）**: Pure validation traversal change.
- **严重程度（中）**: Top-level values remain guarded, but detailed values consumed by analysis and users can be wrong while the gate passes.

### F4-未修复-[中]-missing fee coverage is mislabeled as an actual fee delta

- **入口/函数**: `reconcile_legacy_monthly_report` → `_expected_deltas`
- **文件(行号)**: `src/application/performance/reconciliation.py:284-304`
- **输入场景**: `pnl.realized_gross` has USD 100, while `pnl.realized_net` is `partial` with `missing=["fee:..."]`, `by_currency={}`, and `cny=None`.
- **实际分支**: `_metric_native` returns an empty mapping rather than `None`; the function calculates net-minus-gross and labels the entire USD -100 difference `actual_fee_delta`, even though the net status is explicitly partial.
- **预期行为**: Incomplete fee evidence must be classified as `fee_coverage_incomplete` with no asserted monetary fee delta. `actual_fee_delta` is valid only when net is observed from complete actual-fee facts.
- **实际行为**: The reproduction returned `{code:"actual_fee_delta", delta_by_currency:{"USD":-100.0}, v1_net_status:"partial"}`.
- **直接证据**: The branch at `reconciliation.py:288-295` checks only whether parsed maps are `None`; it reads `net_envelope.status` only for output and never uses it to select the classification.
- **影响**: Reconciliation can present missing PnL as if it were a real fee expense, giving operators a false explanation for a material delta.
- **建议改法和验证点**: Require observed/complete net status before computing an actual fee delta; otherwise classify incomplete coverage and leave `delta_by_currency` null. Add missing-fee and estimated/incomplete-fee tests.
- **修复风险（低）**: Pure classification logic.
- **严重程度（中）**: It does not change production PnL, but it corrupts the migration diagnostic used to approve cutover.

### F5-未修复-[中]-coverage gate accepts an observed non-CNY metric with no CNY/FX evidence

- **入口/函数**: `assess_report_coverage`
- **文件(行号)**: `src/application/performance/reconciliation.py:112-153`
- **输入场景**: An envelope has `status=observed`, non-CNY native amounts (for example USD 1), `cny=None`, no missing reasons, and no FX fact IDs.
- **实际分支**: The observed branch checks only that `missing` is empty. It does not require a CNY result or an explicit FX-missing partial state for non-CNY amounts.
- **预期行为**: Under the v1 contract, missing FX preserves native amounts but makes CNY null and the metric partial with explicit `fx:` missing evidence. An observed non-CNY metric with null CNY is internally inconsistent and must fail the gate.
- **实际行为**: A reproduction returned coverage `status=pass` for `realized_gross={by_currency:{USD:1}, cny:null, status:"observed", missing:[]}`.
- **直接证据**: `reconciliation.py:131-138` validates observed missing reasons and partial FX behavior but has no inverse invariant for observed non-CNY/native data.
- **影响**: Missing FX provenance can be erased while the coverage gate still approves the report.
- **建议改法和验证点**: If an observed envelope contains any non-CNY native currency, require a non-null CNY value and selected FX evidence; alternatively mark it partial with explicit FX missing reasons. Add observed-USD/null-CNY and CNY-only observed controls.
- **修复风险（低）**: Validation-only; ensure native maps whose amounts net to zero remain valid when FX evidence is present.
- **严重程度（中）**: It defeats one of the explicit S10 coverage invariants.
