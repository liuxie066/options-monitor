## Findings

### 1-未修复-低-`put_only_period_net_return` 缺失时 fallback 到 `period_net_return_on_cash_basis`，未显式处理分母非正
- **位置**: `domain/domain/engine/yield_enhancement.py`（staggered / shadow rank key）
- **问题类型**: 契约边界（deferred）
- **当前写法**: `put_period_return = _safe_float(row.get("put_only_period_net_return"))`，缺失时 fallback `period_net_return_on_cash_basis`；无显式非正检查。
- **反例/失败场景**: 若 put 行缺少期间收益字段，rank key 用 `-1.0` 默认值参与排序；若未来 put row 期间收益为负（罕见但可能），会参与排序而非 fail closed。
- **为什么有问题**: plan §7 decision 8 要求“分母非正按主策略 `net_cash_basis_non_positive` 语义 fail closed / 不参与排序”；当前实现依赖主策略扫描早已把非正行过滤，Combo put universe 只含通过主策略 underwriting 的正收益行，因此风险被上游挡住。
- **直接证据**: put 腿来自 `enrich_and_filter_sell_put_underwriting`，主策略 `candidate_engine.py:461-469` 对 `net_cash_basis <= 0` fail closed；Combo put universe 不会包含非正行。
- **影响**: 低；上游保证使该边界在当前数据流不可达。
- **建议改法和验证点**: 作为后续 work unit 在 `_build_pair_row` 增加显式 `put_only_period_net_return` 计算与正性校验，本 slice 保留并记录 owner。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
