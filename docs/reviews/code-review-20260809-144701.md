## Findings

### 1-已修复-高-AI 建议引用的外部证据来源无法渲染，design 15.4 来源行静默缺失
- **入口/函数**: `render_family_advice_lines()` → `_source_lines()`；
  上游 `validation._validate_decision()` → `_decision_row()`；
  调用方 `daily_decision_brief_renderer._ai_advice_lines_for_family()`
- **文件(行号)**: `src/application/ai_decision_advice/render.py:191-213`；
  `src/application/ai_decision_advice/validation.py:188-249`；
  `src/application/daily_decision_brief_renderer.py:883-888`；
  `src/application/ai_decision_advice/collector.py:342-360`
- **输入场景**: 模型对 switch/defer/needs_review 决策给出非空
  `external_evidence_refs`（ADVICE_OUTPUT_SCHEMA 允许的字符串数组）
- **实际分支**: `_source_lines()` 用 refs 在 `evidence_by_ref` 中查找；
  调用方从不传 `evidence_by_ref`，默认 `{}`，所有查找落空，`return []`
- **预期行为**: design 15.4 要求 switch/defer/needs_review 最多展示 3 条来源
  （标题、发布方、日期、URL）；refs 必须能解析到冻结证据中的记录
- **实际行为**: 三个地方共同导致来源永不渲染：
  1. collector 生成的 `symbol_evidence` 记录（collector.py:342-360）没有任何
     稳定 ref id 字段，模型只能编造字符串；
  2. validation 不校验 `external_evidence_refs` 是否解析到冻结证据，任意
     编造字符串原样保留（validation.py:188-191）；
  3. renderer 调用处不传 `evidence_by_ref`（daily_decision_brief_renderer.py:883-888），
     即使 ref 有效也解析不到任何记录。
- **直接证据**: `render_family_advice_lines(section, family=family,
  candidate_contract_by_id=contracts, candidate_rank_by_id=ranks)` 调用缺少
  `evidence_by_ref`；`_source_lines` 中 `row = evidence_by_ref.get(str(ref))`
  恒为 None；`symbol_evidence` 记录键为
  kind/symbol/topic/claim/event_status/source/url/content_fingerprint，无 ref id。
- **影响**: 用户回执中最重要的可审计性承诺（来源引用）静默缺失；模型即使
  引用了真实证据也无法展示，编造引用也不会被发现。属于 contract 未被满足
  且静默失效。
- **建议改法和验证点**: 为 `symbol_evidence` 记录分配确定 ref id
  （如 `ev-<content_fingerprint 前 12 位>`），冻结证据视图携带 ref→记录映射；
  validation 校验 refs ⊆ 冻结视图 refs，未解析则按 demotion 规则降级；
  `_ai_advice_lines_for_family` 传入 `evidence_by_ref`。验证：构造带
  有效/无效 refs 的决策行，断言有效 ref 渲染出来源行、无效 ref 触发降级。
- **修复风险（低/中/高）**: 中（涉及 evidence record 形态、冻结 hash 输入、
  validation 与 renderer 三处联动）
- **严重程度（低/中/高/严重）**: 高

### 2-已修复-中-“checked-at-only 更新不失效复用”的契约未被实现，last_success_at 进入 index hash
- **入口/函数**: `EvidenceIndex.index_hash()`；`build_frozen_inputs()` →
  `find_reusable_completed()`；collector `_status_record()`
- **文件(行号)**: `src/application/ai_decision_advice/evidence_store.py:114-125`；
  `src/application/ai_decision_advice/contexts.py:223-234`；
  `src/application/ai_decision_advice/collector.py:384-388`；
  `src/application/ai_decision_advice/advice_store.py:74-85`
- **输入场景**: 候选/组合/期权持仓语义完全不变；collector 每 4 小时成功刷新
  一次，同一 symbol 无新证据（语义不变，只更新 `last_success_at` 时间戳）
- **实际分支**: `index_hash` 的 payload 含 `last_success_at`；
  `external_evidence_hash = index.index_hash()` 进入四个复用输入 hash 之一；
  `bindings_match` 要求四个 hash 全部相等
- **预期行为**: 按 `advice_store.bindings_match` docstring 与设计 13.2：
  “``last_checked_at``-only updates do not invalidate reuse”——纯刷新时间戳
  变化不应失效复用
- **实际行为**: 每次 collector 成功刷新都更新 `last_success_at` → index_hash
  变化 → `external_evidence_hash` 变化 → 复用失配 → 每 4 小时强制重新调用
  模型。复用优化在常态路径下基本失效，模型调用成本按刷新频率发生。
- **直接证据**: `index_hash()` payload 第 119 行
  `"last_success_at": view.last_success_at`；`_status_record` 在每次成功搜索时
  写入新的 `last_success_at`（时间戳）；`REUSE_INPUT_KEYS` 含
  `external_evidence_hash`。
- **影响**: 复用语义与文档/设计不符；成本与延迟增加；同时跨候选 symbol 的
  无关证据刷新（未传 symbols 的全量 index）也会失效复用。不会导致错误建议，
  属于经济性与契约一致性缺陷。
- **建议改法和验证点**: 从 `index_hash` payload 移除 `last_success_at`（coverage
  与 semantic_hash 已表达 staleness 与内容；纯时间戳不构成语义输入），并把
  freeze 限定到候选 symbols 或对无关 symbol 变化不敏感。验证：新增测试——
  同一语义证据、不同 `last_success_at` 的两次 freeze，`index_hash` 相等且
  `find_reusable_completed` 命中。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
