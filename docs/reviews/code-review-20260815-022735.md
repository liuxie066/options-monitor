### 1-已关闭-误报-DR-W1A-01（null-return 行排在有回报行之前）

- **直接证据**: `_rank_return_bands()`（`domain/domain/engine/candidate_engine.py:1165-1196`）的 `while remaining` 循环中，`band` 的构造条件是 `(value := period_return_fn(row)) is not None and value >= floor`——null-return 行永不进入任何 band；只要 `usable` 非空，band 只含非 null 行并被立即 emit，null-return 行留在 `remaining` 直到所有已知回报行全部 emit 完毕；只有 `usable` 为空（即剩余全为 null-return）时才落入 `if not usable` 的 tie-key 排序分支。原报告描述的"null-return 行以 tie key 排在有回报行之前"路径在代码中不存在。

- **裁决**: 接受 fix 判定的 rejected-as-false-positive；finding 关闭。

### 2-未修复-低-`build_ranking_projection` 不在 Sell Put 空结果时区分 `no_candidate`（合法）与 `data_unavailable`/`partial_data`（fail-closed）

- **入口/函数**: `build_ranking_projection()` -> `ranked_opening_candidate_decisions()`
- **文件(行号)**: `src/application/strategy_lab/top1/ranking.py:210-245`；snapshot 侧语义在 `src/application/opening_candidate_snapshot.py:369-379, 495-506, 951-1019`
- **输入场景**: sealed 且 `content_sha256` 合法的 opening snapshot，其 `strategy_results` 中 `put` 行 `strategy_status` 为 `data_unavailable` 或 `partial_data` 且 `candidate_count == 0`（snapshot 密封器在 `_strategy_results:983-1008` 中明确把这类证据不足情形与合法 `no_candidate` 区分）；对照场景为合法 `no_candidate` 空集
- **实际分支**: `build_ranking_projection` 只调用 `validate_opening_candidate_snapshot(..., require_current_contract=True)`（验证 `strategy_status ∈ STRATEGY_STATUSES`、scope/results 重建一致性），随后取 ranked put decisions——空列表；两种场景都走到同一个空 candidates 分支
- **预期行为**: 按 snapshot 自身合同与项目既有语义，`no_candidate` 是 lawful 空结果，可以产出空 projection 并 rerank 出 `top1_candidate_id=None`；`partial_data`/`data_unavailable` 是证据不足，应 fail closed（`Top1RankingError`），不应产生与合法空集不可区分的 projection
- **实际行为**: 两种场景产出**完全等价**的合法 projection（空 candidates、通过全部校验），rerank 均返回空 order + null Top1；projection payload 中没有携带任何可区分 lawful-empty 与 evidence-unavailable 的字段，下游无法区分
- **直接证据**: `ranking.py:229-245` 只对 ranked decisions 做 accepted/normalized_input 检查，不读取 `snapshot["strategy_results"]`；`validate_opening_candidate_snapshot`（`opening_candidate_snapshot.py:369-379`）只校验 status 枚举成员资格与重建一致性，不把 `data_unavailable`/`partial_data` 判为 invalid；`test_empty_accepted_set_is_a_valid_projection`（`tests/test_strategy_lab_top1.py:284-290`）只覆盖合法 `no_candidate` 空集路径
- **影响**: 实验数据质量风险而非资金/安全风险：W1A 是纯函数、无生产写入、无自动下单，最坏后果是后续 W-模块在证据不足的 snapshot 上得出与合法空集相同的空 ranking 结论；但语义真源（snapshot 已计算 status）存在，下游无需重复计算即可补判
- **建议改法和验证点**: 在 `build_ranking_projection` 中读取已验证 snapshot 的 `strategy_results`：当 ranked put 决策为空且 put `strategy_status != "no_candidate"`（或不属于明确合法空集集合）时 fail closed，reason_code 沿用 `ranking_projection_incomplete` 或新增稳定 reason。验证点：构造 `put` 为 `data_unavailable`/`partial_data` 且零候选的 sealed snapshot，断言 build 抛 `Top1RankingError`；合法 `no_candidate` 空集仍通过
- **修复风险（低/中/高）**: 低
