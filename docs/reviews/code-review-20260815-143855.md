## Findings

### 1 — unresolved — high — the declared research cutoff does not exclude evidence captured after the cutoff

- **Location**: `src/application/strategy_lab/top1/corpus.py:1185-1268`
- **Failure scenario**: a caller supplies a valid cutoff and 40 selected dates, but one indexed expectation was sealed after the cutoff or one point was decided/captured after it. All hashes and calendar bindings remain valid, so the current loop publishes a ready historical dataset.
- **Why this matters**: the parent experiment contract requires the sealed historical dataset to have existed before `research_cutoff_at`. Accepting later evidence introduces look-ahead while still advertising the result as historical and ready.
- **Direct evidence**: the dataset binds `cutoff_at_utc`, but the coverage loop only checks calendar identity, completeness, artifact hashes, and ranking parity. It never compares expectation `sealed_at_utc`, projection `decision_at_utc`, or point-index `captured_at_utc` with the cutoff.
- **Required fix**: reject inconsistent capture chronology at the capture boundary, and classify any selected evidence that is not strictly before the bound cutoff as `research_dataset_coverage_missing`. Add a regression proving no dataset is published.
- **Severity**: high

### 2 — unresolved — medium — an older projection schema is reported as evidence conflict instead of lawful coverage warming

- **Location**: `src/application/strategy_lab/top1/corpus.py:1235-1241`
- **Failure scenario**: after a future ranking-projection schema upgrade, a selected point is clean and immutable but carries the previous schema version. `validate_ranking_projection()` rejects it, `_read_indexed_projection()` maps that to `corpus_artifact_invalid`, and freeze returns `research_corpus_conflict`.
- **Why this matters**: the accepted W4 plan explicitly says schema upgrades require new future Corpus evidence and old evidence is not backfilled. That is missing compatible coverage, not evidence disagreement or a terminal corruption claim.
- **Direct evidence**: the loop does not compare the indexed `ranking_projection_schema_version` with the current version before entering the strict current-schema reader.
- **Required fix**: treat a clean non-current schema row as `research_dataset_coverage_missing`; reserve conflict for a current-schema row whose immutable ref/bytes/bindings disagree.
- **Severity**: medium
