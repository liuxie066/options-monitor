## Assumptions tested

1. The S3 runtime already owns fast/full selection and has one in-transaction
   core; the amendment does not require a second projector or publisher.
2. Public writer facades with adjunct Combo/lifecycle/outbox writes must keep
   one caller-owned transaction, so calling the self-committing S3 entrypoints
   is not safe.
3. Existing writer results expose projection diagnostics. Replaying the full
   prefix after the runtime only to reconstruct them would restore the O(E)
   duplication that S4 exists to remove.
4. Fast and checkpoint-backed projection is already eligible only when its
   diagnostic list is empty. A full fallback may remain publishable with
   warnings, but must not persist that state as a trusted resumable checkpoint.
5. A mixed existing/new batch needs one created flag per submitted event, in
   input order; a single aggregate count is insufficient for current facade
   idempotency and outbox behavior.
6. Transaction ownership stays unambiguous if the narrow entrypoint requires
   an active SQLite transaction and performs no commit/rollback itself.

The amendment resolves the concrete file-ownership and contract gap without
adding a new layer. Its required assertions cover the strongest failure modes:
partial commit, idempotent retry drift, diagnostic loss, hidden prefix replay,
and checkpointing a non-resumable warning state.

## Residual Risk

- Full fallback remains O(E) by design and must be reported separately in S5;
  this is an accepted safety path, not an S4 regression.
- Checkpoint mode remains disabled until S5 evidence and explicit operator
  activation; S4 tests must enable it only on temporary stores.
- Facade integration remains subject to S4 DeepReview and inventory closure.

- Architecture boundary: pass; projection semantics remain in domain/runtime,
