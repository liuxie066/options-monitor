# Deepreview — Daily Decision Brief S2

## Findings

### CR-S2-1 — High — Pipeline failure can be published as a live actionable brief

- **Code location**: `src/application/daily_decision_brief_service.py:202-215`; source contract at `src/application/account_run.py:558-574` and `src/application/tick_account_execution.py:196-220`.
- **Entry point / trigger**: The account pipeline subprocess fails after producing some readable partial artifacts. `decide_pipeline_execution_result()` reports `ran_scan=true` but `AccountRunOutcome.ran_pipeline=false`.
- **Expected behavior**: Pipeline failure is an account-wide blocker; no partial artifact may become a LIVE decision baseline.
- **Actual behavior**: The assembler treats `AccountResult.ran_scan` as pipeline success. The production failure path deliberately preserves `ran_scan=true`, so readable partial files can produce `live_actionable`.
- **Direct evidence**: `account_run.py` returns `AccountResult(... ran_scan=True ...)` together with `AccountRunOutcome.ran_pipeline=False`; `daily_decision_brief_service.py` computes `pipeline_failed = not result_view["ran_scan"]`.
- **Impact**: A failed scan may send stale or incomplete candidates as actionable advice, violating the fail-closed boundary.
- **Fix direction**: Pass the authoritative pipeline-completion fact (`AccountRunOutcome.ran_pipeline` / membership in `ran_pipeline_accounts`) into the assembler and base blocking on that fact, not on `ran_scan` or reason text.
- **Fix risk**: medium because S3 integration must consume the new explicit input.
- **Severity**: High.
- **Decision**: accepted.

### CR-S2-2 — High — Any non-empty delivery key can advance the confirmed pointer

- **Code location**: `src/application/daily_decision_brief_repository.py:198-278`.
- **Entry point / trigger**: Caller supplies a persisted revision and correct digest but swaps `delivery_kind`/`delivery_key`, or confirms a revision using the key for another prepared lifecycle.
- **Expected behavior**: Only confirmation of the exact prepared full/delta envelope may advance the last-delivered pointer.
- **Actual behavior**: The repository validates only that kind is `full|delta` and key is non-empty; it never checks the run-scoped diff or recomputes the expected key.
- **Direct evidence**: Reproduction confirmed revision 0 with `delivery_kind=delta` and `delivery_key=wrong-key`; repository returned `advanced=true` and persisted both values.
- **Impact**: Pointer can skip an undelivered material change, and later diffs will treat that action as already delivered.
- **Fix direction**: Validate confirmation against the target revision's run-scoped diff: full requires `from_revision=null` and the fixed daily full key; delta requires a material diff, its exact `to_revision`, the digest of its `from_revision`, and the exact canonical delta key.
- **Fix risk**: medium; concurrent prepared revisions must remain confirmable from their own immutable run artifacts rather than recomputing against the mutable current pointer.
- **Severity**: High.
- **Decision**: accepted.

### CR-S2-3 — Medium — Malformed delivery state escapes the explicit unavailable contract

- **Code location**: `src/application/daily_decision_brief_repository.py:423-438` and `read_daily_decision_brief_delivery()`.
- **Entry point / trigger**: Delivery JSON has the current schema marker but an invalid date or revision value.
- **Expected behavior**: Old/malformed state returns `available=false, reason=state_invalid` or raises the repository's state error on write paths.
- **Actual behavior**: `_normalize_market_date()` / `_normalize_revision()` raise bare `ValueError`; the read API catches only `DailyDecisionBriefStateError`.
- **Direct evidence**: A pointer with `revision="bad"` raises `ValueError: revision must be a non-negative integer` from the public read API.
- **Impact**: CLI/Agent read surfaces planned for S4 can crash instead of failing closed with structured unavailability.
- **Fix direction**: Wrap all pointer field normalization failures as `DailyDecisionBriefStateError` and add malformed-date/revision regressions.
- **Fix risk**: low.
- **Severity**: Medium.
- **Decision**: accepted.

### CR-S2-4 — Medium — Multi-market briefs share an unfiltered rejection summary

- **Code location**: `src/application/daily_decision_brief_service.py:183-198`.
- **Entry point / trigger**: Manual `--market-config all` run produces US and HK candidate trace rows, then assembler builds the HK brief.
- **Expected behavior**: Every brief is market-qualified; HK rejection counts/samples must exclude US symbols.
- **Actual behavior**: `build_candidate_reject_summary()` filters account/run only. The assembler adds `market="HK"` to the returned account-wide summary without filtering rows.
- **Direct evidence**: Reproduction with one NVDA rejection and one `0700.HK` rejection produced HK `total_rejected=2` and sample symbols `['NVDA', '0700.HK']`.
- **Impact**: HK/US read artifacts can report false rejection counts and wrong symbols even though their identity and paths are separated.
- **Fix direction**: Build the rejection aggregate from market-filtered structured trace/reject rows; do not relabel an account-wide aggregate as market-qualified.
- **Fix risk**: low to medium; reuse existing category/rule classification rather than copying policy.
- **Severity**: Medium.
- **Decision**: accepted.

### CR-S2-5 — Medium — Current state is trusted without its required immutable revision artifact

- **Code location**: `src/application/daily_decision_brief_repository.py:61-73`.
- **Entry point / trigger**: `daily_decision_brief.<market>.current.json` is valid but its referenced day/revision file is missing after partial restore, manual damage, or artifact loss.
- **Expected behavior**: Missing canonical history is explicit unavailable/fail-closed; revision allocation must not guess from an unverifiable current pointer.
- **Actual behavior**: The repository increments directly from current and overwrites it, silently accepting the orphan state.
- **Direct evidence**: No existence/digest check of `daily_decision_brief.<market>.<date>.rNNNN.json` occurs before `revision = current.revision + 1`.
- **Impact**: History continuity and delivery auditability can be permanently lost while the repository reports normal progress.
- **Fix direction**: Validate current against the immutable revision artifact and digest before allocating the next revision; classify absence or mismatch as `DailyDecisionBriefStateError`.
- **Fix risk**: low.
- **Severity**: Medium.
- **Decision**: accepted.
