## Findings

### 1-未修复-高-PM 单账户适配器强制小写映射账户，破坏账户权威绑定
- **入口/函数**: `PortfolioManagementClient.read_distribution()` -> `_normalized_single_account()` -> `_request()`
- **文件(行号)**: `src/infrastructure/portfolio_management_client.py:168-191,351-361,396-405`; `src/application/account_config.py:253-274`; `tests/test_account_config.py:94-106`
- **输入场景**: OM 账户通过 `holdings_account` 显式映射到区分大小写或含空格的 PM 账户，例如现有契约测试中的 `LX` 或 `Feishu EXT`。
- **实际分支**: `_normalized_single_account()` 对请求值执行 `.lower()`，然后用转换后的值发起 query；回包账户也以 lowercase 比较。
- **预期行为**: 按设计使用 `holdings_account` 的精确映射值（仅 trim）请求 PM，并要求回包 `accounts` 与该单账户严格相等；只有未配置时的 OM fallback label 固定是小写。
- **实际行为**: `LX` 被查询为 `lx`，`Feishu EXT` 被查询为 `feishu ext`；且回包 `LX` 也会在请求 `lx` 时被接受。
- **直接证据**: `resolve_holdings_account()` 将配置值原样 trim 后返回，现有测试明确断言 `LX`/`Feishu EXT` 保留；新 helper 在发请前无条件 `.lower()`，新测试还把 `" LX "` 期望成 `account=lx`。PM producer 的 `normalize_accounts()` 只 trim/去重，不承诺大小写归一。
- **影响**: 可查到不同的 PM scope、得到无数据，或在存在大小写相异账户时破坏账户隔离。这会使 Advice 使用错误组合事实或错误降级。
- **建议改法和验证点**: 请求账户只 trim、不 lowercase；`all` 禁止仍做大小写无关判断；回包与发出的 mapped account 做精确比较。新增含空格/大小写映射的 query 和 mismatch 回归测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-中-freshness 校验宽松接受非法枚举，却把未规范化值交给下游
- **入口/函数**: `PortfolioManagementClient.read_distribution()` -> `validate_distribution_response()` -> `_validate_freshness()`
- **文件(行号)**: `src/infrastructure/portfolio_management_client.py:408-425,560-581`; `contracts/portfolio-management/v1.openapi.json` `FreshnessEvidence` schema
- **输入场景**: PM 返回 schema 不允许的 `status="FRESH"` 或 `trust_status="TRUSTED"`。
- **实际分支**: helper 先 `.lower()` 只用于成员检查，因此接受该值；然后返回原 `item`，未把值改为 canonical enum。
- **预期行为**: 严格 wire adapter 应要求 OpenAPI 指定的 lowercase enum，非法协议值 fail closed；或者若明确选择规范化，则必须返回规范化后的值。
- **实际行为**: 非法响应被标记为已验证，同时 S2 无法安全依赖 `fresh|stale|...` / `trusted|partial|...` 精确分支。
- **直接证据**: `_validate_freshness()` 的 `status`/`trust` 是 lowercase 临时值，但 `return item`；当前可复现 `validate_distribution_response()` 接受并返回 uppercase 值。Vendored schema 的 enum 仅包含 lowercase 值。
- **影响**: 协议漂移未能 fail closed，后续 prepared state 可能将实际 fresh/trusted 误分类，或被迫加入下游 loose parsing，扩大语义真源漂移。
- **建议改法和验证点**: 在共享 freshness validator 中对原值做精确枚举比较，并补 distribution 及现有 valuation response 的 uppercase 拒绝测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
