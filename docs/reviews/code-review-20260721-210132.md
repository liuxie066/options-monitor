# Code Review — Channel Notification Renderer Consolidation Slice 2

## Findings

### 1-未修复-中-`preview_notification` 把显式空 renderer 当成缺省 Compact，违反只接受 `compact|legacy` 的边界
- **入口/函数**: `preview_notification` -> `preview_notification_tool()` -> `build_notification()`
- **文件(行号)**: `src/application/agent_tools/notifications_impl.py:7-16`; `src/application/agent_tools/notifications.py:43-50`
- **输入场景**: 调用公共只读工具并显式提交 `{"render_style": ""}`。
- **实际分支**: `payload.get("render_style") or "compact"` 把显式空字符串与字段缺失合并，转换成 `compact`；当前 input schema 只声明普通 string 描述，也没有 machine-readable enum。
- **预期行为**: 只有字段缺失/`None` 使用 Compact 默认；任何显式非 `compact|legacy` 值（包括空字符串）均 fail-closed，schema 应声明允许枚举。
- **实际行为**: 工具返回成功 Compact preview，调用者无法区分“合法缺省”与“无效 renderer 被静默修正”。
- **直接证据**: 本轮执行 `execute_tool("preview_notification", {"alerts_text":"", "render_style":""})` 返回 `ok=true`、`renderer=compact`；同一实现中非空 unknown 值才由 `build_notification()` 拒绝。
- **影响**: Phase A/B 公共兼容契约仍保留一个隐藏 fallback；错误或迁移不完整的 caller 可以被静默接受，削弱 unknown-style fail-closed 验收信号。
- **建议改法和验证点**: 仅当 key 缺失或值为 `None` 时默认 Compact；input schema 改成 `type=string, enum=[compact,legacy]`；新增显式空字符串失败测试，并保留缺省成功测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### 2-未修复-中-`runtime_status` 新 canonical authority/read fields 未进入工具 output contract
- **入口/函数**: `runtime_status` -> `runtime_status_tool()` -> Copilot `compact_observation()`
- **文件(行号)**: `src/application/agent_tools/runtime_status_impl.py:2294-2310`; `src/application/agent_tools/diagnostics.py:59-82`; `src/application/copilot/tools.py:97-149,273-315`
- **输入场景**: Agent/Copilot 调用 `runtime_status` 解释 scheduled renderer authority 或 compatibility artifact；实现已返回 top-level `notification_authority` 与 canonical `compatibility_notification*` fields。
- **实际分支**: `_RUNTIME_STATUS_OUTPUT_CONTRACT` 仍只列旧的 summary/run path facts，`model_preview_fields` 也没有 `notification_authority` 或 canonical compatibility read surfaces；`compact_observation()` 使用该 contract 生成字段优先级与 `result_contract`。
- **预期行为**: 公共 tool contract machine-readably 宣告 Daily Brief authority、canonical compatibility artifact 和 account-summary canonical names，使模型不依赖未声明字段或 deprecated aliases。
- **实际行为**: raw tool payload 包含新字段，但 contract 仍把它们视为未声明附加数据；`result_contract.fact_fields` 不暴露本 Slice 的核心 read-authority contract，现有 contract test 也只更新了 preview tool。
- **直接证据**: `runtime_status_impl.py` 返回 `notification_authority`、`shared.compatibility_notification`；`diagnostics.py:63-81` 的 fact/model fields 无这些路径；`compact_observation()` 从 output contract 计算 priority 和 compact contract。
- **影响**: Agent 在压缩观察、工具选择说明或后续 schema 消费中可能继续把 deprecated `notification`/旧 summary 视为稳定字段，削弱本次“公共可观测面单一权威”的迁移效果。
- **建议改法和验证点**: 将 `notification_authority`、`shared.compatibility_notification`、`accounts`/`account_summary` canonical compatibility fields 加入 runtime-status output contract/model preview；在 agent plugin contract test 断言新 canonical facts 与 authority 可见，旧 alias 只由 payload alias map 标记迁移。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
