## Findings

### DR-S2-01-已修复-中-candidate_index normalizer accepted ineligible representatives
- **入口/函数**: `normalize_daily_decision_brief()` -> `_normalize_candidate_index()`
- **文件(行号)**: `domain/domain/daily_decision_brief.py:247-292`
- **输入场景**: repository/migration/reader receives a `daily_decision_brief.v1` containing a syntactically valid identity, positive `contract_count`, but an empty representative or capacity `< 1`.
- **实际分支**: normalizer validates identity uniqueness and positive count, then writes a bounded representative without checking required contract fields or canonical capacity.
- **预期行为**: explicit `candidate_index` must enforce the same eligible-index contract as the assembler: complete representative contract fields and canonical capacity at least 1; malformed entries fail closed.
- **实际行为**: malformed explicit indexes normalize successfully and can later be treated as alertable identities by Slice 3/4 state logic.
- **直接证据**: lines 260-289 call `_candidate_representative_view()` and append the item; the completeness/capacity check exists only in assembler `_build_candidate_index()` at `src/application/daily_decision_brief_service.py:912-921,965-984`.
- **影响**: malformed/mixed state could create a false candidate alert identity or persist a delivery state that cannot render a valid representative.
- **建议改法和验证点**: normalize the representative first, validate family-specific required fields plus `capacity.contracts_available >= 1`, reject otherwise; add explicit schema tests for missing contract fields and zero capacity while preserving best-effort derivation only when the field is absent on legacy revisions.
- **裁决**: accepted；已在 `domain/domain/daily_decision_brief.py:285-325` 修复，并由 malformed representative 与 repository repeated-normalization tests 验证。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### DR-S2-02-已修复-中-non-live brief could expose alertable candidate identities
- **入口/函数**: `normalize_daily_decision_brief()` -> `_normalize_candidate_index()`
- **文件(行号)**: `domain/domain/daily_decision_brief.py:248-261`
- **输入场景**: planning/blocked legacy brief contains an active opening action but lacks the additive `candidate_index`, or a malformed caller supplies a non-empty explicit index.
- **实际分支**: the initial implementation derived identities whenever the field was absent and did not receive `actionability`.
- **预期行为**: only reliable, currently actionable briefs may expose alertable candidate identities.
- **实际行为**: a non-live old revision could normalize into a non-empty index and later enter pending-candidate state.
- **直接证据**: initial `_normalize_candidate_index()` accepted only account/market/actions; actionability was not part of the branch condition.
- **影响**: after-hours/planning or blocked state could create false candidate alerts.
- **建议改法和验证点**: pass normalized actionability into candidate-index normalization; return empty for absent non-live indexes and reject non-empty explicit indexes.
- **裁决**: accepted；已在 `domain/domain/daily_decision_brief.py:189-195,248-261` 修复，并由 planning/blocked tests 验证。
- **修复风险（低/中/高）**: 低
