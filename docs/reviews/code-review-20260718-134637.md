## Findings

### DR-S2-001-未修复-高-structured/manual open 只保存 snapshot，导致组合身份无法进入投影与 inventory

- **入口/函数**: `execute_manual_open` / `persist_manual_open_event`，以及 assistant manual-open operation
- **文件(行号)**: `src/application/ledger/manual_trades.py:220-270`; `src/application/ledger/publisher.py:112-125`; `domain/domain/ledger/position_fields.py:508-521`; `src/interfaces/cli/option_positions.py:180-196`
- **输入场景**: structured assistant/manual open 提供包含 `strategy=combo_yield`、`leg_role`、`strategy_group_id`、`expiry_structure=diagonal` 的 `strategy_snapshot`；或操作者尝试通过 `om option-positions add` 创建 diagonal 两腿。
- **实际分支**: workflow 接收 `strategy_snapshot`，但 open event `raw_payload` 仅写入 `strategy_snapshot`；publisher 的 `strategy_metadata_fields_from_payload` 只从 payload 顶层读取 `strategy`、`leg_role`、`strategy_group_id` 等字段，不从 snapshot 回填。CLI `add` 还没有参数可传 snapshot。
- **预期行为**: accepted S2 plan 要求 explicit structured/manual open 把 candidate group identity 经过 preview/write/projection/restart 持久化，使 `combo_yield_groups` 能重建该组。
- **实际行为**: projected lot 只有 nested snapshot，没有顶层 `strategy_group_id`/`strategy`; context builder 将顶层空值传给 `build_option_group_inventory`，而 inventory 的纳入条件只检查顶层字段，因此该 lot 被完全排除。CLI manual add 则连 explicit intent 都无法表达。
- **直接证据**: `persist_manual_open_event` 的 payload 在 261-268 行仅保存 snapshot；publisher 125 行调用的 helper 在 512-520 行只读取 payload 顶层；CLI add 参数 180-196 行无 strategy snapshot/group 参数。
- **影响**: 已批准的“真正错期 explicit-intent 开仓”在现有 structured/manual 主路径上无法形成可重建 lifecycle group；preview 看似接受 snapshot，但 restart/context 后组合消失，属于持久化 contract 静默失效。
- **建议改法和验证点**: 从 validated snapshot 明确复制 Combo strategy metadata 到 manual-open event payload 顶层；让 preview fields 与 projected fields 一致；为 CLI add 暴露最小 `--strategy-snapshot-json`；增加 candidate-like snapshot → dry-run preview → write → SQLite restart → `combo_yield_groups` 的 focused test。
- **修复风险（低/中/高）**: 中；需保证只复制既有 strategy metadata keys，不扩张 schema，也不改变普通 manual open。
- **严重程度（低/中/高/严重）**: 高
