## Findings

### PR-01-未修复-高-允许 list/tuple 会把非 SDK 响应伪装成成功缺失

- **位置**: §5 provider response rule 4–5、§6 complete empty DataFrame/list assertion
- **问题类型**: trust-boundary contract / false absence
- **当前写法**: plan accepts DataFrame-like data and plain list/tuple rows; an empty list returns `None`.
- **反例/失败场景**: the quote client returns `(0, [], None)` because an adapter/mock/provider regression stopped constructing the documented DataFrame. The method treats this malformed successful payload as a complete no-row result. A future runner can then record outcome evidence as unavailable instead of surfacing a source-contract defect.
- **为什么有问题**: the installed SDK success contract is a DataFrame and constructs it with known `code/name/requested-field` columns even when there are zero rows. Plain-list support exists only to make fakes easier; it weakens the exact distinction this work unit is meant to add.
- **直接证据**: installed `OpenQuoteContext.request_history_kline()` returns `pd.DataFrame(list_ret, columns=col_list)`; current generic gateway is the intentionally permissive path. This new method is the strict path.
- **影响**: malformed price-source output can be silently downgraded to absence, reducing research coverage or changing variant comparison instead of stopping the experiment.
- **建议改法和验证点**: require a DataFrame-like object with callable `to_dict(orient="records")` and columns containing `code`, `time_key`, and `close`; allow provider extras such as `name`. Only such a frame with zero rows may return `None`. Tests can use the already-installed pandas dependency or a tiny DataFrame-like fake. Assert that empty list/tuple, missing columns, malformed `to_dict`, and non-dictionary materialized rows fail closed.
- **修复风险（低/中/高）**: low
- **严重程度（低/中/高/严重）**: high
