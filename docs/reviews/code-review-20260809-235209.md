### DR-S5-RR-01-未修复-高-设计固定的两批并发完全未生效

- **入口/函数**: `run_evidence_collector()` batch loop
- **文件(行号)**: `src/application/ai_decision_advice/collector.py:391-544`;
  `src/application/ai_decision_advice/config.py:28`
- **输入场景**: 观察集大于一批，单批 web search 耗时接近数分钟。
- **实际分支**: 代码用普通 `for batch in batches` 逐批调用
  `_call_with_repair()`；`EVIDENCE_MAX_CONCURRENT_BATCHES = 2` 没有任何消费点。
- **预期行为**: v1 固定合同要求在共享 5 分钟 deadline 下最多同时
  执行 2 个 batch。
- **实际行为**: 任何时候只有 1 个 batch 在运行，观察标的覆盖能力最多只有
  已确认合同的一半，更容易在 deadline 后留下未搜索标的。
- **直接证据**: 设计文档第 6.1/17 节把并发 2 定为 v1 固定合同；配置
  常量已存在，但 `rg` 显示生产代码没有其他引用。
- **影响**: 用户选定的 5 分钟长搜索预算下，期权持仓或候选标的更容易
  长时间处于 `no_evidence`/unfinished，降低 Advice 可用性。
- **建议改法和验证点**: 以最多 2 个 batch 为一波并发，共享同一 monotonic
  deadline；下一波只在仍有预算时启动。用 barrier 回归证明两批确实重叠，
  并验证不启动超过 deadline 的后续波。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### DR-S5-RR-02-未修复-高-Managed Collector 未接入已设计的 OpenD basic-info 身份回退

- **入口/函数**: `run_managed_collector()` ->
  `build_symbol_identity_snapshot()` -> `_resolve_symbol_identities()`
- **文件(行号)**: `src/application/ai_decision_advice/managed_collector.py:157-171`;
  `src/application/ai_decision_advice/identity.py:186-263`
- **输入场景**: OpenD market snapshot 返回了标的 code，但该行的 `name` 缺失或空；
  `get_stock_basicinfo(code_list=...)` 可以返回合法公司名称。
- **实际分支**: identity domain 已支持 `basic_info_provider`，但唯一生产 caller
  只传 `market_snapshot_provider`；因此 unresolved 行直接进入
  `identity_unavailable`。
- **预期行为**: 按已确认设计，快照名称缺失时应按明确 code list 查
  OpenD `get_stock_basicinfo`，两个 OpenD 路径均失败后才标记身份不可用。
- **实际行为**: 可以由 OpenD 建立的公开身份被误判为不可用，不调用搜索，
  并使账户 Advice 无法达到 `keep`。
- **直接证据**: `identity.py` 的 fallback 仅在 `basic_info_provider is not None`
  时执行；`managed_collector.py` 调用处未传此参数，也没有生产 basic-info
  adapter。
- **影响**: OpenD 可用却长期零证据，与用户特别关注的“持续无数据导致没有
  结果”风险直接相冲突。
- **建议改法和验证点**: 在 Futu gateway 正确所有者边界增加最小
  `get_stock_basicinfo` 能力；managed adapter 按 market/code list 分批调用并交给
  identity builder。回归证明 snapshot 缺 name 但 basic-info 有 name 时仍会进入搜索。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### DR-S5-RR-03-未修复-中-模型提供的超长 IDNA hostname 可越过失败关闭并中断整轮

- **入口/函数**: provider citations/search sources ->
  `_native_citations_by_url()` -> `normalize_https_url()`
- **文件(行号)**: `src/application/ai_decision_advice/collector.py:296-367,615-618`
- **输入场景**: provider response 中包含合法 `https` 形式，但 hostname 单个 label
  超过 IDNA 长度上限。
- **实际分支**: `urlsplit()` 成功，但
  `hostname.encode("idna")` 抛 `UnicodeError`；该转换不在 `try` 内，异常离开
  `_call_with_repair()` 并中断 collector。
- **预期行为**: 所有 provider-controlled URL 解析/规范化错误都应返回 `None`，
  只丢弃不可绑定的证据行，不能撤销其他标的状态。
- **实际行为**: 一个恶意或畸形来源 URL 可使本轮已组装的记录全部不落盘。
- **直接证据**: `normalize_https_url("https://" + "a"*64 + ".com")`
  可稳定复现 `UnicodeError: label empty or too long`。
- **影响**: 外部响应可破坏整轮可用性，且无 per-symbol failed status 审计。
- **建议改法和验证点**: 把 IDNA 编码也置于规范化的 fail-closed
  `try` 内；添加畸形 native source/citation 回归，验证搜索完成但证据为零时
  仍按合同完成。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### DR-S5-RR-04-未修复-低-Observation publisher 可写出自己随即拒绝读取的时间戳

- **入口/函数**: `publish_observation_partition()` -> `_utc_iso()` ->
  `load_observation_set()`
- **文件(行号)**: `src/application/ai_decision_advice/identity.py:437-489,609-684`
- **输入场景**: internal caller 传入 `generated_at="not-a-time"` 或无时区字符串。
- **实际分支**: `_utc_iso()` 对任意字符串原样返回，publisher 计算 hash 并原子
  写入；紧接着 reader 的 `_require_timestamp()` 拒绝同一份快照。
- **预期行为**: writer 在任何文件副作用前验证并规范化成 UTC，不可生成
  自身 contract 无法读取的状态。
- **实际行为**: 一次错误调用会把先前有效的 market partition 替换为损坏快照，
  后续 publisher 和 collector 都 fail closed。
- **直接证据**: 写入 `generated_at="not-a-time"` 成功，随后
  `load_observation_set()` 稳定抛 `ObservationSnapshotError` 。
- **影响**: 内部参数错误可破坏共享观察集，并让下一次 Tick 也无法自动收敛。
- **建议改法和验证点**: writer 先严格解析 aware timestamp、转为 UTC ISO，
  非法输入在取锁/写文件前抛错；回归证明旧快照仍完整。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
