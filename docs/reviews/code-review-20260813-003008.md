### S3-CR-01-未修复-中-S3 缺少计划约定的 US/HK 全路径禁产回归矩阵

- **入口/函数**: `run_watchlist_pipeline_default()` -> strategy status/snapshot sealing -> account run artifact publication
- **文件(行号)**: `tests/test_candidate_csv_retirement.py:39`; `tests/test_pipeline_capture_status_routing.py:43`
- **输入场景**: 分别在 US/HK 运行 Sell Put + Combo Yield，并覆盖策略启用有候选、启用零候选、策略失败、成功但上游无合约行、策略禁用五类结果。
- **实际分支**: 新增测试只静态扫描生产源码中的禁用文件名/写 CSV 调用；现有运行目录测试固定使用 HK，并未把五类状态和两个市场组合后检查实际账户运行目录。
- **预期行为**: S3 退出测试应对 US/HK × 五类结果生成真实账户运行目录，逐一确认禁产 CSV 集合为空，同时 JSON 快照、v2 状态索引与 manifest 仍可加载并保持状态语义。
- **实际行为**: 某个仅在禁用、失败、`success_empty` 或 US 分支发生的兼容 CSV 回归，可能在当前测试套件中不被发现。
- **直接证据**: `test_candidate_csv_retirement.py` 的生产守卫只读取源码；`_run_default_capture()` 将 `market` 和 capacity authority 固定为 `HK`，且现有调用未形成计划约定的结果矩阵。
- **影响**: 本切片尚未满足已批准计划中的 S3 明确验收项；跨市场或异常分支重新引入候选 CSV 时缺少端到端文件系统防线。
- **建议改法和验证点**: 将运行目录测试夹具参数化为真实 market/strategy enablement/status outcome，新增 US/HK × 五类结果矩阵；对每个 case 加载 sealed bundle、v2 状态索引和 manifest，并递归断言禁产 candidate/universe/reject/rank/diagnostic CSV 集合为空。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S3-CR-02-未修复-低-Combo trace 的 evidence_path 指向不存在的运行目录位置

- **入口/函数**: `run_combo_yield_scan_and_summarize()` -> `build_candidate_filter_trace_row()`
- **文件(行号)**: `src/application/combo_yield_steps.py:271`; `src/application/combo_yield_steps.py:318`
- **输入场景**: Combo Yield 产生过滤或最终选择 trace，随后审计方按 `evidence_path` 在账户运行目录中定位权威 JSON 快照。
- **实际分支**: trace 写入 `combo_yield_candidate_snapshot.json`，但 sealed snapshot 实际位于账户运行目录的 `state/combo_yield_candidate_snapshot.json`。
- **预期行为**: trace 应保存相对账户运行目录可解析的 `state/combo_yield_candidate_snapshot.json`，与 opening trace 和实际封存位置一致。
- **实际行为**: trace 的证据指针落在账户运行目录根部的不存在文件；候选权威本身未受影响，但审计链接无法直接解析。
- **直接证据**: 两处 trace builder 都直接使用 basename 常量 `COMBO_YIELD_CANDIDATE_SNAPSHOT_FILE`；Combo snapshot sealer 通过 account-run `state/` 边界写入该文件。
- **影响**: 研究或人工审计读取 trace 时会得到错误的证据位置，削弱 JSON 替代 CSV 后的可追溯性。
- **建议改法和验证点**: trace 中使用 `state/<snapshot filename>`，并在真实 Combo step 测试中断言所有 trace row 的 `evidence_path` 精确等于该相对路径。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
