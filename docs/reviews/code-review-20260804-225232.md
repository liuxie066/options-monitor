## Findings

### DR3-01-未修复-高-health quote doctor 的代表性 symbol 来自 raw watchlist，而不是 canonical effective route

- **入口/函数**: `healthcheck` -> `run_healthcheck_tool()` -> `resolve_futu_quote_route()` / `healthcheck_symbols_for_futu()` -> `run_futu_doctor(required_capability="quote")`
- **文件(行号)**: `src/application/agent_tools/healthcheck_impl.py:571-591`; `src/application/agent_tools/runtime_helpers.py:109-122`; `src/application/futu_quote_routing.py:61-112`
- **输入场景**: watchlist 使用 `use`/template 决定 effective fetch source 或 endpoint；例如第一行 raw symbol 没有内联 `fetch.source`、template 实际将它路由到非 Futu provider，而后续 symbol 才是 canonical Futu quote member。别名 source（如 `futu_api`）也会被 canonical resolver 接受但不被旧 helper 识别。
- **实际分支**: canonical route 正确调用 `apply_profiles()` 和 `resolve_symbol_fetch_source()` 得到 effective Futu members；health 随后却丢弃这些 member symbols，重新调用旧 helper。旧 helper 不展开 profiles，把缺失 source 默认成 `futu`，且只接受字面 `futu|opend`，然后选 raw 第一项。
- **预期行为**: quote doctor 的代表性 symbols 必须来自同一份 `quote_route.members` authority；只有这些 symbols 才证明 canonical endpoint 对实际 Futu workload 的 option-chain/snapshot fields 可用。
- **实际行为**: doctor 可以检查一个实际走 Yahoo/其他 provider 的 symbol，或得到空 symbol list 而跳过 field validation；与此同时真正的 canonical Futu symbol 从未被检查。READY + quote login 因而仍可能让 typed quote、legacy aggregate 和 summary false green。
- **直接证据**: route lines 69-96 展开 profile、规范化 source 并保存 effective member symbol；health line 583 没有使用这些 members；helper lines 111-120 读取 raw rows、默认 `futu`、仅做两个字面值判断并在第一项停止。`required_fields_ok()` 对空 symbols 返回 true，因此空选择也会静默跳过 field gate。
- **影响**: 健康门禁可能继续放行实际 Futu required-data/tick 所需 symbol 已无权限、缺字段或不可查询的 quote endpoint；本轮修复恢复了 doctor，却没有把 probe input 绑定到新的 canonical route 真源。
- **建议改法和验证点**: health 从 `quote_route.members` 选择非空、去重的 representative symbol（至少一个），不要再为该路径二次解析 raw config；若 canonical route 没有可检查 symbol，应 fail closed。新增 profile regressions：raw 第一项 effective non-Futu、后续 effective Futu 时 doctor 只收到后者；Futu alias 被接受；empty member 不得使 fields gate自动成功。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR3-02-未修复-中-真实 required-field failure 会被投影成“quote capability healthy”错误文案

- **入口/函数**: `run_futu_doctor_checks()` -> `run_healthcheck_tool()` -> quote/legacy check message
- **文件(行号)**: `src/application/futu_doctor.py:198-247`; `src/application/agent_tools/healthcheck_impl.py:593-607`; `tests/test_agent_plugin_smoke.py:307-324`
- **输入场景**: SDK 和 quote watchdog 成功，但代表性 symbol 的 required option fields 返回 `ok=false`。
- **实际分支**: doctor 正确返回整体 `ok=false`，但 field-only failure payload没有顶层 `message` 或 `error_code`；其 watchdog 子结果仍是成功并带 `message="OpenD quote capability healthy"`。health message precedence 在检查 overall failure 原因前优先选择 watchdog message。
- **预期行为**: status error 的 typed quote、endpoint aggregate 和 legacy aggregate message 应描述 required-field failure，至少不能宣称 capability healthy。
- **实际行为**: checks 的 status 会是 error，但 message 可显示 `OpenD quote capability healthy`。新增回归替身人为提供了真实 doctor 不会提供的顶层 `message`，因此没有覆盖实际 payload shape。
- **直接证据**: doctor lines 222-227 让 fields failure决定 overall `ok`，但 lines 229-247 没有 overall message；health lines 597-606 在 `quote_ready=false` 时仍优先取 `quote_watchdog.message`；test lines 309-324 注入顶层 message，绕开该分支。
- **影响**: operator、日志和兼容消费者收到互相矛盾的状态/文案，难以定位 entitlement/field failure，并可能误以为 error 只是投影噪声。
- **建议改法和验证点**: health 应先根据 doctor overall facts构造结果消息：SDK failure、watchdog failure、required-fields failure分别投影；仅在 overall ready 时使用成功 watchdog message。测试使用与 `run_futu_doctor_checks()` 完全一致的 field-only failure payload，并断言 typed/legacy error message 不含 `healthy` 且明确指向 required fields。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
