## Assumptions Tested

1. Close-advice already owns and calculates `close_mid`, `realized_if_close`, and `remaining_annualized_return`.
2. `realized_if_close` is net after close fees at the runner boundary.
3. Daily-brief positions accept backward-compatible mapping extensions without a schema bump.
4. Renderer can determine currency from the market-qualified brief.
5. Adding position metrics does not alter action identity or material-diff rules.
6. The proposed close-action allowlist excludes hold/unavailable rows.
7. The proposed wording remains correct when closing realizes a loss rather than a profit.

## Findings

### PR-001-未修复-中-固定写成预计锁定收益会把风险止损误报成收益
- **位置**: Success Signal and Exact changes item 6-7
- **问题类型**: 契约缺失 / 用户可见语义错误
- **当前写法**: Every actionable close detail uses `预计锁定收益` for `realized_if_close`.
- **反例/失败场景**: A legacy risk-exit or stop-loss row can have a negative `realized_if_close`. The plan would render a negative amount under a label that semantically promises locked profit.
- **为什么有问题**: `realized_if_close` is a signed net P&L compatibility field, not a guaranteed positive profit field. The existing close-advice renderer already switches to `平仓损益` for risk-exit rows, and its action label becomes `风险止损` when the value is negative.
- **直接证据**: `src/application/close_advice_runner.py:1399-1407` preserves signed gross P&L and subtracts fees into `realized_if_close`; `src/application/close_advice_runner.py:1823-1826` explicitly treats a negative value as risk stop-loss; `src/application/close_advice_runner.py:2151-2156` uses `平仓损益` for risk exits.
- **影响**: The operator can misread a loss realization as profit locked, defeating the purpose of adding decision details.
- **建议改法和验证点**: Render `预计锁定收益` only when the finite value is non-negative; render `预计平仓损益` when it is negative. Add a negative-value renderer regression with correct sign and wording.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
- **Controller decision**: accepted
