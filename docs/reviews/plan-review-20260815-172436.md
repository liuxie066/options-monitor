## Findings

### PR-01-未修复-中-额度明细时间只验非空会把畸形 provider fact 当成可审计事实
- **位置**: Plan §5 rules 4–6 and §7 required assertions
- **问题类型**: 契约缺失 / 测试缺口
- **当前写法**: `request_time` only needs to be a non-empty trimmed string; no exact format or calendar validity is required.
- **反例/失败场景**: OpenD/SDK returns `request_time="not-a-time"` or `2026-02-30 09:00:00`. The proposed gateway would normalize and return the row as usable even though the official contract defines `yyyy-MM-dd HH:mm:ss` and future W5 authorization needs an auditable seven-day quota history.
- **为什么有问题**: This is the external trust boundary. Returning a malformed timestamp as a valid normalized fact contradicts the confirmed fail-closed success signal and pushes protocol repair into the future runner.
- **直接证据**: Futu v10.9 quota documentation defines `request_time` as `yyyy-MM-dd HH:mm:ss`; plan §5 validates only non-empty text and §7 has no malformed-time assertion.
- **影响**: A later authorization path could hash/persist an invalid quota detail or add downstream loose parsing, making source capability appear green on unusable evidence.
- **建议改法和验证点**: Require exact parse-and-round-trip of `%Y-%m-%d %H:%M:%S` at the gateway, return the same canonical string, and add malformed/impossible-date cases to the fail-closed test matrix.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
