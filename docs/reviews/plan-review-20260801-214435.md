# Plan Review

## Scope

- Plan: `docs/gateflow/om-opend-runtime-boundary/plan.md`
- Work unit: `om-opend-runtime-boundary`
- Review mode: adversarial production-safety review
- Result: changes required

## Findings

### PR-01 - 未修复 - 中 - Profile-backed OpenD limits lack a fail-closed error contract

- **Risk**: The plan says Strategy Lab will load every `service.profile.json.config_paths` entry and otherwise preserve defaults, but it does not distinguish an intentionally profile-free invocation from a supplied production profile whose config is missing, malformed, or unreadable.
- **Failure mode**: A production timer could resolve the correct runtime root yet silently fall back to the library default of 10 calls when a referenced market config cannot be loaded, recreating the exact split limit contract this work unit is intended to remove.
- **Required change**: State that a supplied profile with configured paths must fail with `CONFIG_ERROR` if any referenced config cannot be loaded as an object. Defaults are allowed only when no profile config path is available. Add CLI regression coverage for the failure.

### PR-02 - 未修复 - 低 - Production path acceptance does not separate new writes from retained legacy evidence

- **Risk**: The non-goals correctly retain the stale limiter under the v1.8.2 release, while acceptance says limiter/cache state must exist only under `/var/lib/options-monitor`.
- **Failure mode**: A literal verification would fail because the intentionally retained legacy file still exists, or an operator might delete it to make the assertion pass.
- **Required change**: Verify that the new release tree creates or modifies no limiter/cache files during the canary, using pre/post path and mtime evidence; explicitly allow the unchanged v1.8.2 artifact to remain.

## Residual Risk

- Cross-process callers can still differ if they do not use the runtime profile/config contract. This work unit only closes the Strategy Lab path observed in production.
- `TimeoutStartSec` is a containment boundary, not a guarantee of successful OpenD work; provider rate limiting can still produce a clean deferred outcome.
