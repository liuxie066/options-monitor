## Findings

### SA-01-未修复-高-Malformed structured events are silently converted into complete empty evidence
- **入口/函数**: `EventStore.resolve()` -> `_normalize_fetch_payload()`
- **文件(行号)**: `src/application/events/store.py:285-312`
- **输入场景**: A provider/injected evidence fetcher returns `{"events": "unexpected", "coverage": {"earnings": {"status": "complete"}, ...}}`, or returns a list containing only non-mapping event rows.
- **实际分支**: `_clean_events()` converts the malformed value/items to `[]`, `_clean_coverage()` preserves `complete`, and EventStore persists an `ok` result with empty events and complete coverage.
- **预期行为**: Malformed event payloads must become source error/unknown evidence. They must never be eligible to prove confirmed absence.
- **实际行为**: Later Slice B would receive apparently complete empty evidence and could render “confirmed no event,” violating the core safety metric.
- **直接证据**: `_clean_events()` returns empty for non-list input and drops non-dict items; `_normalize_fetch_payload()` does not validate shape before pairing that empty list with normalized coverage.
- **影响**: False confirmed-none state at the evidence trust boundary; user may execute a Sell Put under an unknown event window.
- **建议改法和验证点**: Make structured payload parsing strict: require `events` to be a list and every item to be a mapping; invalid shape should raise and follow the existing EventStore source-error path. Add a regression asserting malformed structured evidence yields `source_status=error`, empty coverage, and is not cached as a successful absence. Legacy list fetchers should retain their current permissive compatibility only for valid mapping rows.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
