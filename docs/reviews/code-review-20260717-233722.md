### S7-CR-01-未修复-高-证据导入暴露 account/broker 过滤参数但写入时完全不应用
- **入口/函数**: `./om option-performance evidence import` → `_import_evidence`
- **文件(行号)**: `src/interfaces/cli/option_performance.py:45-58,102-147`
- **输入场景**: 操作者执行 `evidence import --file facts.json --account lx --apply`，相信只导入 `lx` 范围。
- **实际分支**: CLI 公共参数注册了 `--account/--broker`，结果 scope 也回显二者，但 `evidence_repo.import_envelope(raw, ...)` 原样导入 envelope 中所有 facts。
- **预期行为**: 写接口不得声明未执行的 scope；v1 import 应只接受 config/store 定位参数，或真实过滤并验证 envelope。
- **实际行为**: 用户可得到带 `scope.account=lx` 的成功结果，同时其他账户/券商证据也已写入。
- **直接证据**: `_add_config_scope_args(import_cmd)` 注册过滤参数；`_import_evidence` 第 127 行直接传入完整 `raw`，没有任何 fact 过滤。
- **影响**: 高风险本地证据状态写入范围与回执不一致，可能污染估值/汇率证据选择。
- **建议改法和验证点**: 将 config/store 参数与 report/capture scope 参数拆开；import 不暴露 account/broker，回执也不声称过滤。增加 argparse 拒绝测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S7-CR-02-未修复-高-费用未知时 estimated_pnl_if_close_net 被错误填成 gross
- **入口/函数**: close advice domain result → runner fee application
- **文件(行号)**: `domain/domain/close_advice.py:869-872`; `src/application/close_advice_runner.py:1369-1397`
- **输入场景**: 定价成功，但 multiplier/fee calculator 不可用或抛错。
- **实际分支**: domain 先把 `estimated_pnl_if_close_net` 设为 gross；runner 在 fee unavailable 分支直接返回并只加 flag。
- **预期行为**: gross 已知、fee 未知时，net 必须为 `null`，不能把未扣费 gross 宣称为 net。
- **实际行为**: 输出同时为 `estimated_close_fee=null` 和 `estimated_pnl_if_close_net=<gross>`。
- **直接证据**: `_result` 直接复制 gross 到 net；`_apply_buy_to_close_fee` 在 mid/multiplier/fee exception 路径不会清空 net。
- **影响**: 对外关闭收益净值高估，且显式字段之间自相矛盾。
- **建议改法和验证点**: domain net 默认 `None`；仅在 runner 成功计算 fee 后设置 net，并增加 fee unavailable 回归测试。兼容 alias 保持原窗口语义并明确其 deprecated 状态。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S7-CR-03-未修复-中-legacy as_of_ms 仍在 schema 中但 adapter 静默忽略并可能刷新当前行情
- **入口/函数**: Agent `monthly_income_report`
- **文件(行号)**: `src/application/agent_tools/positions.py` legacy input schema; `src/application/agent_tools/materialization_impl.py:713-751`
- **输入场景**: 旧调用方传 `as_of_ms` 做历史快照查询，未传 month。
- **实际分支**: adapter 未读取 `as_of_ms`，构建当前 `mtd` 请求且 `refresh_quotes` 默认为 true。
- **预期行为**: staged compatibility 至少应把历史 timestamp 映射成对应自然日的 MTD/YTD截止日并强制 historical no-live，或明确拒绝不支持参数。
- **实际行为**: 返回当前期结果，甚至可采集当前行情，属于静默时间范围漂移。
- **直接证据**: request 只读取 month/refresh_quotes；legacy schema 仍公开 `as_of_ms`。
- **影响**: 旧调用方得到错误期间和错误 freshness，难以从返回值识别。
- **建议改法和验证点**: 无 month 时将 `as_of_ms` 按 `Asia/Shanghai` 转为 `as_of_date` 的 MTD 请求，并强制 refresh false；增加 legacy historical adapter 测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
