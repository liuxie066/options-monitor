### S3-DR-01-未修复-高-检查点后的平仓再开仓可复用同一 lot_id 并覆盖历史关闭记录

- **入口/函数**: `run_position_projection_fast_if_safe()` -> `_try_fast_path()` -> new-lot collision guard
- **文件(行号)**: `src/application/ledger/position_projection_runtime.py:329-354`
- **输入场景**: full checkpoint contains active lot `L`; one fast tail closes and evicts `L` without rotating; a later append-only `open` event reuses `lot_id=L`.
- **实际分支**: tail fold starts from the older checkpoint, applies close then open, and considers `L` active again. Collision lookup excludes every id present in the checkpoint's original publication state, so it never checks the retained SQLite closed row for `L`; changed-lot DML then overwrites that row.
- **预期行为**: a derived open lot id must be unique across retained physical history. The fast path must reject/fallback on any tail open that collides with checkpoint state, another tail open, or a retained SQLite row. The full oracle must remain the authority for the resulting duplicate diagnostic.
- **实际行为**: fast mode publishes a state the full oracle rejects as `duplicate_lot_id`, destroys the retained closed-row representation, and can expose divergent positions/risk.
- **直接证据**: lines 339-342 derive collision candidates only from final touched records absent from the original checkpoint id set. A close and reopen within the suffix leaves the reused id in that original set and therefore bypasses the only indexed collision read. A focused reproduction returned `mode_used=fast_tail` and rewrote the retained row.
- **影响**: checkpoint/tail correctness and historical position-lot retention can diverge from canonical full replay under a legal append sequence.
- **建议改法和验证点**: derive candidate ids from every tail `open`, reject duplicate open ids in the suffix, and perform one indexed lookup for all unique tail-open ids; any collision with checkpoint active ids or retained SQLite rows must force full replay. Add regressions for checkpoint-open -> tail-close -> tail-reopen and open -> close -> reopen in one tail, proving rollback and full-oracle duplicate rejection.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### S3-DR-02-未修复-中-运行时会写出超过解码上限且下一次必定自我拒绝的 trusted checkpoint

- **入口/函数**: `_run_full_path()` / `_try_fast_path()` -> `_build_checkpoint_row()` -> `_decode_checkpoint()`
- **文件(行号)**: `src/application/ledger/position_projection_runtime.py:370-398,473-495,559-634`
- **输入场景**: a valid active resumable state serializes beyond `MAX_CHECKPOINT_STATE_BYTES` during a full seed or cadence rotation.
- **实际分支**: `_build_checkpoint_row()` writes any payload length as `trust_status=trusted`; no write-side bound exists. The next fast transaction rejects the same row at decode because its payload exceeds 64 MiB, marks checkpoint mode untrusted, and falls back.
- **预期行为**: runtime-generated checkpoints must satisfy their own decoder contract. A disposable cache that exceeds its capacity must fail closed without blocking or corrupting the already-canonical lot/head publication.
- **实际行为**: one successful transaction persists a checkpoint it can never consume, needlessly writes a large WAL payload, and converts ordinary valid state into global checkpoint distrust on the next run.
- **直接证据**: `_build_checkpoint_row()` records `state_bytes=len(payload)` unconditionally; `_decode_checkpoint()` rejects `len(payload) > MAX_CHECKPOINT_STATE_BYTES`. Both full seed and derived rotation call the unchecked builder.
- **影响**: large but valid account state causes deterministic cache self-poisoning and repeated full-path behavior; resource limits are enforced only after the expensive write.
- **建议改法和验证点**: apply the same size guard before checkpoint insert. If the checkpoint is too large, keep canonical lots/heads, write no checkpoint payload, and set checkpoint mode untrusted so tail use fails closed. Add a small-limit regression proving full publication commits, no oversized checkpoint is stored, and mode is untrusted.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S3-DR-03-未修复-高-检查点解码在真实可接受状态上超过冻结的 64 MiB 峰值上限

- **入口/函数**: `run_position_projection_fast_if_safe()` -> `_decode_checkpoint()` -> `_decode_accumulator()`
- **文件(行号)**: `src/application/ledger/position_projection_runtime.py:631-728`
- **输入场景**: a valid checkpoint containing 4,000 ordinary active option lots and no tail events.
- **实际分支**: strict JSON parsing retains the full decoded mapping, both state constructors deep-copy their sections, and canonical validation then calls `_encode_accumulator()` while those decoded and constructed graphs are simultaneously live.
- **预期行为**: checkpoint decode/serialization peak allocation must remain `<= max(64 MiB, 2 * payload bytes)` for accepted state; canonical integrity checks must not multiply the complete object graph beyond that frozen limit.
- **实际行为**: the measured 6,936,390-byte checkpoint reached 85,190,208 bytes peak against a 67,108,864-byte limit. The existing 3,000-lot regression passed only narrowly and did not expose the next valid scale point.
- **直接证据**: `_decode_accumulator()` keeps `decoded`, `domain_state`, and `publication_state` live, then `_encode_accumulator()` allocates complete `to_dict()` graphs and serialized bytes again. A deterministic local run reported `{'lots': 4000, 'state_bytes': 6936390, 'peak_bytes': 85190208, 'limit_bytes': 67108864, 'passes': False}`.
- **影响**: S3 fails its explicit stop condition and cannot safely be accepted; a modestly larger valid active state violates the agreed runtime memory bound before S5 activation.
- **建议改法和验证点**: validate canonical JSON bytes before building domain/publication objects, then release the top-level decoded graph as early as possible; avoid a second complete semantic re-encoding while all decoded/state graphs are live. Promote the deterministic 4,000-lot case to the focused memory regression and prove the same bound.
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### S3-DR-04-未修复-中-边界后的未知事件类型不会按契约立即废弃所有检查点

- **入口/函数**: direct/older-writer `trade_events` INSERT -> `trg_trade_events_source_insert`
- **文件(行号)**: `src/application/ledger/repository.py:465-500`
- **输入场景**: a future or otherwise unclassified `event_type` is inserted after every retained checkpoint boundary by a direct/older writer.
- **实际分支**: the trigger treats only `void` and `repair` as global invalidation. Every other type follows the ordinary prefix-intersection branch, so an appended unknown type leaves all checkpoints trusted.
- **预期行为**: the accepted mutation matrix requires every unclassified/direct mutation to invalidate all checkpoints and force the full oracle/fail-closed path.
- **实际行为**: checkpoint metadata continues to claim trust until a later runtime decodes and attempts the unsupported tail. Full replay ultimately rejects publication, but durable invalidation state and the bounded pre-decode guard are missing.
- **直接证据**: the trigger `CASE` and `WHERE` enumerate only `void`/`repair`; the supported append-safe event set is closed in `domain/domain/ledger/events.py`, but the SQL trigger has no complement branch for values outside it.
- **影响**: future-schema or malformed direct inserts repeatedly enter checkpoint selection/decode contrary to the accepted fail-closed state machine, weakening upgrade safety and diagnostics.
- **建议改法和验证点**: make the trigger's append-safe allowlist explicit; any type outside it invalidates all trusted rows with an unclassified reason. Add a direct appended-unknown INSERT regression proving all checkpoints become invalid before runtime projection.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S3-DR-05-未修复-中-现有 crash 测试没有执行任何 lot DML，未证明三类写入的事务回滚

- **入口/函数**: `test_failure_injection_rolls_back_event_lot_head_and_checkpoint()` -> `_publish_touched_projection()`
- **文件(行号)**: `tests/test_position_projection_runtime.py:741-789`
- **输入场景**: an exception occurs after an added, changed, or removed `position_lots` row has been written but before transaction commit.
- **实际分支**: the only crash fixture appends 100 `verification` events. Its projection has no touched lot records, so `apply_position_lot_diff(remove_missing=False)` performs zero add/change/remove DML before every tested failure stage.
- **预期行为**: the accepted S3 crash contract explicitly requires rollback evidence for each lot-DML class in addition to event/head/checkpoint stages.
- **实际行为**: event/head/checkpoint rollback is tested, but a future transaction-boundary regression around lot INSERT/UPDATE/DELETE would not fail this suite.
- **直接证据**: the tail list contains only `event_type='verification'`; no assertion checks the diff counters, and no test raises immediately after repository lot DML for add/change/remove.
- **影响**: the slice lacks required evidence for its main atomic-publication safety claim.
- **建议改法和验证点**: parameterize real open, partial-close, and void/full-fallback scenarios; wrap the existing repository diff method to call the real DML, assert the expected counter is one, then raise. Verify events, lots, heads and checkpoints exactly match their pre-transaction state.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
