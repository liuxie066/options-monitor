### S5-CR-01-已修复-中-持股在 Covered Call 存续期内卖出仍被当作完整 covered attribution
- **入口/函数**: `project_assigned_stock_lifecycle()` 调用 `_attribute_covered_calls()`。
- **文件(行号)**: `domain/domain/assigned_stock.py`，`_attribute_covered_calls` 的候选股数和 reservation 逻辑。
- **输入场景**: assigned-stock lot 在 call open 时有 100 股；随后 call 尚未关闭时先卖出 100 股；as-of 时 call 仍 open 或之后才关闭。
- **实际分支**: 代码只用 `_lot_shares_at(lot, opened_at)` 检查 call 开仓瞬间股数，再记录 `[opened_at, reservation_end)` reservation；sale rows 不会反向校验 reservation interval 内的剩余股数。
- **预期行为**: 只有在整个 call coverage interval 内持续有足够 assigned-stock shares 时才能归因；中途 sale 使 coverage 失效时应 fail closed，输出 review row，且不把该 call economics 归给 assigned-stock lifecycle。
- **实际行为**: call 仍获得 `explicit` 或 `derived_fifo` attribution，`covered_call_pnl` 和 lifecycle quality 可能显示完整/已标记，尽管 stock 在 call 关闭前已卖出。
- **直接证据**: 可用股数只在 call `opened_at` 计算；sale processing 已在 call attribution 之前完成，但 `_active_reserved_shares` 仅防重叠 call，不检查 sale timestamp 是否落在 reservation interval 内。
- **影响**: 错误收益归因和错误 lifecycle quality；把实际上已变成 naked/unsupported 的 call 当作 covered call。
- **建议改法和验证点**: 为每个 candidate lot 计算 coverage interval 内的最小可用股数，扣除 interval 内 sale 与已有 reservations；不足时输出 `covered_call_unallocated`/更具体 conflict diagnostic。增加 “call open -> stock sale -> call close/as-of” 回归测试，并保留 overlapping calls no-double-attribution 测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### S5-CR-02-已修复-中-Stock settlement cash fee 忽略 fee provenance，把 estimated fee 当 observed cash
- **入口/函数**: `build_option_period_performance()` -> `_stock_settlement_facts()`。
- **文件(行号)**: `domain/domain/performance/engine.py`，`_stock_settlement_facts` fee parsing 分支。
- **输入场景**: assignment `stock_settlement` 含 `fees=1` 且 `fee_provenance.basis=estimated`，或历史零费用没有 actual provenance。
- **实际分支**: 只要 `fees`/`fee` 可解析且非负，就直接生成 amount `-fee`、无 missing reason；没有检查 `fee_provenance`。
- **预期行为**: production cash/net fee 只把 actual（包括 explicit actual zero）当 observed；estimated/missing 应保留 principal gross，但 fee cash/total cash quality 为 partial，不能伪装成实际现金。
- **实际行为**: `cash.stock_settlement_fee_cash` 和 `total_cash_change_net` 把估算金额作为 observed 值；与此同时 assigned-stock PnL path 正确地把非-actual fee 视为 partial，造成同一 fee evidence 在 cash 与 PnL 语义不一致。
- **直接证据**: `_stock_settlement_facts` 直接读取数值；`_assigned_stock_period_facts` 则通过 `_actual_fee_amount` 要求 `basis == actual`。
- **影响**: 现金统计错误地提高完整性，历史或人工估算费用被展示为真实现金变动。
- **建议改法和验证点**: 统一解析 stock settlement `fee_provenance`；actual amount（含 0）生成 observed fee cash，estimated/missing 生成 missing amount 和明确 reason。增加 actual zero、estimated、missing 三组 cash/total-cash quality 测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
