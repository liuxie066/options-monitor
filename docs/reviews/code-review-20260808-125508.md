## Findings

### 1-未修复-高-`covered_notional` 用可卖股数而非合约覆盖股数，严重低估收益率
- **入口/函数**: `run_cc_lp_scan`
- **文件(行号)**: `src/application/cc_lp_steps.py:173-175`
- **输入场景**: 账户持有 1000 股、可卖 1000 股，CC+LP 配对 1 张 call（multiplier=100）
- **实际分支**: `covered_notional = spot * int(min(shares_total, shares_can_sell)) = spot * 1000`
- **预期行为**: 与现有 Covered Call 一致，`covered_notional = spot * multiplier = spot * 100`（1 张合约覆盖股数）
- **实际行为**: 分母大 10 倍，`net_return` 被低估 10 倍，排序和门槛失真
- **直接证据**: `covered_call_strategy_risk.py:142-155` `_covered_notional_cny` 用 `spot * multiplier`；`cc_lp_steps.py:173-175` 用 `min(shares_total, shares_can_sell)`
- **影响**: 组合收益率系统性低估、排序错误、可能误淘汰/误选候选
- **建议改法和验证点**: `covered_notional = float(call_leg.spot) * float(call_leg.multiplier)`（1 张合约）；新增测试断言 `net_return == net_credit / (spot * multiplier)`
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-中-`strategy_family=cc_lp` 与 pipeline/snapshot 消费端不一致
