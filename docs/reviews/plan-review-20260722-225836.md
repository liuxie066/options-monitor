## Findings

### PR-20260722-R2-01-未修复-高-美国期权费率缺少账户平台套餐事实却被标记为 exact
- **位置**: 计划 4.1 US fixed-package calculation、4.2 `fee_calc_status` 和 USD rule、S1 tests
- **问题类型**: 契约缺失 / 最佳实践偏离 / 不可直接实施
- **当前写法**: 计划固定使用 `0.30/contract` 的 ordinary fixed platform fee，并把 USD 结果标记为 `exact`。
- **反例/失败场景**: 账户已切换到 Futu tiered platform package；前 50 张平台费为 `0.60/contract`，而计划仍计算 `0.30/contract` 并对外声明 exact。边际平仓会低估费用并可能继续 actionable。
- **为什么有问题**: 官方费率页明确同时提供 fixed 和 tiered platform packages，并说明用户可以切换；当前 PositionLot/Close Advice 输入没有账户 fee-package 字段。没有这个事实就无法声称整笔费用精确。
- **直接证据**: 计划 `:81-92,108-118`；`domain/domain/fee_calc.py:50-74` 只有固定平台费参数且无 account/package 输入；Futu 官方 US fee page 的 4.2.1/4.2.2 同时列出 fixed 与 tiered packages。
- **影响**: public diagnostic 夸大费用可靠性；fee fail-closed gate 可能基于低估费用放行边际动作，违反本 work unit 的安全目标。
- **建议改法和验证点**:
  - 不增加 config 或 fee-package 模型；将 USD 状态改为 `schedule_estimate`，basis 明示 `futu_us_fixed_package_2026-07-22`。
  - 将 `schedule_estimate` 与 HK `conservative_estimate` 明确列为本 work unit 可用于 gate 的两种 estimate；`exact` 保留给未来有账户套餐/实际费用事实的路径，或从本批枚举中删除。
  - 测试断言输出不会把 fixed-package assumption 标为 exact。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### PR-20260722-R2-02-未修复-高-unknown lifecycle 仍可能通过 quote dte 回退进入普通策略评估
- **位置**: 计划 4.4 `unknown` row、4.5 `_calc_dte()` contract、S2 exact changes/tests
- **问题类型**: 状态机漏洞 / 契约缺失 / 测试缺口
- **当前写法**: 计划要求 lifecycle 只由 canonical expiration 和 run business date 决定，但对 `unknown` 仅写“preserve existing fail-closed behavior”，没有明确禁止行情 `dte` 回退。
- **反例/失败场景**: PositionLot expiration 缺失或格式非法，但 required-data quote 带 `dte=20` 和完整价格。classifier 给出 `unknown`，随后现有 `_calc_dte()` 从 quote 取 20，domain 将它当 active row 并可能生成 strong/medium close action。
- **为什么有问题**: 这绕过了计划声称的 canonical expiration 单一权威，而且 existing behavior 并不保证 fail-closed。
- **直接证据**: `src/application/close_advice_runner.py:1039-1046` 捕获缺失/非法 expiration 后直接返回 `quote["dte"]`；计划 `:145-162` 没有删除此 fallback 的明确 decision/test。
- **影响**: 生命周期不明的持仓仍可产生 actionable 决策；不同 quote artifact 可让同一 lot 在 active/unknown 之间漂移。
- **建议改法和验证点**:
  - 明确 `_calc_dte(expiration, business_date)` 不再接收 quote，也绝不使用 quote DTE 决定 lifecycle/action。
  - `unknown` 必须稳定进入已有 `not_evaluable` 数据缺口契约；可继续尝试覆盖诊断，但不得运行经济/策略 action evaluation。
  - 添加 malformed/missing canonical expiration + positive quote DTE 的反例，断言仍为 `position_lifecycle_state=unknown`、`close_action=not_evaluable`。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
