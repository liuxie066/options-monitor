### ADR-01-未修复-中-新增通知依赖未同步生成的架构图，仓库确定性质量门禁失败
- **入口/函数**: `tests/test_dependency_graph_generator.py::test_dependency_graph_generator_check_passes` -> `scripts/generate_dependency_graph.py --check`
- **文件(行号)**: `tests/test_dependency_graph_generator.py:13-22`; generated targets `docs/DEPENDENCY_GRAPH.md`, `docs/dependency_graph.mmd`
- **输入场景**: 在当前分支或 CI 中运行依赖图 freshness 检查。
- **实际分支**: generator 根据当前生产模块/import graph 生成期望内容，并发现两个已提交 generated files 与期望结果不同。
- **预期行为**: architecture-sensitive notification refactor 应提交与当前 import graph 一致的 generated dependency evidence，且 `--check` 返回 0。
- **实际行为**: 命令返回 1，并分别报告 `docs/DEPENDENCY_GRAPH.md` 与 `docs/dependency_graph.mmd` stale。
- **直接证据**: 聚合复现中 `test_dependency_graph_generator_check_passes` 失败；直接运行 `python3.12 scripts/generate_dependency_graph.py --check` 输出两个 `[DEPENDENCY_GRAPH_ERROR] generated file is stale`。
- **影响**: 确定性仓库质量门禁失败，reviewer/CI 无法确认新增 `notification_shells` 及通知链依赖是否已被架构证据覆盖；不是运行时消息错误，但会阻止可验收提交。
- **建议改法和验证点**: 使用现有 generator 重建两个文件，检查 diff 仅反映真实模块/import 变化；随后运行 generator `--check`、对应 pytest 和 cycle/boundary 检查。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
