### 1-未修复-中-`net_debit` 字段在 `CcLpMetrics` 中被计算但从未被门槛/排序使用，属于死字段
- **入口/函数**: `compute_cc_lp_metrics`
- **文件(行号)**: `domain/domain/engine/cc_lp.py:99-100`（`net_debit` 计算）
- **输入场景**: 任何 CC+LP 候选（净 debit 时 net_debit > 0）
- **实际分支**: `net_debit = max(-net_credit, 0.0)` 总是计算
- **预期行为**: 净 debit 应被保留率门槛拒绝（保留率 > 0），或至少在指标中显式暴露供排序/门槛使用
- **实际行为**: `net_debit` 写入 dataclass 但 `validate_cc_lp_pair` 不检查、`cc_lp_rank_key` 不消费，纯死字段
- **直接证据**: `cc_lp.py:99-100` 计算；`validate_cc_lp_pair`（仅校验 delta/结构）和 `cc_lp_rank_key`（仅用 retention/delta/spread/OI）都不读取 net_debit
- **影响**: 保留率已隐含拒绝净 debit（retention < 0 → 排序靠后），但死字段让指标语义不清，后续可能误用；若净 debit 组合恰好 retention 计算为 0.0（call_net_credit=0 时 retention=0.0），会绕过"> 0"约束
- **建议改法和验证点**: 在 `compute_cc_lp_metrics` 中，若 `call_net_credit <= 0` 应拒绝（资金腿必须正权利金），并保留 `net_debit` 作为显式诊断字段供 Slice 2 门槛使用；或在指标中删除 net_debit 直到有消费者
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
