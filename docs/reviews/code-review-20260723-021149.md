## Findings

### 1 — fixed — high — readiness could accept future strategy or replacement evidence

- **Path**: captured episode -> `summarize_close_decision_readiness()` ->
  promotion-usable episode set.
- **Failure**: the first readiness implementation checked that strategy and
  replacement timestamps were non-empty but did not parse or compare them to
  the decision timestamp. A manually corrupted or externally produced close
  facet could therefore pass readiness with hindsight evidence, even though the
  canonical capture path would reject it.
- **Fix**: parse timezone-aware timestamps in readiness and require decision
  quote, strategy context, and replacement source time to be no later than the
  decision. Invalid, naive, or future timestamps are incomplete and remove the
  episode from promotion coverage.
- **Coverage**: future decision quote, strategy context, and replacement run
  regressions plus missing and valid replacement provenance boundaries.

### 2 — fixed — medium — readiness lacked durable strategy/replacement time provenance

- **Path**: `capture_close_decision_episodes()` -> close episode -> readiness.
- **Failure**: S3a validated position context and same-run reallocation timing
  but discarded the proof. S3c could not independently distinguish a valid
  decision-time join from a later replacement artifact.
- **Fix**: persist `strategy_context_at_utc`, its explicit time basis, and
  replacement source run ID/time. Provenance is observational metadata and is
  deliberately excluded from the material decision fingerprint so identical
  same-day ticks still deduplicate.
- **Coverage**: canonical capture asserts the exact retained provenance; P3
  readiness requires it only when `review_switch` makes replacement relevant.

### 3 — fixed — medium — data-plan receipt time could downgrade fresh marks

- **Path**: `run_shadow_replay_data_plan()` -> collection -> mark provenance.
- **Failure**: the plan's generated/receipt time was passed into collection as
  `as_of`. The collection boundary correctly interprets an explicit `as_of` as
  operator-asserted historical time, so even a fresh OpenD collection became
  unusable for promotion.
- **Fix**: data-plan collection no longer supplies an asserted `as_of`; the
  collector records the actual source collection time. Receipt time remains
  separate plan metadata.
- **Coverage**: the data-plan regression verifies `as_of=None` at the
  collection boundary.
