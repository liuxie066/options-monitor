## Finding re-review

### S1-DR-01 — fixed

The semantic implementation result is constructed and frozen at module load.
Publication and read transactions consume the frozen tuple only. A regression
causes all later `Path.read_bytes()` calls to fail and proves that publication
performs no transaction-time source read.

### S1-DR-02 — fixed

Account discovery reads only durable heads and unions the current diff's known
and touched accounts. Event INSERT and projection-affecting UPDATE triggers
create zero-lot heads. SQL trace coverage proves discovery reads neither
`trade_events` nor `position_lots`.

### S1-DR-03 — fixed

The trusted reader checks source/head/schema metadata first inside one read
transaction and only then streams the requested account rows. A stale
generation regression replaces the snapshot reader with an exception and
proves rejection occurs before lot decoding or hashing.

### S1-DR-04 — fixed

The purpose-specific `(account, record_id)` index serves canonical fingerprint
order without a temporary B-tree. Query-plan coverage requires that index and
rejects `TEMP B-TREE`.

### S1-DR-05 — fixed

The publication path has a required repository protocol and no legacy fallback.
Every projecting transaction validates that protocol before opening its
callback or performing event/lot DML. Static writer inventory and runtime
zero-write regressions cover both boundaries.

### S1-DR-06 — rejected with regression evidence

Keeping `list_position_lots()` ordered by `record_id DESC` preserves the
observable ordering of the previous full-replacement implementation, where all
rows received the same publication timestamp. Restoring nominal
`updated_at_ms DESC` priority under exact diff changed close-target selection
and failed two existing resolver/rollback regressions. No ordering change is
accepted in S1.
