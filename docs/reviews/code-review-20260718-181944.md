## Findings

### CR-01-已修复-中-隔离 residual tail 在 PnL 证据缺失时仍宣称 observed
- **入口/函数**: `build_period_performance -> build_strategy_attribution -> _group_report -> _residual_tail`
- **文件(行号)**: `domain/domain/performance/strategy_attribution.py:434-468`
- **输入场景**: 报表窗口完全位于 Funding Put 全量关闭之后，因此 `isolated=True`；Participation Call 仍在持仓，但报表 opening 或 ending valuation mark/fee evidence 缺失，使 `call_pnl.period_total_gross` 或 `period_total_net` 为 `partial`/`not_observed`。
- **实际分支**: 第 461 行直接把整个 `call_pnl` 赋给 tail；第 468 行仅由 `isolated` 决定 `quality.status`，忽略被返回 PnL envelope 的状态。
- **预期行为**: 窗口隔离只证明时间归属可以切分，不证明价格/费用证据完整。只要 tail PnL 的必要 metric 不可观察，tail quality 必须 fail closed 为 `partial` 并给出明确 metric issue；未知 Call residual value 不得与 `observed` quality 并列。
- **实际行为**: 返回的 tail 可以同时包含 `pnl.period_total_net.status=not_observed` 和 `quality.status=observed`。
- **直接证据**: `_pnl_report` 会在无 opening/ending mark facts 时生成 `not_observed` envelope；`_residual_tail` 第 468 行不读取这些 envelope，只检查 `period.effective_start_at_ms >= tail_start`。
- **影响**: 管理归因消费者可能把不可计算的 residual Call 收益误判为已观察，违背 fail-closed 和“未知不按零处理”产品边界。
- **建议改法和验证点**: 为 isolated tail 检查 `period_total_gross`、`period_total_net` 状态；任一不是 `observed` 时 quality 为 `partial`，issues 包含稳定的 metric/status 标识。增加“Put 已关闭、Call 仍开仓、无 valuation marks”的回归测试，并保留已有双边界 marks 时 observed 的测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### CR-02-已修复-中-assigned-stock Combo provenance 冲突和缺失可被静默丢弃
- **入口/函数**: assigned-stock projection rows `-> _assigned_stock_fact_kwargs/_append_stock_capital_segment -> _assigned_stock_attribution`
- **文件(行号)**: `domain/domain/performance/engine.py:1220-1248`
- **输入场景**: (a) `strategy_snapshot.strategy` 或 `expiry_structure` 与 top-level 同名字段均非空但不一致；(b) top-level/snapshot 指示 `strategy=combo_yield`，但 `strategy_group_id` 缺失；(c) 普通非 Combo assigned-stock row 带有自己的非 Combo metadata。
- **实际分支**: 仅 `strategy_group_id` 冲突在 1228 行被检查；`strategy`/`expiry_structure` 使用 `snapshot or row` 静默选值。若 group 缺失，第 1234-1235 行无条件返回 `(None, ())`，即使 strategy 已明确指示 Combo。若非 Combo row 有 group，第 1237-1238 行又产生 Combo attribution unavailable issue。
- **预期行为**: 复用已接受的 snapshot-first/top-level-fallback contract：相关非空 metadata 冲突必须从 management attribution fail closed 并进入 coverage；明确指示 Combo 但缺 group 必须产生 attribution-unavailable/incomplete issue；普通非 Combo assigned stock 仍应是 observed-empty，不因不支持的 management grouping 降级。
- **实际行为**: 部分冲突被 snapshot 静默覆盖，Combo 缺失 group 被静默丢弃，非 Combo metadata 反而可能制造 coverage issue。
- **直接证据**: event attribution 在 `domain/domain/performance/attribution.py` 对 `strategy/leg_role/strategy_group_id/expiry_structure` 全部执行冲突检查；assigned-stock path 只检查 group，并在确认 Combo indication 之前提前返回或报错。Accepted plan `docs/gateflow/cross-expiry-yield-capital-attribution-plan-20260718.md:287-289` 要求 snapshot-first fallback、非空冲突 fail closed、canonical totals 不受影响。
- **影响**: assignment 后的组合连续性可能在 metadata drift 时悄悄消失，coverage 错误地显示完整；同时普通非 Combo 报表可能被不必要降级。
- **建议改法和验证点**: 先解析并比较 `strategy`、`leg_role`、`strategy_group_id`、`expiry_structure`；再判断是否明确指示 Combo。Combo conflict/incomplete 返回稳定 issue，非 Combo 返回 `(None, ())`。增加 strategy/expiry conflict、Combo missing group、ordinary non-Combo 三组 focused tests，并确认 canonical facts/capital totals不变。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
