独立复核要点（均沿真实代码路径直接证据，非 finding；与前序 review 结论一致并经本 pass 重新验证）：

1. **Request contract 闭合**。`get_exact_expiration_close()` 先经 `_normalize_exact_expiration_close_request()` 校验（`futu_gateway.py:884-892`），非法输入在 `_quote_client()` 获取之前经 `_raise_mapped` 抛出，不会触达 OpenD（测试 `tests/test_futu_gateway_minimal.py:520-545` 以 `_ensure_quote_client` 计数断言 0 次访问）。请求经 `_normalize_history_kline_kwargs()` 发送 `code/start=end/ktype=K_DAY/autype=NONE/fields=[time_key,close]/max_count=2` 并显式补 `page_req_key=None`（`futu_gateway.py:896-909`）；`_futu_enum_value()` 将 `time_key` 映射为 `KL_FIELD.DATE_TIME`（`futu_gateway.py:1174-1176`），与 SDK `pack_req` 的 `KL_FIELD.kl_fields_to_flag_val`/`KLType.to_number`/`AuType.to_number` 消费链一致（`quote_query.py:954-963`）。`normalize_start_end_date(start,end,365)` 对同日起止只做格式校验，不会扩展窗口（`common/utils.py:93-99`）。
2. **SDK 返回形状与 pagination 语义自洽**。SDK 成功返回 `(RET_OK, DataFrame, next_page_req_key)`，DataFrame 列固定为 `code,name + 请求字段`（`open_quote_context.py:399-411`）；`max_count` 循环在 `len(list_ret)>=max_count` 时立即 `data_finish=True` 并把残余 `has_next` 暴露为 `page_req_key`（`open_quote_context.py:385-398`），因此 `max_count=2` 只做 cardinality guard、任何非空 continuation 即证明不完整，实现"非空 key 即 fail closed"（`futu_gateway.py:1033-1034`）与之自洽。空成功返回为 `pd.DataFrame([], columns=col_list)`，列仍存在，故"带必需列的零行 frame 返回 `None`"与"plain list/缺列 fail closed"的 empty-vs-malformed 区分成立（`futu_gateway.py:1041-1059`）。
3. **数据绑定校验覆盖 code/date/cardinality/price**。行 `code` 去空格大写后必须等于请求归一 code（`futu_gateway.py:1067-1074`）；`time_key` 只接受 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM:SS` 两种规范形、`strptime`+`strftime` round-trip 且日期等于 expiration（`futu_gateway.py:1076-1091`），`T` 分隔、任意后缀、非法日历日均被拒绝；`close` 必须非布尔 `Real`、有限且 >0，字符串/零/负/NaN/inf 全部 fail closed（`futu_gateway.py:1093-1100`）。SDK 端 blank bar 在 unpack 时即 `continue` 不落行（`quote_query.py:995-996`），不会以零/缺 close 形式进入校验。
