## Reviewed target and scope

- Daily Brief canonical lifecycle 与 user projection 的边界；
- candidate/action 用户语义和现有 stable action identity 的兼容；

## Plan claims verified

1. **不会以关闭 Daily Brief 解决展示问题**：plan 明确保留 revision、diff、repository、confirmation pointer、read tools 和 audit，并禁止 `daily_brief.enabled=false` 成为长期修复。
2. **用户语义与 persisted compatibility 已解耦**：opening action 继续作为 v1 stable lifecycle carrier，但 diff vocabulary 和 renderer 一律归类为 candidate；这避免了同日 schema 语义切换和 rollback false-add，同时解决用户看到“新增行动”的问题。
3. **新展示不依赖 legacy text parser**：现有 renderer 作为 public facade，内部建立 allowlist view → pure renderer 两段边界；旧 compact formatter 仅作为视觉参考。
4. **self-contained payload 不改 delivery state machine**：repository 仍产生 `full/delta/none` 和相同 delivery key；delta 仅是 backend event，用户 payload 是 change banner + current snapshot。
5. **capacity 已按真实 scope 修正**：不再把 first-known candidate capacity 称为全账户统一上限；Sell Put 按具体 strike、Covered Call 按 symbol 展示，且明确共享资金不可相加。
6. **同一变化不会重复计数**：eligibility/state/priority transition 优先于 candidate capacity change；top-level first-known capacity 不再作为 material trigger。
7. **changed item 与消息长度边界已定义**：changed items 优先进入 section；超出 global hard cap 时显式汇总，不静默丢失变化对象。
8. **结构化状态足够支持人类原因映射**：plan 要求将 `evaluation_status/quote_status` 纳入 position view，避免解析自由文本 reason。

## Special review lenses

### Architecture boundary review

**通过。** Canonical brief/repository/delivery 仍拥有状态与事实，renderer 只做受控 projection；legacy text、Markdown 和 broker symbol 不成为中间协议。保留 opening lifecycle carrier 而只调整 user semantics，是比同日迁移 persisted v1 更安全的边界选择。

### Best-practices review

**通过。** Plan 保留 last-confirmed comparison、transport idempotency、no-material early exit、quiet-hours/no-send 不推进 pointer，并增加 DST、unknown status、old/new vocabulary、rollback 和 changed-item truncation tests。展示采用 allowlist 而非黑名单。

### Optimal-solution review

**通过。** 相比两个替代方案：

- 完全回退 legacy notification 会丢失 lifecycle；
- 从 v1 `actions` 直接删除 opening records 会引入同日 version skew 和 rollback false-add；

当前方案以最小 semantic correction 保留 stable identity，在 diff/renderer 层改正用户术语，是当前约束下更实际、更可回滚的路径。彻底 schema 清理被正确拆为未来独立 work unit。

### Overengineering review

**通过。** Plan 没有新增 DB、发送栈、模板 DSL、配置开关、执行 planner 或第二套 candidate diff engine。现有 renderer facade 内增加 view builder 与 pure renderer 足够，不需要通用 presentation framework。

### Overcoupling review

**通过。** Diff 负责 material facts，projection 负责用户分类，renderer 负责布局，repository 负责 delivery state；没有把 legacy parser、canonical mapping、transport 或 config 混成单一层。Development slices 虽有关联，但 release/rollback 被明确为整体单元。

## Findings

**没有发现需要阻止 implementation 的 material finding。**

上一轮的四个 high blockers 已被关闭：

1. rollback boundary 已锁定；
2. candidate/action 用户语义已收敛，同时保留 v1 stable identity；
3. structured projection ownership 已明确，禁止 text round-trip；
4. self-contained payload 与 delta delivery/idempotency 已解耦并给出 failure-path tests。

上一轮 medium 时间语义问题也已关闭：默认只展示 localized data-as-of，不把 `valid_until_utc` 表达成报价保证。

## Open questions

以下问题不阻塞 implementation，但实施时必须按 plan 的 fail-closed 规则处理：

1. Repo-wide preflight 是否发现 repo 外 consumer 将 diff change type 当 closed enum？如发现，必须停止并设计 versioned contract，不能继续扩展 v1 enum。
2. Representative production fixture 中是否存在缺少 explicit expiration/strike、但只有 broker symbol 的 candidate？Plan 已规定显示“合约信息不完整”，不得为追求完整度重新解析 broker code。
3. 通知渠道的实际 character limit 是否低于现有 `_MAX_MESSAGE_CHARS=12_000`？若 provider 有更低限制，应收紧 renderer hard cap，不修改 delivery semantics。
4. Position status 是否还有 `coverage_missing / quote_unusable / unavailable / not_evaluable / error / blocked / priced` 之外的生产值？未知值必须走 generic fallback，不临时透传 reason code。

## Residual risks and suggested tracking destination

### R1 — External consumer enum compatibility

- **Risk**: repo 外 consumer 可能对 `daily_decision_brief_diff.v1` change types 使用 closed enum。
- **Mitigation in plan**: implementation preflight 必须 inventory；发现后停止并改做 versioned contract。
- **Tracking**: implementation Gateflow preflight evidence + release notes。

### R2 — Notification volume after candidate-scoped capacity diff

- **Risk**: 现金变化可能使 `candidate_capacity_changed` 比旧 first-known aggregate 更频繁。
- **Mitigation in plan**: 只比较 contracts integer、transition precedence 去重、price/metric/rank changes 静默。
- **Tracking**: canary/首个交易日的 `daily_brief.prepared` delivery-kind counts；如噪音过高，另开 policy work unit，不在 renderer 临时 suppress。

### R3 — Copy quality is fixture-sensitive

- **Risk**: 技术契约正确但中文信息密度仍可能不如预期。
- **Mitigation in plan**: representative rendered snapshot inspection；示例已固定标题、候选、持仓、条件容量和 recovery banner 信息层次。
- **Tracking**: implementation acceptance fixtures + CEO final visual sign-off before release。

### R4 — Structured audit remains intentionally detailed

- **Risk**: Agent/CLI structured facts 仍含 lot/group/leg identity；若上层模型无选择地复述 JSON，内部字段仍可能被带回用户回答。
- **Mitigation in plan**: `rendered_markdown` user-safe；structured facts 保留是 audit requirement。
- **Tracking**: Agent prompt/tool presentation policy follow-up；不应在本次通知 renderer 中删除 canonical identity。

## Validation required during implementation

Plan 已列出正确的 focused/broader tests。Implementation review 还应特别核实以下 assertions 没有被“改测试迎合实现”：

- canonical opening action identity 在 upgrade/rollback fixture 中保持相同；
- opening transition 的 diff type 从 user semantics 看是 candidate，不是 action；
- old code compatible fixture 不产生批量 false add/invalidation；
- `candidate_capacity_changed` 不与 invalidated/priority transition 重复；
- first-ranked candidate 变化不触发伪 aggregate capacity change；
- delta envelope 的 key、from-digest、confirmation pointer 与改版前完全相同；
- changed items 超 section soft limit 时仍可见，超 global cap 时有明确 omitted count；
- `rendered_markdown` 不含 IDs/raw values，但 structured `brief` 仍保留审计字段。
