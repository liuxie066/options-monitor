### 1-未修复-高-Daily Brief 重算通知资格时绕过 `max_items_per_account`，会重新暴露已被 Close Advice 生产选择淘汰的平仓动作
- **入口/函数**: `run_close_advice()` -> `_selected_notify_rows()` -> `close_advice.csv` -> `assemble_daily_decision_brief()` -> `_position_views()`
- **文件(行号)**: `src/application/close_advice_runner.py:1915-1929,2736-2746`; `src/application/daily_decision_brief_service.py:92,340-353,2200-2233`; `src/application/daily_decision_brief_renderer.py:884-898`; `tests/test_daily_decision_brief_service.py:527-611`
- **输入场景**: 同一账户存在 3 条已定价的 `strong` Close Advice 行；`close_advice.notify_levels=["strong","medium"]`，同时使用配置校验器明确支持的 `close_advice.max_items_per_account=1`；Daily Brief 保持默认 `max_actions_per_priority=5`。
- **实际分支**: Close Advice runner 先排序，再由 `_selected_notify_rows()` 按账户截取 1 条，因此正式 `close_advice.txt` 和 `notify_rows` 只有 1 条；但它仍把全部 3 条写入 `close_advice.csv`。Daily Brief 随后不消费 runner 已形成的 exact selection，而是仅用 `tier in notify_levels` 重新计算 `notification_eligible`，把 3 条全部加入 `actions` 并标为可展示。renderer 看到 3 条 eligibility 都为 true，会把 3 条全部计入“需处理”，并在默认 5 条预算内全部展示。
- **预期行为**: Close Advice 对本轮哪些 lot 进入通知的 exact selection 应是单一事实；Daily Brief 可以保留全部持仓用于总数和审计，但只能把 runner 实际选中的 lot 投影为 actionable details。
- **实际行为**: 同一 run 的专用 Close Advice 报告只通知 1 条，而 Daily Brief 报告 3 条“需处理”，再次产生两个用户可见通知面口径不一致；`brief.actions[]` 也会持久化 3 条动作。
- **直接证据**: runner 在 `1917-1929` 同时执行 `evaluation_status=="priced"`、tier gate、排序和 per-account `max_items` 截断；`2739-2746` 从同一 `close_advice` 配置读取 `max_items_per_account` 并形成 `selected_notify_rows`。新 helper 在 `2200-2223` 只读取 `notify_levels` 和 tier，完全没有 `max_items_per_account`、排序或 exact selected key；组装循环在 `340-353` 因此把所有同 tier 行加入 actions。确定性复现输出为 `{'runner_selected': ['S0'], 'brief_eligible': ['S0', 'S1', 'S2']}`。现有新增测试只覆盖 tier 集合切换，没有覆盖 `max_items_per_account` 或 producer/consumer selection equality。
- **影响**: 合法的限流配置会被 Daily Brief 绕过，用户看到超过配置上限的“需处理”平仓建议；专用报告、filter trace、持久化 Daily Brief actions 和最终飞书消息对同一批持仓给出不同 selection，削弱通知审计与操作信任。
- **建议改法和验证点**:
  - 让 Close Advice producer 在结构化 artifact/manifest 中发布 exact selected lot keys 或逐行 selection status，Daily Brief 只消费该事实；或者把包含 `evaluation_status`、排序、tier 和 `max_items_per_account` 的完整 selector 收束为双方复用的公共契约，禁止 Brief 只重算 tier。
  - 全部持仓仍进入 `positions`，只有 exact selected keys 获得 `notification_eligible=true` 并进入 active close actions；evaluation gap 继续走独立的 typed gap/blocked evidence 路径。
  - 增加端到端回归：同账户 3 条 strong + `max_items_per_account=1` 时，runner `notify_rows`、Daily Brief close actions、`position_actionable_total` 和渲染明细都必须为同一 1 条；另覆盖 `max_items_per_account=0` unlimited、非 priced row、以及多账户各自截断。
