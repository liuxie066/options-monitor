### CR-S1-02-未修复-中-同一策略范围的多个合约原因仍由首个合约锁定而非全范围确定性选择
- **入口/函数**: `candidate_universe_summary()` contract-scope loop
- **文件(行号)**: `src/application/opening_candidate_snapshot.py:690-718`
- **输入场景**: 同一 symbol/mode 有两个 unresolved-only contract scopes，各自带不同具体 nested reason；策略 scope
  只有通用 `partial_data`。
- **实际分支**: 第一个 contract 将通用 strategy entry 替换为自己的具体原因；第二个 contract 看到 existing reason
  已不在 generic 集合，因而不能参与选择。
- **预期行为**: 按 accepted plan，对同一 symbol/mode 的所有具体原因聚合，并从全集选择字典序第一项，结果不依赖
  contract symbol/expiration 的 scope 顺序。
- **实际行为**: 最终原因等于 snapshot 中第一个 contract 的原因。虽然 snapshot 排序使结果可重复，但它不是计划定义的
  reason-level deterministic selection，新增/改名一个较早排序的合约会无关地改变报告原因。
- **直接证据**: 709 行计算单个 contract reason；710-718 行只在 existing 为通用原因时赋值，第一次赋值后后续
  contract 被跳过。当前测试只覆盖一个 NVDA contract scope。
- **影响**: 多合约同时缺证据时，Daily Brief 可能选择任意较早合约的次要原因，诊断文案不稳定地偏离 sealed
  reason 集合的明确选择规则。
- **建议改法和验证点**: 先按 `(symbol, mode)` 聚合所有 unresolved-only contract reason，再在 contract loop
  结束后对每组做 `sorted(reasons)[0]`；仍只替换通用 strategy reason。新增交换 contract scope 顺序的回归。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
