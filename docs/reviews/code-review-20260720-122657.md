## Findings

### DR-01 — 中 — Material change 可以指向被展示上限省略的候选或错误的同标的持仓

- **Entry point**: `render_daily_brief_lifecycle() -> build_daily_brief_user_view() -> _candidate_views() / _position_views()` in `src/application/daily_decision_brief_renderer.py`.
- **Triggering input**: a material diff changes an eligible candidate ranked below `max_candidates_per_strategy`, removes a candidate that is no longer present in the current brief, or changes one position lot while more than the position limit share the same symbol.
- **Actual branch**: `_candidate_views` ignores `diff` and slices each family strictly by existing row order; `_position_views` only promotes all rows sharing a changed symbol and then slices by the soft limit; invalidated candidate summaries aggregate only a count and do not use the structured contract fields already carried in the diff.
- **Expected behavior**: the accepted projection contract requires changed current candidates/positions to be prioritized before unchanged rows, permits changed rows to break section soft limits within the global hard cap, and requires a removed candidate to remain identifiable from the diff's explicit symbol/expiration/strike/option-type facts.
- **Actual behavior**: the message can say “新增/失效候选” or “PDD 持仓建议已变化” while the corresponding contract/lot is absent from the complete snapshot. With several PDD lots, symbol-only promotion can still display the wrong PDD rows. This recreates the user problem of a change notification whose referenced decision cannot be located in the same message.
- **Direct evidence**: `_candidate_views` at lines 240-295 receives no diff; `_position_views` at lines 337-360 builds only `changed_symbols`; `_change_summaries` at lines 476-510 collapses `candidate_invalidated` into a count even though Slice A added structured contract fields to `_action_change_view`.
- **Impact**: material notifications are not reliably self-contained under configured display limits, and operators can inspect the wrong contract or position after a change.
- **Fix direction**: derive internal structured candidate and position change keys from the diff; select changed current rows first, allow them to exceed the section soft limit while respecting the existing global hard cap, reuse the same selected candidate rows for the funds section, and render removed candidate contract labels from diff facts without exposing internal IDs or broker codes. Add adversarial tests for below-limit candidates, multiple same-symbol position lots, and removed candidates.
- **Fix risk**: selection-order changes can desynchronize candidate and capacity sections or leak identity fields if implemented independently; keep one shared allowlisted selection result and test the privacy contract.
- **Severity**: medium.
- **Decision**: accepted; must fix in the current aggregate review loop.
