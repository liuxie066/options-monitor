# Plan Review — Close Advice Strategy Optimization

## Scope

- Reviewed target: `docs/gateflow/close-advice-strategy-optimization-plan-20260723.md`
- Reviewed baseline: `origin/main@64ccd3e0`
- Review mode: adversarial implementation-plan review
- Work unit: `close-advice-strategy-optimization`
- Artifact path: `docs/reviews/plan-review-20260723-004251.md`

## Assumptions tested

- The proposed profile policy can be implemented without inventing a new thesis state machine.
- Same-run replacement evidence is available before the formal recommendation is decided.
- The proposed episode identity can represent every state transition described by the plan.
- Existing candidate-centric Shadow Replay marking and settlement can safely host close-decision episodes.
- Counterfactual and promotion metrics are deterministic enough to gate a production policy.
- Additive recommendation fields can preserve current P0 behavior and old-artifact read compatibility.

The review explicitly applied architecture-boundary, best-practice, optimal-solution, overengineering, and overcoupling lenses.

## Findings

### PR-01-未修复-高-承保 thesis 状态和动作真值表互相矛盾，实施者必须自行发明退出策略

- **位置**: Sections 6.3, 7.3, 7.4, S2
- **问题类型**: 契约缺失 / 状态机漏洞 / 不可直接实施
- **当前写法**: 计划要求把 thesis 分成 `valid`、`weakened`、`lost`、`not_evaluable`，并让 medium + weakened/lost 直接产生 `close`；同一节又规定 IV/RV edge 丢失不能作为 loss stop，willingness=false 只请求 review。
- **反例/失败场景**: 一个 medium Sell Put 只有 IV/RV ratio 低于开仓阈值，assignment 仍可接受。按表格它属于 weakened 并应 close；按约束它只能 support review，不能触发 close。不同实现者会得到不同生产动作。
- **为什么有问题**: 当前 domain 只产出 `valid`、`observe`、`not_evaluable`；没有 `weakened` 或 `lost` 的确定定义，也没有可证明的 risk-exit contract。
- **直接证据**: 计划 231、277-292 行；`domain/domain/close_advice.py:643-660` 明确把任意 IV/RV、delta、event observation 合并成 `observe`，并保留已有 profit-capture 动作。
- **影响**: 实施 Agent 会把观察项误升级为方向性平仓建议，重新引入用户正在修复的“单一指标直接建议平仓”问题。
- **建议改法和验证点**: P2 只使用现有 `valid|observe|not_evaluable`。medium + valid + willingness=true -> hold；medium + observe 或 willingness=false -> review；P2 不允许这些观察项单独产生 close。只有 strong + 完整执行证据可 close。未来 risk-exit 单独 work unit。用表驱动测试覆盖每个组合。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PR-02-未修复-高-replacement evidence 在正式决策之后才生成，计划中的 same-run 正式依赖无法落地

- **位置**: Sections 6.4, 7.3, 13, S6
- **问题类型**: 架构边界 / 过度耦合 / sequencing
- **当前写法**: 正式 P2 可因 `reallocation_status=review_switch` 升级为 close，且要求 evidence 来自同一 run；S6 却未定义两阶段决策或 reallocation owner 的变更。
- **反例/失败场景**: 当前 account run 先完成 `run_close_advice()` 并写出 `close_advice.csv`，随后 reallocation shadow 才读取该 CSV 和 `portfolio_capacity_shadow.csv`。正式 recommendation 在 replacement facts 出现前已经落盘并被计数。
- **为什么有问题**: 让 runner 同时依赖 post-processing shadow 会形成 `close advice -> reallocation -> close advice` 的数据环；直接把 shadow 状态读回 domain 也违反纯 domain facts 边界。
- **直接证据**: `src/application/account_run.py:646-675`；`src/application/close_advice_reallocation_shadow.py:56-84`。计划 S6 allowed files 未包含这两个 ownership 边界。
- **影响**: 要么 production 根本读不到 replacement evidence，要么实现会跨层重排 tick orchestration，扩大并隐藏风险。
- **建议改法和验证点**: 推荐最小方案：P2 正式候选不以 replacement 为 close 条件；replacement 只保留在 P3 shadow/review basis。若未来要晋升 P3，另立 work unit 设计纯 `evaluate_reallocation(close_fact, ranked_candidates, capacity)` 和明确的 base-decision -> reallocation -> final-projection 两阶段流水线。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PR-03-未修复-高-close episode 主键与同日状态变化规则冲突，会覆盖或错误去重证据

- **位置**: Section 9.1, S3
- **问题类型**: 状态机漏洞 / 数据重复与丢失
- **当前写法**: episode key 是 `account + position_lot_id + policy-observation date`，同时规定同日 recommendation、tier、经济 bucket、willingness/thesis/replacement 变化时创建新 episode。
- **反例/失败场景**: 同一 lot 上午 medium/review、下午价格变化到 strong/close。两条 episode 的现有 key 完全相同；写入、mark join 或 dedupe 必然覆盖其一或把两者误认为重复。
- **为什么有问题**: 主键不能同时表达日级 cohort 和日内 material transition。
- **直接证据**: 计划 346-358 行。
- **影响**: paired replay 的分母、提醒重复数、状态转换和 outcome join 均不可信。
- **建议改法和验证点**: 定义 `episode_id = sha256(account|position_lot_id|policy_version|observed_at_utc|material_fact_fingerprint)`；另保留 `episode_date` 用于日级聚合。dedupe identity 使用 lot + policy + material fingerprint，且仅在同一交易日内折叠完全相同事实。测试同日两次转换、跨日相同事实和重复 run。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### PR-04-未修复-高-现有 Shadow Replay 是 candidate-centric，计划没有定义 close facet 的文件和 join 契约

- **位置**: Sections 9, 13, S3, S4
- **问题类型**: 架构边界 / schema 缺失 / 切片过粗
- **当前写法**: “向现有 Shadow Replay 增加 Close Advice facet”，但没有定义 dataset kind、manifest 版本、文件名、兼容规则、mark source identity、settlement dispatch 或 analyzer dispatch。
- **反例/失败场景**: 直接把 close rows 放进 `candidate_snapshots.jsonl` 会污染 candidate readiness/ranking analysis；新增文件而不升级 manifest/dispatch 时，现有 marking 和 settlement 完全不会读取它。
- **为什么有问题**: 当前 `DATASET_FILES` 只有 candidate/filter/rank/mark/outcome；marking 和 settlement 都硬编码读取 `candidate_snapshots.jsonl`，outcome identity 以 instrument 为主而不是 episode。
- **直接证据**: `src/application/shadow_replay/common.py:9-25`；`marking.py:48-63`；`settlement.py:31-87`。
- **影响**: S3 无法直接实现；最可能出现的结果是 candidate replay regressions 或 close episode 证据没有被 mark/settle。
- **建议改法和验证点**: 在计划中定义可选 facet 文件：`close_decision_episodes.jsonl`、`close_decision_marks.jsonl`、`close_decision_outcomes.jsonl`；manifest 保持 v1 向后兼容并登记可选 facet，或明确升级 v2 和 reader compatibility。mark/settle/analyze 以 facet dispatch，candidate 路径行为不变。将 S3 拆为 schema/capture、marks/outcomes、readiness 三个可 review 子切片。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PR-05-未修复-高-反事实收益没有公式和基准时点，可能产生方向或重复计费错误

- **位置**: Sections 9.3-9.5, S4
- **问题类型**: 契约缺失 / 测试缺口
- **当前写法**: 只列出 `close_now_net`、`hold_to_horizon_net`、`hold_to_terminal_lifecycle_net`、`switch_to_selected_replacement_net` 名称，并要求包含费用。
- **反例/失败场景**: 对 short Put，可把从开仓起的累计 P&L 与从 decision timestamp 起的增量 P&L混在一起；close fee 可能在 close-now 和 hold horizon 两侧重复扣除；assigned lot 又可能同时计入期权 payoff 和 ledger lifecycle P&L。
- **为什么有问题**: 这些值直接驱动 regret、avoided loss 和 promotion，符号/基准差异会反转策略结论。
- **直接证据**: 计划 379-412 行；现有 settlement `derive_outcome_facts` 只面向 candidate snapshots，并按 instrument 生成单一 outcome，不能证明 close-decision counterfactual。
- **影响**: 生成看似精确但经济含义错误的政策报告，错误晋升策略。
- **建议改法和验证点**: 固定 decision-time 增量口径并写出 Put/Call 公式、费用发生点、terminal lifecycle precedence、assignment/called-away 不可用时的 inconclusive 规则。所有 variants 在同一 episode 上共享同一 outcome facts，只改变 action projection。加入手算 fixtures 覆盖 close、hold、expiry worthless、assignment、called-away、缺 fee 和缺 mark。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### PR-06-未修复-中-promotion quality gate 使用未定义的“not worse/materially reduced/precision”，无法形成确定 gate

- **位置**: Section 10.2, S4, S5
- **问题类型**: 测试缺口 / open question 未收敛
- **当前写法**: 要求 P95 “not worse”、avoided loss “not materially reduced”、close precision 改善或稳定，但没有 tolerance、denominator、配对缺失处理或 precision 的成功定义。
- **反例/失败场景**: 两个 analyzer 对 0.1% 的 P95 差异、无 terminal outcome 的 close、或 assignment-acceptable 的 hold 使用不同判断，可能一个 pass、一个 fail。
- **为什么有问题**: hard promotion gate 必须可重复计算；否则 CEO artifact 前仍需重新设计验收口径。
- **直接证据**: 计划 431-443 行。
- **影响**: S4 completion 不可验收，S5 决策被模糊统计口径支配。
- **建议改法和验证点**: readiness 保持机械 gate；quality report 改成明确的 paired deltas、coverage 和 bootstrap-free descriptive intervals，不自动 pass/fail。CEO decision artifact逐项记录接受的 trade-off。若仍保留 machine gate，必须在 plan 中给出精确 tolerance 和 denominator。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

## Open Questions

- P2 是否接受“medium underwriting 永不直接 close；observe/willingness=false 只进入 review，replacement 仅作为 review basis”？这是消除 PR-01/PR-02 的最小且最安全定义。
- Close-decision facet 是否需要 OpenD 采集 1/3/7/14 日精确 horizon，还是接受 next-available mark bucket？计划应固定一种规则。

## Residual Risks

- 样本量门槛本身是产品风险偏好，不是统计显著性证明；应保留为 CEO 可见的 readiness guardrail。
- Covered Call 缺少股票方向和税务 lot thesis，P2 只能基于 called-away willingness 与期权执行经济性。
- 历史未采集的 marks 不能补造；forward collection 可能让 S5 跨越多个自然日。

## Conclusion

`fail`

The strategy direction is sound, but the plan is not yet code-generation-ready. PR-01 through PR-05 are blocking findings and must be fixed, then re-reviewed before implementation.
