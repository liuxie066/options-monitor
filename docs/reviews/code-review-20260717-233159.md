## New Finding

### CR-S2-06-未修复-中-Writer fee split 会把非法显式 amount 覆盖为合法 actual

- **入口/函数**: `_close_fee_splits()` → `_payload_with_allocated_fee()`.
- **文件(行号)**: `src/application/ledger/writer.py:222-266`.
- **输入场景**: auto-targeted close 带 `fee_provenance={"basis":"actual","amount":"bad"}`，同时 legacy numeric `fees=1` 可解析。
- **实际分支**: splitter 尝试解析 provenance amount 失败后回退到 event fees；payload helper 仅看 basis 为 actual，就把原始非法 amount 覆盖为分配后的合法字符串。
- **预期行为**: 显式非法 provenance 必须继续 fail closed，使 projection 得到 missing fee；writer 不得静默修复/提升其可信度。
- **实际行为**: malformed amount 被清除，fee 在 projection 中重新成为 actual，CR-S2-05 的 fail-closed 语义在真实 writer 路径失效。
- **直接证据**: `writer.py:233-240` 回退 event fees；`writer.py:260-262` 无条件覆盖 actual/estimated amount。
- **影响**: 不可信 fee 可进入 production realized net，且原始数据质量问题不可见。
- **建议改法和验证点**: payload helper 在原 amount 存在时先验证；若不可解析则保留原值，不写 allocated amount。split numeric event fees 可继续用于兼容 lot state，但 fee fact 必须保持 missing。增加 public writer regression test，断言 lot close、allocation gross 存在、close fee missing、net null。
- **修复风险（低）**: 只影响 malformed explicit amount。
- **严重程度（中）**: 中。
