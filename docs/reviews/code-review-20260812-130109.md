## Findings

### S2-CR-01-未修复-中-账户和市场筛选没有同步裁剪候选证据覆盖门禁

- **入口/函数**: `load_shadow_replay_observed_evidence()` -> `_load_run_window_evidence()` / `_dataset_coverage()` -> `_filter_candidates()`
- **文件(行号)**: `src/application/shadow_replay/candidate_impact.py:99-176, 359-395, 398-442, 492-560`
- **输入场景**: 同一 selected run 有 `lx=supported`、`sy=unsupported_snapshot_missing`，调用方明确传入 `accounts=["lx"]`；或一个仅 HK 的 unsupported account 与被请求的 US scope 共存。
- **实际分支**: run/dataset coverage 在第 115-127 行按全部账户先聚合；候选、过滤和排名行直到第 136-150 行才按 account/market 过滤；第 170 行原样返回未裁剪 coverage。`_run_window_coverage()` 因任一未请求账户的 `strict_replay_authority=false` 把整个请求标为 `candidate_evidence_coverage_incomplete`。
- **预期行为**: 明确的账户/市场 scope 应同时作用于候选事实和其覆盖证明；已能由 classification 的 account/markets 证明不在 scope 的账户不得阻断该 scope。无法证明 market 不相关的 unsupported classification 仍应保守保留并 fail closed。
- **实际行为**: 返回的候选事实只包含 `lx`，但门禁仍被 `sy` 阻断；参数表面生效、authority gate 实际仍按全 run 运行，导致合法的单账户回放和 Strategy Lab 严格评估被误拒绝。
- **直接证据**: `account_filter`/`market_filter` 只传给 `_filter_candidates()` 和 `_filter_replay_observations()`；coverage 既未接收 filters，也未重新计算 status counts、accounts 或 strict flag。现有测试只覆盖行裁剪，没有 mixed supported/unsupported scoped coverage 回归。
- **影响**: 不会错误放行 promotion，但会稳定制造假性 incomplete，令账户隔离分析和可比较 holdout 无法进入严格评估；这与 S2 的 mixed-account 明确分类和 Strategy Lab handoff 合同不一致。
- **建议改法和验证点**: 增加单一 coverage-scope helper，按 account 精确裁剪，按已知 `markets` 排除确定不相关项，对未知 market 的不完整项保守保留；随后重算 counts/strict/reason，并同时用于 run-window 与 dataset coverage。新增 `lx supported + sy unsupported` 的 account-filter 正向用例、无 filter 负向用例，以及已知异市场/未知市场用例。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### S2-CR-02-未修复-中-Combo Funding Put 校验没有把收据重新绑定到 dataset manifest 和 integrity

- **入口/函数**: `evaluate_combo_variant_dataset()` -> `validate_combo_funding_put_source()`
- **文件(行号)**: `src/application/shadow_replay/combo_evaluation.py:189-220`; `src/application/shadow_replay/combo_funding.py:119-193`; `src/application/shadow_replay/common.py:365-493`
- **输入场景**: 已发布 dataset 中的 Funding Put JSONL 和 source receipt 被一起替换为另一组彼此自洽、同 `dataset_id` 的 rows/hash/count/source hashes；dataset manifest 仍保留原始 `combo_funding_put_facet` 和 integrity receipt。另一现实场景是 JSONL 被改后 manifest integrity 已不匹配，但 receipt 同步改为新 hash。
- **实际分支**: validator 只要求 canonical path、receipt schema、`dataset_id` 相等、row/receipt 内部字段一致和 JSONL hash 相等。它不调用 `validate_dataset_integrity()`，也不比较 receipt 与 manifest 的 `combo_funding_put_facet`。因此 JSONL 与 receipt 同步变化时可通过，随后 accepted rows 被重新用于 pair evaluation。
- **预期行为**: S2 计划要求 source receipt 绑定 manifest/Combo snapshot hashes，evaluation 做 hash/schema/source validation；读取时必须验证 dataset integrity，并要求 canonical receipt 与已写入 manifest 的 facet 完全一致，不能以可一起改写的 sidecar 自证来源。
- **实际行为**: publication 虽把 receipt 展开写入 manifest 且 `refresh_dataset_manifest()` 会把 JSONL 纳入 integrity，但 consumer 完全绕过这两份绑定，只信 sidecar；manifest-bound source authority 可被降级为 receipt-self-attested input。
- **直接证据**: `dataset_integrity_payload()` 会枚举 dataset 根目录所有 `*.jsonl` 并记录 hash，但 `validate_combo_funding_put_source()` 第 175-193 行未调用它；第 186-188 行只读 manifest 比较 `dataset_id`，从不读取 `combo_funding_put_facet`。测试仅篡改单个 JSONL，不覆盖 JSONL+receipt 同步篡改或 stale manifest facet。
- **影响**: Shadow Combo research 可在不重新验证源 manifest/snapshot authority 的情况下消费被替换的 accepted Funding Put 集合，污染离线 pair、scorecard 和 promotion evidence。范围限于本地研究 dataset，不直接改变生产候选，因此严重度为中。
- **建议改法和验证点**: 在 dataset read lock 内先后验证 integrity，要求 manifest 的 canonical output/receipt basename 和 facet payload与 receipt 精确匹配；publication 在锁内基于重新读取的 manifest 构建 facet，避免 stale pre-lock dataset identity。新增 JSONL+receipt 同步篡改、facet 篡改、integrity stale、正常幂等读取回归。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中
