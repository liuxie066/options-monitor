## Findings

### 1. 未修复 - 高 - 恢复 loader 可能抛出非 typed 异常，把 PM 软依赖重新变成 Tick 故障

- 入口：`run_tick_account_execution()` recovery -> `load_prepared_portfolio_distribution()` -> `_validate_payload()` -> `_normalize_asset_row()` / `_finite_number()`
- 文件：`src/application/prepared_portfolio_distribution.py:317-324, 864-889`; `src/application/tick_account_execution.py:881-906`
- 场景：同 run 的 PM artifact 是合法 JSON，payload hash 也被同步改写，但资产行含字符串数量、超大整数或其他非法值。
- 实际：loader 的 `_validate_envelope()` 调用没有把 `PortfolioManagementProtocolError`、`OverflowError` 等统一转换为 `PreparedPortfolioDistributionError`；recovery 只捕获后者，因此异常可逃出账户循环并中断整个 Tick。
- 预期：任何 PM artifact 缺失、损坏或语义非法都只产生当前账户 `recovery_artifact_unavailable`，Candidate Engine 继续。
- 修复建议：在 loader 边界把全部 artifact decode/semantic validation 异常收敛为 typed error，同时保留既有明确错误；增加“重算 payload hash 后注入非法数量”的 recovery 回归。
- 严重程度：高

### 2. 未修复 - 中 - 安全读取失败被统一标成 missing，可能对已有但不可信的 artifact 再次调用 PM

- 入口：`prepare_portfolio_distributions()` -> `load_prepared_portfolio_distribution()`
- 文件：`src/application/prepared_portfolio_distribution.py:158-181, 284-294`
- 场景：目标 artifact 已存在但为 symlink、非普通文件或不可安全读取。
- 实际：safe reader 的任意异常都被转换成字符串为 `artifact is missing`；initial path 因此继续调用 PM，之后才在 write-once 发布时失败。
- 预期：只有确实不存在的 artifact 才允许首次 PM 读取；已有但不可信的 artifact 必须直接 fail soft，避免违反 same-run 不重取及 write-once 语义。
- 修复建议：用 exact run/account path 的 `lstat` 仅区分 absent 与 existing/unsafe；不要依赖错误字符串。增加 symlink/非普通文件下 PM 调用数为零的测试。
- 严重程度：中

### 3. 未修复 - 中 - loader 没有完整校验 authority/reason/validation 状态机

- 入口：`load_prepared_portfolio_distribution()` -> `_validate_envelope()` / `_validate_payload()`
- 文件：`src/application/prepared_portfolio_distribution.py:726-793, 846-857`
- 场景：本地 artifact 增加额外 authority 字段，或把 unavailable reason/validation/provider 组合改成不可能状态并重算 payload hash。
- 实际：root 和 payload 是 closed schema，但 authority、validation、integrity 允许额外字段；unavailable 分支在确认资产为空后直接返回，不验证 reason、provider、quality 与 validation 的确定性关系。
- 预期：v1 envelope 是严格、可审计状态机；加载器应拒绝任何 producer 不可能生成的组合，避免恢复路径把自洽 hash 当成合法业务 authority。
- 修复建议：关闭 authority/validation/integrity schema；为 unavailable 原因定义确定性 provider、quality 和 validation 关系；dataset/reason 列表规范化为排序且去重。
- 严重程度：中
