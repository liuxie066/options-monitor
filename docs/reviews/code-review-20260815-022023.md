## Findings

### 1-未修复-中-无排名事实（period return 为 null）的 Sell Put 行在 current_tie_break 下以 tie key 排在有回报行之前，可能把 null 回报合约选为 Top1
- **入口/函数**: `rank_candidate_rows()` -> `_rank_return_bands()` -> `_sell_put_cross_symbol_tie_key()`
- **文件(行号)**: `domain/domain/engine/candidate_engine.py:1158-1194`（`_rank_return_bands`），`domain/domain/engine/candidate_engine.py:1137-1156`（tie key）；该行为为基线既有语义，W1A 通过 `src/application/strategy_lab/top1/ranking.py:339-366`（`rerank_recommendation_point`）将其继承为 Top1 选择
- **输入场景**: sealed opening snapshot 中某个已接受 Sell Put 候选缺全部 return 来源（`period_net_return_on_cash_basis`、`net_income`、`annualized_net_return_on_cash_basis` 均为 null——projection 合同明确允许 ranking facts 为 null），且其 `net_assignment_discount_pct`/`spread_ratio` 优于其他候选
- **实际分支**: `_rank_return_bands` 的 `usable` 只收集非 null return；无 return 的行不进入任何 band，落入 `if not usable` 或残余分支，以 `(tie_key, index)` 直接排序；concentration 相同且 margin 更大时排在有回报的 band 行之前
- **预期行为**: 生产默认排名语义是既有事实，W1A 不得改变；但作为 Sell Put Top1 选择面，"无回报事实的行排在有回报行之前"是否是有意的接受标准，需要 plan/产品层显式确认，而不是由 tie key 碰巧决定
- **实际行为**: null-return 候选可被排到首位；`rerank_recommendation_point` 的 default parity 检查会忠实复制该顺序并把该候选作为 `top1_candidate_id` 返回，`parity_status="matched"` 不暴露此情况
- **直接证据**: `_rank_return_bands`（`candidate_engine.py:1165-1193`）中 `usable` 为空或行不属于任何 band 时直接按 tie key 排序；`_sell_put_period_return`（`candidate_engine.py:1066-1082`）在三组来源全缺时返回 `None`；`_CANDIDATE_SOURCE_FIELDS`/`_RANKING_NUMERIC_FIELDS`（`ranking.py:35-54,108-116`）允许这些字段为 null；`rerank_recommendation_point` 直接取 `ranked_ids[0]` 作为 Top1
- **影响**: 仅局部行为错误但影响实验结论质量：Top1 可能落在没有回报事实的合约上；不改变生产排名，不造成资金或安全风险
- **建议改法和验证点**: 在 plan 或后续 economics/selection 工作单元中显式声明 null-return 候选的 Top1 资格；若决定不合格，最小编排是在 `rerank_recommendation_point` 结果或后续选择层按"存在 period return"过滤，而不是修改 Candidate Engine 基线语义。验证点：构造含 null-return 且 tie key 占优的 projection，断言 Top1 结果符合显式决策
