## Findings

### 1-未修复-高-正式 Advice 记录可与 Daily Brief 投影矛盾却仍被标记为可用

- **入口/函数**: `_with_formal_ai_decision_advice()` -> `_formal_record_matches_brief()` -> `_formal_advice_view()`
- **文件(行号)**: `src/application/agent_tools/daily_brief.py:251-282,302-325,328-410`
- **输入场景**: 同一 `advice_id` 的正式记录与 Daily Brief 中 SP/CC 的 action、selected candidate 或 rationale 不一致；或 JSONL 中存在两个相同 `advice_id`，其中只有一个外层元数据匹配。
- **实际分支**: 读取层只比对 schema、状态、时间、复用标志和零候选标志，不比对 decisions；歧义判定基于过滤后的 `matches`，而不是 `same_id` 的唯一性。
- **预期行为**: Agent 只在正式记录唯一且其逐 scope 决策与 Daily Brief 投影完全一致时返回 `formal_record.available=true`；重复 ID 或投影矛盾必须 fail closed。
- **实际行为**: 一条矛盾记录可能被当作同一正式事实返回；相同 ID 的额外记录若外层元数据不同，也不会触发歧义。
- **直接证据**: `_formal_record_matches_brief()` 没有读取 `record.decisions` 或 Brief 的 `sell_put` / `covered_call` 决策；`same_id` 先被过滤成 `matches`，随后仅以 `len(matches)` 判断歧义。`_formal_advice_view()` 还会静默丢弃非对象 demotion，不能证明正式结构完整。
- **影响**: Agent 消费者可能同时看到“正式记录可用”和与回执不同的 action/目标，破坏“同一正式来源”的审计边界，并可能把损坏记录伪装成完整 Advice。
- **建议改法和验证点**: 先要求 `same_id` 恰好一条，再校验 run/market/status 和逐 scope 决策投影；严格验证 decision、rationale、source refs、demotion 结构和 action/selection 语义。增加决策矛盾、重复 ID、畸形结构的回归测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-中-模型 rationale 可注入回执 Markdown 结构

- **入口/函数**: `render_family_advice_lines()` -> `_render_decision()` -> `_rationale_text()`
- **文件(行号)**: `src/application/ai_decision_advice/render.py:181-197`
- **输入场景**: 模型返回含换行、Markdown 标题、链接或控制字符的 rationale 字段。
- **实际分支**: `_rationale_text()` 直接 `str(...).strip()` 并拼入 `原因｜` 行，没有经过本模块已有的文本净化边界。
- **预期行为**: 模型生成文本只能作为一行简洁原因显示，不能改变回执层级或构造伪造区块。
- **实际行为**: rationale 中的换行或 `##` 可逃逸当前行并注入新的可见结构。
- **直接证据**: 三个 rationale 字段在第 185-189 行直接字符串化，第 196-197 行直接返回给 Markdown renderer；同文件的来源标题已使用 `sanitize_source_text()`，但 rationale 未复用。
- **影响**: 用户可能把模型生成的伪标题、伪结论或链接误认为系统生成的正式模块，降低回执可信度。
- **建议改法和验证点**: 对每个 rationale 子句复用文本净化与长度限制，再拼成单行；增加换行、标题、链接和控制字符输入测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
