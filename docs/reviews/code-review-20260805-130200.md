### DR11-01-未修复-高-重复语义状态校验会泄漏原始异常并遗留 claim，坏历史状态可周期性重放高成本 provider 采集

- **入口/函数**: `reconcile_due_lifecycle_cases_for_source()` -> `reconcile_lifecycle_close_reason()` -> `_require_duplicate_settlement_state_base()` / `_require_duplicate_settlement_allocation_state()`
- **文件(行号)**: `src/application/ledger/writer.py:1161-1188, 1208-1231, 1268-1283`; `src/application/trades/lifecycle_runtime.py:987-1139, 1227-1257`; `src/application/trades/auto_intake.py:1749-1781`; `src/application/ledger/repository.py:3247-3251`
- **输入场景**: 已存在 semantic head 且本次 observation 命中 `duplicate_semantic`，但历史 canonical state 含畸形字段，例如 `derived_summary.resolution_revision="bad"`、无法规范化的 target manifest/分配数量，或 `PRAGMA foreign_key_check` 返回违规。
- **实际分支**: duplicate coherence validator 对 `resolution_revision` 和 allocation 数量直接调用 `int()`，直接调用可能抛 `ValueError` 的 `resolve_allocations()`，并让 `assert_foreign_keys_clean()` 的 `RuntimeError` 原样向上冒泡。runtime 只把 `SettlementAdmissionStateIncoherent` 转成类型化 `unknown_error/canonical_state`；非 compare-and-set 的原始 `ValueError` 会重新抛出，其他原始异常也没有 outcome 分支。异常发生在 provider collection 和 claim 获取之后、`complete_settlement_attempt()` 之前。
- **预期行为**: 所有确定性的 canonical-state 不一致都应统一收敛为 `SettlementAdmissionStateIncoherent`，由 runtime 持久化 `unknown_error`、释放 claim 并执行 5 分钟起步的指数退避；数据库可用性等基础设施异常仍应保持原类型并 fail closed。
- **实际行为**: listener 仅记录 `last_lifecycle_due_error` 并在下一分钟重新进入 due runner；未完成的 claim 要等 lease 到期才可再次获取。此后同一坏状态会按 lease 周期重新调用 broker/quote provider，而不是按 settlement-attempt 退避上限抑制。
- **直接证据**: `writer.py:1167`、`writer.py:1277-1279` 的 `int()` 没有边界转换；`writer.py:1184` 的 `resolve_allocations()` 可在 target manifest 规范化时抛 `ValueError`；`repository.py:3251` 明确抛 `RuntimeError`；`lifecycle_runtime.py:1105-1109` 会重抛非特定文本的 `ValueError`，而 `complete_settlement_attempt()` 直到 `lifecycle_runtime.py:1246-1256` 才执行；外层 `auto_intake.py:1777-1781` 只记录异常并推进一分钟调度时钟。
- **影响**: 一个损坏或旧版本遗留的 canonical row 就能绕过本迭代新增的持久退避和可观测 outcome，反复触发高成本外部查询；这正是本方案试图从 cash-flow 特例推广防止的同类 CPU/延迟失控模式，并且会使运维只看到通用 listener error，无法按 canonical-state 原因定位。
- **建议改法和验证点**: 在 duplicate coherence ownership boundary 精确捕获字段解析、allocation 解析和 foreign-key violation，统一链式转换为 `SettlementAdmissionStateIncoherent`，但不要吞掉 `sqlite3.OperationalError` 等存储故障。新增真实 writer 状态畸形回归和 runtime 闭环测试，证明 provider 只调用一次、claim 被清除、`reason_code=settlement_admission_state_incoherent` 且 `next_attempt_at_ms` 落入预期退避窗口。
