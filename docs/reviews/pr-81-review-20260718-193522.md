## Findings

### PR81-001-未修复-中-bootstrap selector 可经外部 symlink alias 重新选择目标 venv 内解释器
- **入口/函数**: `scripts/install_agent_plugin.sh` -> `om_select_bootstrap_python` -> `_om_python_command_path`
- **文件(行号)**: `scripts/python_runtime.sh:10-27`, `scripts/python_runtime.sh:101-136`
- **输入场景**: `.venv/bin/python` 是 Python 3.12，且 `OM_PYTHON` 或 `PYTHON` 指向目标 venv 外部的 symlink；该 symlink 的最终目标是 `.venv/bin/python`。
- **实际分支**: `_om_python_command_path` 只对候选路径的 parent 执行 `pwd -P`，没有解析候选文件自身的 symlink；`candidate_path` 因此保持为 venv 外 alias，`_om_path_is_within` 返回 false，随后候选通过版本校验。
- **预期行为**: bootstrap selector 必须根据最终物理 executable 判断 containment，拒绝任何最终落在其将创建或更新的目标 venv 内的解释器。
- **实际行为**: selector 返回 venv 外 alias，`scripts/install_agent_plugin.sh` 随后用该解释器执行 `-m venv .venv`，从正在使用的目标环境内部重建目标环境，突破本 work unit 已声明并测试的 self-target safety invariant。
- **直接证据**: `_om_python_command_path` 在 path candidate 分支只 canonicalize `dirname`；bootstrap containment 比较直接消费该未解析最终 symlink 的字符串。独立复现中，`PYTHON=<outside>/python3.12 -> <target>/.venv/bin/python` 返回成功并输出 outside alias。
- **影响**: bootstrap 可在显式或环境继承的 alias 配置下边执行目标 venv 的解释器边重建同一 venv，导致安装行为依赖平台实现、部分覆盖或失败，且与 PR 声称的“never selects the venv it creates”不一致。
- **建议改法和验证点**: portable 地解析 executable 自身的 symlink chain 后再 canonicalize parent；新增 outside alias 指向 target interpreter 的回归测试，并保留已有 symlinked target-venv 测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
