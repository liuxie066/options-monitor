## Findings

### PR-03-未修复-高-safe MTD 默认值会把“只给 month、没给 period”的歧义请求静默改成 MTD

- **位置**: 3.1 AgentTool Copilot adapter；Option performance normalizer matrix；Slice 1 tests
- **问题类型**: 契约缺失 / failure handling / 测试缺口
- **当前写法**: 计划保留“真实 safe defaults”，现有 `period="mtd"` 属于 safe default；随后 normalizer 依据合并后的 period 删除 irrelevant period fields。
- **反例/失败场景**: 模型只提交 `{"month":"2026-06"}`，没有提交 `period`。payload 先获得 safe default `period="mtd"`，normalizer 再把 `month` 当作 irrelevant field 删除，最终执行一个成功的 MTD 查询。当前严格 contract 本来会把默认 MTD 与 `month` 的组合判为 `period=mtd does not accept: month`。
- **为什么有问题**: normalizer 在合并后无法区分 period 是模型显式选择还是 safe default。用隐式 discriminator 删除显式 period detail，会把用户的自然月请求变成另一个期间并返回可信外观的错误金额。
- **直接证据**: `src/application/agent_tools/positions.py:246-259` 当前 safe defaults 包含 `period="mtd"`；`domain/domain/performance/period.py:55-83` 在 period 缺省时本身默认 MTD，并严格拒绝 irrelevant fields；`tests/test_option_performance_agent_tool.py:123` 已把 `period=mtd + month` 固定为 rejection。
- **影响**: Copilot 可能返回错误月份/期间的财务数字，且不会产生可观察错误；新 normalizer 会破坏既有 fail-closed 语义。
- **建议改法和验证点**:
  - 从 Copilot payload safe defaults 中同时移除 `period="mtd"`；canonical `PeriodRequest` 继续在真正无 period detail 时提供 MTD 默认。
  - normalizer 只有在 payload 显式带合法 `period` 时才删除 irrelevant fields；没有 period 时保持 period-specific fields 原样交给 validator。
  - schema description 可说明 omitted period means MTD，但不要通过 payload default 制造 discriminator provenance。
  - 新增测试：空 payload 正常默认 MTD；`month` without `period` 仍 fail closed；explicit `period=mtd` + month/year/range 被 canonicalized；unknown period 不修复。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高
