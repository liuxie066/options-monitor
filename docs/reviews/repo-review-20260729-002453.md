### 1-已修复-高-Option context 不可用被解释为 0 股已锁定，Covered Call 可重复占用持股

- **入口/函数**: `build_pipeline_context()` -> `run_watchlist_pipeline()` -> `run_symbol_monitoring()` -> `run_sell_call_scan_and_summarize()`
- **文件(行号)**: `src/application/pipeline_context.py:190-224,443-452`; `src/application/pipeline_watchlist.py:303-305`; `src/application/positions/context_builder.py:41-70,118-127`; `src/application/symbol_monitoring.py:571-590`; `src/application/sell_call_steps.py:167-207`; `domain/domain/risk_capacity.py:104-143`
- **输入场景**: 账户持有股票且已有 open short call，但 option-position 读取失败、ledger shadow fail-closed，或 option context 未能挂入 portfolio context。
- **实际分支**: context 加载异常返回 `None`；ledger fail-closed 返回两个空 map。下游把缺失 context 折成 `{}`，`locked` 默认保持 `0`，再以全部持股计算可卖 Call 数量。
- **预期行为**: option-position authority 不可用时，已锁定股数应是 unknown；Covered Call 应整体或按 symbol fail-closed 为 unavailable。
- **实际行为**: 缺证据被当成“没有锁仓”，100 股会被判定可再覆盖 1 张 Call。
- **直接证据**: 最小调用 `compute_sell_call_share_capacity(shares_total=100, shares_locked=0, multiplier=100, shares_available_for_cover=100)` 返回 `accepted=true`；上游缺失路径正好提供这组语义。
- **影响**: 可能生成重复覆盖甚至事实上的裸卖 Call 建议，是开仓安全边界失守。
- **建议改法和验证点**: 为 option context 引入 typed availability/status；禁止 `None -> empty`；ledger fail-closed 传播全局/逐 symbol unavailable。新增 load exception、identity conflict、已有 short call 三类全链路回归，均不得产出候选。

- **实际行为**: `symbol_timeout_sec=120` 基本为死参数；最终只能依赖更外层 tick watchdog 杀整个流程。
- **直接证据**: 全仓搜索只找到 timeout 的读取、声明和转传，没有用于 deadline、future timeout 或 remaining budget。
- **影响**: 一个 gateway/标的可拖死整个账户扫描，无法按标的降级或保留其他结果。
- **建议改法和验证点**: owning boundary 使用 monotonic deadline；OpenD 调用接收 remaining budget；线程 orchestration 对 future 做有界等待并产生明确 timeout status。增加阻塞 gateway、多请求 wave、多个 symbol 混合回归。
- **修复风险（低/中/高）**: 高
- **严重程度（低/中/高/严重）**: 中
