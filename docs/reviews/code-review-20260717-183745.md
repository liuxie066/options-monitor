### S6-CR-01-未修复-[中]-年化效率在除法前使用了展示层舍入后的 capital-days
- **入口/函数**: `build_period_performance -> _capital_report -> _annualized_efficiency`
- **文件(行号)**: `domain/domain/performance/engine.py:455-474, 486-492`
- **输入场景**: 很短的日内暴露或低权利金 long option，使精确 capital-days 在小数点后第 6 位之后仍有有效值。
- **实际分支**: 先把 Decimal 聚合值 quantize 到 `CAPITAL_DAYS_QUANTUM`，再把 `rounded_sums` 传给两个效率计算。
- **预期行为**: approved S6 contract 要求 Decimal 精度贯穿聚合和效率除法；只有序列化展示可以舍入。
- **实际行为**: 年化效率分母已被展示精度截断；极小但非零分母还可能展示为 0，导致输出分母与已计算出的效率互相矛盾。
- **直接证据**: `rounded_sums` 在 engine.py:471-474 创建，随后在 engine.py:486-492 直接传入 `_annualized_efficiency`。
- **影响**: 某些短时暴露的效率值有系统性偏差，边界情况下可出现 `capital_days_by_currency=0` 但效率为 observed，破坏公式可复算性。
- **建议改法和验证点**: 效率计算使用未舍入的 `sums`；展示保留足够精度并新增 1ms/低 notional 回归测试，验证输出分母和效率按精确 Decimal 一致。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S6-CR-02-未修复-[中]-FIFO covered-call 零增量资本被标成完整 observed coverage
- **入口/函数**: `project_assigned_stock_lifecycle -> _capital_report`
- **文件(行号)**: `domain/domain/assigned_stock.py:711-723`; `domain/domain/performance/engine.py:394-400, 475-482`
- **输入场景**: covered call 没有 explicit stock-lot link，但 S5 projector 通过纯 assigned-stock inventory 的 FIFO heuristic 完成归因。
- **实际分支**: projector 明确输出 `allocation_status=derived_fifo`，engine 只收集 open_event_id，丢弃 allocation status；没有 missing 时 coverage 直接变成 observed。
- **预期行为**: S5 contract 要求 heuristic attribution 降级 quality；S6 的 capital coverage 也必须保留这个不确定性，不能把 heuristic 和 explicit 等价呈现。
- **实际行为**: FIFO call 被当作确定的 zero-incremental capital，coverage 无 warning 且 status=observed。
- **直接证据**: assigned_stock.py:722 保留了状态；engine.py:396-400 的 set comprehension 只读取 ID；engine.py:475-482 仅依据 missing 决定状态。
- **影响**: 用户会把启发式 covered-call 资金归因误认为精确证据，尤其在同标的多个 assigned-stock lot 时掩盖 attribution risk。
- **建议改法和验证点**: engine 同时读取 allocation status；derived_fifo 加入 coverage warning 并把 coverage 降级为 partial（不改变零增量数值）；新增 explicit 与 FIFO coverage 状态对比测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S6-CR-03-未修复-[低]-已知零成本 exposure 被误报为 basis unavailable
- **入口/函数**: `_append_option_capital_segment` / `CapitalExposureSegment.__post_init__`
- **文件(行号)**: `domain/domain/performance/engine.py:534-544`; `domain/domain/performance/models.py:337-342`
- **输入场景**: 合法 long option open event 的 opening premium debit 为 0，或未来同类明确零成本 basis。
- **实际分支**: long option 按公式算出 notional=0 后命中 `notional <= 0`，或模型拒绝 quantity>0 且 notional<=0，最终加入 `capital_basis_unavailable`。
- **预期行为**: S6 定义的是 opening premium debit；数值为 0 是已知 basis 和零分母，不是缺失 basis，应由 zero-denominator 语义处理。
- **实际行为**: coverage 被错误降级为 partial/missing，无法区分“已知为零”和“未知”。
- **直接证据**: engine 的 positive-notional guard 和 models 的同类 invariant 都把零值归为错误；`TradeEvent`/ledger economics 允许零 price。
- **影响**: 边界输入产生错误质量标签；效率解释与既有 zero-denominator contract 不一致。
- **建议改法和验证点**: 允许 incremental segment 的已知零 notional；保留非负校验；新增零 premium long option 测试，期望 observed coverage 和 not_applicable efficiency。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
