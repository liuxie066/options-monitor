## Findings

### ADR-01-未修复-[高]-per-account bridges accept aggregate or wrong-account source payloads

- **入口/函数**: `build_portfolio_pnl_bridge -> _account_bridge/_metric_evidence`; `build_portfolio_cash_bridge -> _account_bridge/_option_cash_evidence`
- **文件(行号)**: `src/application/portfolio_pnl_bridge.py:75-115,175-186,206-232`; `src/application/portfolio_cash_bridge.py:75-150,198-209,229-254`
- **输入场景**: a bridge row is requested for `lx`, but the PM fact payload says `account="sy"`, or the option report is an aggregate report with `scope.account=null` while containing observed aggregate CNY PnL/cash.
- **实际分支**: PM fact validation checks status/period/month/end date but never checks `facts.account`. Option evidence rejects only a non-empty account that differs, so an empty aggregate scope passes.
- **预期行为**: every per-account bridge row must require both source payloads to prove the exact requested account. Missing/aggregate scope is not valid single-account evidence.
- **实际行为**: the bridge attributes the foreign or aggregate amounts to `lx`, derives `portfolio_and_other_*`, and can publish an `ok` row and combined total.
- **直接证据**: both `_fact_contract_error` implementations omit account validation; `_metric_evidence` and `_option_cash_evidence` use `if scoped_account and scoped_account != account`, allowing empty scope. The normal caller requests per-account reports, but these builders are the accounting boundary and currently trust dictionary keys rather than payload contracts.
- **影响**: silent cross-account/aggregate double attribution in portfolio cash or PnL bridges.
- **建议改法和验证点**: pass `account` into fact validation; require `facts.account == account`; require `scope.account == account` rather than only rejecting a different non-empty value. Add PnL and cash regressions for aggregate option scope and wrong-account PM facts.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### ADR-02-未修复-[中]-bridge period alignment ignores reporting timezone

- **入口/函数**: the same PnL/cash bridge fact and option-report contract validators
- **文件(行号)**: `src/application/portfolio_pnl_bridge.py:175-186,223-228`; `src/application/portfolio_cash_bridge.py:198-209,245-250`
- **输入场景**: PM facts and option performance use the same `period.kind` and calendar `end_date`, but one payload is UTC (or omits timezone) and the other is `Asia/Shanghai`.
- **实际分支**: the validators compare only kind/date and accept the amounts as aligned.
- **预期行为**: the bridge must prove the same operator reporting boundary. Option Performance v1 defines operator dates in `Asia/Shanghai`, and S9 documents aligned cutoff as a prerequisite.
- **实际行为**: calendar labels can match while the effective cutoffs differ by up to eight hours, allowing activity near the boundary to be assigned to different periods on the two sides of the bridge.
- **直接证据**: PM test fixtures already carry `period.timezone="Asia/Shanghai"`; the real v1 option period carries `reporting_timezone`. Neither bridge validates either field.
- **影响**: incorrect residual or incorrect option/other PnL/cash decomposition around natural-day boundaries.
- **建议改法和验证点**: require PM `period.timezone == "Asia/Shanghai"` and option `period.reporting_timezone` to equal it; fail closed with explicit period-timezone mismatch reasons. Add matching and UTC/missing-timezone regressions for both bridges.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### ADR-03-未修复-[高]-assigned-stock review failures can coexist with observed performance

- **入口/函数**: `build_option_period_performance -> build_period_performance -> _assigned_stock_diagnostics -> _diagnostic_is_relevant`
- **文件(行号)**: `domain/domain/performance/engine.py:321-362,1220-1238,1551-1582`; `domain/domain/assigned_stock.py:840-902,988-1074`
- **输入场景**: (a) a prior-period put assignment has no confirmed stock settlement, so no assigned-stock lot can be built; or (b) a current-period assigned-stock sale targets a valid older lot but fails validation, such as selling more shares than remain.
- **实际分支**: both opening/ending projections retain an `assigned_stock_review_rows` entry. `_assigned_stock_diagnostics` turns it into `context="assigned_stock"`, but derives `event_time_ms` only from the lot's assignment time. Missing-settlement reviews have no lot and get zero; sale conflicts inherit the older assignment time. `_diagnostic_is_relevant` only treats `context="valuation"` as boundary-wide, so it filters these assigned-stock failures out when their derived time is outside the requested period or zero with an event id.
- **预期行为**: unresolved assigned-stock lifecycle reviews present in the opening/ending projections must make the selected account/broker report partial; they can affect inventory, sale cash, realized PnL, and both boundary valuations.
- **实际行为**: the public report still exposes the review row under `assignment_lifecycle.review`, but top-level `quality.warnings` is empty. With proven scope it can promote otherwise empty metrics to observed zero. With complete marks it can publish a numeric observed period PnL while silently omitting the invalid sale.
- **直接证据**: read-only reproductions produced: (1) a May assignment without stock settlement followed by a June report with `scope_proven=True` returned `quality.status="observed"`, `period_total_net.cny=0.0`, and a visible `missing_stock_settlement` review; (2) a June sale of 200 shares against a 100-share May lot returned `quality.status="observed"`, `period_total_net.cny=3500.0`, an empty sales list, and a visible `source_conflict` review.
- **影响**: false observed/zero or incomplete numeric performance for assigned-stock accounts; cash and realized PnL can be omitted without degrading report quality.
- **建议改法和验证点**: treat scoped `assigned_stock` diagnostics from the opening/ending lifecycle projections as report-relevant just like valuation diagnostics. Add service regressions for historical missing settlement under proven-zero semantics and an invalid in-period sale with complete marks/FX.
- **修复风险（低/中/高）**: 中；strict fail-closed behavior may reveal pre-existing lifecycle review debt, which is the intended safety outcome.
- **严重程度（低/中/高/严重）**: 高

### ADR-04-未修复-[高]-portfolio bridges trust an observed metric inside a partial report

- **入口/函数**: `build_portfolio_pnl_bridge -> _metric_evidence`; `build_portfolio_cash_bridge -> _option_cash_evidence`
- **文件(行号)**: `src/application/portfolio_pnl_bridge.py:234-262`; `src/application/portfolio_cash_bridge.py:256-285`
- **输入场景**: a per-account option performance report has `quality.status="partial"` because of a scoped decode, lifecycle, valuation, or evidence warning, while the selected PnL/cash metric still has `status="observed"` and a CNY amount.
- **实际分支**: bridge usability is computed only from the nested metric status and CNY value. `report_quality` is copied into evidence but not used as a gate.
- **预期行为**: a cross-system accounting bridge must not publish a complete amount from a report that explicitly says its selected account/period is partial.
- **实际行为**: the bridge uses the amount, derives `portfolio_and_other_*`, and can return an `ok` equation despite unresolved report-level evidence. ADR-03's invalid-sale reproduction is one real trigger: top-level quality must become partial, but the known valuation subtotal remains an observed metric.
- **直接证据**: both helpers currently assign `usable = status == "observed" and raw_amount is not None` and only later attach `report_quality` to the evidence payload.
- **影响**: report-level fail-closed diagnostics are bypassed exactly at the portfolio integration boundary, allowing incomplete option cash/PnL into authoritative bridge totals.
- **建议改法和验证点**: additionally require `report.quality.status == "observed"`; preserve the nested metric amount/status as evidence but set `usable=false` and bridge step amounts to null for partial/not-observed reports. Add PnL and cash regressions.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

- **ADR-04**: accepted. Report-level partial quality must remain binding at downstream accounting boundaries.
