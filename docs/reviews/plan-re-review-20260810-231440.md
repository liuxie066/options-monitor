### 7-未修复-中-`validate_yield_enhancement_pair` 的 gap 参数与 helper 的 policy gap 行字段去留未写死，删除 `structure_mode` 后会留下同类冗余

- **位置**: plan §7 Domain 接口、Slice 1 Exact allowed changes
- **问题类型**: 契约缺失 / 不可直接实施
- **当前写法**: Finding 3 修复只写了删除 `structure_mode` 参数；未提 `validate_yield_enhancement_pair` 的
  `min_expiry_gap_days` / `max_expiry_gap_days` 参数，也未提 `sell_put_call_helper.py` 的
  `policy_min_expiry_gap_days` / `policy_max_expiry_gap_days` 行字段。
- **反例/失败场景**: 实现 agent 按 plan 只删 `structure_mode` 参数，gap 参数留在 `validate_yield_enhancement_pair`
  签名中（其唯一用途是 staggered 分支 gap 校验，yield_enhancement.py:138-141）；helper 继续输出
  `policy_min/max_expiry_gap_days` 行字段（值来自 `resolve_staggered_expiry_gap_days`，被删后无来源）。
  结果与用户"消除冗余代码"的 goal 冲突，review 不可验收。
- **直接证据**: `yield_enhancement.py:124-126`（gap 参数）、`:138-141`（仅 staggered 分支使用）；
  `sell_put_call_helper.py:804-813`（参数与行字段写入）、`:882-887`（传参）、`:998-1005`（gap 来自
  `resolve_staggered_expiry_gap_days`）；`rg "policy_min_expiry_gap_days|policy_max_expiry_gap_days" src/ domain/`
  除 helper 自身外无任何消费者（含 notify/report/render）。
- **影响**: 冗余残留 / 实现跑偏 / review 不可验收
- **建议改法和验证点**: plan Slice 1 显式加入：删除 `validate_yield_enhancement_pair` 的
  `min_expiry_gap_days`/`max_expiry_gap_days` 参数；删除 helper 中 `policy_min_expiry_gap_days` /
  `policy_max_expiry_gap_days` 行字段与对应参数；`expiry_gap_days` 行字段保留（canonical_schema identity，
  同期值恒为 0，S3 render 路径保留）。验证点：S1 完成后 `rg "policy_min_expiry_gap_days|policy_max_expiry_gap_days"`
  零命中；`validate_yield_enhancement_pair` 签名无 gap 参数。

- **严重程度**: 中
