## Findings

### 1-未修复-低-Combo 空结果 seal 依赖 `capture_statuses` 中的 combo 状态，测试链路未覆盖 run 级 seal
- **位置**: `pipeline_watchlist.py` combo seal 条件；`tests/test_pipeline_watchlist_whitelist.py::test_watchlist_combo_sink_receives_pairs`
- **问题类型**: 测试缺口
- **当前写法**: seal 触发条件是 `capture_statuses` 中存在 `family=combo_yield` 的状态；watchlist 测试只验证 sink 透传，不验证 seal 本身。
- **反例/失败场景**: snapshot 模块单测覆盖 seal/load/空结果/篡改，watchlist 集成测试覆盖 sink 透传，但“combo status 存在 → run 级 seal 生成”这一环没有端到端断言。
- **为什么有问题**: 该条件是空结果封存的关键路径（有状态但无 pairs → no_candidate）；若 `_publish_status` 的 family 拼写或状态值变化，测试抓不住。
- **直接证据**: `symbol_monitoring.py:577-585` 发布 `family="combo_yield", status="completed"`；`pipeline_watchlist.py` 过滤 `item.get("family") == "combo_yield"`。
- **影响**: 低；当前实现正确且 snapshot 单测充分，仅端到端链路缺少一条断言。
- **建议改法和验证点**: 后续可在真实 pipeline 集成测试中补充“combo completed + 无 pairs → no_candidate snapshot”断言；本 slice 记录为 residual risk。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Adversarial Failure Pass

- snapshot 不可变：content hash 篡改即拒绝（测试覆盖）；
- 空结果：`seal_combo_yield_candidate_snapshot` 无 pairs 时 `no_candidate`（测试覆盖）；
- failed 状态：combo 全部失败 → `data_unavailable`；部分失败 → `partial_data`；
- Daily Brief 无 snapshot：`combo_snapshot_unavailable` data gap + `available=False`；
- market 过滤：snapshot market 与 brief market 不匹配 → data gap；
- 多 symbol：sink 聚合全部 symbol pairs，run 级只 seal 一次（once-safely）；
- 旧 CSV 路径：`_load_candidate_family` 的 combo 调用已移除，CSV 不再作为正式读路径。

## Semantic Ownership Drift Pass

- Combo snapshot 是独立模块，不修改 opening snapshot 语义；
- 排序仍由 domain `select_best_yield_enhancement_per_symbol` 唯一负责，Daily Brief 只读 snapshot 的 `ranked_pairs`；
- 新增 sink 沿既有 `final_candidates_sink_fn` 模式，不引入平行机制。

## Residual Risks

- run 级 seal 端到端断言缺失：记录为后续测试补充项（owner：pipeline 集成测试）；
- shadow/research 层仍读 CSV（确认文档 non-goal，保留）；
- 生产 `config.us.json` / `config.hk.json` 未改动（S2 只改 defaults/example/system，运行时配置留到发布阶段）。

## Conclusion
