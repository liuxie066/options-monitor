## Findings

### CR-S4-1-未修复-中-Agent Tool 未实现 accepted coverage/source/freshness 与 masked path 输出契约
- **入口/函数**: `./om-agent run --tool daily_decision_brief_read` -> `_daily_brief_read_tool()` -> `read_daily_brief_view()`
- **文件(行号)**: `src/application/agent_tools/daily_brief.py:18-45,91-115,139-153`
- **输入场景**: Agent/Copilot 读取任一 available、not-found 或 `state_invalid` 日报，并需要判断数据覆盖、来源文件及 freshness；损坏 state 的 repository result 还包含诊断 path/error。
- **实际分支**: `read_daily_brief_view()` 将 repository result 压缩为 `brief/effective_actionability/rendered_markdown`；unavailable 分支仅保留 `reason`。handler meta 只返回 `{"read_only": true}`。
- **预期行为**: accepted plan 的 Agent Tool contract 明确输出 `brief、effective actionability、coverage/source/freshness`，并要求 path 经 `mask_path` 后暴露；available/unavailable 都应提供稳定的结构化 coverage/source/freshness，且不得泄露绝对路径。
- **实际行为**: output contract 与实际 payload 都没有 `coverage`、`source`、`freshness` 或 masked state path。调用者只能重新推断 `brief` 内部字段；unavailable/state-invalid 时无法知道读取的是哪个 masked state artifact，也没有结构化 freshness/coverage。
- **直接证据**: `_OUTPUT_CONTRACT.fact_fields` 未声明这些字段（18-45）；unavailable 返回对象只含 schema/available/reason/query/brief/effective/rendered（91-101）；available 返回同样没有 coverage/source/freshness（103-115）；handler meta 固定为 `read_only`（151-153）。accepted plan `docs/gateflow/daily-decision-brief-plan-20260719.md:196-201` 明确要求这些输出与 `mask_path`。
- **影响**: 公共 Agent contract 静默欠实现；模型/消费者在 unavailable 或状态损坏时缺少可验证来源与 freshness/coverage，容易把 `reason` 当作完整诊断，且后续补字段会变成未计划的 schema 变更。
- **建议改法和验证点**: 在 shared view 中为 available/unavailable 都生成最小稳定 `coverage`、`source`、`freshness`；`source.state_path` 使用 `mask_path(result.get("path"))`；available coverage 至少报告 action/position/data-gap/source-artifact counts 与 status，freshness 报告 data-as-of/valid-until/effective actionability；unavailable 使用 null/zero + reason，不回传原始绝对 path/error。同步 `_OUTPUT_CONTRACT`，并增加 available、not-found、state-invalid/绝对路径不泄漏测试。
- **修复风险（低/中/高）**: 低；纯 read payload 扩展，不改变持久化、通知或 pointer 状态。
- **严重程度（低/中/高/严重）**: 中
