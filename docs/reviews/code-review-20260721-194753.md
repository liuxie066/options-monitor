## Findings

### DR-S4-001 — confirmed delivery did not record an attempt timestamp

- Severity: P2
- Status: 已修复
- Location: `src/application/daily_decision_brief_repository.py::confirm_daily_decision_brief_delivery_v2`
- Entry point: provider returns a confirmed send result.
- Triggering input: exact pending or ambiguous v2 envelope with no previous failed attempt.
- Actual branch: confirmation set `status=confirmed` and `confirmed_at_utc`, but left `last_attempt_at_utc=null`.
- Expected behavior: a confirmed provider attempt is also the latest attempt and must leave complete attempt/confirmation audit timestamps.
- Impact: confirmed envelopes could violate the intended attempt audit contract and make operational diagnosis falsely look like no provider attempt occurred.
- Fix: confirmation now sets `last_attempt_at_utc` to the confirmation time atomically with `confirmed_at_utc`; repository test asserts the persisted timestamp.
- Fix risk: low; no key, message, source, candidate or retry selection semantics changed.
