## Findings

### S3-01-未修复-高-非法事件币种会让整个报表抛异常而不是返回 partial
- **入口/函数**: `build_period_performance` -> `_open_event_facts` / `_close_event_cash_facts` / `_allocation_realized_facts` -> `PerformanceFact.__post_init__`
- **文件(行号)**: `domain/domain/performance/engine.py:69-73, 289-319, 322-373, 376-394, 499-506`
- **输入场景**: canonical `TradeEvent.currency` 为非空但不满足 performance 层 ISO-like 规则，例如 `?`。现有 `TradeEvent` 使用非 strict currency normalization，允许该历史/异常事实进入 projection。
- **实际分支**: `_effective_events` 将事件视为有效；fact builder 把原币种直接传给 `PerformanceFact`；`normalize_currency` 抛出 `ValueError`。
- **预期行为**: 缺失或非法币种属于 evidence/quality 不完整。相关 monetary fact 应 fail closed、金额不可用并标记 partial；已知 activity、其他币种事实和诊断仍应返回。报表读路径不得因单条坏事实整体失败。
- **实际行为**: `build_period_performance(...).to_dict()` 整体抛出 `ValueError: currency must be an uppercase ISO-like code`，调用方得不到任何 period report。
- **直接证据**: `TradeEvent.__post_init__` 调用的是 `domain.domain.option_position_identity.normalize_currency(..., strict=False)`，未知值原样保留；S3 `PerformanceFact.__post_init__` 无条件使用更严格的 `domain.domain.performance.models.normalize_currency`。本次反例探针构造 `currency='?'` 的有效 open event，稳定复现整份报表异常。
- **影响**: 任一历史坏币种记录可使 Agent/CLI/analysis 的整个期间收益查询不可用，违反“missing data explicit；never invent zero”和读报表 fail-closed contract。
- **建议改法和验证点**: 在 performance fact normalization 边界安全解析币种；仅允许 `amount is None + missing_reason` 的 monetary fact 使用 unknown currency，或建立等价的 explicit missing representation。event cash、fee、allocation realized、stock settlement 四条路径都要覆盖。增加 invalid/empty event currency 及 invalid allocation currency tests，断言 gross/net/cash 对应 metric 为 partial 而非异常，且合法其他币种 subtotal 保留。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

### S3-02-未修复-中-负数交割股数被 abs 静默转正并生成错误现金流
- **入口/函数**: `build_period_performance` -> `_stock_settlement_facts`
- **文件(行号)**: `domain/domain/performance/engine.py:447-464`
- **输入场景**: assignment/exercise 的 `raw_payload.stock_settlement` 提供 `side='buy'`, `shares=-100`, `price=100`。
- **实际分支**: 代码先验证股数为整数，随后执行 `shares = abs(int(shares_decimal))`；负数被转为 100，`shares <= 0` 校验无法发现异常，最终生成 `USD -10000` observed cash。
- **预期行为**: settlement `side` 已承载方向，`shares` 必须是严格正整数；负数是 malformed evidence，应使 stock settlement cash partial/null，同时不影响已成立的 option realized PnL。
- **实际行为**: 返回一笔不存在的 observed stock principal cash movement，现金方向和金额看似合法，quality 不会提示异常。
- **直接证据**: `abs` 位于正数校验之前。反例探针稳定返回 `stock_settlement_cash_gross.by_currency == {'USD': -10000.0}` 且 status 为 observed。
- **影响**: assignment cash bridge/period cash 可被错误增加或减少整笔股票本金；这是静默财务错误而非仅展示问题。
- **建议改法和验证点**: 不对 shares 取绝对值；先要求 decimal 为整数且 `> 0`，再转换为 int。增加 negative/zero shares tests，断言 settlement cash partial、option realized 保持 observed、total net cash 对该币种不可用。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
