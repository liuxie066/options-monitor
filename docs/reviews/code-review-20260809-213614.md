### DR-S3-01-未修复-中-语义输入 hash 包含每轮时间戳，会让内容未变的 Advice 永远无法复用
- **入口/函数**: `build_frozen_inputs()` -> per-input hashes -> S4 `find_reusable_completed()` exact binding comparison
- **文件(行号)**: `src/application/ai_decision_advice/contexts.py:259-325, 455-463, 583-598, 736-743, 878-881`; `src/application/prepared_option_positions_context.py:148-150, 266-275`
- **输入场景**: 相邻两次 Tick 的候选、PM 分布、开放期权、覆盖状态和证据语义全部不变；只有 option `source_observed_at`、evidence `frozen_at/last_checked_at`，或 PM `observed_at_utc` 更新。
- **实际分支**: option model 直接携带每轮新生成的 `source_observed_at`；portfolio/external/fact-registry 也保留观察或冻结时间。`build_frozen_inputs()` 对整个对象做 JSON hash。
- **预期行为**: 时间仅作质量与审计元数据；语义 hash 应覆盖分布内容、持仓内容、质量/覆盖状态和证据语义。设计 13.2 明确要求仅 `last_checked_at` 变化时仍可复用。
- **实际行为**: 即使投资事实一字未变，`option_positions_hash`、`external_evidence_hash` 及 `fact_registry_hash` 也会变；S4 按已批准方案做 exact binding reuse 后，每轮都会重新调用模型。
- **直接证据**: prepared option producer 每轮用 `datetime.now()` 生成 `source_observed_at`；option model 将其序列化在第 881 行，第 591 行对完整 model hash。External model 包含 `frozen_at` 和 `last_checked_at`，第 592 行同样 hash 整体；fact registry 又复制这些时间并在第 598 行 hash。
- **影响**: 设计中的跨 Tick 复用失效，增加模型调用、30 秒等待、费用和输出随机噪声；用户之前明确关心的耗时边界也被实质破坏。
- **建议改法和验证点**: 保留时间字段给模型与审计，但为 binding 定义显式 semantic view；排除 `observed_at_utc/source_observed_at/frozen_at/last_checked_at/last_success_at` 等非实质时间，仍包含 freshness/trust/coverage/unavailable/evidence 内容。新增回归：只改时间时所有 reuse binding 不变；改变质量状态、持仓、投影、覆盖状态或证据内容时对应 hash 必须变化。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### DR-S3-02-未修复-中-组合标签跳过 ledger 的 exact membership 事实，冲突组也会被声称为已验证 SP+LC
- **入口/函数**: `_freeze_option_positions()` -> `_verified_structures()`
- **文件(行号)**: `src/application/ai_decision_advice/contexts.py:872-877, 981-1044`; `src/application/ledger/decision_snapshot.py:366-385`
- **输入场景**: identity 自身 hash 合法，两个指定 record 仍带同一 group id，但 ledger 的 `account_combo_group_memberships` 已因额外成员、retag 历史、跨账户/跨标的或成员不一致标为 `conflict`；或 identity 中的 contract key 与当前 record 经济合约不符。
- **实际分支**: `_verified_structures()` 只校验 identity hash、record id、group id、类型/方向和 symbol；它完全不读 `account_combo_group_memberships`，也不对比 identity contract keys。
- **预期行为**: 只有 ledger 已解析为 `status=exact`、当前成员与 identity 一致且合约键相符的 group 才能对模型声称“已验证结构”；其他情况不得猜配。
- **实际行为**: 冲突或过期 group 仍会输出 `label=SP+LC` 和腿比例，并生成 `position:structure:*` 可引用事实。
- **直接证据**: prepared loader 的 snapshot contract 只要 membership 行自身结构合法即可接受，包括自洽的 `conflict` 状态；`_verified_structures()` 从第 988 行起仅读 `account_combo_identities`，第 1017-1028 行的成员判断没有 membership status/hash 或 contract-key 判断。
- **影响**: 模型可能把未验证或已分解的持仓当成成套结构，错判现有风险对冲/表达关系，进而支持错误的 `keep/switch/defer` 理由。
- **建议改法和验证点**: 以 `account_combo_group_memberships` 为 membership 唯一语义 owner；要求对应 group 通过 `validate_combo_group_membership()`、`status=exact`、当前 record ids 与 identity 两腿严格相等，再对比 identity contract keys 与当前 row。回归覆盖 exact、conflict、missing membership、contract-key mismatch 和可靠 identity hash 篡改。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

### DR-S3-03-未修复-中-完整 PM 分布中的真实零暴露和负权重被静默改成缺失
- **入口/函数**: `project_one_contract()` current concentration projection
- **文件(行号)**: `src/application/ai_decision_advice/projection.py:40-54, 298-305`; `src/application/prepared_portfolio_distribution.py:689-697, 732-767`
- **输入场景**: Sell Put 候选标的尚未持有，因此完整 PM `asset_weights` 中没有该 symbol；或 PM 合法地表达负现金/做空仓位权重。
- **实际分支**: 对 map 直接 `.get()`，缺 key 得到 `None`；`_nonnegative_float()` 又把任何负数改成 `None`。两者都不生成 gap。
- **预期行为**: 当 portfolio status 为 ready/degraded 时，完整 map 中缺失的 symbol/currency 表示真实零权重；prepared PM v1 允许有限负 value，所以导出的负权重也应原样保留。只有 unavailable 输入才是未知。
- **实际行为**: 常见的“愿意接货但当前未持有”候选输出 `current_symbol_weight=null`，负现金/做空暴露也被隐去，但 scope 仍被标成计算完整。
- **直接证据**: prepared PM 只要 quantity/value 有限即可接受，没有非负限制，并直接用 value/total 生成权重；projection 第 48-54 行不设完整输入的零默认，第 305 行明确拒绝负数。
- **影响**: 模型无法区分“零暴露”和“数据缺失”，并会低估负现金或做空情况，扭曲 Sell Put 集中度与组合承受能力的解读。
- **建议改法和验证点**: 在 ready/degraded 上下文中对不存在的 symbol/currency 使用 `0.0`，并用“有限有符号数”保留真实负权重；unavailable 仍返回 `None`。新增零持仓、负现金/负资产权重和 unavailable 三类回归。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### DR-S3-04-未修复-中-候选标的期权明细二次聚合时丢掉 multiplier 维度
- **入口/函数**: `_freeze_option_positions()` economic aggregation -> model-visible `candidate_contracts`
- **文件(行号)**: `src/application/ai_decision_advice/contexts.py:793-820, 846-870`
- **输入场景**: 同一候选标的存在同 option type/side/strike/expiry 但 multiplier 不同的标准与调整合约。
- **实际分支**: 第一次 `aggregates` 正确以 multiplier 作为第六个 key；但构建 `public_contracts` 时 key 只剩 symbol/type/side/strike/expiry，随后把不同 multiplier 的张数相加。
- **预期行为**: S3 方案规定按 `symbol+option_type+side+strike+expiry+multiplier` 保留经济合约身份；调整合约不得被并成一个普通合约张数。
- **实际行为**: 模型看到一个虚构的合并明细，无法区分每张对应的真实交割规模；确定性 projection 则仍保留两行，使 model detail 与投影事实不一致。
- **直接证据**: `aggregates` key 在第 800-807 行含 `multiplier_key`；`public_key` 在第 852-858 行不含 multiplier，输出行在第 861-868 行也不包含 multiplier。
- **影响**: 调整期权或非标准交割物场景下持仓规模和履约风险被错述，可能让 AI 基于不存在的聚合合约做决策。
- **建议改法和验证点**: `candidate_contracts` 保留 multiplier 并继续以六维经济键排序/输出；新增同 strike/expiry、不同 multiplier 的回归，断言两行分开且张数各自正确。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
