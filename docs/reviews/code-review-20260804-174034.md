## Findings

### DR-01-未修复-中-非有限数值可绕过畸形记忆 fail-open 并持续击穿同一飞书会话
- **入口/函数**: `handle_assistant_request()` -> `run_channel_request()` -> `run_prepared_contract()` -> `prepare_contract_with_existing_memory()` -> `CopilotHostStore.session_memory()`
- **文件(行号)**: `src/application/copilot/conversation_memory.py:17-20`; `src/application/copilot/host_store.py:108-118,121-151`; `src/application/copilot/channel_facade.py:86-105`; `tests/test_copilot_conversation_memory.py:70-101`
- **输入场景**: 已存在会话的 `memory_json.version` 或 `memory_json.compacted_turn_count` 是非有限数值，例如 `Infinity` 或 JSON 数值 `1e309`。现有 `update_session_memory()` 使用默认 `json.dumps()`，也可把 Python `float("inf")` 持久化为 `Infinity`。
- **实际分支**: `json.loads()` 将该值解析成浮点无穷大；`session_memory()` 随后执行 `int(...)`，抛出 `OverflowError`。新增的 fail-open 只捕获 `TypeError` 和 `ValueError`，所以异常继续传播到渠道 facade，并被统一转成 `CHANNEL_RUN_FAILED`。
- **预期行为**: 按计划和设计契约，任何缺失或畸形的 stored memory 都应保持原值、返回未注入记忆的原合同，并继续执行唯一一次主模型请求。
- **实际行为**: 主模型不会被调用，用户收到“Copilot 渠道执行失败”；该非空失败文本随后被记录为新 turn，但损坏的 `memory_json` 不变，因此同一会话的后续请求会重复失败，直到人工修复存储。
- **直接证据**: `conversation_memory.py:19` 的异常集合不含 `OverflowError`；`host_store.py:115-116` 对两个游标字段无条件调用 `int()`；`channel_facade.py:94-105` 把异常折叠为失败并记录该失败 turn。只读复现使用 `{"version":1e309,"compacted_turn_count":0,"pinned_state":{},"episodes":[]}`，稳定得到 `OverflowError: cannot convert float infinity to integer`。现有参数化测试只覆盖坏 JSON 和触发 `ValueError`/`TypeError` 的字段形状，没有覆盖非有限数值。
- **影响**: 单个持久化会话会进入可重复、无自动收敛的用户可见失败；同时直接违反本 work unit 的 malformed-memory 验收契约。
- **建议改法和验证点**: 在 `CopilotHostStore.session_memory()` 的存储所有权边界集中做严格、不会抛异常的 memory normalization：拒绝非有限数字，安全归一化 `version`/`compacted_turn_count`，并验证 pinned/episodes 容器类型；最小补丁至少还需覆盖 `OverflowError`。新增通过 `update_session_memory()` 写入 `float("inf")` 以及直接写入 `1e309` 的参数化回归，并增加渠道级断言：仍只调用一次主模型、返回 answered、原始 memory/turns 不被准备阶段改写。
