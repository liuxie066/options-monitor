### 1-已修复-高-Combo Yield 独立启用时没有真正执行 Funding Put underwriting，且 required-data 不请求必需的 RV

- **实际分支**: Combo policy 声称 `derived_from_sell_put_strategy=insurance_underwriting`，但 facade 将原始 `sell_put_cfg` 原样作为 `yield_sp` 传给 underwriting。`resolve_sell_put_underwriting_config()` 得到空 strategy 后返回 disabled config，过滤函数直接返回未 underwrite 的候选。同时 policy 把 `requires_realized_volatility` 固定为 `False`，required-data 计划不会为独立 Combo 请求 RV。
- **预期行为**: Combo 的 Funding Put 无论 Sell Put step 是否启用，都必须以唯一的 `insurance_underwriting` 语义执行收益、净收入、IV/RV、事件和价格边界门槛，并获取该门槛所需的 RV。
- **实际行为**: 独立 Combo 要么绕过 Funding Put 的净收入和波动率优势硬门槛，要么在其他路径依赖 RV 时因字段缺失被筛空；policy 声明、数据计划和执行语义不一致。

- **影响**: Combo Yield 的独立策略边界不成立，正式推荐可能绕过硬门槛或稳定产出空集，属于开仓推荐正确性问题。
- **建议改法和验证点**: facade 用 policy 明确构造 Funding Put underwriting config；policy 将 RV 标记为必需；补充 Sell Put disabled 且无 strategy 时仍传入 `insurance_underwriting`、required-data 仍请求 RV、低于 underwriting 门槛会被拒绝的回归测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高
- **修复状态**: 已修复。`combo_yield_steps.py:434-450` 强制把 policy 的 underwriting strategy 写入 Funding Put config；`yield_enhancement_config.py:225-238`、`required_data_planning.py:682-686` 和 `required_data_prefetch_planning.py:267-270` 统一要求 RV。新增 Combo-only 回归测试并通过。

### 4-已修复-中-省略 strategy 时验证器没有按运行时默认 insurance_underwriting 检查 event fail-closed 冲突

- **预期行为**: 配置验证与运行时采用同一缺省 strategy；该组合应在 build/validate 阶段明确拒绝。
- **实际行为**: 配置通过后，候选在 runtime 因 event source unavailable 被 fail closed，表现为难以解释的空推荐。
- **直接证据**: validator 只有显式存在 `strategy` 才赋值，而 conflict guard 要求 `strategy == 'insurance_underwriting'`；runtime resolver 对空值直接使用该 profile。
- **影响**: 同一配置在验证和执行阶段语义不一致，错误被延迟为业务空结果。
- **建议改法和验证点**: validator 先解析 effective strategy，缺省为 `insurance_underwriting`；增加省略 strategy 的冲突测试，并保留显式 `event_source_fail_closed=false` 的允许路径。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
- **修复状态**: 已修复。`config_validator.py:345-379` 与 runtime 使用同一默认 strategy；冲突拒绝和显式 fail-open 允许路径均有测试。
