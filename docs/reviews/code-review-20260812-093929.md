## Findings

### CR-PR-01-未修复-高-紧凑固定简报会静默丢弃已封存的期限匹配 RV 硬证据缺失

- **入口/函数**: `build_daily_brief_user_view()` -> `_fixed_report_error_reminders()`
- **文件(行号)**: `src/application/daily_decision_brief_renderer.py:116,163-168,1612-1670`
- **输入场景**: sealed opening snapshot projects a strategy gap with
  `reason=opening_candidate_strategy_partial_data` and
  `reason_code=term_matched_rv_unavailable`.
- **实际分支**: the compact fixed-report reminder allowlist keeps only prefetch failures, strategy-step failures,
  and snapshot availability failures. It drops every `opening_candidate_strategy_partial_data` row, including the
  stable RV hard-evidence code that this work unit deliberately propagated.
- **预期行为**: generic partial-data noise may remain hidden, but a known sealed hard-evidence cause must render the
  specific Chinese RV explanation. The renderer must not reinterpret it as a generic fetch failure.
- **实际行为**: the structured Brief retains the RV cause while the scheduled user-facing fixed report silently
  removes it, recreating the original “RV 问题怎么没体现” failure at the final delivery projection.
- **直接证据**: `_PARTIAL_DATA_REASON_TEXT` already recognizes the stable RV code and the non-compact renderer can
  render it, but `_fixed_report_error_reminders()` never consults that map.
- **影响**: an incomplete Sell Put or Covered Call universe can look like a clean zero-candidate result in the exact
  scheduled card the user receives.
- **建议改法和验证点**: keep generic partial gaps suppressed, but allowlist only recognized stable hard-evidence
  `reason_code` values and render their specific text. Add a fixed-card regression containing one recognized RV gap
  and one generic partial gap; assert only the RV reminder survives.
- **修复风险**: low
- **严重程度**: high

### CR-PR-02-未修复-中-全局 AI 未完成提示会抹掉无候选策略自己的排序事实

- **入口/函数**: `_render_user_view()` / `_render_user_view_card()` -> `_fixed_report_ai_notice()`
- **文件(行号)**: `src/application/daily_decision_brief_renderer.py:490-565,672-713,866-886`
- **输入场景**: AI Advice is `unavailable`; Covered Call has canonical candidates while Sell Put has none.
- **实际分支**: latest-main compact rendering removes unavailable AI families from `ai_visible_families`, so only
  the candidate-bearing Covered Call module remains. `_fixed_report_ai_notice()` sees at least one rendered candidate
  and emits one global “以下仅为策略排序” line. The absent Sell Put module can no longer say that it has no raw
  ranking.
- **预期行为**: keep the one-line global compact notice, but preserve both strategy modules and use canonical
  per-family candidate presence. The empty family must say there is no displayable strategy ranking; a candidate
  family must not repeat the unavailable boilerplate.
- **实际行为**: the compact report collapses a per-family fact into an any-family fact and omits the empty strategy
  entirely.
- **直接证据**: the pre-budget `_ai_raw_candidate_presence` map exists, but the global notice reads the truncated flat
  list and the fixed-report visibility predicate explicitly excludes `status=unavailable` families.
- **影响**: a report with one empty and one non-empty strategy can again imply that raw rankings exist uniformly,
  contrary to the work-unit success signal.
- **建议改法和验证点**: preserve AI-visible SP/CC modules, drive the global notice from canonical raw presence, and
  compact the per-family unavailable lines into either no line (candidate exists) or “本轮无可展示的策略排序”。
  Cover legacy fixed markdown and compact-card projection.
- **修复风险**: medium
- **严重程度**: medium

### CR-PR-03-未修复-中-opening 状态缺失时确定性经济拒绝投影可能 fail open

- **入口/函数**: `_calculation_decision_record()`
- **文件(行号)**: `src/application/candidate_scanning.py:138-159`
- **输入场景**: the projection helper receives `opening_contract_status=""` together with the stable calculation
  reason `net_premium_non_positive`, for example through an injected scan dependency or a future caller whose
  readiness gate drifts.
- **实际分支**: `if opening_status and opening_status != "ready"` treats an empty status like ready and maps the
  calculation reason to `policy_rejected`.
- **预期行为**: only explicit `ready` may enter the definitive economic-reject allowlist. Missing readiness evidence
  must remain `input_invalid` and unresolved.
- **实际行为**: the helper can seal a clean policy rejection without proving the opening-readiness precondition.
- **直接证据**: Candidate Engine currently prevents this combination in the normal call path, but the application
  projection function is independently callable through injected `CandidateScanDependencies`; its own condition does
  not enforce the contract it documents.
- **影响**: a future or test adapter can turn missing readiness evidence into lawful `no_candidate`, weakening the
  fail-closed boundary.
- **建议改法和验证点**: require `opening_status == "ready"` before applying the definitive-reason allowlist, preserve
  canonical non-ready reasons, and add an empty-status regression that remains `input_invalid` / unresolved.
- **修复风险**: low
- **严重程度**: medium
