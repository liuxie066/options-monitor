## Findings

### 1-未修复-中-新 binding 字段仍可以由旧 `portfolio_context_hash` 静默充值

- **入口/函数**: `run_decision_advice()` -> `FrozenInputs.input_bindings()`
- **文件(行号)**: `src/application/ai_decision_advice/advice.py:218-220,282-295`;
  `src/application/ai_decision_advice/contexts.py:79-87`
- **输入场景**: 调用者传入一个仅填写旧
  `portfolio_context_hash` 、而 `portfolio_distribution_hash=""` 的
  `FrozenInputs`；其他新事实注册表字段有效。
- **实际分支**: `input_bindings()` 用
  `portfolio_distribution_hash or portfolio_context_hash` 生成名为
  `portfolio_distribution_hash` 的输出键。`run_decision_advice()` 只检查键集合，
  因此会把这份 legacy-only 输入当作新正式 binding，并可能调模型、
  落新记录及参与复用。
- **预期行为**: S4 Advice 入口必须要求直接的新
  `portfolio_distribution_hash` 和 `fact_registry_hash`；旧字段只能留给尚未切换的
  内部调用者，不能伪装成新 Advice binding。
- **影响**: 违反已批准计划“旧 binding 不作为新正式记录的兼容输入”；
  后续 S6 或其他调用者回归到旧输入时不会 fail closed，也会让旧/新 PM
  数据权威边界在审计记录中无法区分。
- **建议改法和验证点**: 在 Advice 入口检查
  `frozen.portfolio_distribution_hash` 和 `frozen.fact_registry_hash` 本身是非空字符串，
  不通过时在模型调用前持久化 `unavailable: input_bindings_invalid`。新增回归测试
  证明 legacy-only 对象不调模型，同时正式 S3 builder 输出仍通过。
- **修复风险**: 低
- **严重程度**: 中

### 2-未修复-低-共享预算已不足以发起第二次调用时仍记为已修复

- **入口/函数**: `run_decision_advice()` repair loop
- **文件(行号)**: `src/application/ai_decision_advice/advice.py:344-387`
- **输入场景**: 首次模型返回 `incomplete_output`，校验后账户截止时间只剩
  0 到 1 秒。
- **实际分支**: 首次末尾只检查 `clock() < deadline` 就把
  `repair_attempted=True`；第二轮又因 `remaining < 1` 直接退出，没有发起第二次
  provider 调用。
- **预期行为**: `repair_attempted` 只在第二次模型调用实际开始前置为
  `true`；共享预算不足时记录 `timeout` 且保持 `false`。
- **影响**: 不改变投资动作，但会让格式修复审计记录误报一次从未发生的
  provider 调用，与“同一 30 秒账户总预算”的可审计要求不一致。
- **建议改法和验证点**: 由每轮开头统一检查剩余预算，只在
  `attempt == 2` 且检查通过后标记 repair。新增子秒级剩余预算回归测试，
  证明只有一次 model call 且 `repair_attempted=false`。
- **修复风险**: 低
- **严重程度**: 低
