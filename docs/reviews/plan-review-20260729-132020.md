## Previous finding closure

2. watchlist 外持仓 routing 只接受 resolved runtime binding，不使用隐式 endpoint；

### Second review

第二轮 2 个 findings 已实质关闭：

1. **PR2-01 candidate route precedence**：plan §7.1 现在先构造并保留既有 candidate binding set；单一 candidate binding 与 position binding 冲突时，只拒绝冲突 position requirement，candidate fetch 保持一次且 route 不变。只有没有 candidate demand 且 position-only bindings 互相冲突时，才不 fetch 该 symbol。candidate config 本身已经多 route 时，plan 保留既有 candidate items，并把 ambiguity 留给独立 config-validation tracking。
2. **PR2-02 Close Advice eligibility**：plan §5、§6 和 S2 现在只为 effective `close_advice.enabled=true` 的 scanning accounts 读取 ledger、构造 requirements 和参与 status denominator；disabled account 显式记录为 `not_applicable`，不影响 routing、budget、fetch payload 或 plan identity。

对应的回归断言已补到 §10.4：candidate + conflicting position 保留 candidate fetch；position-only conflict 不 fetch；disabled account 的 active positions、missing binding 或 divergent route 均不能改变 enabled consumer 的计划。

## Assumptions tested

1. **新增 Close Advice requirement 不能降低既有 candidate availability**：通过。§7.1 定义 candidate-first precedence，§7.3、S3 和 §10.4 都有同向验收，不再存在“保留 demand”与“整 symbol 不 fetch”的矛盾。
2. **只有实际运行 Close Advice 的账户产生 position requirements**：通过。eligibility 来自 barrier 前已经构造的 effective account runtime config；这与当前 `account_run.py` 仅在 `close_advice.enabled=true` 时调用 Close Advice 的行为一致。
3. **Position-only route conflict 不会让两个 endpoint 写同一 shared symbol path**：通过。无 candidate demand 且 bindings 不一致时，所有冲突 requirements typed unavailable，fetch count 为 0。
4. **Candidate config 的既有多 route ambiguity 不会被本 work unit 静默“修复”或放大**：通过。plan 不选择、删除或合并既有 candidate items，只拒绝 position exact-contract injection，并要求诊断和后续 config-validation tracking。
5. **Integrity failure 可以复用现有 Daily Brief reliability authority**：通过。plan 继续使用 `AccountRunOutcome.ran_pipeline=False -> ran_pipeline_accounts -> pipeline_succeeded=false`，与当前 notification flow 的可靠性判定点一致。
6. **Frozen receipt 是唯一 freshness/provenance authority**：通过。plan 禁止 mutable `.meta.json` 推翻已验证 manifest/receipt，也禁止它恢复 invalid receipt。
7. **Requirements artifact 可以安全重入且不发生 live replanning**：通过。safe relpath、schema/run/content/file hash、business date 和 manifest binding 均有明确验证；失败分支禁止 ledger reread、prefetch 和 post-seal fallback。
8. **方案保持一个 prefetch owner**：通过。position requirements 是 planning-only input，最终通过现有 side-plan merge 进入一次 `prefetch_required_data()`；没有第二条 network path、cache 或 receipt authority。

## Special review lenses

### Architecture boundary review

边界清晰且依赖方向合理：

- ledger I/O 和 effective-account orchestration 留在 application barrier；
- 新 helper 只拥有 canonical requirement/lifecycle 纯语义；
- market-data binding 解析和 candidate/position merge 留在 required-data planning owner；
- Close Advice 只消费 sealed snapshot；
- Daily Brief 继续拥有 notification reliability authority。

修订后的 candidate-first precedence 使依赖保持单向：Close Advice 可以复用 candidate route，但 Close Advice-specific failure 不能反向撤销 candidate authority。

### Best-practice review

计划采用 fail-closed integrity、position-scoped ordinary gap、canonical hash、deterministic ordering、commit-marker-last、pending/failed stale-success invalidation 和 manifest-bound recovery。新增 eligibility 在读取 ledger 前裁剪无消费者需求，符合 demand-driven planning 和最小权限原则。

### Optimal-solution review

当前方案是针对已确认根因的最小完整 root fix：把运行期补拉提前到唯一 seal 前 barrier，并让两个 consumer 读取同一不可变事实。无需新增 broker routing registry、多 endpoint output namespace、第二套 cache 或跨进程锁。

### Overengineering review

requirements artifact、report status marker 和 `not_applicable` 状态都有直接的审计、恢复或 stale-success 防护用途。计划同时明确不冻结整个 position context、不改 thesis/policy、不引入通用 snapshot framework，并把既有 candidate multi-route ambiguity 留给独立工作，范围控制合理。

### Overcoupling review

第二轮发现的过度耦合已解除：

- disabled Close Advice account 不再进入 ledger/routing/budget；
- conflicting position route 只影响对应 position requirement；
- candidate config 自身 ambiguity 不由 Close Advice work unit 改写；
- account-level integrity failure 只阻断受影响账户，未受影响账户仍可 reliable。

## Residual risks and suggested tracking

- **Existing candidate multi-route ambiguity**：本 work unit 保留当前 candidate items，因此既有配置若让同一 symbol 指向多个 endpoint，原有 shared-output 风险仍可能存在。按 plan 记录 `candidate_route_ambiguous`，建立独立 config-validation issue；不要在本修复中猜选 route。
- **Off-watchlist positions**：找不到 resolved binding 的 position 会 `required_data_symbol_config_missing` 并 not-evaluable。跟踪该 metric；只有持续发生且有明确 authoring contract 时再扩展配置。
- **External writer race**：plan 能在消费/发布前检出 bytes mismatch 并阻断受影响账户，但不能阻止进程外 writer。继续跟踪 integrity audit，不在本 work unit 引入跨进程锁。
- **Rate-limit growth**：exact position expirations 可能增加 chain calls。实施时核对 dedup 后 symbol/expiration/contract counts、budget waves 和等待时间。
- **Dirty worktree overlap**：实施前检查计划列出的 core files 是否已有未归属修改；如重叠，先确认所有权或使用独立 clean worktree。

## Conclusion

**pass-with-risks**

第二轮的 candidate route precedence 和 Close Advice eligibility 缺口已关闭，且相应验收覆盖了冲突、disabled account、order independence 和 single-prefetch invariants。计划现在具有一致的 authority 边界、失败隔离、恢复契约和可执行切片，可以交给 implementation；上述 residual risks 应按各自 tracking/stop condition 管理，不需要扩大本 work unit。
