## Findings

### CR-S1-01-未修复-高-Combo Funding Put 的硬证据缺口在状态链中被折叠为干净无候选

- **入口/函数**: `process_symbol()` -> `run_combo_yield_for_symbol_and_summarize()` ->
  `run_combo_yield_scan_and_summarize()` -> `enrich_and_filter_sell_put_underwriting()` ->
  `_yield_snapshot_status()` -> `_load_combo_yield_snapshot_family()`
- **文件(行号)**: `src/application/combo_yield_steps.py:232-293`;
  `src/application/symbol_monitoring.py:590-644`; `src/application/pipeline_watchlist.py:288-305,1042-1056`;
  `src/application/daily_decision_brief_service.py:775-823`
- **输入场景**: Combo Yield `sp_lc` 已启用；一张 Funding Put 通过扫描/资金门槛，但其
  `earnings_evidence_status=data_unavailable` 且没有其他确定拒绝原因。反例也包括“一张已完整证明的
  Funding Put 可配对，另一张因硬窗口缺口未决”的部分候选集。
- **实际分支**: Combo 调用 underwriting 时没有传 `decision_sink_fn`，扫描时也没有传
  `calculation_decision_sink_fn`，因此只得到过滤后空 DataFrame。`symbol_monitoring` 对 `sp_lc` 返回无条件设
  `combo_capture_status="completed"` 且 reason 为空。`_yield_snapshot_status()` 只看 status 集合，全部
  `completed` 时返回 `None`，最终空 Combo snapshot 自动封存为 `no_candidate`。Daily Brief 加载器忽略
  snapshot `opening_status`，对任何成功加载的 snapshot 都返回 `available=True`。
- **预期行为**: Combo Funding Put 应像 Sell Put/Covered Call 一样区分确定拒绝与结果未决；纯
  hard-window 缺口且零候选应封存为 `data_unavailable`/`partial_data`，有已证明配对时应保留配对
  并披露 partial universe。
- **实际行为**: 交易安全上该 Funding Put 会 fail closed，但外部状态与 Daily Brief 把“无法判定”
  表达为“已完整扫描且无候选”，也不会显示部分范围警告。
- **直接证据**: `combo_yield_steps.py:283-289` 的 underwriting 参数中缺少 decision sink；
  `symbol_monitoring.py:602-603` 在非 `cc_lp` 分支固定 completed/None；
  `pipeline_watchlist.py:298-300` 在 states 仅 completed 时忽略 reason 并返回默认状态；
  `combo_yield_candidate_snapshot.py:173-177` 会把空 pairs 默认成 `no_candidate`；
  `daily_decision_brief_service.py:805-823` 既不根据 `opening_status` 标记 gap，也始终返回 available。
- **影响**: 直接重现本 work unit 要消除的状态错分类：用户会把 OpenD 硬证据缺口误认为真实
  零候选，混合范围也会被表述为完整候选集。这不会放行不安全交易，但会产生错误的决策简报和审计状态。
- **建议改法和验证点**: 在 Combo Funding Put 扫描和 underwriting 中捕获同一套 per-contract decisions，
  复用候选证据聚合/状态投影，将 `_strategy_status`/`_strategy_reason` 传到 `symbol_monitoring`；
  `_yield_snapshot_status()` 需识别 completed+partial reason，Daily Brief 需尊重 Combo snapshot/status index 的
  `partial_data`/`data_unavailable`。增加真实链路回归：纯硬窗口缺口+0 pair 不是 no-candidate；
  valid pair+未决 sibling 保留 pair 且告警；财报缺口+其他确定拒绝仍是干净确定结果。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高
