# Plan Review

## Reviewed Target and Scope

- Target: `docs/plans/feishu-agent-response-latency-critical-path-plan-20260804-171723.md`
- Scope: removal of synchronous memory compaction from the Feishu/Copilot response critical path, compatibility of existing structured memory, validation gates, delivery boundaries, and deferred long-term-memory work.
- Review mode: adversarial plan review; no implementation review.

## Assumptions Tested

1. Existing structured memory can remain stale without becoming execution authority.
2. Recent conversation context remains available independently of compaction.
3. Removing the pre-run compaction call does not require a storage migration, background worker, or Feishu protocol change.
4. The proposed timestamps can distinguish critical-path overhead from main-model and delivery latency.
5. Long-term memory restoration can safely remain outside this latency work unit.

## Review Lenses

- **Architecture boundary**: the plan keeps the change inside Copilot memory preparation and its harness; channel transport, reply outbox, provider settings, and storage schemas remain unchanged.
- **Best practice**: optional, failure-prone LLM maintenance is removed from the user-facing critical path; existing context fails open and current facts remain tool-backed.
- **Optimal solution**: the plan solves the measured latency mechanism directly rather than introducing an unproven background-delivery system.
- **Overengineering**: no queue, worker, state machine, migration, configuration surface, or public API is added.
- **Overcoupling**: Feishu and future channel adapters do not acquire memory-worker lifecycle responsibilities.

## Findings

No material findings.

The prior review blockers are resolved:

- there is no job-target coalescing or late-completion race;
- there is no background provider call that can contend with foreground chat;
- there is no turn-sequence/job-enqueue transaction to specify;
- durable compaction delivery is no longer assumed necessary;
- the root-cause gate is separated from the external-provider-dependent user SLO.

## Open Questions

None blocking implementation.

## Residual Risks and Tracking

- Structured long-term memory will no longer advance. Track this as a separate memory-quality work unit only after an offline evaluation demonstrates a material regression beyond the recent-message window.
- The 8-second user SLO still depends on the main model and Feishu delivery. If the root-cause gate passes but the SLO fails, route the evidence to provider/transport diagnosis rather than reverting this fix.
- The current sliding-array compaction cursor remains unsuitable for any future writer. A future compaction plan must replace it with stable turn identity before re-enabling writes.
- Twenty natural requests may take time to accumulate; deterministic tests and the root-cause timing gate establish source correctness, while the production SLO remains a post-upgrade observation gate.

## Conclusion

`pass-with-risks`

The plan is implementation-ready for the scoped latency fix. Residual risks are explicit, non-authoritative, and intentionally deferred rather than hidden inside the current work unit.
