## Contract and Entry-Point Review

### Notification entry point

Traced:

```text
run_tick_notification_flow
  -> _prepare_daily_brief_notification
  -> decide_daily_brief_notification
  -> render_fixed_report | render_candidate_alert | render_fixed_failure
  -> prepare_daily_decision_brief_delivery
  -> exact target commit
  -> existing provider route
```

Verified:

- fixed reports use the full successful brief and mark the entire current identity set only after confirmation;
- candidate alerts use persisted pending identities and render at most three representative candidates;
- candidate rendering fails closed if an identity is absent from the immutable successful brief;
- half-hour display uses `scheduled_scan_target_market` when no fixed-report target exists;
- fixed failures never read or render previous successful current as the failed round;
- renderer changes do not rewrite an already persisted pending/ambiguous exact envelope.

### Query entry points

Traced:

```text
./om daily-brief latest
./om-agent daily_decision_brief_read
  -> resolve runtime root
  -> read_daily_brief_view
  -> canonical runtime-config scope selection for aggregate latest
  -> read_latest_daily_decision_brief per section
  -> render_query_brief
```

Verified:

- account+market latest remains a direct successful-current read;
- missing latest filters aggregate only configured account/market scopes;
- day/revision remains an operator read, with account required and the existing US market default preserved;
- aggregate sections remain isolated and do not merge funds;
- query paths call no scan, broker, sender, repository write, delivery confirmation, or candidate-state transition;
- tests preserve a delivery-state file byte-for-byte across aggregate query.

## Adversarial Failure Pass

Checked the following failure scenarios against code and tests:

1. **Fixed scan fails:** explicit failure text; no candidate snapshot; successful current unchanged.
2. **Half-hour candidate identity cannot be resolved:** renderer raises before durable envelope/target commit rather than sending an empty or wrong alert.
3. **More than three pending identities:** only three render and the remainder count directs the user to query; per-strategy config cannot silently suppress identities inside that top-three set.
4. **Funds missing or malformed:** user sees `暂不可用`; no total-assets fallback and no invented zero.
5. **One aggregate section missing:** available sections still render; top-level result is `partial` with a warning.
6. **No enabled scope matches:** returns explicit unavailable aggregate rather than guessing historical state directories.
7. **Historical/current query after validity or trading date:** stale/planning wording appears; revision stays structured-only.
8. **Existing delivery retry after renderer upgrade:** stored Markdown/key/hash remain the replay authority; no re-render path was introduced.
9. **CLI public compatibility:** day/revision keeps the prior US default; only `latest` gains optional aggregate filters.
10. **Agent contract regression:** pure-read and plugin contract/smoke suites pass with no required default scope.
