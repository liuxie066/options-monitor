## Findings

### CR-AGG-01-未修复-中-渲染预算截断会把真实有候选的策略误写成没有原始排序
- **入口/函数**: `build_daily_brief_user_view()` -> `_candidate_views()` -> `_ai_advice_lines_for_family()`
- **文件(行号)**: `src/application/daily_decision_brief_renderer.py:99-103, 149-189, 939-951, 981-1018`
- **输入场景**: canonical Brief 某策略族有候选且 AI status=`unavailable`；但另一个策略族的 material/AI-referenced
  rows 消耗共享 `_RenderBudget`，或该族因展示上限被完全截断。
- **实际分支**: `build_daily_brief_user_view()` 只把截断后的 flat `candidate_views` 放入 view；
  `_ai_advice_lines_for_family()` 再从这个 flat list 判断 `has_raw_candidates`。若该族所有 rows 被截断，值为
  `False`，尽管 canonical Brief 的原始排序真实存在且 `candidate_omissions` 还会说明未展开数量。
- **预期行为**: “是否存在策略原始排序”应由 canonical Brief 的完整 per-family candidate rows决定；显示预算只控制
  是否展开明细，不能把存在性改写为零候选。候选存在时应保留原有“以下仅展示策略原始排序”的降级说明，或至少不能
  声称没有可展示的原始排序。
- **实际行为**: 同一报告可同时出现“Covered Call 另有 N 个策略候选未展开”和“本轮没有可展示的策略原始排序”，
  形成事实矛盾。
- **直接证据**: 99-103 行执行共享预算选择；149-189 行未携带 canonical per-family existence；939-951 行只查
  view 的截断结果；981-1018 行的 `budget.take()` 可返回空 list 但仍记录 omission。新增 Slice 2 测试只覆盖未被预算
  截断的一有一无场景。
- **影响**: 在 material change 或 AI-referenced candidate 较多的合法输入上，用户会收到与候选事实相反的 AI 降级文案；
  这违反本 work unit 的“真实有候选行时保留现有降级说明”。
- **建议改法和验证点**: 在 `build_daily_brief_user_view()` 从 canonical mapping-shaped `brief["candidates"]`
  计算并携带一个仅供渲染的 private per-family presence map；`_ai_advice_lines_for_family()` 优先使用该 map，兼容直接
  flat-view 调用时再回退到现有检查。新增低 `max_candidates_per_strategy` + 大量 material Sell Put rows 使 Covered Call
  全部被截断的回归，断言 Covered Call 保留候选存在文案且 omission 不与文案矛盾；空族仍使用无排序文案。
- **修复风险（低/中/高）**: 低
