## Assumptions tested

1. S1 must freeze one trading date before expiration discovery and use it for discovery/cache identity, exact requests, row DTE, RV, raw metadata, and receipt evidence.
2. S1 may preserve the existing single-spec subprocess path, but S6 must remain the sole owner of multi-spec JSON parsing and subprocess exact-spec execution.
3. Generic snapshot loading must not import or parse the Close Advice plan owner; the composition/consumer boundary must retain typed Close Advice validation.
4. Generated dependency files are checked repository artifacts, not a new architecture owner or hand-maintained design surface.
5. Previously accepted S1 scope amendments remain out of this review; only the four named allowlist additions and their directly necessary validation were challenged.

## Adversarial lens results

### Architecture boundary review

- `required_data_planning.py` freezes the date once and passes it into expiration discovery. The actual discovery call and date-keyed expiration cache live in `opend_symbol_chain_fetching.py`; excluding that owner would leave a second ambient clock. Adding this file is ownership-correct and necessary.
- `required_data_snapshot.py` currently has no import on `close_advice_required_data.py`. Generic loading validates the snapshot schema/content hash/run/root and symbol evidence without parsing the optional Close Advice plan. Seal/reseal validates the attachment's safe relative path and exact bytes/hash as `RequiredDataSnapshotError`; `resolve_bound_close_advice_required_data_plan()` owns plan path/schema/run/content validation as `CloseAdviceRequiredDataPlanError`; `close_advice_runner.py` is the composition point and converts either integrity error into `snapshot_integrity_failed` before promotion.
- A read-only `scripts/generate_dependency_graph.py --check` reported only the two expected stale generated artifacts, with no parse, forbidden-import, or production-cycle error. Regenerating the two checked outputs from final S1 source is therefore the narrow mechanical scope needed to make the guard current.

### Best-practice review

- Explicit date injection is preferable to ambient clock reads at multiple layers and is covered by an exact CLI-forwarding test plus a provider test whose `raises` case fails on any ambient clock read.
- The snapshot/Close Advice split preserves one-way dependency direction and distinct typed errors at the generic artifact and business-plan boundaries.
- The planned graph regeneration and `--check` acceptance signal make the architecture claim reproducible rather than relying on a prose assertion.

### Optimal-solution review

- A scalar internal `--trading-date` bridge is the smallest compatible repair for the already-supported single-spec subprocess. A new public command, config key, schema, callback framework, neutral Close Advice schema module, or second snapshot abstraction would be broader without improving this S1 contract.
- Keeping business-plan parsing at the actual Close Advice consumer is simpler and safer than reintroducing a reverse import solely so the generic snapshot owner can understand an optional attachment.

### Overengineering review

- The amendment introduces no new provider call, cache, public `./om` surface, multi-spec payload, business schema, or orchestration state. The generated graph files are deterministic outputs of an existing checked generator.
- No evidence supports expanding S1 into S6's multi-spec parser/executor work.

### Overcoupling review

- Subprocess multi-spec is rejected before command creation/execution/finalization, while S6 explicitly retains the exact-spec JSON parser, multi-spec CLI plumbing, shared spot observation, and one-save/finalizer lifecycle. Adding a single date scalar does not pull those concepts into S1.
- Snapshot loading, attachment byte binding, and Close Advice semantic validation remain separately owned; `close_advice_runner.py` composes them without a production module cycle.

## Findings

No material findings. The four added allowlist entries are the narrowest ownership-correct scope found, and the amendment does not steal S6 work.

1. The subprocess dispatch regression currently proves that `--trading-date` is present and ISO-shaped, while exact equality is proven across the adjacent planning, CLI, and provider tests plus the direct data flow from the plan identity. Tightening that one assertion to the frozen discovery date would improve locality but is not a reason to add another production owner or pull S6 forward. Track in the S1 focused test pass.

Keep the existing strict publication rejection as the S1 boundary and track any offline migration outside S1; do not silently make the scheduled validator accept the legacy bundle.
