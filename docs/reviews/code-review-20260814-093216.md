### DR-S4-01-未修复-中-候选事件错误被统一改写为 current-shadow 错误，破坏既有公开错误契约

- **入口/函数**: `preflight_manual_open()` / close / adjust preflight -> `_preview_append_projection()`
- **文件(行号)**: `src/application/ledger/preflight.py:323-350`; base behavior at `5930e5ce:src/application/ledger/preflight.py:370-377,526-530,661-667`
- **输入场景**: 当前 ledger projection 合法，但本次候选 open、close 或 adjust 事件会产生 projection diagnostic，例如新 open 复用了现有 `lot_id`。
- **实际分支**: resumed candidate 先变为 ineligible 并安全回退 full preview；`_preview_append_projection()` 随后把 current 与 candidate diagnostics 合并，并无条件抛出 `ledger_shadow_invalid`。
- **预期行为**: 保留既有候选错误代码和 payload：open 为 `open_projection_invalid`，close 为 `close_projection_invalid`，adjust 为 `adjust_projection_invalid`，details 使用各自的 `errors`；只有当前历史本身无效时才返回 `ledger_shadow_invalid`，并分别报告 import/projection errors。
- **实际行为**: 三种候选错误都变成 `ledger_shadow_invalid`；同一合并后的错误列表还同时写入 `import_errors` 和 `projection_errors`，使调用方无法区分历史损坏与本次请求无效。
- **直接证据**: 新 helper 在 `preflight.py:331-349` 合并两阶段 diagnostics 后只构造一个错误分支；accepted S4 contract 在 `docs/gateflow/data-storage-runtime-projection-p3a/plan.md:1203-1207,1213-1220` 明确要求 resumed preflight 同时保留 public error parity。
- **影响**: CLI/自动化会把用户候选参数错误误判为 ledger 历史损坏，依赖稳定 error code/details 的恢复和提示分支会走错；操作仍 fail closed，不会产生数据损坏。
- **建议改法和验证点**: helper 先独立检查 current projection 的 effective import/domain diagnostics，再检查 candidate projection diagnostics；按调用方传入的既有 candidate error code/message/details shape 抛错。新增至少一个 candidate-invalid 回归，同时冻结 current-invalid 的 import/projection 分类和 fast/full 两种 preview 的错误一致性。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
