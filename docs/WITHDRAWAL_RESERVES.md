# 出金预扣与手动订正

PM Cash Flow 记录已提交出金，amount 为含手续费的预计总扣款金额，flow_date 为北京时间提交日。
OM 通过 PM `/api/v1/cash-flows` 完整读取账户事实；不直读飞书、不回写 PM 或券商余额。
需要提供该接口的 PM 版本及已安装 PM 插件，接口不可用时新增开仓容量不可用，不默认没有出金。

## 计算和匹配

现金总额 = 原币现金（含负数）+ 聚合基金 + 聚合在途；聚合字段只折算一次。
可用担保现金 = 现金总额 - 出金预扣 - 已占用担保。
初次发现最近七个自然日出金，停机后补查至上次成功覆盖日；已跟踪记录持续核对金融字段变化。
发现窗口外的历史待处理出金需要启用前核对。

匹配必须同券商、物理账户、环境、币种、金额，方向 OUT，清算日在提交日至当前日期之间。
明确的基金申购、期权指派等其他交易排除；自动只接受双向唯一的一对一对应。
匹配后正常读取有效资金并保存成功，解除预扣，不向现金加钱。
正常 OpenD 缓存可能短暂滞后于流水，这是已接受的时效取舍；不额外强制刷新。
账户缓存不能代替本轮 PM 出金核对。新口径不再叠加旧指派推断或货基凭证补计。

技术状态存储在 runtime root 的 `output_shared/state/withdrawal_reserves.sqlite3`，US/HK 共享账户状态，
与期权交易账本分开。预扣、流水占用、订正审计和读取进度在同一事务中保存。
只读查询不保存预扣；重新核对后仅可沿用已保存的保守金额，新增或增额未能保存时额度不可用。

## 失败与恢复

- PM、资金或状态不可用：额度显示 `—`，不用于新增开仓。
- 富途流水暂不可用或没有唯一对应：已有出金继续预扣；输入完整时可用保守额度。
- 已匹配、已平账、已取消记录发生金融字段变化：保留证据并暂停该账户开仓额度，不猜差额。
- 新增、增额或恢复预扣保存失败：容量不可用，不能沿用较低旧预扣。
- 只有单纯解除预扣保存失败且其他状态完整时，才保留原较高预扣继续计算。
- 记录删除不是取消；超过七天不会自动解除。金额、账户、币种、日期等是金融字段，备注不是。

## 手动订正

通过现有 `./om tools` 的 `withdrawal_correct` 工具，默认预览；确认受现有写工具门禁保护。
输入账户、PM record_id、action、reason、actor 及需要的 flow_ids；确认另需 expected_hash、operation_id、confirm=true。

- `settle`：指定真实 OUT，一笔或多笔合计等于含费金额；不能占用其他有效平账的流水。
- `restore`：撤销错误平账或取消，恢复当前版本全额预扣，转为人工待核对，不自动重新匹配。
- `cancel`：人工确认申请取消，解除预扣。已有匹配先处理争议，不把取消当作退款。

恢复预扣后，争议流水仍保留占用；人工为另一条记录指定该流水时，预览展示占用变化，在同一事务中转移。
预览展示预扣前后、来源与选定流水关联、资金证据；未读取担保时开仓总额度明确不可用，不猜测。
确认前重新取证并核对预览指纹，重复操作 ID 幂等。订正不改 PM amount、券商余额或期权账本。

## 对客文案

- 出金待确认｜HK$10,000 已预扣
- 出金核对失败｜HK$10,000 继续预扣
- 出金待核对｜HK$10,000 继续预扣
- 出金已扣款｜HK$10,000 暂保留预扣
- 出金记录不可用｜暂停自动开仓
- 担保现金不可用｜暂停自动开仓

金额使用既有 ¥ / HK$ / US$ 格式；不可用优先于普通等待提示，不新增推送。
