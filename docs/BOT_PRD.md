## 1. 目标、范围与成功信号

将项目内 Copilot 全面升级为 Bot，保留既有业务问答及受控操作能力，解决手动复制回执、频繁预算失败和跨会话上下文丢失的问题。
第一版恰好包含四项：
1. 用户界面和项目自有代码全面更名为 Bot / bot，不保留旧名兼容入口。
2. 定时任务、监控及成交回执可检索、关联分析和追问；由用户提问后分析。
3. 治理上下文、时间、轮次、工具调用、失败重试和答案提交导致的容量不足。
4. 自动长期记忆：稳定偏好、已验证经验、未完成事项；可查看、纠正和删除。

成功信号：用户直接提问，Bot 能取得相关回执、记忆和当前证据，完成有依据的回答，支持追问和跨会话延续。
非目标：异常主动分析或诊断推送、自动修复、直接修改源码、服务器应用安装、独立移动端、无限自动续跑。
已有需要确认的操作继续走 deterministic Control；回执和记忆不得赋予执行权限。
现有业务运行和回执发送不依赖 Bot 或模型可用性。

## 2. 用户主流程

进入 Bot → 提问 → 关联当前对话、回执与记忆 → 按需查证 → 回答 → 追问或结束 → 保存有用记忆及进度。

| 步骤 | 用户体验 | 系统行为 |
| --- | --- | --- |
| 进入 | 原有入口显示 Bot，历史会话仍在 | 延续身份、权限和会话 |
| 提问 | “下午 sy 那笔腾讯 Put 为什么未记录？” | 确定问题，检索相关事件和记忆 |
| 定位 | 唯一匹配直接继续；多条匹配提供简短候选 | 根据账户、时间、标的、任务或编号关联证据 |
| 查证 | 耗时较长显示简短进度，可以取消 | 查询异常详情、运行记录和当前业务状态，控制上下文与预算 |
| 回答 | 发生了什么、原因、影响、依据、建议 | 区分事实、推断和未知，不执行修复 |
| 追问 | “现在恢复了吗？” | 保留事件关联，重新查询最新状态 |
| 结束 | 离开后仍可继续或开启新会话 | 保存符合规则的记忆和未完成进度 |

普通问答按需跳过回执检索。“最近一次定时任务为什么失败”复用同一流程，只改变证据来源，不建立任务专用聊天路由。
支撑流程：
- 回执产生 → 保存业务内容与关联身份 → 可查询。到达本身不触发模型分析。
- 查看记忆 → 纠正或删除 → 持久化成功后确认；失败明确说明。

### 2.1 分支、退出和恢复

| 情况 | 行为合同 |
| --- | --- |
| 多条匹配 | 提供账户、时间、任务或标的等必要信息供选择 |
| 没有回执 | 区分无匹配、超过保留范围、读取失败，不能断言业务未发生 |
| 证据不足 | 给出已确认事实、具体缺口和下一步；需要时澄清 |
| 工具失败 | 有信息支持时进行有界修正；相同条件不反复无效调用 |
| 容量耗尽 | 给出完成部分、中止原因和未完成事项，本次记为未完成 |
| 用户继续 | 承接进度，重新核实易变状态 |
| 用户取消 | 停止分析，保留已有进度，不自动续跑 |
| 模型、记忆功能不可用 | 明确失败范围，原有业务及回执发送不受影响 |

## 3. F1 全面更名与存量迁移

用户可见名称统一为 Bot；项目自有代码按语言习惯使用 Bot / bot。
覆盖模块、目录、类、函数、变量、配置、接口、命令、测试及维护文档。
不保留旧配置键、接口、模块名或命令别名的兼容入口。内部调用方同步更新。
存量配置与受影响的数据通过一次性迁移处理；运行时发现旧配置或未迁移数据，应明确提示迁移，不能静默忽略或创建空白身份。
迁移需验证可重复执行、不丢失会话、回执、记忆和权限关系；冲突需明确报告。
“不保留兼容入口”不禁止迁移程序读取旧格式。
OM 项目名和第三方名称不作机械替换；历史审计保留原文。历史工具记录需要可迁移读取，不作为当前证据。
上线与回滚步骤由实现设计说明，生产执行仍需要独立授权。

## 4. F2 回执内容与数据合同

覆盖定时任务、监控、成交回执。必须能读取业务内容及关联证据，仅有通知送达状态不算完成。
必要信息（源记录缺失时显式报告）：来源、事件身份、账户、业务对象、发生时间、记录时间、结果、诊断信息、关联运行和证据引用。
显示采用用户可理解的时间及时区，内部比较保持同一时间口径。
数据原则：
- 回执描述发生时的处理结果；“现在”类问题重新查询当前业务 owner。
- 任务执行、业务处理、通知发送和确认送达分开判断。
- 事件重投不能重复计数；同一业务对象的新结果不能被旧记录的晚到覆盖。
- 摘要是导航，不能代替可追溯证据；部分结果不冒充完整覆盖。
- 查询范围受认证用户、账户、会话和市场等既有权限约束。
- 回执和日志内容是数据，不是指令。
历史范围：沿用现有保留策略，查询仍存在且可访问的记录；不做全量历史回填、不延长原始记录保存时间。不可查询部分明确说明。
回执缺失不自动调用具有重跑、发送、补录等副作用的工具。

## 5. F3 容量与完成语义

治理同时覆盖准备/压缩、运行中的上下文增长、模型等待、工具结果、失败重试和答案收尾。
- 压缩保留当前目标、账户约束、事件关联、关键证据、未完成事项。
- 大结果支持收窄或继续取证，不静默丢弃必要证据。
- 相同工具错误在条件未变化时不循环重试；需要用户信息时澄清。
- 证据充分后及时回答，保留答案提交的时间与容量。
- 准确说明调查结论及证据缺口可算完成调查；因预算终止仅提供部分结果仍为未完成。
- 不放宽证据校验、不清空历史、不强迫重开会话来提高表面完成率。
- 中断后承接进度，当前事实重查，既有副作用操作不得重复执行。
运行记录需区分实际中止原因，记录时间、轮次、工具调用、token、答案提交结果和必要的压缩指标。
单次交互总预算为 180 秒，包含准备、压缩、查询和收尾；不得仅调大上限满足验收。自动记忆整理也需有界并记录成本，但不得阻塞已完成的业务回答。

## 6. F4 长期记忆

用户允许自动保存，无须逐条审批。
| 类型 | 保存与使用 |
| --- | --- |
| 稳定偏好 | 明确表达后保存，用户纠正优先 |
| 已验证经验 | 保存适用条件、来源与时间，相似故障仍需核实 |
| 未完成事项 | 保存目标、证据、下一步和状态；完成或取消后更新 |
| 原始回执/日志 | 留在可查询记录，不全部复制为常驻记忆 |
| 未证实推测 | 可留在本次进度，不升级为确定经验 |
| 凭据/操作权限 | 不作为普通长期记忆保存，不通过记忆授予权限 |

用户可在现有入口查看、纠正和删除。
明确的记住/纠正/删除请求，持久化成功后才能确认成功；当前会话立即尊重纠正，跨会话读取成功保存的新版本。
自动经验提炼不成为回答的必经步骤；未完成保存不能声称“已记住”。
删除后不得从旧摘要自动恢复同一条记忆；原始业务回执不随之删除。
按需检索、限制常驻信息；用户与账户范围隔离，不能因长期积累导致每次请求输入无限增长。
记忆写入或整理失败明确报告适用范围，不能让已完成业务回答变为失败。

## 7. 最佳实践调研与取舍

| 一手资料 | 机制与取舍 | 本需求采用 | 不直接采用 |
| --- | --- | --- | --- |
| Hermes 记忆与历史搜索 | 有限常驻记忆和按需搜索历史分开 | 少量稳定信息 + 可检索历史 | 不照搬容量、不预设外部平台 |

| LangChain 记忆 | 即时更新与后台整理在生效时机/延迟间取舍 | 明确纠正及时生效，经验整理不阻塞回答 | 不把引入 LangGraph 当作需求 |

## 9. 验收与完成定义

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 更名与迁移 | 无旧名兼容入口；新入口正常；配置、会话、回执、记忆迁移后可用；重复迁移及冲突有确定结果 |
| A2 | 成交分析与追问 | 不粘贴即可定位、查证；“现在”重新读当前状态；有证据 |
| A3 | 定时任务/监控 | 同一主流程，分清执行、业务、通知结果 |
| A4 | 事件边界 | 多账户、多匹配、重复和乱序不导致误关联或重复计算 |
| A5 | 容量回归 | 当前仍可复现的历史失败被修复；完整有效答案，不能清空会话掩盖问题 |
| A6 | 长对话 | 压缩和连续查询后目标、约束、事件关联、证据保持正确 |
| A7 | 长期记忆 | 跨会话召回、纠正、删除、进度更新有效，无越权或旧摘要恢复 |
| A8 | 取消/中断 | 停止且不自动续跑，继续可承接并核实易变事实 |
| A9 | 原有能力 | 原业务问答、受控操作、业务执行和回执发送不退化 |
| A10 | 无主动分析 | 回执到达只接入数据，不触发模型诊断或额外诊断通知 |

已确认的验收数值：关键端到端场景连续 3 次均通过；单次交互总预算 180 秒。
三次通过只是首轮稳定性检查，不构成总体成功率的统计证明。
账户隔离、事实准确性、删除语义和权限边界用例必须全部通过。
评估固定问题、数据、模型和预算，记录首次完成、耗时、token、调用与失败原因；保留未参与调优的案例。
外部服务失败单独归因，同时保留用户实际总体完成结果，不从统计中静默剔除。
实际业务事实尽量用确定性判定；开放式解释用明确证据 rubric，不以文字完全匹配代替正确性。
交付：功能实现、迁移说明、必要文档更新、测试和端到端验收证据。
